## 单选题

<a name="LLM-POS-001"></a>

### LLM-POS-001　基础 · 考频 ★★★

为什么 Transformer 必须额外引入位置编码？下列解释最准确的是：

- **A.** 注意力的计算量随序列长度平方增长，位置编码让模型只关注附近 token，把计算量降下来
- **B.** 不含位置信息的自注意力对输入顺序置换等变，无法区分「狗咬人」与「人咬狗」
- **C.** Softmax 需要位置信息来确定归一化的顺序，否则每行注意力权重之和无法保证为 1
- **D.** 没有位置编码时，多头注意力的各个头会收到相同的输入，最终退化成完全相同的头

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：注意力本身把输入当成一个「集合」。

不加位置信息、也不加掩码时，第 $i$ 个 token 的输出是 $\sum_j\mathrm{softmax}_j(q_i\cdot k_j)\,v_j$，只取决于「自己是谁」和「集合里有哪些 token」。把输入顺序打乱，每个 token 的输出只是跟着换了位置，数值完全不变（置换等变）；FFN、归一化都是逐位置计算的，也不引入顺序。于是「狗咬人」和「人咬狗」中每个词看到的内容一模一样，必须额外注入位置信息。

- A 错：位置编码不改变计算量，也不会让注意力只看附近 token（限制注意力范围的是稀疏或窗口注意力）。
- C 错：权重和为 1 由 Softmax 本身保证，与位置、顺序无关。
- D 错：各头的输入虽然相同，但投影矩阵不同，不会因为缺少位置编码而退化成相同的头。

补充：Decoder-only 的因果掩码本身会泄露一些位置信息（第 $t$ 个位置恰好能看到 $t$ 个 token），有研究发现不加位置编码（NoPE）的因果语言模型也能学到位置，但显式位置编码在实践中稳定得多。

<sub>考点：绝对位置编码</sub>

</details>

<a name="LLM-POS-005"></a>

### LLM-POS-005　进阶 · 考频 ★

RoBERTa 的可学习绝对位置编码只有 512 个位置。Longformer 想基于 RoBERTa 继续预训练出一个支持 4096 长度的模型，它对新增位置编码的处理方式是：

- **A.** 把 RoBERTa 已学到的 512 个位置向量反复复制，作为 4096 个位置的初始化，再继续预训练
- **B.** 新增位置随机初始化，并冻结原有的 512 个位置向量，只训练新增的部分
- **C.** 不需要任何处理，可学习的位置编码可以直接查询第 513 及以后的位置
- **D.** 把 4096 个位置按比例映射回 0～511，与 RoBERTa 共用同一张位置表，不再训练

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：复制初始化 + 继续预训练。

Longformer 论文指出，BERT 类模型的注意力头有很强的「关注局部上下文」的偏好，所以把 512 个位置向量重复复制填满 4096 个位置：每个 512 窗口内的局部结构被完整保留，只在复制的边界处不连续，比随机初始化收敛快得多，之后再用长文本继续预训练。

- B 错：随机初始化丢掉了已学到的位置结构，冻结旧位置也没有必要。
- C 错：可学习位置编码是一张 $L_{max}\times d$ 的查找表，第 513 个位置根本没有向量可查，这是它的硬上限。
- D 错：这类似于对查找表做「插值」，但相邻位置会共用同一个向量，且不训练无法适应。

<sub>考点：可学习位置编码、长度外推　｜　出处：Longformer arXiv:2004.05150</sub>

</details>

<a name="LLM-POS-007"></a>

### LLM-POS-007　进阶 · 考频 ★★

关于 T5 的相对位置编码，下列描述正确的是：

- **A.** 为每个截断后的相对距离学习一个 $d$ 维向量，加到 key 和 value 的计算中
- **B.** 把相对距离乘以一个固定斜率后从注意力分数中减去，不含任何可学习参数
- **C.** 为每个头的每个距离桶学一个标量偏置加到 logits 上，远距离按对数分桶
- **D.** 把向量每两维看成一个复数，按位置旋转 query 和 key，使打分只依赖相对位置

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：T5 的相对位置编码是「分桶的标量偏置」。

T5 论文中每个位置「嵌入」只是一个标量，直接加到对应的注意力 logit 上；共 32 个桶，近距离一个距离一个桶，更远处桶的范围随距离按对数增大，直到距离 128，超过 128 的所有距离共用一个桶。每个头有自己的一组偏置。这样近距离分辨得细、远距离粗略处理，对比训练更长的输入也有一定泛化能力。

- A 错：这是 Shaw 等（2018）的相对位置表示。
- B 错：这是 ALiBi，斜率固定、不学习。
- D 错：这是 RoPE。

<sub>考点：相对位置编码　｜　出处：T5 论文 arXiv:1910.10683</sub>

</details>

<a name="LLM-POS-015"></a>

### LLM-POS-015　挑战 · 考频 ★

Meta 原始 Llama 代码用复数乘法实现 RoPE，把相邻两维 $(2i, 2i+1)$ 配成一对；Hugging Face 的实现用 `rotate_half`，把第 $i$ 维与第 $i+d/2$ 维配成一对。关于两者，下列说法正确的是：

- **A.** 两种配对只是实现方式不同，对同一组权重给出完全相同的输出，可以直接混用
- **B.** 两种配对的数学性质不同，只有相邻配对才满足打分只依赖相对位置，rotate_half 是近似
- **C.** rotate_half 方式需要额外学习一个维度映射矩阵，才能与相邻配对的结果对齐
- **D.** 两者只差一个固定的维度置换，转换权重时需重排 $W^Q$、$W^K$ 的输出维度

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：两种配对都是合法的 RoPE，但对**同一组权重**是不同的函数。

只要 $q$ 和 $k$ 用同一种配对，打分就只依赖相对位置。区别在于「哪两维被当成一对旋转」：相邻配对旋转 $(x_{2i},x_{2i+1})$，`rotate_half` 旋转 $(x_i,x_{i+d/2})$。如果对 $W^Q$、$W^K$ 的输出维度（即每个头内部的维度顺序）做一次固定重排，把原来的 $(2i,2i+1)$ 挪到 $(i,i+d/2)$，两种实现的打分就完全一致。Hugging Face 的 Llama 权重转换脚本里正是用一个 `permute` 函数做这件事。

- A 错：不做重排直接加载，模型等于用错误的配对旋转，输出会严重失真。
- B 错：两种配对都是精确的 RoPE，只要 $q$、$k$ 用同一种配对，打分就只依赖相对位置。
- C 错：只需要一次固定的维度置换，不需要任何新参数。

实践提醒：自己移植模型或混用不同框架的 RoPE 实现时，要确认配对方式与权重格式一致；V 和 $W^O$ 不受 RoPE 影响，不需要重排。

<sub>考点：RoPE实现与基频</sub>

</details>

<a name="LLM-POS-018"></a>

### LLM-POS-018　进阶 · 考频 ★★

把 RoPE 的 base 从 10000 调大到 500000（头维度 128 不变），下列关于其效果的说法，正确的是：

- **A.** 所有维度的旋转频率都等比例降低 50 倍，相当于把位置编号统一除以 50 的位置插值
- **B.** 最高频维度不变，越低频的维度降得越多，最低频维度的波长从约 5.4 万变为约 256 万
- **C.** base 只影响位置编码的数值精度，调大可减少半精度下的舍入误差，与上下文长度无关
- **D.** 调大 base 后低频维度不再出现越界角度，模型无需长文本训练就能处理 50 倍长的上下文

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：改 base 是一种**非均匀**的频率缩放。

第 $i$ 对的频率变为原来的 $(500000/10000)^{-2i/d}=50^{-2i/128}$：$i=0$ 时为 1（不变，$\theta_0=1$）；$i=32$ 时约 $1/7.1$；$i=63$ 时约 $1/47$，最低频维度的波长从约 5.4 万个 token 变为约 256 万个 token。高频几乎不动、低频大幅变慢，这与 NTK-aware 缩放「改 base 而不改位置」的思路一致。

- A 错：所有频率统一除以同一个数是位置插值（PI）的效果。
- C 错：base 决定最低频的波长，直接影响远距离位置能否被区分，是长上下文的关键超参数。
- D 错：改了 base，模型在训练中见过的角度分布也变了，必须用长文本（继续）训练。Meta 的 Llama 2 Long 工作就是把 base 从 10000 调到 500000，再做长文本继续预训练。

<sub>考点：RoPE实现与基频、长度外推　｜　出处：Effective Long-Context Scaling of Foundation Models（Xiong 等, 2023）arXiv:2309.16039</sub>

</details>

<a name="LLM-POS-019"></a>

### LLM-POS-019　基础 · 考频 ★★

ALiBi（Attention with Linear Biases）是如何注入位置信息的？

- **A.** 把可学习的位置向量加到每一层的 query 和 key 上，让各层都能直接感知位置
- **B.** 按相对距离旋转 query 和 key，使点积只依赖相对位置，距离越远旋转角越大
- **C.** 在输入层给词向量加正弦位置编码，并在注意力中硬截断超出窗口的远处 token
- **D.** 不加位置向量，而是在注意力分数上减去与距离成正比的惩罚，斜率按头固定

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：ALiBi 的打分为
$$\mathrm{score}(i,j)=\frac{q_i\cdot k_j}{\sqrt{d_k}}-m_h\,(i-j),\quad j\le i$$
不给输入加任何位置向量，也没有可学习参数。斜率按头取等比数列（8 个头时为 $1/2,1/4,\dots,1/256$）：斜率大的头只看附近，斜率小的头能看得远。

Train Short, Test Long（Press 等, 2022）报告：在 1024 长度上训练的 13 亿参数模型，在 2048 长度上的困惑度与直接在 2048 上训练的正弦编码模型相当，且训练更快、更省显存。BLOOM、MPT 采用了 ALiBi。

- A 错：那是可学习位置编码的变体。
- B 错：那是 RoPE。
- C 错：ALiBi 不使用正弦编码，也没有硬截断，而是「软」的线性扣分。

<sub>考点：ALiBi　｜　出处：ALiBi 论文 arXiv:2108.12409</sub>

</details>

<a name="LLM-POS-022"></a>

### LLM-POS-022　进阶 · 考频 ★★★

一个使用 RoPE、在 4K 长度上训练的模型，不做任何处理直接处理 16K 的输入，困惑度急剧上升。从 RoPE 各维度的角度看，最主要的原因是：

- **A.** 低频维度在 4K 内连一圈都没转完，16K 时出现训练中没见过的旋转角度
- **B.** 高频维度转得太快，16K 时的累计角度过大，超出了半精度浮点数的表示范围
- **C.** RoPE 预先计算的位置参数表只有 4K 行，更远的位置只能复用最后一行的旋转参数
- **D.** 所有维度的旋转角度都被放大 4 倍，注意力打分整体变为原来的 4 倍，Softmax 因此饱和

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：问题出在低频维度的「角度越界」。

第 $i$ 对维度在位置 $m$ 的角度是 $m\theta_i$。高频维度（波长远小于 4K）在训练中已转过很多圈，$[0,2\pi)$ 内的角度都见过，16K 时的新位置只是重复见过的角度；低频维度（波长大于 4K）在训练中只转到 $4096\,\theta_i$，16K 时角度变为 4 倍，是从未见过的取值，注意力行为失常。一个例子（头维度 64、训练长度 2048、扩展 4 倍）：最低频维度的角度上限从 0.273 弧度涨到 1.092 弧度。

- B 错：角度只是一个实数，cos / sin 是周期函数，不存在「超出表示范围」；高频维度反而最安全。
- C 错：RoPE 没有可学习的参数表，cos / sin 缓存也可以按需扩展，任何位置都能算出角度；有硬上限的是可学习绝对位置编码。
- D 错：旋转不改变向量长度，打分不会整体放大；角度变大的只是位置更远的 token。

<sub>考点：长度外推、RoPE原理</sub>

</details>

<a name="LLM-POS-025"></a>

### LLM-POS-025　基础 · 考频 ★★

位置插值（Position Interpolation, PI）把训练长度 $L$ 扩展到 $L'=sL$ 的做法是：

- **A.** 把 RoPE 的 base 乘以 $s^{d/(d-2)}$，位置编号保持不变，高频维度几乎不受影响
- **B.** 只对低频维度插值，高频维度保持不变，并给注意力 logits 乘一个温度系数
- **C.** 把所有位置编号除以 $s$，使最大位置落回训练范围，再用少量长文本微调
- **D.** 把训练时没见过的位置当作新的可学习参数，用长文本从零训练这些位置的编码

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：PI 改的是**位置**：把所有位置编号除以 $s$（$m\to m/s$），等价于把所有频率统一除以 $s$。

最远位置 $sL-1$ 被映射到 $L-1/s$ 附近，所有维度的角度都落回训练时见过的范围，不再越界。代价是相邻 token 的角度差也缩小为 $1/s$，高频维度对近距离的分辨率下降，所以需要短暂微调来适应。Chen 等（2023）用约 1000 步微调就把 Llama 从 2048 扩展到 32768。

- A 错：那是 NTK-aware 缩放（改 base、不改位置）。
- B 错：那是 YaRN（分段插值 + 注意力温度）。
- D 错：RoPE 没有位置参数，PI 也不引入新参数。

<sub>考点：位置插值　｜　出处：Extending Context Window of Large Language Models via Positional Interpolation arXiv:2306.15595</sub>

</details>

<a name="LLM-POS-030"></a>

### LLM-POS-030　进阶 · 考频 ★★

关于 YaRN（Yet another RoPE extensioN method），下列描述正确的是：

- **A.** 把所有位置统一除以扩展倍数 s，并且完全不需要训练
- **B.** 只把 base 放大为 $\mathrm{base}\cdot s^{d/(d-2)}$，对所有维度做平滑的非均匀缩放
- **C.** 为超过训练长度的位置新增可学习的位置向量，并用长文本训练它们
- **D.** 按每个维度的波长与训练长度之比分段：高频维度不插值、低频维度完全插值、中间平滑过渡，并给注意力 logits 乘一个随 s 增大的系数

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：YaRN = 按维度分段的插值（NTK-by-parts）+ 注意力温度修正。

对第 $i$ 对维度计算 $r_i=L/\lambda_i$（训练长度内转了几圈）：$r_i$ 很大（高频，转了很多圈）的维度不插值，保留近距离分辨率；$r_i<1$（低频，一圈都没转完）的维度按 PI 完全插值，消除越界角度；中间线性过渡。另外按 $\sqrt{1/t}=0.1\ln s+1$ 放大 $q$、$k$，抵消上下文变长、插值之后注意力分布变「平」的问题。少量微调（论文中约为预训练数据的 0.1%）即可得到很好的长上下文效果。

- A 错：这是 PI，而且 PI 也需要微调。
- B 错：这是 NTK-aware 缩放。
- C 错：RoPE 没有位置参数，YaRN 也不引入新参数。

<sub>考点：YaRN　｜　出处：YaRN 论文 arXiv:2309.00071</sub>

</details>

<a name="LLM-POS-034"></a>

### LLM-POS-034　进阶 · 考频 ★★

要把基座模型的上下文从 8K 扩展到 128K，下列长上下文训练做法中最合理的是：

- **A.** 从预训练第一步起就全部使用 128K 长度的序列，让模型尽早适应长依赖，省去后期扩展
- **B.** 在预训练后期分阶段增大序列长度并调整 RoPE，使用长度上采样的长文本并保留部分短文本
- **C.** 只需按目标长度调大 RoPE base 或做位置插值，长上下文能力不需要额外的长文本训练
- **D.** 长上下文训练只用长文本，完全去掉短文本，避免模型被短文本「拉回」短上下文

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：「先短后长、分阶段扩展、长短混合」是主流做法：在预训练后期分阶段增大序列长度（同时调大 RoPE base 或配合插值），使用经过长度上采样、领域均衡的长文本，并保留一定比例的短文本。

Llama 3 技术报告写明：注意力的计算量随序列长度平方增长，所以不在预训练早期使用长序列；在预训练的最后阶段分步增加上下文长度，Llama 3 405B 从 8K 起分 6 个阶段扩展到 128K，共用了约 8000 亿 token；每个阶段以「短上下文评测完全恢复」且「大海捞针在该长度上全部通过」作为适配成功的标准。Fu 等（2024）的研究发现，在 128K 上的检索能力只需约 5 亿～50 亿 token 的继续预训练就能获得，关键在于按来源做长度上采样并保持领域均衡。

- A 错：从头用 128K 训练极其昂贵，而且早期训练并不需要那么长的依赖。
- C 错：位置编码只是前提，有效的长上下文能力必须靠长文本训练获得。
- D 错：完全去掉短文本会让短上下文能力退化，实践中都会保留短数据并监控短上下文基准。

**解析：**

- C 错：RULER 正是在不同长度（如 4K～128K）上评测的长上下文基准。

<a name="LLM-POS-043"></a>

### LLM-POS-043　进阶 · 考频 ★★

Qwen2-VL 提出的多模态旋转位置编码 M-RoPE 把每个 token 的位置拆成时间（t）、高（h）、宽（w）三个分量。关于它的编号规则与实现，下列说法正确的是：

- **A.** 图像中的每个视觉 token 按它在整个输入序列中的下标编号，t、h、w 三个分量都取这个下标，与一维 RoPE 的做法完全相同
- **B.** 文本 token 的 t、h、w 三个分量取互不相同的值，这样文本也能获得二维空间信息，与图像共用同一套空间坐标
- **C.** 文本的三个分量相同；同一张图内视觉 token 的时间分量相同，高、宽分量取行号、列号加起始偏移
- **D.** t、h、w 三个分量各自用完整的头维度做一次旋转，再把三次旋转后的 q、k 相加，作为最终参与注意力计算的 q、k

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：M-RoPE 对文本「退化」为一维 RoPE，对视觉 token 用（行、列）编码空间位置，并用「最大编号 + 1」衔接下一段内容。

编号规则（Qwen2-VL 论文与 Hugging Face 的 `get_rope_index` 实现）：
- 文本：三个分量相同、逐个加 1，与普通 RoPE 等价，纯文本能力不受影响；
- 图像：时间分量固定为起始偏移 $s$，高、宽分量为 $s+i$、$s+j$（$i$、$j$ 为合并后视觉 token 的行号、列号）；
- 视频：在图像规则的基础上，时间分量随帧（时间网格）递增；
- 下一段内容的起点 = 此前所有 token 三个分量中的最大值 + 1。一张 $h\times w$ 个视觉 token 的图只「消耗」约 $\max(h,w)$ 个位置号，而不是 $h\times w$ 个。论文认为这降低了图像与视频的位置编号，有利于推理时外推到更长的序列。

频率如何分配：头维度 128 共有 64 对旋转频率，Qwen2-VL 按 `mrope_section = [16, 24, 24]` 把它们分成三段，分别用 t、h、w 的编号计算旋转角，三个分量共用一个头维度。

- A 错：这是一维 RoPE 的做法，丢掉了二维空间结构，位置号还会随视觉 token 数线性增长。
- B 错：文本三个分量相同，正是为了与一维 RoPE 兼容。
- D 错：三个分量占用头维度中不同的频率段，而不是各自做完整的旋转再相加。

<sub>考点：多模态位置编码、RoPE原理　｜　出处：Qwen2-VL arXiv:2409.12191；Hugging Face transformers 中 Qwen2-VL 的 get_rope_index 与 apply_multimodal_rotary_pos_emb 实现</sub>

</details>

### LLM-POS-003　进阶 · 考频 ★★

关于原始 Transformer 的正弦位置编码 $PE_{(pos,2i)}=\sin(pos/10000^{2i/d})$、$PE_{(pos,2i+1)}=\cos(pos/10000^{2i/d})$，下列说法**正确**的有：

- **A.** 对任意固定偏移 $k$，$PE_{pos+k}$ 可由 $PE_{pos}$ 经线性变换（逐对旋转）得到
- **B.** 各维度对的波长从 $2\pi$ 到约 $10000\cdot2\pi$ 成等比数列，编号小的维度转得快
- **C.** 它是确定性函数、没有可学习参数，理论上可以为任意位置生成编码
- **D.** 既然平移可写成线性变换，用正弦位置编码的模型在远超训练长度的序列上也能外推得很好
- **E.** 正弦位置编码在每一层注意力之前都会重新加一次，以免位置信息在深层被冲淡

<details>
<summary>答案与解析</summary>

**答案：ABC**

**解析：**

**结论**：A、B、C 正确。

- A 对：每对 $(\sin,\cos)$ 平移 $k$ 相当于乘一个固定的 $2\times2$ 旋转矩阵，原论文正是希望模型借此学会关注相对位置。
- B 对：第 $i$ 对的波长为 $2\pi\cdot10000^{2i/d}$，从 $2\pi$ 增长到接近 $10000\cdot2\pi$，像一组转速不同的表针。
- C 对：它是确定性的函数，没有参数，任何位置都能算出编码。
- D 错：「能算出编码」不等于「能外推」。位置向量与词向量混合后再经投影，模型学到的模式在没见过的位置上并不可靠；ALiBi 论文的实验显示，正弦编码模型超过训练长度后困惑度迅速上升。
- E 错：原始 Transformer 只在输入层把位置编码加到词向量上一次（RoPE 才是每层都施加）。

### LLM-POS-009　进阶 · 考频 ★★

下列关于各类「相对位置」方案的说法，**正确**的有：

- **A.** 各类相对位置方案都要在打分时显式构造 $T\times T$ 的偏置矩阵，显存随长度平方增长
- **B.** T5 的相对位置偏置为每个距离单独学一个标量，能区分任意远的距离，外推不受影响
- **C.** ALiBi 在注意力分数上减去与距离成正比的惩罚，各头的斜率是固定的、不需要学习
- **D.** RoPE 只按每个 token 自己的绝对位置旋转 q、k，已缓存的 K 不需要随新 token 更新
- **E.** Shaw 等（2018）为截断后的相对距离学习向量表示，加到 key（以及 value）的计算中

<details>
<summary>答案与解析</summary>

**答案：CDE**

**解析：**

**结论**：C、D、E 正确。

- A 错：RoPE 不需要任何 $T\times T$ 偏置矩阵；ALiBi 的偏置可以在注意力内核中按需计算（FlashAttention 支持 ALiBi）；需要显式偏置矩阵的主要是 T5 这类查表式偏置。

- D 对：相对位置在点积中「自然出现」。这是 RoPE 的工程优势：位置操作逐 token 完成，K 写进 KV Cache 后就不用再动。
- E 对：Shaw 等把距离截断在 $[-k,k]$，每个距离对应一个可学习向量 $a_{ij}^K$、$a_{ij}^V$。

### LLM-POS-012　基础 · 考频 ★★

关于 RoPE，下列说法**正确**的有：

- **A.** RoPE 在每一层的 Q、K 投影之后都要施加，而不是只在输入层施加一次
- **B.** RoPE 引入了与最大序列长度成正比的可学习参数
- **C.** RoPE 把位置向量加到词向量上，因此需要一张可学习的位置表
- **D.** RoPE 只作用于 Q 和 K，不作用于 V
- **E.** RoPE 的「远程衰减」来自旋转时按相对距离缩短 q、k 的长度，距离越远，向量越短

<details>
<summary>答案与解析</summary>

**答案：AD**

**解析：**

**结论**：A、D 正确。

- A 对：RoPE 作用在每层的 Q、K 上，打分才能在每一层都只依赖相对位置。
- B、C 错：RoPE 不加位置向量，也没有任何可学习参数，cos / sin 表由公式直接算出，各层共用。
- D 对：位置信息只需要体现在打分 $q\cdot k$ 中；V 是被加权求和的「内容」，旋转它反而会让输出与位置耦合。
- E 错：RoPE 是纯旋转，每对维度乘的都是正交矩阵，施加前后向量长度不变，只改变方向（而且旋转角度由各自的绝对位置决定）。RoPE 论文所说的「远程衰减」是指：各维度对的频率不同，相对距离增大时各分量的相位逐渐错开，点积的上界随之减小，并不是缩短了向量。

- D 错：只用短文本训练，模型从未见过长距离的相对位置和长依赖，无法学会利用它们。
- E 对：长上下文扩展常见的副作用是短上下文能力下降，两类评测都要看。

### LLM-POS-021　基础 · 考频 ★★

ALiBi 让注意力分数随距离线性衰减，因此它特别擅长从很长的上下文中精确取回远处的某条信息（如大海捞针）。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

<a name="LLM-POS-029"></a>

### LLM-POS-029　进阶 · 考频 ★

「动态 NTK」（Dynamic NTK）根据当前输入的实际长度实时计算缩放倍数：当输入长度不超过原始训练长度时，RoPE 与不做缩放时完全一致，短文本的效果不受影响。

## 填空题

<a name="LLM-POS-010"></a>

### LLM-POS-010　基础 · 考频 ★★★

二维 RoPE 中，位置 $m$ 的旋转矩阵为 $R_m=\begin{pmatrix}\cos m\theta&-\sin m\theta\\ \sin m\theta&\cos m\theta\end{pmatrix}$。位置 $m$ 的 query 与位置 $n$ 的 key 旋转后的点积可以写成 $(R_mq)^\top(R_nk)=q^\top R_x\,k$，其中下标 $x=$ ____，可见点积只依赖于两者的____。

<details>
<summary>答案与解析</summary>

**答案：** (1) n-m / n − m / -(m-n)；(2) 相对位置 / 相对距离 / 位置差

**解析：**

旋转矩阵是正交矩阵，$R_m^\top=R_{-m}$；两次旋转的角度可以相加，$R_{-m}R_n=R_{n-m}$。所以
$$(R_mq)^\top(R_nk)=q^\top R_m^\top R_n\,k=q^\top R_{n-m}\,k$$
绝对位置 $m$、$n$ 被消掉，只剩相对位置 $n-m$。

例如 $\theta=30^\circ$：$q$ 在位置 3（转 $90^\circ$）、$k$ 在位置 1（转 $30^\circ$），夹角多出 $60^\circ$；挪到位置 7 和 5，多出的夹角仍是 $60^\circ$，点积不变。推广到 $d$ 维时，把向量分成 $d/2$ 对，第 $i$ 对用频率 $\theta_i=\mathrm{base}^{-2i/d}$ 各自旋转。

<sub>考点：RoPE原理</sub>

</details>

### LLM-POS-031　进阶 · 考频 ★

YaRN 把注意力 logits 除以温度 $t$，并建议取 $\sqrt{1/t}=0.1\ln s+1$（$s$ 为扩展倍数），实现时把 $q$、$k$ 都乘以 $\sqrt{1/t}$。当 $s=16$ 时，$\sqrt{1/t}\approx$ ____（保留 4 位小数），注意力 logits 整体被放大为原来的约 ____ 倍（保留 2 位小数）。

## 计算题

<a name="LLM-POS-017"></a>

### LLM-POS-017　进阶 · 考频 ★★

RoPE 第 $i$ 对维度的频率为 $\theta_i=\mathrm{base}^{-2i/d}$，波长（转一整圈所需的 token 数）为 $\lambda_i=2\pi/\theta_i$。设头维度 $d=128$：
(1) base = 10000 时，最高频（$i=0$）与最低频（$i=63$）的波长分别是多少？
(2) Llama 3 把 base 调到 500000 后，最低频的波长变成多少？
(3) 这对长上下文有什么意义？

<details>
<summary>答案与解析</summary>

**答案：(1) 最高频约 6.28 个 token，最低频约 5.44 万个 token；(2) 约 256 万个 token；(3) 低频维度转得更慢，在更长的距离内角度仍不重复，为长上下文留出余量**

**解析：**

**(1)** $\theta_0=1$，$\lambda_0=2\pi\approx6.28$（与 base 无关）。$\theta_{63}=10000^{-126/128}\approx1.155\times10^{-4}$，$\lambda_{63}=2\pi\times10000^{0.984375}\approx2\pi\times8660\approx5.44\times10^4$。

**(2)** $\lambda_{63}=2\pi\times500000^{0.984375}\approx2\pi\times4.07\times10^5\approx2.56\times10^6$，约 256 万个 token。

**(3)** 高频维度负责分辨近距离，几个 token 就转一圈；低频维度负责远距离。若最长波长比上下文短，远处的位置会与近处的位置「撞角度」，难以区分；调大 base 让最慢的表针转得更慢，长距离内仍可区分。但调大 base 不是免费的外推：模型仍需要在目标长度上用长文本训练，才能学会使用这些角度。Llama 3 用 base = 500000 预训练，再通过长上下文继续训练支持 128K（Llama 3.1）。

<sub>考点：RoPE实现与基频</sub>

</details>

### LLM-POS-023　挑战 · 考频 ★

头维度 $d=128$ 的 RoPE 模型在长度 $L=4096$ 上训练，第 $i$ 对维度（$i=0,\dots,63$）的波长为 $\lambda_i=2\pi\cdot\mathrm{base}^{2i/d}$。
(1) base = 10000 时，有多少对维度在训练长度内连一整圈都没转完（$\lambda_i>L$）？
(2) base = 500000 时呢？
(3) 这些维度为什么是长度外推的关键？

<details>
<summary>答案与解析</summary>

**答案：(1) 18 对（i = 46～63）；(2) 32 对（i = 32～63）；(3) 它们在训练中只见过一部分角度，推理长度超过 L 后会出现没见过的角度**

**解析：**

**(1)** $\lambda_i>L\iff\mathrm{base}^{i/64}>\dfrac{4096}{2\pi}\approx651.9\iff\dfrac{i}{64}>\dfrac{\ln651.9}{\ln10000}=\dfrac{6.480}{9.210}\approx0.7036\iff i>45.03$，即 $i=46,\dots,63$，共 **18 对**。

**(2)** $\dfrac{i}{64}>\dfrac{\ln651.9}{\ln500000}=\dfrac{6.480}{13.122}\approx0.4938\iff i>31.6$，即 $i=32,\dots,63$，共 **32 对**。

**(3)** 这些维度在训练中只见过 $[0,L\theta_i)$ 范围内的角度。推理长度超过 $L$ 时，它们会出现从未见过的角度；而波长小于 $L$ 的维度已经转过完整的圈，新位置只会产生见过的角度。所以 PI、NTK-aware、YaRN 本质上都是在处理这部分低频维度，YaRN 正是对 $\lambda_i>L$ 的维度做完全插值。

注意：base 越大，这类维度反而越多（18 对 → 32 对）。调大 base 本身不能免训练地解决外推，它要配合在目标长度上的长文本继续训练，让模型见到并学会使用这些更慢变化的角度。

<a name="LLM-POS-028"></a>

### LLM-POS-028　挑战 · 考频 ★★

<details>
<summary>答案与解析</summary>

**答案：(1) base′ = base · s^{d/(d−2)}；(2) 约 40890；(3) 约 1/2.02**

**解析：**

**(1)** 最低频 $\theta_{d/2-1}=\mathrm{base}^{-(d-2)/d}$。要求 $\mathrm{base}'^{-(d-2)/d}=\mathrm{base}^{-(d-2)/d}/s$，即 $(\mathrm{base}'/\mathrm{base})^{(d-2)/d}=s$，得
$$\mathrm{base}'=\mathrm{base}\cdot s^{d/(d-2)}$$
最高频 $\theta_0=\mathrm{base}^0=1$，与 base 无关，自动保持不变。

**(2)** $4^{128/126}=4^{1.0159}\approx4.089$，$\mathrm{base}'\approx40890$。

**(3)** 第 $i$ 对的压缩倍数为 $(\mathrm{base}'/\mathrm{base})^{2i/d}=s^{2i/(d-2)}$。$i=32$ 时 $4^{64/126}\approx2.02$，频率变为原来的约 $1/2.02$。

所以 NTK-aware 的压缩倍数从高频的 1 平滑增加到低频的 $s$：高频维度（负责近距离分辨）几乎不受影响，这正是它比 PI 好的地方。名字中的 NTK 来自神经正切核理论的直觉：网络难以从被压缩的高频信息中学习，所以应尽量保留高频。

<sub>考点：NTK-aware缩放</sub>

## 代码输出题

<a name="LLM-POS-002"></a>

### LLM-POS-002　进阶 · 考频 ★★

下面的代码计算原始 Transformer 正弦位置编码（$d=64$）中不同位置之间的点积。输出是什么？

```python
import numpy as np

def sinusoid(pos, d=64):
    i = np.arange(d // 2)
    ang = pos / 10000 ** (2 * i / d)
    pe = np.empty(d)
    pe[0::2], pe[1::2] = np.sin(ang), np.cos(ang)
    return pe

dot = lambda a, b: round(float(sinusoid(a) @ sinusoid(b)), 3)
print(dot(10, 15), dot(100, 105))
print(dot(10, 5), dot(10, 10))
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
23.504 23.504
23.504 32.0
```

**解析：**

每对维度贡献 $\sin(a\omega_i)\sin(b\omega_i)+\cos(a\omega_i)\cos(b\omega_i)=\cos\big((a-b)\omega_i\big)$，所以
$$PE_a\cdot PE_b=\sum_{i=0}^{d/2-1}\cos\big((a-b)\omega_i\big)$$

- **只依赖偏移**：(10, 15) 与 (100, 105) 的偏移都是 5，点积相同。
- **分不清方向**：余弦是偶函数，偏移 +5 与 −5 的点积完全一样，所以 `dot(10, 5)` 也是 23.504。
- **自身点积**：每对 $\sin^2+\cos^2=1$，共 32 对，所以 `dot(10, 10)` 为 32.0。

这说明正弦编码向量**本身**带有干净的相对位置结构，但在模型里，它先与词向量相加，再经过 $W^Q$、$W^K$ 投影，$(x_i+p_i)^\top W^{Q\top}W^K(x_j+p_j)$ 中出现了词与位置的交叉项，$p_i^\top W^{Q\top}W^Kp_j$ 一般也不再只是 $i-j$ 的函数，相对位置在打分中并不「干净」。这正是后来出现相对位置编码和 RoPE 的动机之一。

<sub>考点：绝对位置编码</sub>

### LLM-POS-016　进阶 · 考频 ★★

下面的代码把几个位置编号直接存成 BF16。输出是什么？这对 RoPE 的实现有什么启示？

```python
import torch

pos = torch.tensor([255.0, 257.0, 4097.0, 100001.0], dtype=torch.bfloat16)
print(pos.tolist())
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
[255.0, 256.0, 4096.0, 99840.0]
```

**解析：**

BF16 只有 8 位有效二进制位（7 位尾数加 1 位隐含位）。区间 $[2^k,2^{k+1})$ 内相邻可表示数的间隔为 $2^{k-7}$：
- 255 在 $[128,256)$ 内，间隔 1，可以精确表示；
- 257 在 $[256,512)$ 内，间隔 2，恰好落在 256 与 258 中间，按「就近舍入到偶数」得到 256；
- 4097 在 $[4096,8192)$ 内，间隔 32，舍入为 4096；
- 100001 在 $[65536,131072)$ 内，间隔 512，最近的可表示数是 $195\times512=99840$。

**启示**：BF16 连位置编号本身都存不准，更不用说角度 $m\theta_i$。最高频维度 $\theta_0=1$ 时角度就等于位置，误差上百弧度意味着 cos / sin 完全错乱。所以 RoPE 的角度必须在 FP32（或更高精度）下计算，算好 cos / sin 后再转成模型精度。Hugging Face 的实现会在计算角度时强制使用 FP32 并关闭自动混合精度。即使是 FP32，位置到百万量级时间隔也会达到 0.06 左右，超长上下文时要留意角度精度。

### LLM-POS-045　进阶 · 考频 ★

Qwen2.5-VL 把视频的时间位置编号与绝对时间对齐：每 `temporal_patch_size` 帧合成一个时间网格，一个网格覆盖 `temporal_patch_size / fps` 秒；第 $i$ 个网格的时间编号为「$i\times$ 每格秒数 $\times$ `tokens_per_second`」取整（官方配置中 `temporal_patch_size = 2`、`tokens_per_second = 2`）。下面的代码按不同的采样帧率计算各网格的时间编号。输出是什么？

```python
def t_ids(n_grids, fps, temporal_patch_size=2, tokens_per_second=2):
    sec_per_grid = temporal_patch_size / fps     # 每个时间网格覆盖的秒数
    return [int(i * sec_per_grid * tokens_per_second) for i in range(n_grids)]

a = t_ids(4, fps=2.0)
b = t_ids(2, fps=1.0)
c = t_ids(3, fps=0.5)
print(a, b, c)
print(a[2] == b[1], c[-1])
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
[0, 2, 4, 6] [0, 4] [0, 8, 16]
True 16
```

**解析：**

- fps = 2：每格 1 秒，编号步长 $1\times2=2$，得到 `[0, 2, 4, 6]`；
- fps = 1：每格 2 秒，步长 4，得到 `[0, 4]`；
- fps = 0.5：每格 4 秒，步长 8，得到 `[0, 8, 16]`；
- `a[2] == b[1]`：fps = 2 的第 2 格与 fps = 1 的第 1 格都从第 2 秒开始，编号都是 4，输出 `True`；`c[-1]` 为 16（第 8 秒）。

**含义**：无论按什么帧率采样，同一时刻对应同一个时间编号（每秒 2 个编号单位），模型能从编号的间隔读出真实时间的流逝，回答「第几秒发生了什么」。Qwen2-VL 的 M-RoPE 只按网格序号递增，不同帧率下同样的编号间隔代表的时长不同。

**代价**：编号随视频时长而不是 token 数增长。1 小时的视频，最后的时间编号约为 $3600\times2=7200$，而采样到的网格可能只有几百个，编号又大又稀疏；要学会这种对齐，还需要覆盖多种帧率的训练数据。Qwen3-VL 技术报告正是因为这两点，改为在每个时间片前插入「<3.0 seconds>」这样的文本时间戳。

补全 Hugging Face 风格的 RoPE 实现：第 $i$ 维与第 $i+d/2$ 维配对；`cos`、`sin` 的形状与 `x` 相同，前后两半使用相同的角度。

```python
import torch

def rotate_half(x):
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat(____, dim=-1)

def apply_rope(x, cos, sin):
    return x * cos + ____ * sin
```

<details>
<summary>答案与解析</summary>

**答案：** (1) `(-x2, x1)`；(2) `rotate_half(x)`

**解析：**

答案：`torch.cat((-x2, x1), dim=-1)` 与 `x * cos + rotate_half(x) * sin`（写成列表 `[-x2, x1]` 同样正确）。

$$x\cos\phi+\mathrm{rotate\_half}(x)\sin\phi=(a\cos\phi-b\sin\phi,\ b\cos\phi+a\sin\phi)$$

## 编程题

<a name="LLM-POS-013"></a>

### LLM-POS-013　挑战 · 考频 ★★★

用 numpy 实现 RoPE，采用 Hugging Face 的 `rotate_half` 配对方式：第 $i$ 维与第 $i+d/2$ 维为一对，旋转角为 $m\theta_i$，$\theta_i=\mathrm{base}^{-2i/d}$。

```python
def apply_rope(x, pos, base=10000.0): ...
```

- `x` 形状 `(T, d)`，`d` 为偶数；`pos` 形状 `(T,)`，是每一行的整数位置；
- 对第 $i$ 对 $(a,b)=$ `(x[:, i], x[:, i + d/2])`，输出为 $(a\cos-b\sin,\ a\sin+b\cos)$；
- 返回形状 `(T, d)` 的数组。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
import numpy as np

def apply_rope(x, pos, base=10000.0):
    T, d = x.shape
    half = d // 2
    inv_freq = base ** (-np.arange(half) * 2.0 / d)               # θ_i，形状 (d/2,)
    ang = np.asarray(pos, dtype=np.float64)[:, None] * inv_freq   # (T, d/2)：第 m 行是 m·θ_i
    cos, sin = np.cos(ang), np.sin(ang)
    a, b = x[:, :half], x[:, half:]                               # 第 i 维与第 i+d/2 维配对
    return np.concatenate([a * cos - b * sin, a * sin + b * cos], axis=-1)
```

**测试用例：**

```python
rng = np.random.default_rng(0)
d = 16
q, k = rng.normal(size=(1, d)), rng.normal(size=(1, d))

# 1) 位置 0 不旋转
assert np.allclose(apply_rope(q, [0]), q)

# 2) 旋转不改变向量长度
assert np.isclose(np.linalg.norm(apply_rope(q, [12345])), np.linalg.norm(q))

# 3) 打分只依赖相对位置（换一个 base 也成立）；相对距离 +7 与 -7 一般不同
def score(m, n, base=10000.0):
    return (apply_rope(q, [m], base) @ apply_rope(k, [n], base).T).item()
s = [score(m, m - 7) for m in (10, 110, 1010)]
assert max(s) - min(s) < 1e-9
s2 = [score(m, m - 7, base=500000.0) for m in (10, 110, 1010)]
assert max(s2) - min(s2) < 1e-9
assert abs(score(10, 3) - score(10, 17)) > 1e-6

# 4) 与逐对旋转的显式定义对拍（d=4：配对 (0,2) 与 (1,3)，θ = 1 与 0.01）
x = np.array([[1.0, 2.0, 3.0, 4.0]])
m = 5
th = np.array([1.0, 10000.0 ** -0.5])
a, b = x[0, :2], x[0, 2:]
expect = np.concatenate([a * np.cos(m * th) - b * np.sin(m * th),
                         a * np.sin(m * th) + b * np.cos(m * th)])
assert np.allclose(apply_rope(x, [m]), expect)

# 5) 每一行使用自己的位置
X = rng.normal(size=(3, d))
out = apply_rope(X, [0, 4, 9])
for r, p in enumerate([0, 4, 9]):
    assert np.allclose(out[r], apply_rope(X[r:r + 1], [p])[0])
```

**解析：**

**思路**：
1. 频率 $\theta_i=\mathrm{base}^{-2i/d}$，$i=0,\dots,d/2-1$，从高频（$\theta_0=1$）到低频；
2. 角度表 $m\theta_i$ 由位置与频率做外积得到，形状 `(T, d/2)`；
3. 把向量拆成前后两半 $a$、$b$，第 $i$ 对 $(a_i,b_i)$ 按二维旋转公式计算。

**测试的含义**：位置 0 不变、长度不变是旋转的基本性质；第 3 组测试验证 RoPE 的核心——打分只依赖 $m-n$，且与 base 取值无关；同时 +7 与 −7 的打分不同，说明 RoPE 能区分方向（对比正弦绝对编码的点积是偶函数）。第 4 组与显式定义对拍，能发现「配对方式写成相邻两维」或「旋转方向写反」之类的错误。

**易错点**：用 `x.reshape(-1, 2)` 做相邻配对，与题目要求的前后半配对不一致（两种配对都能实现 RoPE，但不能与另一种格式的权重混用）；角度用低精度计算；把 RoPE 也施加到 V 上。

<sub>考点：RoPE原理、RoPE实现与基频</sub>

### LLM-POS-006　基础 · 考频 ★★

请比较正弦绝对位置编码、可学习绝对位置编码和相对位置编码（以 T5 的相对位置偏置为例）：它们分别在哪里注入位置信息、有无参数、能否处理超过训练长度的输入？各有哪些优缺点与代表模型？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **正弦绝对位置编码**：在输入层把固定的正弦 / 余弦向量加到词向量上；无参数；理论上能为任意位置生成编码，但实际外推效果差；位置与词向量混合后再经投影，相对位置在打分中不「干净」。代表：原始 Transformer。
2. **可学习绝对位置编码**：一张 $L_{max}\times d$ 的查找表，加到输入上；有参数（如 GPT-2 small 为 $1024\times768\approx0.79$M）；超过 $L_{max}$ 无向量可查，是硬上限；靠后的位置在训练中出现得少，学得不充分；优点是简单灵活。代表：BERT（512）、GPT-2（1024）。
3. **相对位置编码**：在注意力打分中直接引入 $i-j$ 的信息。Shaw 等（2018）为截断后的相对距离学习向量，加进 key / value；T5 为每个头的每个「距离桶」学一个标量偏置，近距离逐个分桶、远距离按对数分桶。参数很少，对没见过的长度有一定泛化能力；代价是要为每对 $(i,j)$ 计算或查找偏置，与高效注意力内核结合较麻烦。代表：Transformer-XL、T5、DeBERTa。
4. **后续主流**：RoPE（旋转 Q、K，兼具逐 token 处理与相对位置）和 ALiBi（按距离线性扣分）成为大模型的主流选择。

**评分要点（共 10 分）：**

- 正确说明三者注入位置信息的位置与方式（3 分）
- 说明参数量与长度上限 / 外推能力的差异（3 分）
- 说明各自的主要缺点，如可学习编码的硬上限、相对偏置的实现代价（2 分）
- 给出代表模型，并提到 RoPE / ALiBi 等后续方案（2 分）

**讲解：**

**常见失分点**：说正弦编码「可以无限外推」；不知道可学习位置编码有硬上限；把 T5 的相对偏置说成向量（它是标量）；把 RoPE 归为「加在输入上的绝对位置编码」。

<a name="LLM-POS-011"></a>

### LLM-POS-011　进阶 · 考频 ★★★

RoPE（旋转位置编码）的原理是什么？为什么说它「用绝对位置的操作实现了相对位置编码」？与把位置向量加到输入上的做法、以及 T5 式的相对位置偏置相比，它有哪些优点？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **做法**：把 $q$、$k$ 的 $d$ 维切成 $d/2$ 对，第 $i$ 对在位置 $m$ 旋转 $m\theta_i$，$\theta_i=\mathrm{base}^{-2i/d}$（base 默认 10000）。只作用于 Q、K，不作用于 V；每一层投影之后都要施加。
2. **相对性推导**：旋转矩阵满足 $R_m^\top R_n=R_{n-m}$，所以 $(R_mq)^\top(R_nk)=q^\top R_{n-m}k$，打分只依赖相对位置 $n-m$，绝对位置被消掉。
3. **「绝对的操作」**：每个 token 只按自己的位置旋转，可以独立计算——K 算一次就能存进 KV Cache，之后不需要再改；不必像 T5 那样为每对 $(i,j)$ 计算偏置，和 FlashAttention 等内核天然兼容。
4. **对比加性绝对编码**：位置向量与词向量相加后再经 $W^Q$、$W^K$ 投影，点积中混有交叉项，相对位置不「干净」；RoPE 让相对位置在每一层的点积中精确成立。
5. **其他性质**：零参数；旋转不改变向量长度；多频率分工（高频维度分辨近距离、低频维度分辨远距离）；打分上界随距离增大而下降（远程衰减）；长度扩展方便，PI、NTK-aware、YaRN、调大 base 都作用在 RoPE 的频率或位置上。

**评分要点（共 10 分）：**

- 说明逐对旋转与频率公式，并指出只作用于 Q、K（2 分）

<a name="LLM-POS-027"></a>

### LLM-POS-027　进阶 · 考频 ★★★

模型训练长度为 4K，要扩展到 32K。请比较 PI（位置插值）、NTK-aware 缩放和 YaRN：它们各自改动了什么？对高频和低频维度分别有什么影响？是否需要训练？工程上如何选择？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **问题根源**：低频维度在 4K 内没转完一圈，32K 时出现训练中没见过的角度；高频维度在训练长度内早已见过所有角度。
2. **PI**：改位置，$m\to m/s$（$s=8$）。所有频率统一压缩 8 倍：低频回到训练范围；高频也被压缩，相邻 token 的角度差变为 1/8，近距离分辨率下降。需要少量微调（原论文约 1000 步）。
3. **NTK-aware**：不改位置、改 base：$\mathrm{base}'=\mathrm{base}\cdot s^{d/(d-2)}$。最高频 $\theta_0=1$ 完全不变，最低频恰好压缩 $s$ 倍，中间第 $i$ 对压缩 $s^{2i/(d-2)}$ 倍，平滑过渡。不训练也能用（效果有限），微调后更好；「动态 NTK」按当前长度实时计算 $s$，短输入完全不受影响。
4. **YaRN**：按每个维度的波长与训练长度之比分段（NTK-by-parts）：波长远小于 $L$ 的高频维度不插值，波长大于 $L$ 的低频维度完全插值（同 PI），中间线性过渡；再给注意力 logits 乘一个随 $s$ 增大的系数（$\sqrt{1/t}=0.1\ln s+1$），抵消插值后注意力分布变「平」的问题。少量微调后效果最好，Qwen2.5、DeepSeek-V3 等模型使用了它。
5. **选型**：能训练时首选 YaRN，或直接调大 base 后做长文本继续预训练；完全不能训练时用动态 NTK 应急；PI 实现最简单，但损失近距离分辨率。无论哪种方法都要配合长文本数据，并用大海捞针、RULER 等评测有效长度。

**评分要点（共 10 分）：**

- 说明外推失败源于低频维度出现未见过的角度（2 分）
- 正确描述 PI 改位置、对高低频的影响及微调需求（2 分）
- 正确描述 NTK-aware 改 base 的公式与「高频不变、低频压缩」的特点（2 分）
- 正确描述 YaRN 的分段插值与注意力温度（2 分）
- 给出合理的工程选型，并提到长文本训练与评测（2 分）

**讲解：**

**常见失分点**：把 PI 和 NTK 说成一回事；说 NTK-aware「改的是位置」；不知道 YaRN 还有温度系数；以为改大 `max_position_embeddings` 就能支持更长输入；只讲方法、不提长文本训练和有效长度评测。

<sub>考点：位置插值、NTK-aware缩放、YaRN　｜　出处：YaRN 论文 arXiv:2309.00071</sub>

### LLM-POS-042　进阶 · 考频 ★★

什么是 Lost in the Middle 现象？请从模型角度分析可能的成因，并分别从模型训练和应用（如 RAG、长文档问答）两个层面给出缓解办法。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **现象**：关键信息位于长输入的开头或结尾时，模型利用得最好；位于中间时明显变差，准确率随位置呈 U 形。扩展了上下文窗口的模型同样存在这一问题，某些设置下中间位置的表现甚至低于不给文档。
2. **可能成因**（多因素共同作用，仍在研究中）：
   - 训练数据的分布：指令和问题多出现在开头或结尾，自然文本中与预测相关的信息也多在附近，模型学到了偏好这些位置的习惯；
   - 注意力的位置偏置：因果注意力中开头的 token 对所有位置可见，常成为接收大量注意力的 attention sink（首因）；RoPE 的远程衰减和局部模式让模型偏好最近的 token（近因）；
   - 有效上下文不足：长文本训练不充分，远距离、中间位置的检索能力弱。
3. **模型训练层面**：构造关键信息均匀分布在各个位置的长上下文训练数据（如合成的长文档问答，答案证据随机放置）；增加高质量长文本训练；研究中也有对位置注意力偏置做校准的方法。
4. **应用层面**：
   - 减少无关内容：检索后精排、设置相关性阈值，只送最相关的少量段落；
   - 调整顺序：把最相关的段落放在开头或结尾；
   - 把问题放在文档前后各一次（论文中这对键值检索任务帮助很大，对多文档问答改善有限）；
   - 长文档分段处理后汇总（map-reduce），或先结构化抽取关键信息再问答。
5. **验证**：用「证据位置 × 输入长度」的对照实验评估缓解效果。

**评分要点（共 10 分）：**

- 准确描述 U 形现象及其普遍性（2 分）
- 从训练数据分布、注意力位置偏置、有效上下文不足等角度分析成因（3 分）
- 给出模型训练层面的缓解办法（2 分）
- 给出应用层面的缓解办法，如减少文档、调整顺序、分段汇总（2 分）
- 提到用位置对照实验验证（1 分）

**讲解：**

**常见失分点**：认为只有小模型或短窗口模型才有这个问题；认为把上下文窗口开得更大就能解决；把成因完全归结为位置编码；缓解办法只有「换更大的模型」；不知道减少无关文档往往比增加检索条数更有效。

<sub>考点：Lost in the Middle　｜　出处：Lost in the Middle arXiv:2307.03172</sub>

<a name="LLM-POS-046"></a>

### LLM-POS-046　挑战 · 考频 ★

从 Qwen2-VL 到 Qwen2.5-VL、Qwen3-VL，多模态位置编码经历了三次调整：M-RoPE、与绝对时间对齐的时间编号、交错式 MRoPE（Interleaved-MRoPE）加文本时间戳。请说明：(1) M-RoPE 怎样在一个头维度内同时编码 t、h、w，它的频率分配有什么问题；(2) 时间编号与绝对时间对齐解决了什么，又带来了什么新问题；(3) Qwen3-VL 的两项改动分别针对什么。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **M-RoPE（Qwen2-VL）**：头维度 128 有 64 对旋转频率 $\theta_i=\text{base}^{-2i/d}$，$i$ 越小频率越高。Qwen2-VL 按 `mrope_section = [16, 24, 24]` 把它们**分段**：前 16 对用时间编号，接着 24 对用高度编号，最后 24 对用宽度编号；文本三个编号相同，等价于一维 RoPE。问题：时间信息全部落在**最高频**的一段，宽度全部落在最低频的一段，每个轴只覆盖部分频谱。高频分量转得快，擅长区分近距离，距离一远就反复绕圈；长视频中相隔很远的帧缺少低频分量来表达时间上的远近，长程时间建模变弱。
2. **绝对时间对齐（Qwen2.5-VL）**：Qwen2-VL 的时间编号只随帧序号递增，帧率不同时，同样的编号间隔代表的真实时长不同。Qwen2.5-VL 让时间编号与时间戳对齐（每秒固定数量的编号单位），模型可以从编号间隔感知事件的节奏、做秒级定位，不同帧率的视频口径一致，也不需要额外的计算。新问题：编号随视频时长增长，长视频的时间编号过大、过稀疏，削弱长上下文中的时间理解；要学会这种对齐，还需要覆盖多种帧率、分布均匀的训练数据，构造成本高。
3. **Qwen3-VL 的两项改动**：
   - Interleaved-MRoPE：把 t、h、w 按 T、H、W、T、H、W……的方式**交错**分配到各个频率上（Hugging Face 实现中默认 `mrope_section = [24, 20, 20]`，交错之后余下的维度归 t），让每个轴都同时覆盖高频与低频，频谱均衡，改善长视频的长程位置建模；
   - 文本时间戳：不再把时间编号与绝对时间绑定，而是在每个时间片前插入「<3.0 seconds>」这样的文本（训练时还混用「时:分:秒」格式），由文本 token 显式给出时间；代价是上下文略有增加，换来更精确的时间定位。
4. **主线**：既要让文本退化为一维 RoPE、不损害语言能力，又要给视觉 token 合理的空间与时间结构；频率怎么分、时间用位置号还是用文本表达，是在编号尺度、频谱覆盖与数据成本之间取舍。

**评分要点（共 10 分）：**

- 说明 M-RoPE 按 [16, 24, 24] 分段分配频率、文本退化为一维 RoPE（2 分）
- 指出分段分配使时间轴只占高频、各轴频谱覆盖不全，影响长视频的长程建模（2 分）
- 说明绝对时间对齐的收益：不同帧率口径一致、可做秒级定位（2 分）
- 指出绝对时间编号在长视频上过大过稀疏、需要多帧率数据（2 分）
- 说明交错式分配与文本时间戳各自解决的问题（2 分）

**讲解：**

**常见失分点**：以为 t、h、w 各自占用完整的头维度；分不清「频率段」与「位置编号」（前者决定转得多快，后者决定转了多少圈）；只知道 Qwen2.5-VL「对齐了时间」，不知道它带来的编号稀疏问题；把 Qwen3-VL 的文本时间戳误解为又加了一个位置编码分量。

核实说明：`mrope_section` 的取值与交错实现见 Hugging Face transformers 中 qwen2_vl、qwen2_5_vl、qwen3_vl 的模型代码（2026-11 查阅）。

<sub>考点：多模态位置编码、RoPE实现与基频　｜　出处：Qwen2-VL arXiv:2409.12191；Qwen2.5-VL arXiv:2502.13923；Qwen3-VL 技术报告 arXiv:2511.21631；Hugging Face transformers 中 qwen2_vl、qwen3_vl 的实现</sub>

</details>

### LLM-POS-039　挑战 · 考频 ★★

某开源模型宣称支持 128K 上下文，团队把它用于「上传整份年报（约 10 万 token）后问答」。抽检发现：问题涉及的信息在文档开头或结尾时回答较准，在中间章节时经常答错或回答「文中未提及」；而大海捞针测试显示全长度「全绿」。请分析可能的原因，设计一套评测方案来确认问题，并给出改进措施。

**参考答案：**

**1. 可能原因**：
- **有效上下文远小于标称长度**：大海捞针只考字面检索，「全绿」不代表能在 10 万 token 中定位、理解并整合信息。
- **Lost in the Middle 式的位置偏置**：模型对开头（首因）和结尾（近因）的信息利用最好，中间最差；与训练数据中关键信息的位置分布、注意力偏向开头 token 和最近 token 等因素有关。
- **任务比单针检索难得多**：年报问答涉及表格数字、跨章节比对与汇总，属于多跳或聚合型任务。
- **推理配置问题**：`rope_scaling` 配置与训练不一致、被悄悄截断、KV 量化等都可能放大长程误差。

**2. 评测方案**：
- **位置 × 长度矩阵**：把同一问题的证据段分别放在 0%、25%、50%、75%、100% 的深度，总长度取 8K、32K、64K、100K，比较准确率，确认是否呈 U 形；
- **难度分层**：RULER 的多键检索、变量追踪、聚合任务，估计有效长度；
- **业务集**：真实年报问答并标注证据位置；把证据段单独给模型（短上下文）测上限，区分「找不到」与「看懂了也答不对」；
- **对照组**：闭卷（不给文档）与只给检索段落（RAG）的准确率。

**3. 改进措施**：
- 应用侧：先检索再阅读，只把相关段落送入模型；把最相关的段落放在开头或结尾；长文档分段处理后汇总（map-reduce）；对表格等关键信息先结构化抽取；
- 模型侧：换有效长度更长的模型；用证据分布在各个位置的长上下文问答数据微调；

- 指出 Lost in the Middle 式的位置偏置并解释（2 分）
- 设计「位置 × 长度」对照评测，并能区分检索失败与理解失败（3 分）
- 给出应用侧（检索、调整位置、分段汇总）与模型侧（换模型 / 长上下文微调）的改进（2 分）
- 提到检查推理配置，如 rope_scaling、截断、KV 量化（1 分）

**常见失分点**：看到大海捞针全绿就认定模型没问题；只说「换更大的模型」；不设计对照实验就下结论；没有区分「检索不到」和「理解错误」两类失败；忽略推理配置可能导致的截断。
