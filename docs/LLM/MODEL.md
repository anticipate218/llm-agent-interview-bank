<a name="LLM-MODEL-001"></a>

### LLM-MODEL-001　基础 · 考频 ★★

与 GPT-1 相比，GPT-2（2019 年，论文名为《Language Models are Unsupervised Multitask Learners》）最核心的主张是：

- **A.** 改用编码器—解码器结构，把各类任务统一成文本到文本的格式，从而兼顾理解与生成
- **B.** 在更大、更多样的 WebText 上训练更大的语言模型，不做任务微调即可零样本完成多种任务
- **C.** 提出上下文学习：在提示中给几个示例即可完成新任务，并系统评测了 1750 亿参数的模型
- **D.** 先做有监督微调，再用人类偏好训练奖励模型并做强化学习（RLHF），让输出更符合人类意图

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：GPT-2 的关键词是「零样本多任务」：语言模型足够大、数据足够多样时，下游任务可以直接用自然语言描述出来，不必再为每个任务微调。

- GPT-1（2018）：生成式预训练 + 针对每个任务的有监督微调；
- GPT-2（2019）：最大 15 亿参数，在约 40 GB 的 WebText（从 Reddit 高赞外链抓取的网页）上训练，上下文 1024；把任务写成文本条件，如在文章后接「TL;DR:」诱导模型写摘要；结构上把 LayerNorm 移到子层输入端（Pre-Norm）；
- GPT-3（2020）：1750 亿参数，系统展示了零样本、单样本、少样本的上下文学习；
- InstructGPT（2022）：用 RLHF 让模型遵循指令，之后才有 ChatGPT。

- A 错：GPT 系列一直是 Decoder-only；把任务统一成文本到文本格式的 Encoder-Decoder 模型是 T5。
- C 错：这描述的是 GPT-3。
- D 错：这描述的是 InstructGPT。

<sub>考点：GPT系列演进　｜　出处：Language Models are Unsupervised Multitask Learners（Radford 等, 2019）</sub>

</details>

<a name="LLM-MODEL-005"></a>

### LLM-MODEL-005　进阶 · 考频 ★★

BERT 论文特意把 BERT-Base 的规模设计得与 OpenAI GPT（GPT-1）相同（12 层、768 维、12 头），而它在 GLUE 上明显超过了 GPT。结合论文的消融实验，最能解释这一差距的是：

- **A.** BERT 的预训练语料（BooksCorpus 加英文维基）比 GPT 大得多，消融显示数据规模是主因
- **B.** BERT 采用 Pre-Norm，GPT 采用 Post-Norm，归一化位置的不同决定了效果
- **C.** 双向上下文：同等条件下改成从左到右的单向模型（并去掉 NSP），各任务明显下降，SQuAD 尤甚
- **D.** BERT 在下游任务中冻结预训练模型、只训练顶层分类器，而 GPT 需要微调全部参数

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：BERT 论文明确指出，提升的大部分来自两个预训练任务以及它们带来的双向性。

BERT 与 GPT 的差异不止一处：BERT 用 BooksCorpus 加英文维基百科，GPT 只用 BooksCorpus；预训练批量、[CLS] / [SEP] 的学习方式也不同。为了分离这些因素，论文做了消融：同样数据、同样规模下，把模型改成从左到右（LTR）并去掉 NSP，各任务效果都下降，MRPC、SQuAD 下降尤其明显；在 LTR 模型上再加一个随机初始化的 BiLSTM，SQuAD 有所改善，但仍明显不如双向预训练。原因在于 token 级任务需要每个位置都能看到右侧上下文，而单向模型在第 $t$ 个位置看不到后文。

- A 错：数据确实更多，但消融说明它不是主要原因。
- B 错：GPT-1 和 BERT 都沿用原始 Transformer 的 Post-Norm，Pre-Norm 是 GPT-2 才引入的。
- D 错：两者都采用「微调全部参数」的范式；冻结特征的用法是 ELMo 的典型方式。

<sub>考点：BERT与GPT路线　｜　出处：BERT 论文 arXiv:1810.04805（3.4 节与 5.1 节）</sub>

</details>

<a name="LLM-MODEL-011"></a>

### LLM-MODEL-011　进阶 · 考频 ★★★

LLaMA（2023 年 2 月）论文在原始 Transformer 的基础上做了三处主要修改，并注明了各自借鉴的来源。下列对应关系正确的是：

- **A.** 前置归一化——借鉴 GPT-3；SwiGLU 激活——借鉴 PaLM；RoPE——借鉴 GPT-Neo
- **B.** 前置归一化——借鉴 BERT；SwiGLU 激活——借鉴 T5；RoPE——借鉴 GPT-3
- **C.** 前置归一化——借鉴 PaLM；SwiGLU 激活——借鉴 GPT-3；RoPE——借鉴 T5
- **D.** GQA——借鉴 PaLM；SwiGLU 激活——借鉴 GPT-Neo；RoPE——借鉴 Chinchilla

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：LLaMA 论文的原文写法是「Pre-normalization [GPT3]、SwiGLU activation function [PaLM]、Rotary Embeddings [GPTNeo]」。

- **前置归一化**：对每个子层的输入而不是输出做归一化，以提升训练稳定性，这一做法来自 GPT-3；归一化函数换成了 RMSNorm（Zhang 与 Sennrich, 2019），GPT-3 用的是 LayerNorm。
- **SwiGLU**：来自 PaLM，LLaMA 把中间维度取为 $\frac23\times4d$，使参数量与普通 FFN 持平。
- **RoPE**：去掉绝对位置编码，在每一层对 Q、K 施加旋转位置编码，来自 GPT-Neo 系列的做法（RoPE 本身由 Su 等提出）。

其他关键选择：只用公开数据训练（7B、13B 用 1T token，33B、65B 用 1.4T token），上下文 2048；LLaMA-13B 在多数基准上超过 GPT-3（175B）。初版以非商用的研究许可发布。

- B 错：BERT 是 Post-Norm，原始 T5 的 FFN 用 ReLU，GPT-3 用学习式绝对位置编码，三处出处都不对。
- C 错：GPT-3 的 FFN 用 GELU，T5 用相对位置偏置而非 RoPE；前置归一化在 LLaMA 论文中注明借鉴的是 GPT-3。
- D 错：LLaMA 第一代没有使用 GQA，Llama 2 的 34B、70B 才开始使用。

<sub>考点：Llama系列　｜　出处：LLaMA: Open and Efficient Foundation Language Models arXiv:2302.13971</sub>

</details>

<a name="LLM-MODEL-014"></a>

### LLM-MODEL-014　进阶 · 考频 ★★★

根据 Qwen3 技术报告（2025 年 5 月），下列关于 Qwen3 相对上一代所做改变的说法，正确的是：

- **A.** 全系列改用 DeepSeek 提出的 MLA 注意力，KV Cache 降到 Qwen2.5 的十分之一左右
- **B.** MoE 模型沿用了 Qwen2.5-MoE 的共享专家设计，并以每个 token 激活 2 个专家为主
- **C.** 稠密模型去掉了 QKV 投影上的偏置，并在注意力中引入 QK-Norm 以稳定训练
- **D.** 为配合思考模式的推出，Qwen3 把开放权重的许可从 Apache 2.0 改为仅限研究用途

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：Qwen3 在 Qwen2.5 的骨架（GQA、SwiGLU、RoPE、Pre-RMSNorm）上做了「稳定性 + 数据 + 稀疏化」三方面的调整。

- **结构**：去掉 Qwen2 系列在 QKV 投影上使用的偏置，加入 QK-Norm，约束注意力 logits 的尺度，提升大规模训练的稳定性。
- **数据**：约 36T token，是 Qwen2.5（18T）的两倍；语言从 29 种扩展到 119 种。预训练分三个阶段：约 30T token 的通用阶段、约 5T 高质量 token 的推理强化阶段、上下文 32K 的长文本阶段（RoPE 基频从 1 万调到 100 万），推理时再配合 YaRN 等把可用长度扩大 4 倍。
- **MoE**：Qwen3-30B-A3B 与 Qwen3-235B-A22B 每层 128 个专家、每个 token 激活 8 个，**不使用**共享专家，并采用全局批次级的负载均衡损失。

- A 错：Qwen3 用的是 GQA。
- B 错：Qwen3 的 MoE 去掉了共享专家，每个 token 激活 8 个专家。
- D 错：Qwen3 全部开放权重模型都以 Apache 2.0 发布，比 Qwen2.5（3B 与 72B 另有许可）更宽松。

<sub>考点：Qwen系列　｜　出处：Qwen3 Technical Report arXiv:2505.09388</sub>

</details>

<a name="LLM-MODEL-016"></a>

### LLM-MODEL-016　进阶 · 考频 ★★★

下列关于 DeepSeek 系列各项关键技术「首次出现在哪个版本」的说法，正确的是：

- **A.** MLA 首次出现在 DeepSeek-V3，DeepSeek-V2 仍使用 GQA，靠 MoE 降低推理成本
- **B.** DeepSeek-R1 在 DeepSeek-V3 的基础上，把注意力换成了稀疏注意力 DSA
- **C.** DeepSeek-V3 只在推理阶段使用 FP8 量化，训练全程仍使用 BF16 混合精度
- **D.** MLA 与 DeepSeekMoE 在 V2 中一起使用；无辅助损失负载均衡与 MTP 在 V3 中引入

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：DeepSeek 的技术是逐代叠加的。

- **DeepSeek-V2（2024 年 5 月）**：总参数 236B、激活 21B，首次提出 MLA（压缩 KV Cache），并与 DeepSeekMoE（细粒度专家 + 共享专家，最早在 2024 年 1 月的 DeepSeekMoE 16B 中提出）组合使用，支持 128K 上下文。
- **DeepSeek-V3（2024 年 12 月）**：671B / 37B，新增无辅助损失的负载均衡、MTP 训练目标，并首次在超大规模上验证 FP8 混合精度**训练**。
- **DeepSeek-R1（2025 年 1 月）**：在 V3-Base 上用大规模强化学习训练推理能力，架构与 V3 相同，MIT 许可。
- **V3.1（2025 年 8 月）**：一个模型同时支持思考与非思考模式。
- **V3.2-Exp（2025 年 9 月）**：在 V3.1-Terminus 的基础上续训，引入 DeepSeek 稀疏注意力（DSA）。
- **V4（2026 年 4 月预览）**：1M 上下文，采用 CSA 与 HCA 两种压缩注意力的混合结构。

- A 错：MLA 在 V2 就已提出。
- B 错：R1 的架构与 V3 相同，DSA 出现在 V3.2-Exp。
- C 错：V3 的亮点之一正是 FP8 混合精度训练。

<sub>考点：DeepSeek系列　｜　出处：DeepSeek-V2 arXiv:2405.04434；DeepSeek-V3 arXiv:2412.19437；DeepSeek-V3.2 arXiv:2512.02556；DeepSeek-V4 模型卡</sub>

</details>

<a name="LLM-MODEL-020"></a>

### LLM-MODEL-020　基础 · 考频 ★★

Mistral 7B（2023 年 9 月）发布后引起了广泛关注。下列描述与其论文和发布信息相符的是：

- **A.** 以 Apache 2.0 开放权重，结合 GQA 与滑动窗口注意力降低长序列的推理成本
- **B.** 它采用 MoE 架构：8 个前馈专家、每个 token 由路由选出 2 个，激活参数约 13B
- **C.** 它只以仅限研究用途的许可发布，商业使用需向 Mistral AI 另行申请授权
- **D.** 它用 MLA 压缩 KV Cache，并直接在 128K 长度的序列上完成了预训练

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：Mistral 7B 的卖点是「小而强、许可宽松、推理便宜」。

论文报告它在全部评测基准上超过 Llama 2 13B，在推理、数学和代码上超过 Llama 1 34B；结构上用 GQA 加快推理，用窗口为 4096 的滑动窗口注意力配合滚动缓存，降低长序列的计算与显存；权重以 Apache 2.0 发布。这让「7B 级模型也能实用」成为共识，也推动了大量基于它的微调模型。

- B 错：这是 2023 年 12 月的 Mixtral 8×7B。
- C 错：Mistral 7B 使用 Apache 2.0，可以商用。
- D 错：MLA 是 DeepSeek-V2 提出的；Mistral 7B 用的是 GQA 加滑动窗口注意力。

<sub>考点：Mistral与Mixtral　｜　出处：Mistral 7B arXiv:2310.06825</sub>

</details>

<a name="LLM-MODEL-022"></a>

### LLM-MODEL-022　进阶 · 考频 ★

关于 Gemma 3（2025 年 3 月）的多模态设计，下列说法正确的是：

- **A.** 全系列（含 1B）都支持图像输入，按原生分辨率切 patch，视觉 token 数随图像面积线性增长
- **B.** 4B 以上共用冻结的 SigLIP 编码器，图像缩放到 896×896 后压缩成固定 256 个 token
- **C.** 视觉编码器与语言模型从头联合训练，没有使用任何预训练视觉模型，以保证模态对齐
- **D.** 图像通过插入的交叉注意力层注入语言模型，视觉 token 不占用语言模型的上下文长度

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：Gemma 3 走的是「冻结的预训练视觉编码器 + 固定数量的视觉 token 拼接进序列」路线。

4B、12B、27B 共用同一个 SigLIP 编码器，约 4 亿参数，训练中保持冻结，输入固定为 896×896，输出经平均池化压缩成 256 个视觉 token，作为软 token 拼进文本序列。固定分辨率对长条形图片和小字不友好，于是推理时可选 Pan & Scan：把图像切成若干等大的块分别缩放、编码，代价是视觉 token 成倍增加。报告中 4B 模型在 DocVQA 上用 P&S 从 72.8 提升到 81.0。

- A 错：1B 模型是纯文本模型（上下文 32K）；每张图（或每个切块）固定 256 个 token，不随分辨率增长。
- C 错：视觉编码器是预训练好的 SigLIP，训练中保持冻结。
- D 错：视觉 token 直接拼进语言模型的输入序列，会占用上下文长度；用交叉注意力注入视觉信息的是 Flamingo、Llama 3.2 Vision 等模型。

其他相关事实：Gemma 3 的 4B、12B、27B 支持 128K 上下文，局部与全局注意力按 5:1 交替，用 QK-Norm 取代 Gemma 2 的软截断。

<sub>考点：Gemma系列　｜　出处：Gemma 3 Technical Report arXiv:2503.19786</sub>

</details>

<a name="LLM-MODEL-024"></a>

### LLM-MODEL-024　挑战 · 考频 ★★

某开放权重模型的技术资料中有以下描述：(1) 稠密层与 MoE 层交替排列；(2) 每个 MoE 层有 128 个路由专家和 1 个共享专家，每个 token 除了经过共享专家，只被路由到 1 个路由专家；(3) 部分注意力层不使用位置编码，与使用 RoPE 的层交错排列；(4) 原生多模态，文本与视觉 token 早期融合进同一骨干。它最可能是：

- **A.** DeepSeek-V3
- **B.** Qwen3-235B-A22B
- **C.** Mixtral 8×7B
- **D.** Llama 4 Maverick

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：这些特征都出自 Meta 对 Llama 4 Maverick 的介绍：稠密层与 MoE 层交替；128 个路由专家加 1 个共享专家，每个 token 走共享专家和 1 个路由专家；iRoPE（交错的无位置编码注意力层）；早期融合的原生多模态。

对比其他选项：
- **DeepSeek-V3**：注意力是 MLA；每个 MoE 层 1 个共享专家加 256 个路由专家，每个 token 激活 8 个；只有前 3 层是稠密 FFN，其余层都是 MoE；纯文本模型。
- **Qwen3-235B-A22B**：128 个专家、每个 token 激活 8 个，不设共享专家；GQA 加 RoPE；纯文本模型。
- **Mixtral 8×7B**：每层 8 个专家选 2 个，没有共享专家；纯文本模型。

辨识模型的技巧：先看注意力（MLA / GQA / 滑动窗口 / 混合线性注意力），再看 MoE 的专家数、激活数和共享专家，最后看位置编码与模态。这些「架构指纹」往往比参数量更能区分模型家族。

<sub>考点：Llama系列、DeepSeek系列、Qwen系列、Mistral与Mixtral　｜　出处：Meta 博客 The Llama 4 herd（2025-04-05）；DeepSeek-V3 arXiv:2412.19437；Qwen3 arXiv:2505.09388；Mixtral arXiv:2401.04088</sub>

</details>

<a name="LLM-MODEL-026"></a>

### LLM-MODEL-026　进阶 · 考频 ★★

关于「开放权重（open weights）」与「开源（open source）」的区别，下列说法最准确的是：

- **A.** 权重可公开下载且允许商用，就符合 OSI 对开源 AI 的定义，代码与数据不在考虑范围内
- **B.** OSI《开源 AI 定义》要求以认可的条款提供参数、完整代码和足够详细的数据信息
- **C.** 按 OSI 的定义，开源 AI 必须公开全部原始训练数据，涉及版权的数据也不能例外
- **D.** 权重以 Apache 2.0 许可发布，就自动满足 OSI《开源 AI 定义》的全部要求

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：「能下载权重」只说明是开放权重；OSI 意义上的开源 AI 要求使用、研究、修改、分享四项自由，并提供修改所需的「首选形式」：参数、代码、数据信息。

OSI 于 2024 年 10 月发布的《开源 AI 定义》1.0 列出了三项要求：

- **参数**：以 OSI 认可的条款提供权重等参数；
- **代码**：数据处理、训练、推理的完整源代码；
- **数据信息**：足够详细，让有经验的人能构建出实质等价的系统，包括数据来源、筛选、清洗方法；公开数据要列出获取途径。

逐项点评：
- A 错：能下载、可商用只说明是开放权重，开源 AI 还要求完整代码和数据信息；带有月活门槛、可接受使用政策的自定义许可（如 Llama 社区许可）更是限制了「任意用途使用」的自由，不满足开源定义。
- C 错：定义要求的是「数据信息」，对无法公开的数据允许只做描述，并不强制公开全部原始数据。

### LLM-MODEL-035　挑战 · 考频 ★★

Qwen3-Next（2025 年 9 月）把每 4 层中的 3 层换成 Gated DeltaNet（一种线性注意力），只保留 1 层门控的全注意力；MoE 部分有 512 个专家，每个 token 激活 10 个路由专家和 1 个共享专家，总参数约 80B、激活约 3B。关于这些设计，下列说法**正确**的有：

- **B.** Gated DeltaNet 层的状态大小也随上下文长度线性增长，与全注意力层没有本质区别
- **C.** 只有全注意力层的 KV Cache 随上下文增长，长上下文下约为同层数全注意力模型的四分之一
- **D.** 保留少量全注意力层，主要是为了弥补线性注意力在精确检索、复制远处信息方面的不足
- **E.** 每个 token 只激活约 3B 参数，所以部署时只需加载这部分参数，显存需求与 3B 稠密模型相当

<details>
<summary>答案与解析</summary>

**答案：CD**

**解析：**

**结论**：C、D 正确。

- A 错：模型卡显示 Qwen3-Next 的门控注意力层仍使用 RoPE（只对每个头的部分维度施加旋转）。
- B 错：线性注意力（包括 Gated DeltaNet）的递推状态大小与序列长度无关，这正是它省显存的原因。
- C 对：48 层中只有 12 层是全注意力，随上下文增长的 KV Cache 只存在于这些层；Gated DeltaNet 层把历史压缩进固定大小的矩阵状态，长度增加时状态不变。

- E 错：MoE 的计算量由激活参数决定，显存占用却由总参数决定：每个 token 选中的专家各不相同，下一个 token 可能用到任何一个专家，全部约 80B 参数都要常驻显存（或可快速访问的存储）。每个 token 的计算量接近 3B 稠密模型，这才是「A3B」的含义。官方称 Qwen3-Next-80B-A3B 以约十分之一的训练成本超过 Qwen3-32B-Base，32K 以上的长上下文推理吞吐提升 10 倍以上。

这套设计在 2026 年 2 月发布的 Qwen3.5 中被沿用到旗舰模型（60 层，15 组「3 层 Gated DeltaNet + 1 层门控注意力」），说明混合线性注意力已从实验性模型走进主力系列。

### LLM-MODEL-008　基础 · 考频 ★

T5 把所有任务统一成「文本输入、文本输出」。对于 STS-B 这种要预测 1～5 之间相似度分数的回归任务，T5 把分数四舍五入到 ____ 的倍数，再转成字符串作为目标文本（例如 2.57 写成 "2.6"），相当于把回归问题变成了一个 ____ 类的分类问题。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0.2；(2) 21

**解析：**

T5 论文观察到 STS-B 的大多数分数本来就以 0.2 为间隔标注，于是把分数四舍五入到 **0.2** 的倍数，转成字符串让模型生成。1 到 5 之间以 0.2 为步长共有 $(5-1)/0.2+1=$ **21** 个取值。测试时，如果模型输出的字符串能解析成 1～5 之间的数，就转回浮点数计算指标，否则直接判错。

这个例子说明了「文本到文本」框架的彻底性：分类输出类别名（如 "entailment"），翻译、摘要直接输出文本，连回归也写成字符串。好处是所有任务共用同一个模型、同一个损失（交叉熵）、同一套超参数和解码方式；任务用输入前缀区分，如 "translate English to German:"、"summarize:"、"stsb sentence1: ... sentence2: ..."。后来的指令微调可以看作把这些前缀换成了自然语言指令。

## 计算题

<a name="LLM-MODEL-017"></a>

### LLM-MODEL-017　进阶 · 考频 ★★★

DeepSeek-V3 技术报告给出：每训练 1T token 需要 18 万（180K）H800 GPU 小时，预训练共 14.8T token；之后的上下文扩展用了 119K GPU 小时，后训练用了 5K GPU 小时；按每 GPU 小时 2 美元的租用价格折算成本。
(1) 预训练需要多少 GPU 小时？在 2048 张 H800 上约需多少天？
(2) 训练总成本约多少美元？
(3) 这个数字常被简化为「DeepSeek-V3 只花了 557 万美元」，这种说法遗漏了什么？

<details>
<summary>答案与解析</summary>

**答案：(1) 2664K GPU 小时，约 54 天；(2) 2788K GPU 小时 × 2 美元 ≈ 557.6 万美元；(3) 它只是正式训练一次的 GPU 租用价，不含前期研究与消融实验、数据、人力和集群购置等成本**

**解析：**

**(1)** $14.8\times180\text{K}=2664\text{K}$ GPU 小时。在 2048 张卡上：$2{,}664{,}000/2048\approx1301$ 小时 $\approx54$ 天，与报告中「不到两个月完成预训练」一致；每 1T token 约 $180\text{K}/2048\approx88$ 小时 $\approx3.7$ 天。

**(2)** 总计 $2664\text{K}+119\text{K}+5\text{K}=2788\text{K}$ GPU 小时，乘以 2 美元得 **557.6 万美元**。

**(3)** 报告本身就注明，这一成本只包括 DeepSeek-V3 的正式训练，不包括此前在架构、算法、数据上的研究与消融实验。此外也不含数据采集与处理、人员、以及拥有 2048 张 H800 规模集群的资本开销。把它理解为「同等规模的一次正式训练，按租卡价格计算的算力账单」才准确。

**延伸**：这个数字之所以低，关键在于 MoE 使每个 token 只激活 37B 参数（按 $6ND$ 估算，计算量远小于同等总参数的稠密模型），FP8 训练、DualPipe 与通信重叠提高了硬件利用率，训练中也没有出现需要回滚的损失尖峰。

### LLM-MODEL-003　进阶 · 考频 ★★★

请梳理 OpenAI 从 GPT-1 到 GPT-4 的演进：每一代（GPT-1、GPT-2、GPT-3、InstructGPT、ChatGPT、GPT-4）的关键变化是什么？这些变化背后的主线是什么？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **GPT-1（2018）**：12 层 Transformer 解码器，在 BooksCorpus 上做语言模型预训练，再对每个下游任务微调；用「输入变换」把各种任务改写成序列，几乎不改模型结构。
2. **GPT-2（2019）**：放大到 15 亿参数，换成约 40 GB、更多样的 WebText，主张不做微调、用自然语言描述任务即可零样本完成；结构上改为 Pre-Norm，上下文扩到 1024；因担心被滥用而分阶段发布权重。

5. **ChatGPT（2022 年 11 月）**：与 InstructGPT 同一路线，基于 GPT-3.5 系列模型，用对话格式的数据和 RLHF 训练，把能力包装成人人可用的对话界面。

7. **主线**：先靠规模（参数、数据、算力）换来通用能力（预训练 → 零样本 → 少样本），再靠对齐和交互形式把能力变得可用、可控（指令遵循 → 对话），之后走向多模态；后续又出现了用强化学习训练长思维链的推理模型。另一条副线是逐渐从公开论文与权重走向闭源，直到 2025 年 8 月发布开放权重的 gpt-oss。

- 说明 GPT-4 的多模态与不公开细节等变化（2 分）

**常见失分点**：把上下文学习说成 GPT-2 提出的；以为 ChatGPT 只是更大的 GPT-3；说不出 InstructGPT 的意义（对齐让小模型也更受偏好）；声称知道 GPT-4 的参数量和结构（官方并未公布）。回答时注意区分「论文公开的事实」和「坊间传闻」。

<summary>答案与解析</summary>

**参考答案：**

1. **Qwen2.5（2024 年 9 月）**：稠密模型 0.5B～72B，预训练数据扩到约 18T token；沿用 Qwen2 起全系列使用的 GQA；大部分模型为 Apache 2.0，3B 与 72B 另有许可。主线是「数据更多、更好」。
2. **Qwen3（2025 年 4—5 月）**：
   - 数据翻倍到约 36T token，语言扩到 119 种；分通用、推理强化、长上下文三个阶段预训练。

   - 推出 MoE（30B-A3B、235B-A22B），128 个专家选 8 个，不设共享专家。
   - 同一模型支持思考与非思考两种模式，可设置思考预算。
   - 全部改为 Apache 2.0。

4. **Qwen3.5（2026 年 2 月）**：旗舰模型 397B-A17B 沿用同样的混合布局（60 层，15 组「3 层 Gated DeltaNet + 1 层门控注意力」）与高稀疏 MoE；开放权重模型带视觉编码器，成为原生多模态模型；原生上下文 262K，可扩展到约 100 万；继续使用 MTP，以 Apache 2.0 发布。动机：把在 Qwen3-Next 上验证过的高效架构推向主力系列，并统一文本与视觉。
5. **总体趋势**：数据规模持续扩大 → 稀疏化（MoE 稀疏度越来越高）→ 注意力结构从全注意力走向混合线性注意力 → 原生多模态；许可越来越宽松。

- 说清 Qwen3-Next 的混合注意力与高稀疏 MoE 设计（3 分）
- 说明 Qwen3.5 的变化（混合架构进入主力系列、原生多模态）（2 分）
- 能分析每一步的动机并总结趋势（2 分）

<a name="LLM-MODEL-018"></a>

### LLM-MODEL-018　挑战 · 考频 ★★★

DeepSeek-V3（2024 年 12 月）以较低的训练成本达到了当时开放权重模型的领先水平。请从模型架构、训练目标、训练效率（精度与并行）三个方面说明它的关键技术选择，以及每项选择要解决的问题。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **模型架构**：
   - **MLA**：把 K、V 压缩成低秩潜向量，每层每 token 只缓存 512 + 64 维，解决长上下文推理时 KV Cache 过大、Decode 受带宽限制的问题。
   - **DeepSeekMoE**：每个 MoE 层 1 个共享专家 + 256 个细粒度路由专家，每个 token 激活 8 个，总参数 671B、激活 37B，用较小的计算量换取大容量。
   - **无辅助损失负载均衡**：给每个专家一个只用于选择的偏置，按负载动态调整，避免辅助损失干扰主目标；另有系数极小的序列级平衡损失。
   - **节点受限路由**：每个 token 最多发往 4 个节点，控制跨节点 All-to-All 的通信量。
2. **训练目标**：**MTP**（深度 1，即额外预测再往后一个 token），让训练信号更密集，可能促使模型提前规划；推理时可以直接丢弃，也可以拿来做投机解码的草稿。
3. **训练效率**：
   - **FP8 混合精度训练**：细粒度（分块）缩放量化配合高精度累加，首次在超大规模模型上验证可行，相对 BF16 的损失误差小于 0.25%，显著节省计算与显存。
   - **DualPipe 流水线并行**：前向与反向的计算和通信相互重叠，减少流水线气泡，掩盖专家并行带来的跨节点通信；配合定制的 All-to-All 通信内核。
   - **并行策略**：16 路流水线并行、跨 8 个节点的 64 路专家并行、ZeRO-1 数据并行，通过节省显存做到训练中不使用代价较高的张量并行。
4. **结果**：14.8T token 的预训练用约 2.664M H800 GPU 小时完成，全程没有出现不可恢复的损失尖峰，也没有回滚；后训练中还从 R1 系列蒸馏了推理能力。

**评分要点（共 10 分）：**

- 架构：MLA、细粒度 MoE + 共享专家、无辅助损失负载均衡，并说明各自目的（3 分）
- 训练目标：MTP 及其在推理时的处理方式（2 分）
- 训练效率：FP8 混合精度训练、DualPipe / 通信重叠或并行策略（3 分）
- 能把技术选择与成本或稳定性结果联系起来（2 分）

**讲解：**

**常见失分点**：把 MLA 说成量化或省参数；把 MTP 说成推理时必须保留的模块；认为 FP8 只用于推理；只罗列名词，不说每项技术解决什么问题。这类题常接着追问「为什么激活 37B 却要部署 671B 的显存」「MTP 和投机解码是什么关系」，可以提前准备。

### LLM-MODEL-033　挑战 · 考频 ★★

从 2K 到 128K 乃至 1M，大模型的上下文长度增长依赖哪些技术进步？请以 Llama 3.1、DeepSeek-V3、Qwen3 为例，说明它们分别如何把上下文扩展到 128K；并说明标称上下文长度与实际可用能力之间可能存在的差距。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **技术基础**：
   - 位置编码：从可学习的绝对位置编码转向 RoPE，配合调大基频（ABF）、位置插值、NTK、YaRN 等方法扩展长度；
   - 注意力实现：FlashAttention 让注意力的额外显存从 $O(T^2)$ 降到 $O(T)$；训练时用上下文并行（如 Ring Attention）把长序列切到多张卡上；
   - 缓存与结构：GQA、MLA、滑动窗口或局部 / 全局交替、混合线性注意力、稀疏注意力，压低长上下文推理的 KV Cache 与计算量；
   - 数据与训练：主体预训练用较短的序列，最后再用长文本做分阶段的继续训练。
2. **三个例子**：
   - **Llama 3.1**：主体预训练用 8K，之后分六个阶段逐步加长到 128K，每个阶段等短文本能力恢复、长文本检索通过后再加长，长上下文阶段约用 800B token。
   - **DeepSeek-V3**：预训练用 4K，之后用 YaRN 分两个阶段（各 1000 步）扩展：4K → 32K → 128K。
   - **Qwen3**：预训练的长上下文阶段把 RoPE 基频从 1 万调到 100 万（ABF），在 32K 长度上训练；推理时再用 YaRN 与双块注意力（DCA）把可用长度扩大到 4 倍，即 128K。
3. **标称与实际的差距**：
   - 「大海捞针」接近满分，不代表能做多跳检索、信息聚合（RULER 上常随长度下降）；
   - 存在 Lost in the Middle 现象，中间位置的信息利用率低；
   - 靠推理时外推获得的长度，效果通常不如在该长度上真正训练过；
   - 长上下文的延迟与成本很高，很多场景下 RAG、摘要压缩仍然更划算。
   - 因此应当用贴近真实任务的长文本评测确定「有效长度」。

**评分要点（共 10 分）：**

- 列出位置编码、注意力实现、KV 压缩、数据与分阶段训练中的至少三类技术（3 分）
- 正确说明 Llama 3.1、DeepSeek-V3、Qwen3 中至少两个的扩展方式（4 分）
- 说明标称长度与有效长度的差距及评测方法（3 分）

**讲解：**

**常见失分点**：把 FlashAttention 当成「扩展上下文的位置编码方法」；以为把 RoPE 基频调大、不训练就能可靠地用到 128K；只报标称长度，不谈有效长度与评测。各家的具体做法可在技术报告中核对，回答时说清是预训练阶段的做法还是推理时的外推。

## 场景分析题

<a name="LLM-MODEL-025"></a>

### LLM-MODEL-025　挑战 · 考频 ★★★

一家金融科技公司计划建设两个大模型应用：(a) 面向内部研究员的「投研助手」，要阅读上百页的研报与公告并做多步推理；(b) 面向数百万客户的「智能客服」，高并发、对成本和延迟敏感。合规要求客户数据不能发送给境外的第三方服务；团队自有 16 张 H100（80 GB）。请从能力、合规、成本、可控性、许可证等角度分析闭源 API 与开放权重模型的取舍，给出你的选型方案，并说明如何验证。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 评估维度**
- **能力**：最强的闭源模型在复杂推理与长文档上往往仍有优势，但差距随版本变化很快，必须在自有评测集上实测，不能只看公开榜单。
- **合规与数据**：客户数据不得出境，客服必须私有化部署，或使用满足合规要求的境内托管服务；投研如果只处理公开研报，可以评估合规的 API，一旦涉及内部或客户数据，同样需要私有化。
- **成本**：API 按 token 计费，适合流量小、波动大的场景；高并发、稳定的流量下，自建推理的单位成本通常更低，但要算上 GPU 折旧、运维人力和利用率。
- **可控性**：开放权重可以微调（领域术语、话术与合规风格）、量化、约束解码，版本由自己掌握；闭源 API 升级或下线可能改变线上行为，还存在供应商锁定。
- **许可证**：Apache 2.0、MIT 最省心；自定义许可要核对月活门槛、使用政策、署名与命名要求，以及衍生模型的许可继承。
- **生态**：推理框架（vLLM、SGLang）与量化工具对候选模型的支持程度。

**2. 选型方案**
- **客服**：选一个许可宽松、激活参数较少的开放权重模型（中等规模的 MoE，或 7B～32B 的稠密模型），用客服对话做 SFT 或 LoRA，结合 RAG 接入知识库；FP8 或 INT4 量化后私有化部署，从 16 张卡中划出一部分专门承载高并发。
- **投研**：优先评估大规模开放权重 MoE 模型的私有化部署。例如 235B 级 MoE 用 BF16 约需 470 GB 显存，单机 8 卡可以放下；6710 亿参数级别的模型用 FP8 仅权重就约 671 GB，需要占用两台机器。若公开资料场景允许，可接入合规的闭源 API 作为补充，处理非敏感任务。
- **架构**：在应用与模型之间加一层模型网关，统一接口，按任务类型和数据敏感级别路由，便于随时替换或升级模型。

**3. 验证**
- 构建自有评测集：客服意图识别、话术合规、知识准确率；投研的长文档问答、财务计算、引用准确性。
- 比较候选模型的准确率、幻觉率、延迟、吞吐与每千次请求成本。
- 灰度上线，监控投诉率与人工接管率，定期用新版本模型回归评测。

**评分要点（共 10 分）：**

- 从能力、合规、成本、可控性、许可证中至少分析四个维度（4 分）
- 针对两个应用分别给出合理选型，并做显存或成本的量级估算（3 分）
- 提到许可证核查与模型网关、可替换性等工程设计（1 分）
- 给出基于自有数据的评测与灰度验证方案（2 分）

**讲解：**

**常见失分点**：只说「开源便宜、闭源强」；忽视数据合规这一硬约束；不核对许可证就默认开放权重可以随意商用；不估算显存，给出放不下的方案；没有自有评测集，只引用公开榜单。

<a name="LLM-MODEL-034"></a>

### LLM-MODEL-034　挑战 · 考频 ★★

某团队有三项计划：
1. 用 Llama 3.3 70B Instruct 批量生成合成数据，用这些数据微调一个基于 Qwen2.5-7B 的模型，并公开发布它的权重；
2. 把 Qwen2.5-72B 微调后部署在自家 SaaS 产品中，预计月活跃用户约 3000 万；
3. 以 Gemma 3 4B 为教师，蒸馏出一个端侧小模型并公开发布。
请逐项指出需要注意的许可问题，并给出建议。

<details>
<summary>答案与解析</summary>

**参考答案：**

**计划 1**
- Llama 3.3 社区许可允许用其输出训练其他模型（早期的 Llama 3 许可曾禁止用输出改进其他大语言模型），但用 Llama 材料或其输出训练的模型一旦对外发布或提供，**名称开头必须包含「Llama」**；还要遵守 Meta 的可接受使用政策。
- 基座 Qwen2.5-7B 是 Apache 2.0：再分发时附上许可副本，保留版权与 NOTICE，在修改过的文件中注明修改。
- 最终模型同时受两方面约束。如果不希望模型名带「Llama」，可以改用 Apache 2.0 或 MIT 许可的模型来生成数据。

**计划 2**
- Qwen2.5-72B 使用 Qwen License（不是 Apache 2.0）：允许商用，但产品月活超过 1 亿时需要向阿里云申请许可，3000 万暂时在门槛之下，要预留增长后的预案；
- 用它（或其输出）训练、微调并对外提供的模型，需要在产品文档中显著标注「Built with Qwen」或「Improved using Qwen」；再分发时附带许可与规定的 Notice。
- 注意同系列的 Qwen2.5-3B 是仅限研究用途的许可，不能直接商用。若希望简化，可评估 Apache 2.0 的 Qwen3 系列。

**计划 3**
- Gemma 3 使用 Gemma Terms of Use。按其定义，通过蒸馏（包括利用 Gemma 生成的合成数据）让模型表现得与 Gemma 相似，得到的模型属于「Model Derivatives」，同样受这份条款约束。
- 分发时必须把禁止用途等使用限制作为可执行条款写进与下游的协议，向接收者提供条款副本，附带规定的 Notice 文件，并标注修改过的文件。
- 可考虑改用 2026 年 4 月起以 Apache 2.0 发布的 Gemma 4 作为基础，以简化合规。

**通用做法**：为每个模型建立「血缘档案」，记录基座、数据来源、所用外部模型及其许可与服务条款；上线与发布前由法务逐条确认；许可文本以实际下载版本为准，不同小版本的条款可能不同。

**评分要点（共 10 分）：**

- 计划 1：指出 Llama 3.3 输出训练的命名要求，并兼顾 Qwen2.5-7B 的 Apache 2.0 义务（3 分）
- 计划 2：指出 Qwen2.5-72B 不是 Apache 2.0、1 亿月活门槛与署名要求（2 分）
- 计划 3：指出蒸馏模型属于 Gemma 的 Model Derivatives，使用限制需向下游传递（3 分）
- 给出血缘档案、法务审核或换用宽松许可基座等通用做法（2 分）

**讲解：**

**常见失分点**：把所有开放权重模型都当成 Apache 2.0；以为「只用了输出、没用权重」就不受基座许可约束；不知道同一系列中不同规格的许可可能不同（如 Qwen2.5 的 3B 与 72B）；忽视使用限制需要向下游传递。注意：本题只讨论许可条款本身，实际业务还要结合所在地区的法规与数据合规要求。
