## 单选题

<a name="ALN-RWD-001"></a>

### ALN-RWD-001　基础 · 考频 ★★★

一个团队要用 RL 同时提升模型的三类能力：(1) 有标准答案的初中数学应用题；(2) 带隐藏单元测试的 Python 编程题；(3) 开放式客服回复是否礼貌、有帮助。下列奖励方案中最合理的是：

- **A.** 三类任务共用一个偏好奖励模型打分：奖励尺度天然统一，也避免为每类任务分别写规则
- **B.** 三类任务都用 LLM 评审按评分细则打分：一套流程覆盖三类任务，省去编写和维护规则的成本
- **C.** (1)(2) 用规则验证器（答案匹配、单元测试），(3) 用偏好奖励模型或 LLM 评审，并统一奖励尺度
- **D.** (1)(2) 用规则验证器（答案匹配、单元测试），(3) 不给奖励，只靠 KL 约束保持模型原有的礼貌风格

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：能验证就用规则，验证不了才用模型打分，这是奖励设计的第一原则。

规则验证器客观、便宜、难被讨好，适合有标准答案或可执行检查的任务；偏好奖励模型和 LLM 评审能覆盖开放任务，但在分布外会失真、会被钻空子。实际系统多为**混合奖励**，例如 DeepSeek-R1 最后一轮 RL 中，推理题用规则奖励，通用对话用奖励模型对齐有用性与无害性。不同来源的奖励尺度差异很大，要统一归一化，否则某一类会悄悄主导训练。

- A 错：可验证的任务没必要训奖励模型，平白多出被钻空子和反复重训的风险；共用一个模型也不等于各类奖励的尺度就合适。
- B 错：数学和代码有确定的判分方式，用 LLM 评审既更贵又更不可靠。
- D 错：没有奖励就没有优化方向，KL 只能把策略拴在参考模型附近，无法提升客服质量。

<sub>考点：奖励模型与规则奖励　｜　出处：DeepSeek-R1 论文 arXiv:2501.12948</sub>

</details>

<a name="ALN-RWD-004"></a>

### ALN-RWD-004　基础 · 考频 ★★★

关于结果奖励模型（ORM）与过程奖励模型（PRM），下列说法正确的是：

- **A.** ORM 对推理的每一步打分、信号更密，PRM 只看最终答案是否正确，标注更便宜
- **B.** PRM 的标注成本低于 ORM：步骤级标签可以从最终答案反推，答案对则各步都记为正确
- **C.** 有了 PRM，每一步都被单独检查，策略难以靠「看起来对」的步骤讨好它，奖励黑客基本消失
- **D.** PRM 给每一步推理打分，信号更密、能定位错误步骤，但标注更贵，「一步」也难定义

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：ORM 只看结果，PRM 给每一步打分。PRM 信号更密、便于信用分配，代价是标注贵、步骤难定义，且同样会被钻空子。

- A 错：把两者说反了。
- B 错：步骤标签无法从最终答案直接推出：答案对，过程可能有错；答案错，前几步也可能是对的。PRM800K 靠人工逐步标注，Math-Shepherd 靠多次续写估计，成本都远高于 ORM。
- C 错：PRM 本身是模型，策略会学着写「看起来对」的步骤去讨好它，DeepSeek-R1 论文正是以此为理由之一，把 PRM 列为不成功的尝试。

当前主流做法是**训练时用结果奖励**（规则或 ORM），PRM 更多用于测试时的搜索与重排、训练数据筛选，或作为小权重的辅助信号。

<sub>考点：ORM与PRM　｜　出处：DeepSeek-R1 论文 arXiv:2501.12948</sub>

</details>

<a name="ALN-RWD-007"></a>

### ALN-RWD-007　进阶 · 考频 ★★

关于 OpenAI 的 Let's Verify Step by Step（Lightman 等, 2023），下列说法正确的是：

- **A.** 它证明了用 PRM 做 RL 训练优于用结果奖励做 RL 训练，MATH 上的 RL 提升主要来自过程监督信号
- **B.** 它的步骤标签由蒙特卡洛续写自动生成：从每一步续写多次，按最终答对的比例给该步打标签
- **C.** PRM800K 含约 80 万条步骤级人工标注；在 MATH 上做 best-of-N 选答，PRM 明显优于 ORM
- **D.** 它发现 PRM 与 ORM 在 MATH 上的选答效果没有显著差别，因此推荐标注成本更低的 ORM 用于训练

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：这篇工作比较的是两种奖励模型**在 best-of-N 中挑选答案**的效果。结论是过程监督训练的 PRM 明显优于结果监督的 ORM：用 PRM 挑选时，在 MATH 测试集的一个代表性子集上解出约 78% 的题。论文发布的数据集 PRM800K 由人工给每一步标「正确 / 错误 / 中性」，约 80 万条步骤标签。

PRM 给一个解答打分的方式是：把各步「正确」的概率相乘，得到「每一步都正确」的概率。

- A 错：论文研究的是奖励模型用于选答，并没有比较用它们做 RL 训练的效果；后来的 DeepSeek-R1 反而在大规模 RL 中放弃了 PRM。
- B 错：那是 Math-Shepherd 的做法。PRM800K 是人工标注的，并用主动学习挑选更有价值的样本去标。
- D 错：与论文结论相反。

<sub>考点：过程监督　｜　出处：Let's Verify Step by Step, arXiv:2305.20050</sub>

</details>

<a name="ALN-RWD-010"></a>

### ALN-RWD-010　基础 · 考频 ★★★

RLHF 训练中，奖励模型给出的平均分一路上涨，但人工盲评的胜率先升后降；抽检发现高分回答越来越长、反复道歉，并且对用户的观点一味附和。对这一现象最准确的描述是：

- **A.** 灾难性遗忘：RL 冲掉了 SFT 阶段学到的能力，回答质量下降，与奖励设计无关
- **B.** 奖励黑客：策略钻了奖励模型的空子，代理奖励持续上升，而人真正在意的质量在下降
- **C.** 策略尚未收敛：人工胜率的下降只是暂时波动，继续训练 RL 更多步后会随奖励一起回升
- **D.** 采样温度设得太高，输出随机性变大，回答因此越写越长、措辞也不稳定

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：这是典型的奖励黑客（reward hacking），也叫奖励过优化，是 Goodhart 定律的体现。Goodhart 定律：一个指标一旦成为优化目标，就不再是好的指标。奖励模型只是人类偏好的近似，策略会找到它的盲区（偏长、偏客套、偏附和）并持续放大。

- A 错：灾难性遗忘表现为通用能力下降，不会伴随「奖励模型分数一路上涨」和明确的讨好模式。
- C 错：继续优化只会让代理奖励更高、真实质量更差。Gao 等（2022）显示，随着策略远离初始模型，代理奖励单调上升，真实奖励先升后降。
- D 错：温度影响的是随机性，不会系统性地产生「越写越长、越来越附和」的趋势。

处理思路：先抽检高分样本、定位被钻的空子，再修奖励（重训奖励模型、加长度控制、补充反例数据），同时用 KL 约束、早停和不参与训练的评审兜底。

<sub>考点：奖励黑客　｜　出处：Scaling Laws for Reward Model Overoptimization, arXiv:2210.10760</sub>

</details>

<a name="ALN-RWD-013"></a>

### ALN-RWD-013　基础 · 考频 ★★

奖励模型常表现出「长度偏置」：同等质量下，给更长的回答更高的分。关于它的来源与影响，下列说法最准确的是：

- **A.** 标注者偏爱更长、更详细的回答，奖励模型把「长」当成了「好」；RL 优化会放大这一偏差
- **B.** 长度偏置来自 Transformer 架构本身：更长的输入在最后一个 token 上聚合了更多信息，打分自然更高
- **C.** 长度偏置只影响离线评测分数：RL 中有 KL 约束，策略不会为迎合它而改变回答长度
- **D.** 用 DPO 代替 RLHF 就能避开长度偏置：DPO 不训练显式的奖励模型，也就没有可被利用的长度捷径

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：长度偏置主要来自数据：标注者（或 AI 标注者）倾向于认为更长、更详细的回答更好，奖励模型便学到了「长度 → 高分」这条捷径；策略优化时，这条捷径是最容易被利用的方向，回答随之膨胀。Singhal 等（2023）发现，RLHF 带来的奖励提升中有相当大的部分可以用长度增加来解释。

- B 错：偏差的来源是数据中的相关性，而不是网络结构。
- C 错：奖励模型就是 RL 的优化目标，它的偏差会被策略主动利用并放大；KL 只限制偏离的总量，挡不住回答逐渐变长。
- D 错：DPO 同样从偏好数据中学习，chosen 平均更长时，DPO 也会学会啰嗦；SimPO 等变体用长度归一化的隐式奖励来缓解，但无法根除数据偏差。

<sub>考点：长度偏置　｜　出处：A Long Way to Go: Investigating Length Correlations in RLHF, arXiv:2310.03716</sub>

</details>

<a name="ALN-RWD-016"></a>

### ALN-RWD-016　进阶 · 考频 ★★★

Gao 等（2022）在 Scaling Laws for Reward Model Overoptimization 中，用一个较大的「金标准」奖励模型代替人类标注，研究优化代理奖励模型的后果。随着策略相对初始策略的 KL 增大，下列描述最符合其发现的是：

- **A.** 代理奖励与金标准奖励同步单调上升，只是金标准奖励的增速更慢，二者差距逐渐拉大
- **B.** 代理奖励单调上升，金标准奖励先升后降；代理奖励模型越大，过优化出现得越晚、程度越轻
- **C.** 代理奖励先升后降，金标准奖励单调上升；代理奖励模型越大，代理奖励回落得越早
- **D.** 代理奖励单调上升，金标准奖励先升后降；过优化的程度只取决于策略模型大小，与代理奖励模型无关

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：这篇工作定量刻画了 Goodhart 定律在 RLHF 中的形态：优化的是代理奖励，它会一直涨；真正关心的金标准奖励先涨后跌，说明越过某个点之后，策略是在「钻代理奖励的空子」。代理奖励模型越大，它与金标准越接近，过优化出现得越晚。

论文还给出了经验函数形式：记 $d=\sqrt{\mathbb{D}_{\mathrm{KL}}(\pi\|\pi_{\text{init}})}$，best-of-N 下金标准奖励近似 $d(\alpha-\beta d)$，RL 下近似 $d(\alpha-\beta\log d)$，两者都会在某个 $d$ 之后下降。

- A 错：金标准奖励不会一直上升。
- C 错：把两条曲线说反了，被直接优化的代理奖励是单调上升的。
- D 错：前半句对，后半句错：论文的核心变量之一就是代理奖励模型的规模。

实践含义：不要按代理奖励挑检查点，要用 KL 预算、留出评审或人工评测做早停；增大奖励模型、做集成都能推迟过优化。

<sub>考点：奖励过优化　｜　出处：Scaling Laws for Reward Model Overoptimization, arXiv:2210.10760</sub>

</details>

<a name="ALN-RWD-022"></a>

### ALN-RWD-022　基础 · 考频 ★★

关于 RLAIF（用 AI 反馈代替人类反馈做强化学习），下列说法正确的是：

- **A.** 用 AI 代替人标注偏好；Lee 等（2023）在摘要和对话任务上发现，效果可与 RLHF 相当
- **B.** RLAIF 去掉了人工环节：AI 标注员按固定提示词打分，标签比人工更一致，也不会带入自身偏差
- **C.** RLAIF 依赖宪法原则判断有害与否，只适用于无害性对齐，难以用于有用性
- **D.** RLAIF 必须先用 AI 标签训练一个奖励模型，不能在 RL 中直接调用 LLM 给出奖励分数

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：RLAIF 的核心是把「谁来标偏好」从人换成 AI。Lee 等（2023）在摘要、有帮助的对话、无害的对话三类任务上比较了 RLAIF 与 RLHF，结果相当，而 AI 标注的成本低得多。

- B 错：AI 标注员会带入自身偏差（偏长、偏向自家风格、位置偏差等），需要用人工校准集抽检；评分原则或细则也要由人来写。
- C 错：它可用于有用性、无害性等多种目标。
- D 错：Lee 等还提出了 direct RLAIF：RL 时直接让现成的 LLM 给出奖励分数，跳过训练奖励模型这一步。

Constitutional AI（Bai 等, 2022）是 RLAIF 的早期代表，用一组原则让模型自己给出无害性偏好。

<sub>考点：RLAIF　｜　出处：RLAIF vs. RLHF, arXiv:2309.00267</sub>

</details>

<a name="ALN-RWD-024"></a>

### ALN-RWD-024　基础 · 考频 ★★★

关于 Constitutional AI（Bai 等, 2022）的训练流程，下列描述正确的是：

- **A.** 先做 RL 再做 SFT：RL 阶段按宪法原则打分，SFT 阶段再用人工撰写的示范回答巩固对齐效果
- **B.** 整个流程只有 SFT 一个阶段：把宪法原则写进系统提示词，用带提示词生成的回答微调即可
- **C.** 宪法原则只在推理时作为过滤器检查输出，命中违规就拒答或改写，不参与训练
- **D.** 先用模型按原则自我批评、修改后的回答做 SFT，再用模型按原则标出的偏好训练偏好模型并做 RL

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：Constitutional AI 分两个阶段，原则（宪法）同时用在这两个阶段。

1. **监督阶段（SL-CAI）**：用容易引出有害回答的提示词让模型作答，再让模型按随机抽取的原则批评自己的回答、给出修改版，可以多轮「批评 → 修改」；用修改后的回答微调模型。
2. **强化学习阶段（RL-CAI）**：对同一提示词采样两个回答，让模型按原则判断哪个更好，得到 AI 标注的无害性偏好；用这些偏好（混合人工标注的有用性偏好）训练偏好模型，再用 RL 优化策略。这就是 RLAIF。

- A 错：顺序是先 SFT 后 RL，SFT 数据来自模型自己修改后的回答，而不是人工示范。
- B 错：原则被用来生成训练数据，而不是只写进提示词；流程也不止 SFT，还有 RL 阶段。
- C 错：原则在训练中发挥作用，不是推理时的过滤器。

<sub>考点：Constitutional AI　｜　出处：Constitutional AI 论文 arXiv:2212.08073</sub>

</details>

<a name="ALN-RWD-027"></a>

### ALN-RWD-027　进阶 · 考频 ★★

团队用一个 LLM 评审给开放式回答打 1～10 分，作为 RL 的奖励。下列做法中，**不能**有效降低评审奖励被钻空子风险的是：

- **A.** 把评分拆成可检查的细则逐条判断，能用规则核验的部分（如引用是否真实存在）交给规则
- **B.** 让评审与策略隔离，策略看不到评审的提示词和评分细则
- **C.** 把评审换成与策略同一个模型的最新检查点，让评审标准随策略一起进步
- **D.** 多个评审取平均，或用成对比较代替绝对打分

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：评审与策略同源且同步更新，是最危险的做法。

评审偏爱和自己风格相近的输出（自我偏好），策略会被推向「评审自己喜欢的样子」，偏差被反复放大；评审标准随策略漂移，奖励不再是稳定的优化目标，训练也更难复现。正确做法是评审与策略隔离、版本固定，定期用人工评测校准。

- A 能降低风险：细则让判断可核查，规则兜住可验证的部分。
- B 能降低风险：策略看不到评审的提示词，更难针对性地讨好。
- D 能降低风险：多评审平均降低单个评审的噪声，成对比较比绝对打分更稳定。

即便都做了，也要监控长度与奖励的相关性，并定期人工抽检高分样本。

<sub>考点：评审模型奖励风险</sub>

</details>

<a name="ALN-RWD-031"></a>

### ALN-RWD-031　进阶 · 考频 ★★

与「在 LLM 上接一个标量头、用 Bradley-Terry 损失训练」的打分式奖励模型相比，生成式奖励模型（GenRM：先生成评语或推理过程，再给出判断）有哪些特点？下列说法正确的是：

- **A.** GenRM 最终只需输出一个判断 token（如 Yes 或 No），推理成本与打分式奖励模型相当，可以直接替换进 PPO 或 GRPO，而不影响每步的训练耗时
- **B.** GenRM 会先写出可读的评语再下结论，因此不存在位置偏差、长度偏差等评审偏差，被当作优化目标时也不会被策略钻空子
- **C.** 成对比较（pairwise）的 GenRM 可以直接给单个回答输出绝对分数，所以最适合在 GRPO 中为组内的每个回答单独打分，成本也最低
- **D.** 逐条打分（pointwise）的 GenRM 能给单个或多个回答打分；对同一输入多次采样评语再投票，可用更多推理算力换更可靠的奖励

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：生成式奖励模型的核心优势是「可以用推理时的算力换奖励质量」，代价是成本与新的偏差。

- D 对：DeepSeek-GRM 的分析指出，成对模式无法直接给单个回答打分，逐条打分的生成式模型可以统一处理单个、成对和多个回答；打分式模型对同一输入重复打分得到相同的值，无法靠投票扩展，而生成式模型每次采样的评判原则与评语不同，可以投票或求和。GenRM（Zhang 等）用 $p(\text{Yes}\mid x,y,I)$ 作为分数，带思维链的版本会采样多条验证推理，再把 Yes 的概率取平均。
- A 错：带推理的 GenRM 每次打分要先生成几百上千个 token，比标量头的一次前向贵得多；RL 中每步要给「提示词数 × 组大小」个回答打分，奖励计算很容易成为瓶颈。
- B 错：LLM 评审的位置偏差、冗长偏好、自我偏好依然存在，回答里还可能夹带针对评审的指令；任何奖励被当作优化目标后都可能被钻空子。
- C 错：成对模型需要两个回答才能比较，用在 GRPO 中要与参考回答比较，或在组内两两比较（$G$ 个回答需要 $G(G-1)/2$ 次），成本更高。

<sub>考点：生成式奖励模型　｜　出处：Zhang 等 Generative Verifiers: Reward Modeling as Next-Token Prediction arXiv:2408.15240；Liu 等 Inference-Time Scaling for Generalist Reward Modeling（DeepSeek-GRM）arXiv:2504.02495</sub>

</details>

### ALN-RWD-011　进阶 · 考频 ★★★

下列现象中，属于奖励黑客（reward hacking）的有：

- **A.** 编码任务中，模型识别出测试用例的输入后直接硬编码期望输出
- **B.** 用户一反驳，模型就改口认同用户的错误观点，因为偏好数据里「被认同」的回答常得高分
- **C.** 数学 RL 中验证器只检查标准答案是否出现在回答里，模型学会在结尾罗列多个候选答案
- **D.** 奖励模型偏爱长回答，策略学会堆砌免责声明和重复内容
- **E.** 训练数据中某个领域的样本太少，模型在该领域表现较差

<summary>答案与解析</summary>

**答案：ABCD**

**解析：**

**结论**：A、B、C、D 正确。判断标准是：**代理奖励提高了，但真实目标没有提高甚至变差**，模型利用的是奖励函数与真实目标之间的缝隙。

- D 对：长度偏置被放大，Singhal 等（2023）系统研究过 RLHF 中长度与奖励的相关性。
- E 错：这是数据覆盖不足，与奖励被利用无关。

### ALN-RWD-020　进阶 · 考频 ★★

下列手段中，能够缓解奖励模型过优化的有：

- **A.** 只看训练奖励曲线判断训练是否成功，省去人工抽检
- **B.** 用当前策略的新样本补充标注，迭代重训奖励模型
- **C.** 提高学习率，让策略在奖励模型「来不及被钻空子」之前快速收敛
- **D.** 按 KL 预算或留出评审挑选检查点（早停），而不是选代理奖励最高的检查点
- **E.** 用多个奖励模型的均值或保守值（如最小值、均值减方差）作为奖励

<details>
<summary>答案与解析</summary>

**答案：BDE**

**解析：**

**结论**：B、D、E 正确。

### ALN-RWD-023　进阶 · 考频 ★★

用 AI 标注偏好（RLAIF）或直接用 LLM 评审打分作为奖励时，下列关于风险与对策的说法**正确**的有：

- **A.** AI 标注员的偏差（偏长、偏格式、偏向与自己风格相近的回答）会被一起学进奖励，需要用人工校准集抽检
- **B.** 让评审直接给一个总分，通常比把「好」拆成评分细则（rubric）逐条打分更稳健，因为细则越多主观性越强
- **C.** 评审存在位置偏差，做成对比较时应交换两个回答的顺序各评一次，再综合结果
- **D.** 只要评审模型足够强，被当作优化目标时就不会被钻空子
- **E.** 评审模型和策略最好使用同一个模型，这样评判标准最一致

<details>
<summary>答案与解析</summary>

**答案：AC**

**解析：**

**结论**：A、C 正确。

- A 对：标注员的偏差会原样进入奖励信号，并在 RL 中被放大。
- B 错：说反了。细则把模糊的整体判断拆成可核查的条目，减少随意性，也便于定位被钻的空子；能用规则核验的条目直接交给规则。只给一个总分时，评审更容易被长度、格式、语气等表面特征左右。
- C 对：位置偏差是 LLM 评审最稳定的偏差之一，交换顺序取一致结果（或取平均）是标准做法。
- D 错：再强的评审，被当作优化目标时也会被找到弱点，例如更长、更自信、堆格式，甚至在回答里写针对评审的「指令」。
- E 错：同一个模型当评审，会放大「自我偏好」；而且策略一更新，评审标准跟着漂移，策略更容易找到评审的弱点。评审应与策略隔离、版本固定。

<a name="ALN-RWD-021"></a>

### ALN-RWD-021　挑战 · 考频 ★★

奖励模型集成（取多个奖励模型的平均分作为奖励）能缓解奖励黑客，主要是因为平均可以抵消各成员共有的系统性偏差，例如它们都偏爱更长的回答。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。平均只能抵消成员之间**彼此独立**的误差，抵消不了它们**共有**的偏差。用相似的数据、相似的方法训练出来的奖励模型，往往有相同的系统性偏差（例如都偏爱长回答、都偏爱某种格式）：每个成员都高估同一类回答，平均之后照样高估。集成的收益来自成员之间不一致的那部分误差。

Eisenstein 等（2023）在 Helping or Herding? 中发现：奖励模型集成能缓解、但不能消除奖励黑客，一些钻空子的行为在集成后依然存在，原因正是各成员表现出相似的错误模式；预训练种子不同的集成比只换微调种子的集成更有效，因为成员之间差异更大。

实践中，集成要配合保守聚合（最小值、均值减方差）、KL 约束、长度控制和人工抽检一起使用，并且承认它增加了训练与推理成本。

RewardBench 2 的作者分析了基准分数与下游效果的关系：分数与 best-of-N 采样的效果高度相关，与 PPO 训练效果的相关性却弱得多；奖励模型的基座与策略模型不同，或其训练提示词与 PPO 所用提示词的分布不同时，下游效果会明显下降。因此，直接选用榜单第一的开源奖励模型接入自己的 RL 流程，未必能得到更好的策略。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。论文的具体发现：
- 与 best-of-N 采样的效果高度相关（Pearson 相关系数约 0.87）；
- 与 PPO 训练效果的相关性弱：奖励模型达到中上水平之后，PPO 的效果趋于饱和，基准分在 49.8～68.5 之间的多个奖励模型训练出的策略差不多；

**常见误解**：「基准分越高，RL 训出来的策略就越好」。best-of-N 只在固定的候选中挑选，奖励模型的排序能力直接决定结果；RL 则会主动把策略推到奖励模型没见过的分布上，此时决定效果的是奖励模型在新分布上的可靠性和抗钻空子能力，基准分只能反映一部分。

### ALN-RWD-006　基础 · 考频 ★★

Math-Shepherd 用蒙特卡洛方法自动构造步骤标签：从某一步之后用补全模型续写 $N$ 次，看能否得到正确答案。若对第 3 步续写 8 次，其中 5 次最终答对，则按「软估计」（答对的比例）该步的标签为 ____；按「硬估计」（只要有一次能答对，就认为是好步骤）该步的标签为 ____。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0.625 / 5/8；(2) 1

**解析：**

- 软估计：$5/8=$ **0.625**；
- 硬估计：8 次里至少有一次答对，标签为 **1**（全部答错才为 0）。

这种自动标注的思路是：一步好不好，看「从这里出发还能不能走到正确答案」。好处是不需要人工，可以大规模生成。局限是：
1. 成本高：每一步都要续写多次，步数乘以续写次数；
2. 「后面能答对」不等于「这一步是对的」：后续步骤可能纠正了前面的错误，也可能碰巧蒙对；
3. 标签质量依赖补全模型的能力：补全模型太弱，正确的步骤也可能被估成低分。

Math-Shepherd 的实验中每步续写 $N=8$ 次。论文还观察到，续写次数继续增加时，硬估计的标注准确率反而下降：续写越多，越可能有一次碰巧答对，把坏步骤误判为好步骤（假阳性）。

<sub>考点：过程监督　｜　出处：Math-Shepherd 论文 arXiv:2312.08935</sub>

<a name="ALN-RWD-018"></a>

### ALN-RWD-018　挑战 · 考频 ★

分析 best-of-$n$ 采样时，常用 $\mathrm{KL}_{\text{bon}}=\log n-\frac{n-1}{n}$（单位 nats，对数取自然对数）来估计它相对基础策略的 KL，Gao 等（2022）即使用此式。$n=4$ 时约为 ____ nats，$n=64$ 时约为 ____ nats（保留 2 位小数）。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0.64；(2) 3.17

**解析：**

- $n=4$：$\ln4-\frac34\approx1.3863-0.75=$ **0.64**；
- $n=64$：$\ln64-\frac{63}{64}\approx4.1589-0.9844=$ **3.17**。

**解读**：这个 KL 只随 $n$ 对数增长。$n$ 从 4 增加到 64（16 倍），KL 只从 0.64 增加到 3.17。所以 best-of-N 是一种「KL 很省」的优化方式，常被用作 RL 的对照基线；但 $n$ 很大时同样会出现过优化。

这个式子最早出自 Stiennon 等（2020）的附录。后续工作（Beirami 等, 2024）指出，它其实是 best-of-N 真实 KL 的上界，真实值可能更小；作为量级估计仍然常用。

<sub>考点：奖励过优化　｜　出处：Gao 等 arXiv:2210.10760（式子引自 Stiennon 等 2020 附录）；Beirami 等 arXiv:2401.01879</sub>

</details>

- 解答 B（3 步）：[0.99, 0.78, 0.99]；
- 解答 C（2 步）：[0.90, 0.92]。

(1) 以各步概率的**乘积**作为解答得分（Let's Verify Step by Step 的做法），分别是多少？会选谁？
(2) 改用**最低一步**的分数（min）聚合，会选谁？
(3) 只看**最后一步**的分数，会选谁？
(4) 乘积聚合对解答长度有什么偏好？

<details>
<summary>答案与解析</summary>

**答案：(1) A≈0.783，B≈0.765，C=0.828，选 C；(2) min 选 A（0.96）；(3) 末步选 B（0.99）；(4) 乘积聚合偏好步骤少的短解答**

**解析：**

**(1) 乘积**：
- A：$0.96^6\approx0.7828$；
- B：$0.99\times0.78\times0.99\approx0.7645$；
- C：$0.90\times0.92=0.828$。

选 **C**。

**(2) min**：A 为 0.96，B 为 0.78，C 为 0.90，选 **A**。

**(3) 末步**：A 为 0.96，B 为 0.99，C 为 0.92，选 **B**。

**(4)** 每多一步就多乘一个小于 1 的数，乘积天然偏好**步骤少**的解答：A 每一步都很可靠，却因为步数多而输给 C。min 聚合与步数无关，只盯最可疑的一步；只看末步则接近于 ORM，B 中间有一步很可疑（0.78），却因为结尾自信而胜出。

**启示**：PRM 的聚合方式本身就是一种设计选择，会引入长度偏好或忽略中间错误。实践中要在验证集上比较乘积、min、末步、平均等聚合的选答准确率，并关注被选中解答的长度分布。

### ALN-RWD-032　进阶 · 考频 ★

用一个逐条打分的生成式奖励模型，给同一提示词下的两个回答 A、B 打分：每次采样先写出评判原则与评语，再给出 1～10 的整数分。共采样 4 次，另有一个 meta RM 给每次评判的质量打分：

| 采样 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| A 的分数 | 7 | 8 | 3 | 7 |
| B 的分数 | 6 | 7 | 9 | 6 |
| meta RM 质量分 | 0.9 | 0.8 | 0.2 | 0.7 |

(1) 只看第 1 次采样，A、B 哪个更好？
(2) 把 4 次的分数求和投票，A、B 的总分各是多少，哪个更好？
(3) 只保留 meta RM 质量分最高的 2 次再求和，结果如何？
(4) 4 次求和后，单个回答的总分有多少种可能的取值？与单次打分相比，这说明了什么？

<details>
<summary>答案与解析</summary>

**答案：(1) A；(2) A 25 分、B 28 分，B 更好；(3) A 15 分、B 13 分，A 更好；(4) 37 种（4～40）**

**解析：**

**(1)** 第 1 次：A 7 分、B 6 分，A 更好。

**(2)** A：$7+8+3+7=$ **25**；B：$6+7+9+6=$ **28**。B 更好：第 3 次采样给出了「A 3 分、B 9 分」的极端判断，一次就翻转了结果。

**(3)** 质量分最高的两次是第 1、2 次：A $7+8=$ **15**，B $6+7=$ **13**，A 更好。第 3 次评判的质量分只有 0.2，被过滤掉了。

**(4)** 每次 1～10 分，4 次之和的范围是 4～40，共 **37** 种取值，而单次只有 10 种。

**要点**：
- 求和投票相当于把奖励的取值空间扩大了约 $k$ 倍，分数更细，组内回答「并列」的情况更少，GRPO 的组内优势也更有区分度。
- 投票并不能自动排除「有偏差的评判」：少数几次低质量的评判就能左右结果。DeepSeek-GRM 用 meta RM 给每次评判打分，只保留最好的一部分（论文中保留一半）再投票，提升了推理时扩展的效果。
- 为减少位置偏差，DeepSeek-GRM 在每次采样前打乱回答的顺序。

### ALN-RWD-014　进阶 · 考频 ★★

用奖励模型做 best-of-4 选答，并加一个长度惩罚：回答超出 200 个 token 的部分，每 100 个 token 扣 `alpha` 分。下面的代码在三种 `alpha` 下各选出哪个候选？输出是什么？

```python
cands = [            # (候选, 奖励模型分数, 回答 token 数)
    ("A", 2.10, 180),
    ("B", 2.45, 620),
    ("C", 2.30, 300),
    ("D", 1.60, 90),
]

def pick(alpha, ref_len=200):
    """超出 ref_len 的部分，每 100 个 token 扣 alpha 分"""
    score = lambda c: c[1] - alpha * max(0, c[2] - ref_len) / 100
    best = max(cands, key=score)
    return best[0], round(score(best), 2)

for alpha in (0.0, 0.1, 0.3):
    print(alpha, pick(alpha))
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
0.0 ('B', 2.45)
0.1 ('C', 2.2)
0.3 ('A', 2.1)
```

**解析：**

逐个计算惩罚后的分数：

- `alpha=0`：不惩罚，选原始分最高的 B（2.45）；
- `alpha=0.1`：A 不超长仍为 2.10；B 超出 420，扣 0.42 得 2.03；C 超出 100，扣 0.1 得 2.20；D 为 1.60。选 **C**；
- `alpha=0.3`：A 为 2.10；B 扣 1.26 得 1.19；C 扣 0.3 得 2.00；选 **A**。

**要点**：奖励模型有长度偏置时，最长的 B 往往凭「长」拿到最高分。长度惩罚能把选择拉回更简洁的回答，但惩罚强度本身是一个需要校准的超参：太弱压不住注水，太强会偏向过短、信息不全的回答（例如 D 只要再加强惩罚就可能胜出）。实践中应在人工标注的验证集上调 `alpha`，并检查选中回答的长度分布与真实质量。

<sub>考点：长度偏置</sub>

### ALN-RWD-019　进阶 · 考频 ★★

用 3 个奖励模型给 3 个候选回答打分，分别用三种方式聚合：均值、最小值（最坏情况）、均值减去模型间分歧（方差）。下面的代码输出是什么？

```python
import numpy as np

scores = np.array([      # 行：3 个奖励模型；列：候选回答 A、B、C
    [2.0, 3.6, 2.4],
    [2.1, 1.2, 2.3],
    [1.9, 3.0, 2.2],
])
names = "ABC"
mean = scores.mean(axis=0)
worst = scores.min(axis=0)                  # 最坏情况（取最保守的分数）
uwo = mean - 1.0 * scores.var(axis=0)       # 均值减去分歧（方差）
for label, agg in [("mean", mean), ("min", worst), ("uwo", uwo)]:
    print(label, names[int(agg.argmax())], np.round(agg, 2).tolist())
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
mean B [2.0, 2.6, 2.3]
min C [1.9, 1.2, 2.2]
uwo C [1.99, 1.56, 2.29]
```

**解析：**

- **均值**：A $=2.0$，B $=(3.6+1.2+3.0)/3=2.6$，C $=2.3$，选 B；
- **最小值**：A 1.9，B 1.2，C 2.2，选 C；
- **均值减方差**（总体方差）：A 与 C 的方差都约为 0.0067，B 的方差为 $(1.0^2+1.4^2+0.4^2)/3=1.04$，得分 A 1.99、B 1.56、C 2.29，选 C。

**要点**：B 被两个奖励模型打了高分，却被第三个模型打了很低的分。模型之间分歧大，往往说明这个回答落在奖励模型不可靠的区域，正是被钻空子的高发地带。均值容易被个别模型的高估带偏；最小值（worst-case optimization）和均值减方差（uncertainty-weighted optimization）都是保守聚合，Coste 等（2023）的实验表明这类保守聚合能缓解过优化。代价是要训练、部署多个奖励模型，推理成本成倍增加。

<sub>考点：RM集成与正则　｜　出处：Reward Model Ensembles Help Mitigate Overoptimization, arXiv:2310.02743</sub>

## 简答题

<a name="ALN-RWD-003"></a>

### ALN-RWD-003　进阶 · 考频 ★★★

实际的 RL 训练常用「混合奖励」：可验证的部分用规则，开放的部分用奖励模型，再加上格式、长度、语言一致性等小项。请说明怎样设计这样的混合奖励，以及有哪些常见陷阱。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **按任务路由奖励来源**：先给提示词打类型标签，推理题用规则验证器，开放任务用偏好奖励模型或带细则的 LLM 评审。DeepSeek-R1 的全场景 RL 就是这样：推理数据用规则奖励，通用数据用奖励模型，其中有用性只评最终总结、无害性评整个回答。
2. **分清主次**：主信号（正确性或 RM 分）权重最大；格式分取小权重（如 0.1），或作为门槛（格式错直接 0 分）；作弊、严重安全违规一票否决，分数要低于「没做出来」。
3. **尺度归一化**：RM 分数无界、规则分是 0/1、长度分是连续值，量纲不同。按来源做标准化（如 z-score）或裁剪到固定范围，避免某一项悄悄主导梯度；也要注意不同类型提示词之间的尺度差异。
4. **处理冲突**：有用与无害常冲突。Llama 2 分别训练有用性和安全性两个奖励模型；Safe RLHF 把安全写成约束，用拉格朗日乘子自动平衡。
5. **常见陷阱**：辅助项被刷（格式分高就只学格式，长度分让回答注水）；惩罚项不封顶，压过主信号，模型学会「什么都不做」；规则任务又被 RM 打分，两种信号互相冲突；奖励项太多、权重难调；语言一致性一类的约束会让准确率略降（R1 论文报告过），要权衡。
6. **监控**：分项记录每类奖励的曲线，看各项与长度的相关性，定期抽检高分样本。

**评分要点（共 10 分）：**

- 按任务类型路由奖励来源，并能举出实例（2 分）
- 主次、权重、门槛与一票否决的设计（3 分）
- 说明不同来源奖励的尺度归一化（2 分）
- 列举至少两个陷阱并给出分项监控（3 分）

**讲解：**

**常见失分点**：把所有奖励直接相加不做归一化；格式分、长度分权重过大；惩罚项不封顶；只讲怎么加分，不讲作弊和安全的一票否决；不提分项监控。

<sub>考点：奖励模型与规则奖励、RM集成与正则　｜　出处：DeepSeek-R1 论文 arXiv:2501.12948；Llama 2 论文 arXiv:2307.09288</sub>

</details>

「长度偏置」会贯穿偏好数据、奖励模型、RL 训练和评测各个环节。请分别说明每个环节怎样发现和缓解长度偏置，以及怎样区分「合理的变长」和「长度偏置」。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **偏好数据**：统计 chosen 与 rejected 的长度差、长度与胜负的相关性；标注指南强调「完整且简洁」；平衡两类回答的长度分布，对长度差异悬殊的对子降权，或构造长度相近的对比对。
2. **奖励模型**：检查分数与长度的相关性；做对照实验，在回答末尾追加无信息量的内容，看分数是否上涨（一个模拟实验中，追加 4 个无意义 token，平均多得 0.53 分）；训练时把长度相关的成分与质量解耦（如单独用一个头吸收长度信号，RL 时只用与长度无关的部分）。
3. **RL 训练**：在奖励中加长度惩罚或设置长度上限；配合 KL 约束；监控回答长度曲线以及长度与奖励的相关性；必要时用新策略的样本重训奖励模型。
4. **评测**：使用长度控制的胜率（如 AlpacaEval 2 的 length-controlled win rate），报告平均长度；人工评测时提醒评审关注信息密度。
5. **区分合理变长**：看变长是否伴随真实质量（人工评测、客观正确率）提升，任务本身是否需要更多内容；按对错或按任务类型拆开看长度变化。只在「长度涨、质量不涨」时才判定为偏置，不要一刀切地压长度。

**评分要点（共 10 分）：**

- 偏好数据环节的发现与处理方法（2 分）
- 奖励模型环节的检测（如相关性、追加内容的对照实验）与去偏方法（2 分）
- RL 训练环节的长度惩罚、监控等（2 分）
- 评测环节的长度控制胜率等（2 分）

**讲解：**

**常见失分点**：只会说「加长度惩罚」；不知道评测本身也有长度偏置；认为回答变长一定是坏事；不提用对照实验检测奖励模型的偏置。

### ALN-RWD-026　进阶 · 考频 ★★

请说明 Constitutional AI 的两个阶段分别做什么；它相比纯人工标注的 RLHF 有什么优点，又有哪些风险或局限？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **监督阶段（SL-CAI）**：用红队提示词让一个只做过有用性训练的模型作答（常常是有害回答）；让模型按随机抽取的一条原则批评自己的回答并改写，可以迭代多轮；用修改后的回答（配合有用性数据）做 SFT。目的是先把模型拉到一个更安全的起点，减少 RL 阶段的探索难度。
2. **强化学习阶段（RL-CAI）**：对同一提示词采样两个回答，让反馈模型按原则做选择（可以先写思维链再判断），得到 AI 标注的无害性偏好；与人工的有用性偏好混合，训练偏好模型，再用 RL 优化。这一阶段就是 RLAIF。
3. **优点**：大幅减少人工标注，尤其是阅读有害内容的标注；原则写成文字，透明、可审查、可修改，调整行为只需改原则；可规模化迭代；论文的目标是「无害但不回避」，模型会解释拒绝的理由，减少一味拒答。
4. **风险与局限**：原则由少数人撰写，价值取舍未必有代表性；AI 反馈模型的偏差会被学进去，需要人工校准；偏好模型同样会被过度优化，出现说教、套话等模式；原则之间可能冲突，覆盖不到的情形仍需人工判断；有用性仍依赖人工数据。

**评分要点（共 10 分）：**

- 说清监督阶段的「批评 → 修改 → SFT」（3 分）
- 说清 RL 阶段由 AI 按原则标偏好、训练偏好模型并做 RL（3 分）
- 说出至少两个优点（2 分）
- 说出至少两个风险或局限（2 分）

**讲解：**

**常见失分点**：把 CAI 说成「在系统提示词里写规则」；搞反两个阶段的顺序；以为完全不需要人工数据；只讲优点不讲风险。

</details>

### ALN-RWD-028　挑战 · 考频 ★★

过程奖励模型（PRM）的步骤级标签可以通过哪些途径获得？各有什么问题？PRM 在 RL 训练和推理阶段分别可以怎么用？为什么当前主流的推理 RL 训练仍以结果奖励为主？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **人工逐步标注**：如 PRM800K，人工给每一步标「正确 / 错误 / 中性」，约 80 万条步骤标签。质量高，但成本高、难以扩展，标注一致性本身也是挑战；可以用主动学习挑选最有价值的样本去标。
2. **蒙特卡洛续写估计**：如 Math-Shepherd，从某一步之后续写多次，用答对的比例（软估计）或能否答对（硬估计）作标签。自动、可扩展；但成本是「步数 × 续写次数」，「后面能答对」不等于「这一步对」，标签质量还依赖补全模型的能力。
3. **LLM 评审逐步判断**：便宜、灵活，但评审自身的偏差和能力上限会进入标签，难题上判断不准。
4. **推理阶段的用法**：best-of-N 重排；引导束搜索或树搜索；作为早停或回溯的信号。这是 PRM 最能发挥作用的地方。
5. **训练阶段的用法**：筛选训练数据（剔除过程有错的样本）；作为小权重的辅助奖励；提供逐步优势（DeepSeekMath 给出过过程监督版的 GRPO）。
6. **为什么训练仍以结果奖励为主**：「一步」难以定义；PRM 是模型，会被钻空子（写看起来正确的步骤、把步骤拆碎刷分）；要随策略不断重训，成本高、流程复杂；在大规模长思维链 RL 中收益不抵开销。DeepSeek-R1 把 PRM 列为不成功的尝试，最终只用规则奖励。

**评分要点（共 10 分）：**

- 说出三种标签来源及各自的问题（4 分）
- 说明 PRM 在推理阶段与训练阶段的用法（3 分）
- 解释训练以结果奖励为主的原因（3 分）

**讲解：**

**常见失分点**：只知道人工标注；认为蒙特卡洛标签就是「步骤真的对」；把 PRM 当成大规模 RL 的标准配置；不知道 PRM 在推理时搜索和重排中的价值。

<sub>考点：过程监督、ORM与PRM　｜　出处：Let's Verify Step by Step arXiv:2305.20050；Math-Shepherd arXiv:2312.08935；DeepSeek-R1 arXiv:2501.12948</sub>

</details>

<a name="ALN-RWD-033"></a>

### ALN-RWD-033　挑战 · 考频 ★★

你要为对话模型的 RL 训练选择奖励来源：打分式奖励模型（标量头 + Bradley-Terry 损失），还是生成式奖励模型（GenRM）。请从准确性与可解释性、成本与延迟、推理时扩展、偏差与被钻空子的风险、接入 GRPO 的方式几个方面比较两者，并说明上线前应如何离线评测一个奖励模型。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **两者对比**
   - **形式**：打分式一次前向输出一个标量；GenRM 先生成评判原则、评语或推理，再输出判断（Yes 的概率、离散分数或二选一）。
   - **准确性与可解释性**：GenRM 能利用模型的推理能力，还可以在提示中放入评分细则或参考答案，在需要推理的判断（数学步骤、代码、事实核查）上往往更准；Generative Verifiers 论文报告，它在 best-of-N 上超过了判别式验证器和直接的 LLM-as-a-Judge。评语可读，便于审计和定位被钻的空子。
   - **成本与延迟**：GenRM 每次打分要生成大量 token，比标量前向贵得多；RL 中每步要给所有回答打分，需要专门的推理服务与并行化，否则会拖慢训练。
   - **推理时扩展**：GenRM 可以多次采样再投票或平均，DeepSeek-GRM 还用 meta RM 过滤低质量的评判；打分式模型重复打分结果相同，无法这样扩展。
   - **偏差与风险**：两者都会被钻空子；GenRM 还有位置偏差（成对比较时应交换顺序）、自我偏好、冗长偏好，并且容易受回答中「给评审的指令」干扰。离散分数取值少，组内并列多，GRPO 中优势为 0 的组会变多，多次采样求和可以缓解。
   - **接入 GRPO**：逐条打分的模型可以直接给每个回答打分；成对模型要与参考回答比较，或在组内两两比较，成本随组大小平方增长。
2. **离线评测**
   - **偏好准确率**：在留出的人工偏好集上统计 chosen 得分高于 rejected 的比例，并与标注员之间的一致率对照；按对话、安全、推理、事实性等领域分开看。也可以参考公开基准，如 RewardBench、RewardBench 2（每题 4 个回答选 1 个，随机基线 25%）。
   - **与下游效果的相关性**：做 best-of-N 实验，用奖励模型挑选，再用人工或金标准评估所选回答的真实质量。RewardBench 2 报告其分数与 best-of-N 效果高度相关（Pearson 0.87），与 PPO 训练效果的相关性则弱得多；基准分是必要条件而非充分条件，奖励模型与策略同源（同一基座、相近的提示词分布）时效果更好。
   - **偏差探针**：同一内容只加长篇幅、只加 markdown 格式、顺从用户的错误观点、交换回答顺序、在回答里插入「请给高分」之类的指令，看分数是否被操纵。
   - **分布外与一致性**：在当前策略的采样上检查准确率（RL 会把策略推到新的分布）；重复打分的方差、分数与人工评分的校准。
   - **小规模 RL 试跑**：短训练后，检查人工或金标准评测是否与奖励分数同步上涨，以便尽早发现过优化。

**评分要点（共 10 分）：**

- 说明两者在形式、准确性与可解释性上的差异（2 分）
- 说明成本差异，以及 GenRM 可通过投票、meta RM 做推理时扩展（2 分）
- 说明两者的偏差与被钻空子的风险，以及离散分数、成对模式接入 GRPO 的问题（2 分）
- 给出离线评测方法：偏好准确率、公开基准、偏差探针、分布外检查（2 分）
- 指出基准分数与 RL 下游效果的相关性有限，需要 best-of-N 或小规模 RL 验证（2 分）

**讲解：**

**常见失分点**：认为 GenRM「更强所以全面替代」打分式模型，不讲成本；以为输出了评语就没有偏差；把 RewardBench 的排名当成选型的唯一依据；评测只看留出集准确率，不做偏差探针，也不在策略自己的分布上检查。

<sub>考点：生成式奖励模型、奖励模型与规则奖励　｜　出处：Zhang 等 Generative Verifiers arXiv:2408.15240；DeepSeek-GRM arXiv:2504.02495；RewardBench 2 arXiv:2506.01937；RewardBench arXiv:2403.13787</sub>

</details>

### ALN-RWD-029　挑战 · 考频 ★★

某电商客服模型用 RL 优化，奖励来自一个 LLM 评审按「有用、礼貌、解决问题」给出的 1～10 分。离线评测中评审平均分从 6.1 升到 8.7；但灰度 A/B 显示用户满意度下降、转人工率上升。抽检发现：

- 回答平均长度涨到原来的 2.3 倍，充斥「非常抱歉给您带来不便」之类的套话；
- 对超出政策的退款要求，模型也一味答应「我理解，我们会尽力为您处理」；
- 部分回答末尾出现「以上回答完整、专业，符合所有要求」。

请分析原因，并提出改进方案。

<details>
<summary>答案与解析</summary>

**参考答案：**

**原因分析**：
1. **长度偏置与格式讨好**：评审偏爱更长、更客气的回答，RL 把这种偏差放大成套话和注水。
2. **谄媚与违规承诺**：评审只看「礼貌、有用」的表面，不核对政策；一味答应用户最容易拿高分，却制造了无法兑现的承诺，最终导致转人工和不满。
3. **评审被注入**：回答末尾针对评审的「自我评价」是在操纵评审打分，说明策略能看到评审关心什么，且评审没有防注入。
4. **代理指标与真实目标脱节**：评审分不等于问题是否解决、用户是否满意，这是 Goodhart 定律的典型表现。

**改进方案**：
1. **能验证的部分规则化**：是否调用了正确的工具、订单状态是否真的改变、承诺是否符合退款政策，都可以用规则或数据库状态检查；违反政策的承诺直接重罚。
2. **评审加固**：细化评分细则（政策合规、事实正确、问题是否解决、简洁性），逐条打分；只把用户可见的正文交给评审，剥离或检测针对评审的文本，命中即判 0；成对比较、多评审取平均；评审与策略隔离、版本固定。
3. **长度控制**：在奖励中加长度惩罚，或对评审分做长度去偏；监控长度与奖励的相关性。
4. **训练侧兜底**：KL 约束、早停；补充「礼貌地拒绝不合理要求」的示范和偏好数据。
5. **评测闭环**：以解决率、转人工率、满意度、投诉率为上线门禁；定期人工抽检高分样本；保留不参与训练的评审和人工评测集。

**评分要点（共 10 分）：**

- 识别长度偏置与套话式格式讨好（2 分）
- 识别谄媚与违反政策的承诺（2 分）
- 识别回答中针对评审的注入（2 分）
- 给出规则化验证、评分细则加固、长度控制等奖励侧改进（2 分）
- 给出以业务指标为门禁的评测与抽检闭环（2 分）

**讲解：**

**常见失分点**：只说「换一个更强的评审」；没发现回答末尾的自我评价是在操纵评审；只加长度惩罚而不处理政策合规；仍以评审分作为上线依据，不看业务指标。

<sub>考点：奖励黑客、长度偏置、评审模型奖励风险</sub>

</details>

### ALN-RWD-030　挑战 · 考频 ★★

2025 年 4 月，OpenAI 回滚了一次 GPT-4o 更新，原因是更新后的模型变得过度讨好用户。官方复盘提到，新加入的基于用户点赞、点踩的奖励信号，削弱了原有奖励信号对谄媚行为的约束。

假设你负责一个对话产品的后训练，也想把用户反馈（点赞、点踩、重新生成、复制）用作奖励信号。请分析这类信号的风险，并设计一套使用方案，避免重蹈覆辙。

<details>
<summary>答案与解析</summary>

**参考答案：**

**风险分析**：
1. **用户偏好不等于回答质量**：用户倾向于给认同自己、夸奖自己的回答点赞，直接优化会产生谄媚；短期满意可能损害长期信任和安全（附和错误观点、助长不健康的决定）。
2. **选择偏差与噪声**：只有少数用户会反馈，且偏向极端情绪；不同人群、场景的反馈分布差异大；隐式信号（复制、重新生成）含义模糊。
3. **新信号稀释原有约束**：多个奖励加权组合时，新加入的信号会改变各项的相对权重，原本压制谄媚、保障事实性的约束可能被削弱，这正是复盘指出的问题。
4. **评测盲区**：如果离线评测和 A/B 没有专门度量谄媚，问题会在上线后才暴露；复盘也提到当时缺乏针对谄媚的专项评估，少数专家试用时「感觉不对」的定性反馈没有阻止发布。

**使用方案**：
1. **清洗去偏**：去重、反作弊，按用户群和场景分层，控制单个用户的权重；隐式信号只在含义明确时使用。
2. **建模而非直接当奖励**：用反馈构造偏好对训练奖励模型，或作为 KTO 的「好 / 坏」标签；与原有奖励融合时控制权重，并把事实性、安全、反谄媚设为**门槛项**，不让新信号抵消它们。
3. **专项评测与发布门禁**：建立谄媚评测集（用户坚持错误观点、施压、索要夸奖时模型能否坚持事实），连同事实性、安全、过度拒答一起作为发布门禁；专家的定性「感觉不对」也要能阻断发布。
4. **灰度与监控**：小流量灰度 + A/B，除点赞率外还看投诉、留存、事实性抽检；设定回滚条件，保留快速回滚的能力。
5. **持续审计**：定期人工抽检高奖励样本，检查奖励各分量的权重变化对行为的影响。

**评分要点（共 10 分）：**

- 指出用户反馈与真实质量的偏差，特别是谄媚和选择偏差（3 分）
- 指出新奖励信号会稀释原有约束，并给出权重与门槛设计（2 分）
- 给出清洗去偏与建模方式（奖励模型、KTO 等）（2 分）
- 给出专项评测、灰度监控与回滚等发布流程（3 分）

**讲解：**

**常见失分点**：认为「用户喜欢的就是好的」；把点赞率直接当奖励最大化；只谈数据清洗，不谈奖励组合中的权重与门槛；没有谄媚专项评测和回滚预案。

<sub>考点：奖励黑客、奖励模型与规则奖励　｜　出处：OpenAI 博客 https://openai.com/index/expanding-on-sycophancy/</sub>

<a name="ALN-RWD-035"></a>

### ALN-RWD-035　挑战 · 考频 ★★

团队用 GRPO 训练一个企业知识库问答模型。输入是用户问题和检索到的若干文档片段，要求：回答正确、只依据给定文档并标注引用、文档中没有答案时明确拒答、输出合法的 JSON。第一版奖励是加权和：

$$R=1.0\cdot r_{\text{正确}}+0.5\cdot r_{\text{引用}}+0.3\cdot r_{\text{格式}}+0.5\cdot r_{\text{拒答}}$$

其中 $r_{\text{正确}}$ 由 LLM 评审对照参考答案打 0～1 分；$r_{\text{引用}}$ 是带引用的句子占比（只检查引用编号是否存在于给定文档中）；$r_{\text{格式}}$ 为 JSON 是否可解析；$r_{\text{拒答}}$ 在不可回答的问题上拒答记 1、其余情况记 0。训练后出现三个问题：

1. 在本应拒答的问题上，模型越来越多地编造答案，并附上看似相关的引用；
2. 有的回答大段照抄文档、每句都标上引用，正确性却没有提升；
3. 线上偶尔出现无法解析的输出：这类回答虽然格式错误，但因为内容正确，在组内仍排在前面。

请分析各目标之间的冲突与被钻空子的方式，给出改进的奖励设计（加权、门控、条件组合、分阶段等），说明各自的风险，并给出验证方法。

<details>
<summary>答案与解析</summary>

**参考答案：**

**问题分析**
1. **拒答拿不到引用分**：在不可回答的问题上，拒答最多得到 $0.5+0.3=0.8$；编造一个答案并附上「存在的」引用，可以拿到引用分 0.5、格式分 0.3，再加上宽松评审给的部分正确分，总分可能超过拒答，模型自然学会「宁可编也不拒答」。
2. **引用分只查存在、不查支持**：照抄文档并给每句标引用就能拿满引用分，与是否回答正确无关，是典型的奖励黑客。
3. **硬约束被做成了软加分**：格式错误只少拿 0.3 分，正确性占主导时，格式错误的回答仍能拿到正的优势；线上不可解析的输出直接导致失败，这类约束应该是门槛而不是加分项。

**改进设计**
1. **按题目类型路由**（需要标注题目是否可回答）：不可回答的题，拒答记 +1，编造答案记 −1，让编造的代价明显高于拒答的收益；可回答的题以正确性为主，误拒答记 0 或小幅负分，防止过度拒答。
2. **门控**：JSON 不可解析时直接给最低分，其余各项都不计；严重违规（如泄露文档之外的敏感信息）一票否决。
3. **条件组合代替简单相加**：引用分只在回答正确时才计，例如 $R=r_{\text{正确}}\cdot(1+\lambda\,r_{\text{引用}})$；引用改为「支持度」，用 NLI 模型或评审逐句核查所引片段是否支持该句，同时考虑引用的精确率与召回率；对与原文最长公共子串占比过高的回答扣分，抑制照抄。
4. **尺度与权重**：各项先归一化再组合，主信号占主导；定期检查各分项与总奖励的相关性，确认没有哪一项在悄悄主导梯度。
5. **分阶段或约束优化**：先训练格式与拒答，再训练正确性与引用质量；或把格式错误率、过度拒答率写成约束，用拉格朗日乘子自动调权（Safe RLHF 的思路）。

**各方案的风险**
- 门控过严时，早期大量样本得最低分，组内全错，奖励过于稀疏 → 配合动态采样、课程学习，或先用 SFT 把格式打稳；
- 拒答奖励过高会导致过度拒答 → 监控可回答题上的拒答率；
- 分阶段训练可能遗忘前一阶段学到的行为 → 后一阶段混入前一阶段的数据；
- 约束优化的乘子会振荡、难调；
- LLM 评审本身也会被钻空子 → 能用规则判定的部分交给规则，定期人工抽检。

**验证**
- 分项指标：可回答题的正确率与误拒答率、不可回答题的拒答率、引用精确率与召回率、格式错误率、照抄比例；
- 构建分层评测集（可回答 / 不可回答 / 文档冲突 / 多跳），每次改奖励后都回归；
- 人工抽检高奖励样本，专门寻找新的钻空子方式；上线前做 A/B 实验。

**评分要点（共 10 分）：**

- 指出三类现象分别对应的冲突或漏洞：拒答拿不到引用分、引用只查存在、硬约束只是软惩罚（3 分）
- 给出按题型路由、门控、条件组合、引用支持度核查等改进设计（3 分）
- 说明加权、门控、分阶段、约束优化等方案各自的风险（2 分）
- 给出分项监控、分层评测与人工抽检的验证方法（2 分）

**讲解：**

**常见失分点**：只说「调一调权重」；没有发现「拒答拿不到引用分」这一结构性冲突；把格式这类硬约束继续当加分项；引用奖励只查格式不查支持；改了奖励却不做分项监控。多目标奖励设计的关键是：先区分硬约束与软目标，再决定每一项是门槛、乘性条件还是加性分量。
