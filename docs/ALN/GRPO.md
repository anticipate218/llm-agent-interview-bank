## 单选题

<a name="ALN-GRPO-001"></a>

### ALN-GRPO-001　基础 · 考频 ★★★

GRPO 对同一提示词用旧策略采样 $G$ 个回答，得到奖励 $r_1,\dots,r_G$（只在回答结尾给一个结果奖励）。第 $i$ 个回答中**各个 token** 的优势 $\hat A_{i,t}$ 如何确定？

- **A.** 由 critic 给每个位置估计 $V(s_t)$，再用 GAE 算出逐 token 不同的优势
- **B.** 只有回答的最后一个 token 拿到优势 $(r_i-\mathrm{mean}(r))/\mathrm{std}(r)$，其余 token 的优势为 0
- **C.** 回答内所有 token 共享同一个优势 $(r_i-\mathrm{mean}(r))/\mathrm{std}(r)$，均值与标准差在同组 $G$ 个奖励上计算
- **D.** 回答内所有 token 共享同一个优势 $r_i-\bar r$，其中 $\bar r$ 是整个 batch 中所有提示词全部回答的平均奖励

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：GRPO 的优势是「组内相对、序列级」的：先在同一提示词的 $G$ 个奖励上做标准化，再把这个值广播给该回答的每个 token。

$$\hat A_{i,t}=\frac{r_i-\mathrm{mean}(r_1,\dots,r_G)}{\mathrm{std}(r_1,\dots,r_G)},\qquad t=1,\dots,|y_i|$$

这正是 DeepSeekMath 中结果监督版 GRPO 的做法：基线来自同题多采的组均值，不需要 critic。

- A 错：这是 PPO 的做法，GRPO 恰恰去掉了 critic 和 GAE。
- B 错：策略梯度要作用在回答的每个 token 上；只给最后一个 token 优势，前面的推理过程得不到任何信号。
- D 错：用整个 batch 的均值做基线，会把不同难度的题混在一起：简单题的回答普遍高于 batch 均值，即使整组全对也会被继续推高；难题的回答则普遍被压低。GRPO 的基线是**按提示词**分组计算的。

<sub>考点：GRPO组内优势　｜　出处：DeepSeekMath 论文 arXiv:2402.03300</sub>

</details>

<a name="ALN-GRPO-003"></a>

### ALN-GRPO-003　进阶 · 考频 ★★★

PPO 需要一个与策略规模相当的 critic 来估计 $V(s_t)$，GRPO 把它去掉了。在「只在回答结尾给一个结果奖励」的设定下，GRPO 能这样做的主要依据是：

- **A.** LLM 的状态转移是确定性的，给定提示词后状态价值就等于采到的那条回答的最终奖励，不必单独估计
- **B.** GRPO 在 loss 中加入了对参考模型的 KL 项，由它稳定更新、降低梯度方差，起到了 critic 的作用
- **C.** GRPO 用比率裁剪限制了每步的更新幅度，裁剪后的目标即使没有基线，梯度方差也足够小
- **D.** 同一提示词下 $G$ 个回答的平均奖励就是状态价值 $V(x)$ 的蒙特卡洛估计，可直接充当基线

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：只有结果奖励时，「这道题采 $G$ 次的平均分」本身就是 $V(x)$ 的无模型估计，可以代替 critic 做基线。

$V(x)=\mathbb{E}_{y\sim\pi(\cdot\mid x)}[r(x,y)]$，组均值 $\frac1G\sum_i r_i$ 正是它的蒙特卡洛估计。这样省掉了一个和策略一样大的模型（及其梯度和优化器状态），也绕开了「奖励只在结尾、中间 token 的价值难估」导致 critic 难训的问题。代价是每题要采 $G$ 次，而且基线只在提示词层面，无法给不同 token 不同的优势。

- A 错：转移是确定的，但策略是随机的；$V(x)$ 是对所有可能回答取期望，不等于某一条回答的奖励。
- B 错：KL 项约束策略不偏离参考模型太远，与「降低策略梯度方差」的基线是两回事。
- C 错：裁剪限制的是单步更新幅度，不能代替基线降方差；没有基线时奖励若全为正，所有回答都会被推高，只是程度不同。

<sub>考点：去掉价值模型</sub>

</details>

<a name="ALN-GRPO-009"></a>

### ALN-GRPO-009　基础 · 考频 ★★★

关于 KL 约束在 PPO（RLHF 的经典实现）与 GRPO 中的处理方式，下列说法正确的是：

- **A.** PPO 的逐 token KL 惩罚（k1）并入奖励，经优势影响梯度；GRPO 的 k3 估计直接加进 loss，不进入优势
- **B.** PPO 与 GRPO 都把 KL 惩罚并入每个 token 的奖励、再经优势影响梯度，区别只在于 GRPO 把 k1 换成了 k3 估计器
- **C.** GRPO 把 KL 作为独立项加进 loss 之后，只需当前策略的 log-prob 即可计算，不再需要参考模型
- **D.** GRPO 先把 KL 惩罚并入奖励再做组内归一化，因此 KL 会改变组内各回答优势的相对大小

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：PPO 的 KL 在**奖励**里、用 k1；GRPO 的 KL 在 **loss** 里、用 k3。这是高频追问。

PPO 的逐 token 奖励为 $r_t=-\beta(\log\pi_{\text{old}}-\log\pi_{\text{ref}})+\mathbb{1}[t=T]\,r_\phi$，KL 通过 GAE 进入每个 token 的优势。GRPO 的 loss 是「裁剪的策略梯度项 $+\ \beta\cdot$k3」，优势只由任务奖励组内标准化得到。

- B 错：GRPO 恰恰没有把 KL 并入奖励。
- C 错：k3 需要 $\pi_{\text{ref}}$ 的 log-prob，原版 GRPO 仍要参考模型；DAPO 去掉 KL 项之后才可以不要。
- D 错：这正是 GRPO 避免的做法。若把 KL 并入奖励，各回答的 KL 大小不同，会和任务奖励混在一起参与组内归一化，干扰「答对 / 答错」这一主信号。

<sub>考点：KL估计器</sub>

</details>

<a name="ALN-GRPO-010"></a>

### ALN-GRPO-010　基础 · 考频 ★★★

下列任务中，最**不**适合直接用 RLVR（基于可验证奖励的强化学习）训练的是：

- **A.** 附带隐藏单元测试的算法编程题
- **B.** 有标准数值答案的数学竞赛题
- **C.** 为一款新产品撰写一篇有说服力的发布新闻稿
- **D.** 要求「恰好列出三条要点、总字数不超过 100 字」的指令遵循任务

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：RLVR 的前提是奖励能由程序判定。新闻稿「有没有说服力」没有标准答案，只能用奖励模型或 LLM 评审打分，不属于可验证奖励。

RLVR 一词由 Tülu 3（Lambert 等, 2024）提出，用程序判分代替奖励模型：
- A：在沙箱里运行单元测试，按通过与否给分；
- B：抽取最终答案，做数值或符号等价比较；
- D：「条数」「字数」这类约束可以用程序检查，Tülu 3 的 RLVR 数据就包含这类可验证的指令约束。

开放式任务若硬套 RLVR，往往只能验证格式、长度这类表面特征，模型会学会满足表面约束，内容却不会变好。

<sub>考点：RLVR　｜　出处：Tülu 3 技术报告 arXiv:2411.15124</sub>

</details>

<a name="ALN-GRPO-012"></a>

### ALN-GRPO-012　进阶 · 考频 ★★★

DAPO 针对 GRPO 在长思维链训练中暴露的问题提出了四项改进。下列「改进 —— 针对的问题」对应**错误**的是：

- **A.** Clip-Higher —— 对称裁剪下低概率 token 的概率涨不动，策略熵迅速下降
- **B.** 动态采样 —— 组内全对或全错时优势为 0，有效样本越来越少、梯度噪声变大
- **C.** token 级 loss —— 先在样本内按长度平均，导致长回答中每个 token 的权重偏小
- **D.** 超长奖励整形 —— token 级重要性比率的噪声随回答长度累积，导致长回答训练崩溃

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：D 描述的是 GSPO 的动机，不是 DAPO 超长奖励整形针对的问题。

DAPO（Yu 等, 2025, arXiv:2503.14476）的超长奖励整形针对**截断样本的奖励噪声**：被截断的回答可能推理正确、只是没写完，一律判 0 会误导模型。做法是截断样本不计 loss（overlong filtering），并对接近长度上限的回答线性扣分（soft overlong punishment）。

A、B、C 的对应都正确：Clip-Higher 解决熵坍塌，动态采样解决零方差组，token 级 loss 解决样本级平均对长回答的稀释。D 所说的 token 级比率噪声，是 GSPO 改用序列级重要性比率要解决的问题。

<sub>考点：DAPO改进　｜　出处：DAPO 论文 arXiv:2503.14476；GSPO 论文 arXiv:2507.18071</sub>

</details>

<a name="ALN-GRPO-015"></a>

### ALN-GRPO-015　进阶 · 考频 ★★★

DAPO 的 Clip-Higher 只放宽裁剪上界（$\varepsilon_{\text{high}}=0.28$），下界仍保持 $\varepsilon_{\text{low}}=0.2$。不同时放宽下界的主要原因是：

- **A.** 下界只作用于优势为正的 token，防止好 token 的概率下降过多，放宽它对鼓励探索没有帮助
- **B.** 放宽下界会让负优势 token 的概率一步被压得过低，收窄采样空间，反而加剧熵坍塌
- **C.** 下界放得过宽时，裁剪后的比率可能变成负数，导致对数概率无定义、训练数值不稳
- **D.** 下界的作用已由 KL 项承担：DAPO 用对参考模型的 KL 惩罚来约束坏 token 概率的下降

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：上界管「好 token 最多涨多少」，下界管「坏 token 最多降多少」。熵坍塌的症结是低概率 token 涨不动，所以只需放宽上界；放宽下界会让被惩罚的 token 一步降得更狠，概率被压向 0，可选的 token 更少，与维持熵的目标背道而驰。

- A 错：下界 $1-\varepsilon_{\text{low}}$ 只对优势为**负**的 token 生效：比率降到下界以下后，不再给它压低的梯度。
- C 错：比率是两个概率之比，恒为正；下界 $1-0.2=0.8$，即使放宽到 0.3 也只是 0.7，与负数无关。
- D 错：DAPO 恰恰去掉了 KL 项。

<sub>考点：Clip-Higher与熵坍塌　｜　出处：DAPO 论文 arXiv:2503.14476</sub>

</details>

<a name="ALN-GRPO-019"></a>

### ALN-GRPO-019　进阶 · 考频 ★★★

GRPO 原版对每个回答先按自身长度求 token 平均，再对回答求平均（样本级平均）；DAPO 改为把整个 batch 的有效 token 放在一起平均（token 级 loss）。关于两者的差别，下列说法正确的是：

- **A.** 样本级平均下每个回答的总权重相同；token 级平均下每个 token 等权，长回答在梯度中占比更大
- **B.** 两种方式只差一个整体缩放，相当于换了一个学习率，各个 token 之间的梯度比例保持不变
- **C.** token 级平均让短回答中每个 token 的权重变大，长回答被稀释，因此会鼓励模型把回答写短
- **D.** token 级平均主要是为了配合序列打包（packing）、免去按样本求均值，从而节省显存，对优化结果没有影响

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：两种聚合只差在分母，却改变了不同长度回答之间的相对权重。

设回答 $i$ 长 $|y_i|$、优势为 $A_i$。样本级平均中，它每个 token 的梯度权重约为 $A_i/(G\,|y_i|)$，一个回答无论多长，总权重都是 $A_i/G$；token 级平均中每个 token 的权重都是 $A_i/\sum_j|y_j|$，长回答 token 多，整体占比更大。

DAPO 的动机：样本级平均下，长回答里的推理模式学得慢，长回答中的重复、乱码等坏模式又罚得轻；改成 token 级后，这些模式按 token 数被充分奖惩。

- B 错：两者不是同一个常数缩放：分母不同，长短回答之间的相对权重变了，总梯度的方向也会变。
- C 错：token 级平均下每个 token 等权，并不偏向短回答；恰恰是样本级平均让短回答的每个 token 权重更大。
- D 错：两者的计算量和显存几乎相同，打包与否也不影响这一点；区别在优化目标。

<sub>考点：Token级损失　｜　出处：DAPO 论文 arXiv:2503.14476</sub>

</details>

<a name="ALN-GRPO-022"></a>

### ALN-GRPO-022　挑战 · 考频 ★★

复现 R1-Zero 式训练（GRPO 原版目标）时观察到：平均回答长度持续上涨；但按对错拆开看，**正确**回答的长度基本稳定，**错误**回答越写越长，不少顶到了长度上限。按 Dr. GRPO 的分析，最可能的原因是：

- **A.** 模型在难题上学会了更深入的思考：错误回答多来自难题，所以先变长，这是推理能力提升的正常表现
- **B.** 标准差归一化放大了几乎全对或全错题目的优势，使模型倾向于在这些题上把回答写长
- **C.** 目标按 $1/|y_i|$ 对每个回答做长度平均，错误回答越长，每个 token 分到的惩罚越轻
- **D.** KL 系数过大，策略被拉回参考模型原本偏长的输出分布，而错误回答离参考模型更近

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：这是 Dr. GRPO（Liu 等, 2025）指出的**长度偏差**。$1/|y_i|$ 让每个回答的总权重与长度无关：答对时（$A>0$）越短的回答每个 token 得到的奖励越大，鼓励正确回答简洁；答错时（$A<0$）越长的回答每个 token 挨的罚越轻，模型就有动力把错误回答写长。R1-Zero 式训练中「回答越来越长」，有一部分可能来自这个偏差，并不都是「学会了深度思考」。

- A 错：如果是真正的深度思考，正确回答也应变长，且长度增长应伴随准确率提升；这里变长的主要是错误回答，而且是顶到长度上限、写不完的回答。
- B 错：标准差归一化带来的是**难度偏差**（几乎全对或全错的题 std 小、优势被放大），影响的是不同题目之间的权重，并不直接造成「错误回答变长」。
- D 错：KL 把策略整体拉向参考模型，没有理由只让错误回答变长；「错误回答离参考模型更近」也没有依据。

修正：去掉 $1/|y_i|$（改除以固定常数，即 Dr. GRPO 的做法），或使用 token 级平均；同时配合超长惩罚，并按对错分别监控长度和截断率。

<sub>考点：Dr.GRPO　｜　出处：Understanding R1-Zero-Like Training: A Critical Perspective, arXiv:2503.20783</sub>

</details>

<a name="ALN-GRPO-025"></a>

### ALN-GRPO-025　进阶 · 考频 ★★

GSPO 定义序列级重要性比 $s_i(\theta)=\big(\pi_\theta(y_i\mid x)/\pi_{\text{old}}(y_i\mid x)\big)^{1/|y_i|}$，并在序列级做裁剪。关于它，下列说法正确的是：

- **A.** $s_i$ 是各 token 比率的算术平均，因此个别 token 的比率很大时，$s_i$ 也会被显著拉高
- **B.** GSPO 用序列级比率代替了组内相对优势，比率本身已反映回答好坏，不再需要对奖励做组内归一化
- **C.** 序列比率由多个 token 比率累积而成、波动更大，所以 GSPO 的裁剪范围要比 GRPO 常用的 0.2 大得多
- **D.** 开 $1/|y_i|$ 次方让长短回答的比率处于同一量级，否则 token 比率连乘会随长度爆炸或趋于 0

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：$s_i=\exp\big(\frac{1}{|y_i|}\sum_t\log\frac{\pi_\theta(y_{i,t}\mid\cdot)}{\pi_{\text{old}}(y_{i,t}\mid\cdot)}\big)$，是 token 比率的**几何平均**。长度归一化之后，不同长度的回答可以共用同一个裁剪范围。

- A 错：几何平均对个别极端值很不敏感。一个 token 的比率为 3、其余都为 1，长度 400 时 $s_i=3^{1/400}\approx1.0028$。
- B 错：重要性比率衡量的是新旧策略的差异，不反映回答好坏；GSPO 的优势仍是组内相对优势，它只改了比率与裁剪的粒度。
- C 错：恰恰相反。几何平均后的 $s_i$ 非常接近 1，论文的裁剪范围取 $3\times10^{-4}$ 和 $4\times10^{-4}$；照搬 0.2 等于不裁剪。

<sub>考点：GSPO　｜　出处：GSPO 论文 arXiv:2507.18071（v2 实验部分给出裁剪范围 3e-4 / 4e-4）</sub>

</details>

<a name="ALN-GRPO-029"></a>

### ALN-GRPO-029　基础 · 考频 ★★

GRPO 训练中把组大小 $G$ 从 4 增加到 16，其余设置不变。最主要的影响是：

- **A.** $G$ 越大，组内平均后的更新越平稳，策略离参考模型的 KL 越小，因此可以去掉 KL 项
- **B.** 组均值基线更准，难题也更容易出现「有对有错」的组，但每题的生成开销约变为 4 倍
- **C.** $G$ 越大，单步梯度越平滑，新旧策略的重要性比率越接近 1，因此可以去掉裁剪
- **D.** $G$ 只影响基线估计的方差，一组全对或全错的概率只由题目难度决定，与 $G$ 无关

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：$G$ 是「基线质量与信号覆盖」和「生成成本」之间的权衡。

- 组均值作为基线，是 $V(x)$ 的蒙特卡洛估计，$G$ 越大估得越准，标准差的估计也越稳（$G=2$ 时只要两条奖励不同，标准化后永远是 $\pm0.71$）。
- 一组全同的概率是 $p^G+(1-p)^G$：$p=0.1$ 时，$G=4$ 约 0.66，$G=16$ 约 0.19，难题更容易采到成功样本。
- 代价是每题生成量线性增长，而生成往往是 RL 中最慢的环节。DeepSeekMath 每题采 64 个，后来的推理 RL 常用 8～16。

- A 错：KL 由学习率、更新步数、$\beta$ 等决定，与组大小没有直接关系。
- C 错：比率反映新旧策略的差异，取决于每批数据更新了几次、步长多大，与 $G$ 无关。
- D 错：见上面的公式，$G$ 越大，全同的概率越小。

<sub>考点：组大小与采样　｜　出处：DeepSeekMath 论文 arXiv:2402.03300；DAPO 论文 arXiv:2503.14476</sub>

</details>

<a name="ALN-GRPO-032"></a>

### ALN-GRPO-032　进阶 · 考频 ★★

数学题 RLVR 的奖励设为 $R=r_{\text{correct}}+w\cdot r_{\text{format}}$，其中 $r_{\text{correct}},r_{\text{format}}\in\{0,1\}$。某提示词的一组 4 个回答为：① 答对且格式对；② 答对但格式错；③ 答错但格式对；④ 答错且格式错。关于权重 $w$，下列说法正确的是：

- **A.** $w=1$ 时 ② 与 ③ 的优势相同，这组数据体现不出「答对比格式对更重要」
- **B.** 组内归一化会减去均值、除以标准差，所以 $w$ 取多少都不影响各回答的优势
- **C.** $w$ 越大越好：格式奖励更容易拿到，能先提供稳定的梯度信号，正确性自然会跟上
- **D.** $w=0.1$ 时 ③ 的奖励高于组内最低分，优势为正，会鼓励「答错但格式对」的回答

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：组内归一化会消掉奖励的整体平移和缩放，但消不掉各奖励分量之间的**相对权重**。

- $w=1$：奖励 $[2,1,1,0]$，均值 1，② 和 ③ 的优势都是 0，「答对」和「格式对」在这组里同等重要。
- $w=0.1$：奖励 $[1.1,1.0,0.1,0]$，均值 0.55，③ 的优势为负（$0.1-0.55<0$），② 为正，正确性主导排序。

- B 错：归一化是对整组奖励做同一个仿射变换，各回答之间的相对差距仍由 $w$ 决定。
- C 错：格式权重过大时，格式信号在早期主导梯度，模型可能先只学格式；DeepSeek-R1-Zero 用「准确率 + 格式」两项规则奖励，实践中格式分通常取小权重或作为门槛。
- D 错：优势是相对组均值而不是相对最低分，计算见上，③ 的优势为负。

<sub>考点：规则奖励设计　｜　出处：DeepSeek-R1 论文 arXiv:2501.12948</sub>

</details>

### ALN-GRPO-038　基础 · 考频 ★★★

GRPO（$\beta=0.04$，优势计算的分母加了 eps）训练中，某提示词的 4 个回答全部答对。这 4 个样本在本步更新中的作用是：

- **A.** 它们的奖励高于 batch 平均，因此获得正优势，被进一步强化
- **B.** 组内优势全为 0，策略梯度项为 0，只剩 KL 项的梯度把策略拉向参考模型
- **C.** 组内标准差为 0，优势为 NaN，这组样本必须从 batch 中删除
- **D.** 每个样本获得 $1/G=0.25$ 的优势，用于巩固已学会的能力

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：组内奖励全相同 → 偏差全为 0 → 优势全为 0，裁剪的策略梯度项对这些 token 没有贡献；loss 中只剩 $\beta\cdot$k3 的梯度。

- A 错：GRPO 的基线是**本组**均值，不是 batch 均值。

- D 错：没有这样的设计。

<a name="ALN-GRPO-045"></a>

### ALN-GRPO-045　进阶 · 考频 ★★

异步 RL 训练中，样本往往由几个版本之前的权重生成，落后的版本数称为陈旧度（staleness）。关于陈旧度，下列说法正确的是：

- **A.** 异步训练沿用 PPO 的裁剪即可，不必限制最大陈旧度：比率超出范围的 token 会被自动裁掉，旧样本引入的偏差可以忽略
- **B.** 可中断的 rollout（生成到一半时换上新权重继续解码）得到的轨迹，可以统一用最新的权重重算一遍 log-prob，作为行为策略的概率来计算比率
- **C.** 陈旧度上限只影响吞吐、不影响收敛效果：AReaL 的实验表明，陈旧度上限放得越大，训练越快，最终效果也越好
- **D.** one-step off-policy 流水线中，训练端用第 k 批更新参数时，推理端用更新前的权重生成第 k+1 批，每批恰好落后一个版本；陈旧度上限为 0 即同步训练

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：one-step off-policy 用「陈旧度恰好为 1」换取生成与训练的重叠，是最简单的异步形式。

- D 对：第 k+1 批由 $\theta_k$ 生成，却用来把 $\theta_{k+1}$ 更新为 $\theta_{k+2}$，落后一个版本。AReaL 用参数 $\eta$ 表示允许的最大陈旧度，$\eta=0$ 时就是同步 RL。
- A 错：PPO 的裁剪以「旧策略」为中心，前提是旧策略就是采样策略、且与当前策略相差不大。AReaL 的实验中，即使陈旧度不大，直接套用 PPO 的效果也明显变差（$\eta=4$ 时 AIME24 为 23.3，使用解耦目标后为 42.2）；所以既要限制陈旧度，也要做重要性修正。
- B 错：可中断生成的一条轨迹由多个版本的权重分段生成，每段的行为策略不同。必须在生成时逐 token 记录推理端的 log-prob；用最新权重重算会把 off-policy 样本伪装成 on-policy，比率恒为 1 附近，修正失效。
- C 错：AReaL 报告适度的陈旧度（$\eta\le8$）对最终效果影响很小；陈旧度不设上限时，即使用了解耦目标，效果也不如同步训练（AIME24 为 36.9 对 42.0）。实验中数学任务取 $\eta=8$、代码任务取 $\eta=4$。

<sub>考点：异步RL与陈旧度　｜　出处：AReaL 论文 arXiv:2505.24298；verl 文档 One Step Off Policy Async Trainer</sub>

</details>

### ALN-GRPO-004　进阶 · 考频 ★★★

关于 GRPO 去掉价值模型（critic）带来的影响，下列说法**正确**的有：

- **A.** 基线只依赖提示词，所以即使组内回答全对或全错，策略梯度项也不为 0
- **B.** 每个提示词要采样 $G$ 个回答才能算出基线，生成开销随 $G$ 线性增长
- **C.** 同一回答的所有 token 共享一个优势，无法区分哪一步推理是关键步骤

- **E.** 没有 critic 就无法计算重要性比率，因此每批数据只能做一次梯度更新

<details>
<summary>答案与解析</summary>

**答案：BCD**

**解析：**

**结论**：B、C、D 正确。去掉 critic 是「用采样换模型」：省显存、省工程，付出的是生成开销和更粗的信用分配。

- C 对：这是序列级优势的固有局限，长思维链中关键的一步和无关的废话拿到同样的信号。
- D 对：以 7B 为例，混合精度 Adam 的训练态约每参数 16 字节，critic 单独就要约 112 GB。
- E 错：重要性比率是 $\pi_\theta/\pi_{\text{old}}$，只需要采样时保存的旧策略 log-prob，与 critic 无关；GRPO 同样可以把一批数据切成多个 mini-batch 更新，靠裁剪兜底。

<a name="ALN-GRPO-007"></a>

### ALN-GRPO-007　挑战 · 考频 ★★

样本 $y\sim\pi_\theta$，$r=\pi_{\text{ref}}(y)/\pi_\theta(y)$。三种单样本 KL 估计为：k1 $=-\log r$，k2 $=\frac12(\log r)^2$，k3 $=r-1-\log r$。下列说法**正确**的有：

- **A.** 把 k2 直接当 loss 时，梯度的期望恰好等于 $\nabla_\theta\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$
- **B.** k1 与 k3 都是 $\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$ 的无偏估计；两者相比，k1 的单样本值可能为负，k3 恒非负
- **C.** 把 k3 直接当 loss 时，梯度的期望等于 $\nabla_\theta\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$，与目标函数中写的 KL 方向一致
- **D.** 无论两个分布相距多远，k3 的方差都小于 k1
- **E.** 固定样本、只对 $\log\pi_\theta(y)$ 求导时，把 k1 直接当 loss，梯度的期望为 0，起不到约束作用

<details>
<summary>答案与解析</summary>

**答案：ABE**

**解析：**

**结论**：A、B、E 正确。「估计 KL 的值」与「用它的梯度去优化 KL」是两回事。

- A 对：$\nabla k_2=(\log\pi_\theta-\log\pi_{\text{ref}})\nabla\log\pi_\theta$，期望为 $\sum_y(\log\pi_\theta-\log\pi_{\text{ref}})\nabla\pi_\theta$，恰好等于 $\nabla\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$（展开后另一项 $\sum_y\pi_\theta\nabla\log\pi_\theta=0$）。
- B 对：$\mathbb{E}_{\pi_\theta}[-\log r]=\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$；又因 $\mathbb{E}_{\pi_\theta}[r]=\sum_y\pi_{\text{ref}}(y)=1$，k3 的期望也等于这个 KL。k1 单样本可正可负，k3 由 $\log x\le x-1$ 保证非负。
- C 错：$\nabla k_3=(1-r)\nabla\log\pi_\theta(y)$，期望为 $-\sum_y\pi_{\text{ref}}(y)\nabla\log\pi_\theta(y)=\nabla\mathbb{D}_{\mathrm{KL}}(\pi_{\text{ref}}\|\pi_\theta)$，是**正向** KL 的梯度。策略离参考模型不远时两者方向接近，k3 照样能把策略往回拉，但它优化的并不是目标里写的那个 KL。
- D 错：分布接近时 k3 的方差远小于 k1（数值实验：KL≈0.02 时标准差 0.032 对 0.205）；分布很远时 $r$ 偶尔极大，k3 的方差反而更大（KL≈1.09 时 3.40 对 1.11）。
- E 对：$\nabla k_1=\nabla\log\pi_\theta(y)$，而 $\mathbb{E}_{\pi_\theta}[\nabla\log\pi_\theta]=0$。所以 PPO 把 k1 放进**奖励**，经策略梯度才得到 KL 的梯度。

<sub>考点：KL估计器　｜　出处：John Schulman 博客 Approximating KL Divergence（2020）</sub>

</details>

### ALN-GRPO-011　基础 · 考频 ★★

关于 RLVR（可验证奖励），下列说法**正确**的有：

- **A.** 奖励由程序判定，便宜、客观，可以支撑大规模、长时间的在线训练
- **B.** 把 LLM 评审的打分当成「验证器」，就能把 RLVR 直接推广到开放式写作，并且同样难以被钻空子
- **C.** 奖励通常稀疏且接近二值，「差一点做对」和「完全不会」常常得到同样的分数
- **D.** 只要使用规则奖励，就不必再抽检高奖励样本，因为规则判分不会出错
- **E.** 验证器本身也会有漏洞，例如判分过宽时，模型会学会一次写出多个候选答案碰运气

<details>
<summary>答案与解析</summary>

**答案：ACE**

**解析：**

**结论**：A、C、E 正确。RLVR 的优势是客观、便宜，局限是覆盖面窄、信号稀疏，而且验证器并非无懈可击。

- B 错：LLM 评审是模型打分，有偏长、偏格式、可被注入等问题，不属于可验证奖励；被当作优化目标时更容易被钻空子。
- C 对：二值奖励分不出「差一点」和「差很多」；可以用部分分（如测试通过比例）缓解，但要防止模型专刷容易的部分。
- D 错：规则写得宽松或有漏洞时同样会被钻空子（罗列多个答案、针对测试硬编码、利用超时等），要定期人工抽检高奖励样本。
- E 对：验证器只检查「是否出现正确答案」时，罗列答案是最常见的作弊方式之一，对策是严格抽取唯一的最终答案。

### ALN-GRPO-018　基础 · 考频 ★★

关于 DAPO 的动态采样（dynamic sampling），下列说法**正确**的有：

- **A.** 主要代价是额外的生成开销；训练越往后、全对的题越多，开销越大
- **B.** 它只保留当前「学得动」的题，相当于一种自动课程，也会改变训练数据的分布
- **C.** 留下的组都有对有错，所以不再需要组均值基线，直接用 0/1 奖励作优势即可
- **D.** 它过采样提示词，丢弃准确率为 0 或 1 的组，直到凑满一个 batch 的有效组
- **E.** 被过滤掉的全错题会被永久移出训练集，以免后续每一步都在它们身上浪费生成算力

<details>
<summary>答案与解析</summary>

**答案：ABD**

**解析：**

**结论**：A、B、D 正确。

- A 对：一个模拟实验中，训练中期朴素地采 16 题有 9 组优势全为 0，动态采样一共采了 40 题才凑满 16 个有效组，生成量约为 2.5 倍。
- B 对：数据分布会偏向中等难度，所以要监控被过滤的比例，并定期让全错题「回炉」。
- C 错：动态采样只是挑出组内有差异的样本，优势仍按组内均值（和标准差）计算；直接用 0/1 奖励作优势，答错的回答得不到负信号，梯度方差也更大。
- D 对：这是动态采样的定义，保证每一步都有足量、方向明确的梯度，有效 batch 不会因为大量零方差组而忽大忽小。
- E 错：过滤只针对本步采到的组。全错的题之后还可以再采（模型变强后可能有对有错），或配合课程调整难度；永久删除会丢掉最难、最有价值的题。

<a name="ALN-GRPO-031"></a>

### ALN-GRPO-031　进阶 · 考频 ★★

为数学题 RLVR 编写规则验证器时，下列做法中**合理**的有：

- **A.** 回答中出现多个互相矛盾的最终答案时直接判 0 分
- **B.** 格式分与正确性分设成同样的权重（都为 1），让模型尽快学会格式
- **C.** 正式训练前，先用一批人工核对过对错的回答检验验证器，分别统计假阳性和假阴性的比例
- **D.** 只从约定位置（如最后一个 `\boxed{}`）抽取最终答案，而不是在全文中搜索
- **E.** 对答案做数值或符号等价比较，例如把 `1/2`、`0.5`、`\frac{1}{2}` 视为相同

<details>
<summary>答案与解析</summary>

**答案：ACDE**

**解析：**

**结论**：A、C、D、E 正确。验证器既要「不冤枉对的」，也要「不放过错的」，同时堵住常见的投机方式。

- A 对：这是防「多答案碰运气」的直接手段。
- B 错：格式分权重过大，格式信号会在早期主导梯度，正确性进步慢；常见做法是格式分取小权重（如 0.1），或把格式当门槛（格式错直接 0 分）。
- C 对：验证器就是奖励函数，它的错误会直接变成奖励。假阳性（错答判对）会被策略发现并放大利用；假阴性（对答判错）等于给正确行为加噪声。先在人工核对过的样本上量化这两类错误，训练中再定期抽检高奖励样本。
- D 对：约定抽取位置，让「最终答案」唯一、可检查；抽不到答案按错误处理，并单独统计抽取失败率。反过来，若只要标准答案作为子串出现就判对，模型会学会罗列一堆候选答案，或在推理中「顺带」提到各种数字。
- E 对：只做字符串严格相等会把大量正确答案判错（假阴性），等于给奖励加噪声；数学题常用符号计算库或数值容差做等价判断。

<sub>考点：规则奖励设计</sub>

<a name="ALN-GRPO-041"></a>

### ALN-GRPO-041　进阶 · 考频 ★★

GRPO 训练常用推理引擎（如 vLLM、SGLang）生成 rollout，用训练框架（如 FSDP、Megatron）计算梯度。即使两端加载的是同一份权重，同一个 token 的对数概率也常常对不上，这被称为「训推不一致」。关于它的成因与修正，下列说法**正确**的有：

- **A.** PPO / GRPO 的比率 $\pi_\theta/\pi_{\text{old}}$ 已经修正了这层偏差：$\pi_{\text{old}}$ 是用训练引擎在同一批样本上重新计算的，样本由哪个引擎生成并不影响比率的含义，无需额外处理
- **B.** MoE 模型中，微小的数值差异就可能让路由选中不同的专家，放大两端的差异；可以记录推理时的路由结果，训练时强制使用同样的专家（如 Rollout Routing Replay、DeepSeek-V3.2 的 Keep Routing）
- **C.** 推理引擎为追求吞吐，使用与训练框架不同的算子实现和并行切分，而且归约顺序还会随 batch 的组成变化（缺乏 batch invariance）；浮点加法不满足结合律，所以同一 token 在两端算出的概率不同
- **D.** 数值精度本身也有影响：BF16 只有 7 位尾数、舍入误差较大；Qi 等（2025）把训练端与推理端都改用 FP16（10 位尾数），两端对数概率的差异明显缩小，训练也更稳定
- **E.** rollout 使用 top-p / top-k 采样时，真正的采样分布是截断后重新归一化的分布，训练端却按完整的 softmax 计算概率；DeepSeek-V3.2 保存采样时的截断掩码，训练时对当前策略施加同样的掩码

<details>
<summary>答案与解析</summary>

**答案：BCDE**

**解析：**

**结论**：B、C、D、E 正确。训推不一致让「名义上的同策略训练」变成了 off-policy：样本来自推理端的分布 $\mu$，梯度却按训练端的 $\pi$ 计算。

- A 错：PPO 比率的分母是训练端重算的 $\pi_{\text{old}}$，它修正的是「本步内参数更新」带来的偏移；真正生成样本的是推理端的 $\mu$，$\mu$ 与 $\pi_{\text{old}}$ 之间的差距并没有被修正。常见做法是再乘一个截断权重 $\min(\pi_{\text{old}}/\mu,\,C)$（TIS），或屏蔽比率超出区间的 token（MIS、IcePop）。
- B 对：top-k 路由对 logits 的微小扰动很敏感，两端选中的专家不同，激活的参数子空间就不同，差异被放大。Rollout Routing Replay（R3）记录推理端的路由并在训练时回放；DeepSeek-V3.2 报告称 Keep Routing 对 MoE 模型的 RL 稳定性至关重要。
- C 对：两端的注意力与矩阵乘内核、张量并行切分都不同，内核的归约策略还会随 batch 大小变化。Thinking Machines（2025）指出，推理结果不确定的主因正是内核缺乏 batch invariance；他们用 batch-invariant 内核让采样端与训练端逐位一致，两端的 KL 始终为 0，代价是推理吞吐下降。
- D 对：FP16 比 BF16 多 3 位尾数，精度高 8 倍，能吸收两端实现上的细小差别，不让舍入误差沿序列累积。论文称只需几行代码改用 FP16，就能基本消除这种不一致，优化更稳定、收敛更快；代价是动态范围小，需要做损失缩放（loss scaling）防止下溢。
- E 对：截断让两端的「动作空间」不一致，违背了重要性采样的前提。DeepSeek-V3.2 的 Keep Sampling Mask 把采样时的截断掩码用到训练端。
- 补充：不要把这种差异当成均值为零、平均后就能抵消的噪声。它集中在推理端概率很低的 token 上，与内核、硬件有关，而且可能随训练逐步变大；Liu、Li 等（2025）观察到，两端的 KL 在训练崩溃前持续上升，同时伴随梯度范数和熵的尖峰。

<sub>考点：训推不一致与修正　｜　出处：Yao 等博客 Your Efficient RL Framework Secretly Brings You Off-Policy RL Training（2025-08）；Liu、Li 等博客 When Speed Kills Stability（2025-09）；Thinking Machines 博客 Defeating Nondeterminism in LLM Inference（2025-09）；R3 论文 arXiv:2510.11370；Qi 等 Defeating the Training-Inference Mismatch via FP16, arXiv:2510.26788；DeepSeek-V3.2 技术报告 arXiv:2512.02556</sub>

</details>

<a name="ALN-GRPO-049"></a>

### ALN-GRPO-049　进阶 · 考频 ★★

GRPO 训练的监控面板上出现下列现象。对应的判断与处理**合理**的有：

- **A.** 梯度范数偶尔出现尖峰，但奖励和熵都正常：说明尖峰只是少数样本的正常波动，可以关闭梯度裁剪，避免裁剪在平时也削弱正常的学习信号
- **B.** 平均回答长度持续上涨、截断率随之升高，验证集准确率也在上涨：说明模型在有效地思考，截断只是长推理的正常副作用，保持现有长度上限继续训练即可
- **C.** PPO 比率的裁剪比例从 1% 突增到 30%，近似 KL 同步变大：每步更新幅度过大，应检查学习率、每批数据的更新轮数，以及异步陈旧度、训推不一致等 off-policy 来源
- **D.** 策略熵在几十步内从 0.8 跌到 0.05，上界裁剪比例偏高：这是熵坍塌的典型信号，可尝试 Clip-Higher、降低学习率或减少每批数据的更新轮数
- **E.** 训练奖励长期不涨，零方差组的比例高达 80%，其中绝大多数是全错组：说明学习率太小、策略更新太慢，应先把学习率调大几倍，并增加每批数据的更新轮数，让奖励尽快涨起来

<details>
<summary>答案与解析</summary>

**答案：CD**

**解析：**

**结论**：C、D 正确。排障时要把奖励、熵、零方差组比例、长度与截断率、裁剪比例、KL、梯度范数放在一起看。

- A 错：偶发的梯度尖峰往往来自少数异常样本（如极端的重要性比率、低概率 token），梯度裁剪正是为此兜底；它只在范数超过阈值时才生效，平时并不削弱正常信号。应定位尖峰对应的样本，而不是去掉保护。
- B 错：长度增长本身可能是健康的，但截断率上升意味着越来越多的回答写不完。截断样本若按 0 分处理，会给奖励引入噪声，还可能惩罚正确但偏长的推理。应按对错拆开看长度、检查是否出现重复，并采用超长过滤、软超长惩罚或调大长度上限。
- C 对：裁剪比例和近似 KL 是「每步走多远」的直接度量。学习率过大、每批数据更新太多轮、样本陈旧或训推不一致，都会让比率偏离 1。
- D 对：上界裁剪比例偏高，说明大量优势为正的低概率 token 被裁掉。对称裁剪下，低概率 token 的概率涨不上去，概率质量集中到少数路径，熵迅速坍塌、探索停止。DAPO 的 Clip-Higher 放宽上界正是针对这一点；降低学习率、减少更新轮数可以减小每步的变化。
- E 错：全错组的优势全为 0，没有任何梯度信号，奖励自然不涨；调大学习率、增加更新轮数都解决不了「没有信号」的问题，只会放大其余样本的噪声，更新轮数过多还会加剧 off-policy。这说明题目对当前模型太难：难度应落在模型「有时对、有时错」的区间，训练前按通过率重新筛题或补充较易的题，训练中用动态采样过滤零方差组并补采。

<sub>考点：Clip-Higher与熵坍塌、动态采样、组大小与采样　｜　出处：DAPO 论文 arXiv:2503.14476</sub>

### ALN-GRPO-050　挑战 · 考频 ★

下列「GRPO 改进方法 —— 具体做法与针对的问题」的对应中，**正确**的有：

- **A.** GFPO：每题采样更大的组，按长度或「奖励 / token 数」筛出一部分回答，只在保留子集内计算优势、其余回答优势置 0；针对回答长度膨胀的问题
- **B.** GFPO：在奖励中显式加入随回答长度线性增长的惩罚项，再按原版 GRPO 的方式在整组回答上计算均值与标准差、得到优势；针对回答长度膨胀的问题
- **C.** GSPO（Qwen 团队）：把各 token 比率的算术平均作为序列级比率，裁剪范围沿用 GRPO 常用的 0.2；针对错误的长回答受罚过轻、回答长度膨胀的问题
- **D.** CISPO（MiniMax-M1）：对重要性权重同时设上界和下界，并让梯度流经裁剪后的权重，比 PPO 更严格地限制每步更新幅度；主要用于防止训练早期的策略崩溃
- **E.** CISPO（MiniMax-M1）：裁剪重要性权重本身并对它停止梯度，不再丢弃越界 token 的梯度；针对 However、Wait 等低概率反思 token 首次更新后即被裁掉的问题

<details>
<summary>答案与解析</summary>

**答案：AE**

**解析：**

**结论**：A、E 正确。

- A 对：GFPO 的做法是「采样更多、只学其中一部分」：在保留子集上计算均值与标准差，未保留的回答优势为 0，相当于一种隐式的奖励塑形。论文在 Phi-4-reasoning 上报告，长度膨胀减少 46%～71%，按「奖励 / token 数」筛选时减少 71%～85%，准确率基本不变。
- B 错：GFPO 不改奖励函数，而是通过「筛选哪些样本参与学习」来实现隐式的长度控制；显式的长度惩罚是另一类做法（如 DAPO 的软超长惩罚）。
- C 错：GSPO 的序列级比率 $\big(\pi_\theta(y_i\mid x)/\pi_{\text{old}}(y_i\mid x)\big)^{1/|y_i|}$ 是 token 比率的**几何平均**，不是算术平均；序列级比率的裁剪范围比 0.2 小得多（论文用 $3\times10^{-4}$、$4\times10^{-4}$ 量级）。它针对的是 token 级比率噪声大、随长度累积，以及 MoE 模型训练不稳定的问题；「错误的长回答受罚过轻」是 Dr. GRPO 指出的长度偏差，对策是去掉按长度 $1/|y_i|$ 的平均。
- D 错：MiniMax-M1 在实践中没有为重要性权重设下界，只调了上界；而且权重处于停止梯度之下，梯度不会流经它。
- E 对：MiniMax-M1 观察到，However、Recheck、Wait、Aha 这类反思 token 在基座模型中概率很低，更新时比率容易偏大，在第一次 on-policy 更新后就被裁掉，后续的 off-policy 更新中不再贡献梯度。CISPO 的目标为 $\mathrm{sg}(\hat r_{i,t})\hat A_{i,t}\log\pi_\theta(o_{i,t})$，$\hat r$ 是裁剪后的重要性权重：梯度虽因截断略有偏差，但所有 token 都保留了贡献。

<a name="ALN-GRPO-008"></a>

### ALN-GRPO-008　进阶 · 考频 ★★

GRPO 选用 k3 估计器 $r-1-\log r$，是因为它无偏、恒非负且方差小；因此即使训练后期策略已经远离参考模型，KL 项也不会成为梯度噪声的主要来源。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。k3「方差小」只在策略接近参考模型时成立。$r=\pi_{\text{ref}}(y)/\pi_\theta(y)$ 在采到「当前策略认为不太可能、参考模型却认为很可能」的 token 时会非常大，k3 随之暴涨。一个数值实验中，KL 约 0.02 时 k3 的标准差只有 0.032（k1 为 0.205）；KL 约 1.09 时 k3 的标准差达到 3.40，是 k1（1.11）的 3 倍。

所以训练后期要监控 KL 曲线有没有尖峰。常见做法有：调小 $\beta$；对 k3 的取值做截断（一些框架的实现这样做）；或者像 DAPO 那样，在长思维链 + 规则奖励的场景下直接去掉 KL 项。

<sub>考点：KL估计器　｜　出处：John Schulman 博客 Approximating KL Divergence（2020）</sub>

</details>

<a name="ALN-GRPO-016"></a>

### ALN-GRPO-016　基础 · 考频 ★★

在 GRPO 训练中，策略熵随训练缓慢下降是正常现象；真正危险的是准确率还没上去，熵就迅速跌到接近 0：此时同一提示词的 $G$ 个回答几乎一样，组内没有差异，探索停止，pass@k 也不再提升。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。RL 本来就是把概率集中到高奖励的回答上，熵下降是学习的自然结果。例如一个玩具任务（每题只有唯一正确答案）中，熵从 2.29 降到 0.05，同时准确率升到 0.98，这是正常收敛。

熵坍塌指**过早**变得确定：准确率尚未提升，熵已接近 0，组内回答趋同、零方差组比例上升，pass@k 停止增长。排查时要把熵、零方差组比例、裁剪比例和 pass@k 放在一起看。对策包括 Clip-Higher、降低学习率或每批数据的更新轮数、提高采样温度、补充有区分度的题目。有研究（Cui 等, 2025）指出，熵的变化由动作概率与 logit 更新量之间的协方差驱动，而策略梯度类算法中 logit 的更新量与优势成正比：高概率 token 再拿到正优势，熵就下降。他们据此提出只限制高协方差 token 更新的 Clip-Cov、KL-Cov。

</details>

<a name="ALN-GRPO-021"></a>

### ALN-GRPO-021　进阶 · 考频 ★★

DAPO 把 loss 从「先在样本内按长度平均」改为「整个 batch 的有效 token 一起平均」。这样改之后，较长回答在总梯度中的整体占比变大，长回答中出现的重复、乱码等不良模式会受到更充分的惩罚。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。样本级平均下，一个回答不管多长，总权重都是 $A_i/G$，摊到每个 token 上是 $A_i/(G|y_i|)$；token 级平均下每个 token 的权重都是 $A_i/\sum_j|y_j|$，回答越长、token 越多，整体占比越大。

举例：一组中短的正确回答 4 个 token、长的错误回答 12 个 token，优势 ±0.5。样本级平均时，长错答整体受罚 0.25，与短对答整体所得相同；token 级平均时，长错答整体受罚 $12\times0.5/16=0.375$，短对答整体只得 0.125。

DAPO 论文的动机正是：样本级平均下，长样本中的重复、乱码等坏模式罚得太轻，长样本里有价值的推理模式也学得太慢。

<sub>考点：Token级损失　｜　出处：DAPO 论文 arXiv:2503.14476</sub>

</details>

### ALN-GRPO-028　挑战 · 考频 ★

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

<a name="ALN-GRPO-030"></a>

### ALN-GRPO-030　进阶 · 考频 ★★

组大小 $G=2$ 时，只要两个回答的奖励不同，按「减组均值、除以无偏标准差」归一化后，优势永远是 $+0.707$ 和 $-0.707$，与两者的奖励相差多少无关。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。设奖励为 $a>b$，均值 $\frac{a+b}{2}$，偏差 $\pm\frac{a-b}{2}$；无偏标准差 $\sqrt{2\cdot(\frac{a-b}{2})^2/1}=\frac{a-b}{\sqrt2}$，优势 $=\pm\frac{(a-b)/2}{(a-b)/\sqrt2}=\pm\frac{1}{\sqrt2}\approx\pm0.707$（用总体标准差则是 $\pm1$）。

所以 $G=2$ 时，标准化只保留了「谁好谁坏」的排序，「好多少」的信息全部丢失：奖励 0.9 对 0.1 与 0.51 对 0.49 得到同样的梯度。组太小时标准差的估计极不稳定，这是 $G$ 一般取 8 以上的原因之一；若必须用小组，可以考虑不除以 std（Dr. GRPO 的做法），或在更大的范围内归一化。

<sub>考点：组大小与采样、GRPO组内优势</sub>

</details>

### ALN-GRPO-039　基础 · 考频 ★★

<a name="ALN-GRPO-044"></a>

### ALN-GRPO-044　进阶 · 考频 ★

MiniMax-M1 的技术报告发现，训练与推理两端算出的 token 概率存在明显差异，根源是输出层 LM head 的高幅激活；把 LM head 提升到 FP32 后，两端概率的相关性从约 0.9 提高到约 0.99。由此可知，训推不一致的根源就是 LM head 的精度：任何模型只要把 LM head 改为 FP32，就能消除这一问题。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。前半句是 MiniMax-M1 报告的事实，后半句以偏概全。

- **成因因模型、引擎和硬件而异**：Liu、Li 等（2025）在自己的设置中把 vLLM 的 lm_head 改为 FP32 后，两端的 KL 仍然持续上升，训练照样崩溃；他们还发现差异大小与 GPU 型号有关，在 A100 上关闭 cascade attention，就能把两端的 KL 从约 $3\times10^{-2}$～$10^{-1}$ 降到约 $10^{-3}$。
- **其他常见来源**：内核缺乏 batch invariance、注意力实现不同、MoE 路由不一致、采样截断（top-p / top-k）、KV Cache 或权重量化。

<a name="ALN-GRPO-006"></a>

### ALN-GRPO-006　基础 · 考频 ★★★

GRPO 在 loss 中对每个采样到的 token 估计 KL。设某个 token 上 $\log\pi_\theta=-1.0$、$\log\pi_{\text{ref}}=-1.5$，记 $r=\pi_{\text{ref}}/\pi_\theta$。则 k1 估计 $-\log r=$ ____，GRPO 使用的 k3 估计 $r-1-\log r=$ ____（保留 3 位小数）。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0.5 / 0.500；(2) 0.107

**解析：**

$\log r=\log\pi_{\text{ref}}-\log\pi_\theta=-1.5-(-1.0)=-0.5$，$r=e^{-0.5}\approx0.6065$。

- k1 $=-\log r=$ **0.5**；
- k3 $=r-1-\log r\approx0.6065-1+0.5\approx$ **0.107**；
- 顺带 k2 $=\frac12(\log r)^2=0.125$。

反过来，若 $\log\pi_\theta=-1.5$、$\log\pi_{\text{ref}}=-1.0$：k1 $=-0.5$ 是**负数**，而 k3 $=e^{0.5}-1-0.5\approx0.149$ 仍为正。k3 恒非负，因为对所有 $x>0$ 都有 $\log x\le x-1$；又因 $\mathbb{E}_{\pi_\theta}[r]=\sum_y\pi_{\text{ref}}(y)=1$，k3 与 k1 一样是 $\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$ 的无偏估计。单个样本的 k1 可正可负，这是它方差大的直观原因。

<sub>考点：KL估计器</sub>

</details>

### ALN-GRPO-023　进阶 · 考频 ★★

组大小 $G=8$，二值奖励。「难题」8 个回答中只答对 1 个，「中等题」答对 4 个。按 GRPO 原版（减组均值、再除以无偏标准差），难题中答对样本的优势为 ____，中等题中答对样本的优势为 ____；若按 Dr. GRPO 只减均值、不除标准差，两者分别为 ____ 和 ____（保留 3 位小数）。

<details>
<summary>答案与解析</summary>

**答案：** (1) 2.475；(2) 0.935；(3) 0.875；(4) 0.5 / 0.500

**解析：**

- 难题：均值 $1/8=0.125$，答对样本的偏差为 $0.875$；无偏标准差 $\sqrt{\frac{8}{7}\times0.125\times0.875}=\sqrt{0.125}\approx0.3536$，优势 $0.875/0.3536\approx$ **2.475**。
- 中等题：均值 0.5，偏差 0.5；无偏标准差 $\sqrt{\frac{8}{7}\times0.25}\approx0.5345$，优势 $0.5/0.5345\approx$ **0.935**。
- 不除标准差：分别为 **0.875** 和 **0.500**。

除以 std 后，难题答对样本的优势是中等题的 2.65 倍；不除时只有 1.75 倍。Dr. GRPO 把这称为**难度偏差**：组内标准差小的题（几乎全对或几乎全错）权重被放大。几乎全对的简单题里，唯一答错的样本同样会挨 $-2.475$ 的重罚。是否保留 std 归一化存在取舍：保留它会让「偶尔做对一次的难题」学得更多；Dr. GRPO 选择去掉，让目标回到无偏的策略梯度。

### ALN-GRPO-035　基础 · 考频 ★★

DAPO 的软超长惩罚为：

$$R_{\text{len}}(y)=\begin{cases}0, & |y|\le L_{\max}-L_{\text{cache}}\\ \dfrac{(L_{\max}-L_{\text{cache}})-|y|}{L_{\text{cache}}}, & L_{\max}-L_{\text{cache}}<|y|\le L_{\max}\\ -1, & |y|>L_{\max}\end{cases}$$

设 $L_{\max}=20480$、$L_{\text{cache}}=4096$。长度为 15000 的回答惩罚为 ____；长度为 18432 的回答惩罚为 ____；长度为 20480 的回答惩罚为 ____。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0 / 0.0；(2) -0.5 / −0.5；(3) -1 / −1 / -1.0

**解析：**

缓冲区起点为 $L_{\max}-L_{\text{cache}}=16384$。
- $15000\le16384$：惩罚为 **0**；
- 18432 落在缓冲区内：$(16384-18432)/4096=-2048/4096=$ **−0.5**；
- 20480 恰好到上限：$(16384-20480)/4096=$ **−1**。

这组参数与 DAPO 论文一致：预期最大长度 16384、缓冲区 4096、生成上限 20480。这一项加在正确性奖励上，长度越接近上限扣得越多，提醒模型在额度内写完，而不是被一刀切地截断判 0。DAPO 还配合了「超长过滤」：真正被截断的样本不计入 loss，避免把「推理正确但没写完」当成错误来学。软惩罚提供平滑、可学习的信号，过滤则去掉截断带来的奖励噪声。

<sub>考点：DAPO改进　｜　出处：DAPO 论文 arXiv:2503.14476</sub>

<a name="ALN-GRPO-002"></a>

### ALN-GRPO-002　进阶 · 考频 ★★★

用 GRPO 训练代码模型，奖励设计为：通过的单元测试比例（0～1），编译或运行崩溃记 −0.5。某提示词采样 $G=4$ 个回答，结果为：

- 回答 1：5 个测试全部通过；
- 回答 2：5 个测试通过 3 个；
- 回答 3：一个测试都没通过；
- 回答 4：编译失败。

请按 GRPO 计算 4 个回答的优势（标准差用无偏估计，即除以 $G-1$；忽略 eps），保留 3 位小数。若改用总体标准差（除以 $G$），结果有何变化？

<details>
<summary>答案与解析</summary>

**答案：无偏标准差：[+1.098, +0.492, −0.417, −1.174]；总体标准差：[+1.268, +0.568, −0.481, −1.356]，符号与排序不变，数值整体放大 √(4/3)≈1.155 倍**

**解析：**

1. 奖励：$r=[1.0,\ 0.6,\ 0.0,\ -0.5]$；
2. 组均值：$(1.0+0.6+0-0.5)/4=0.275$，偏差 $r-\bar r=[0.725,\ 0.325,\ -0.275,\ -0.775]$；
3. 偏差平方和：$0.525625+0.105625+0.075625+0.600625=1.3075$；
4. 无偏标准差：$\sqrt{1.3075/3}=\sqrt{0.43583}\approx0.6602$；
5. 优势：$[0.725,\ 0.325,\ -0.275,\ -0.775]/0.6602\approx[+1.098,\ +0.492,\ -0.417,\ -1.174]$。

总体标准差为 $\sqrt{1.3075/4}\approx0.5717$，优势为 $[+1.268,\ +0.568,\ -0.481,\ -1.356]$，是前者的 $\sqrt{4/3}\approx1.155$ 倍。

**要点**：
- 优势只取决于组内相对位置：「通过 3 个」高于本组均值，拿到正优势；换一组更强的回答，同样「通过 3 个」也可能是负优势。
- 组内优势之和恒为 0。
- `torch.std` 默认无偏，`numpy.std` 默认总体，两种实现对拍前要先对齐口径；$G$ 越小差别越大。
- 部分分（测试通过比例）让奖励更密，但要警惕模型专刷容易通过的测试；崩溃的负分不宜过大，以免压过主信号。

<sub>考点：GRPO组内优势</sub>

### ALN-GRPO-014　进阶 · 考频 ★★

某步更新中，三个 token 的优势都为正，旧策略下的概率分别为 $\pi_{\text{old}}=0.02$、$0.2$、$0.9$。裁剪目标在比率 $\pi_\theta/\pi_{\text{old}}$ 超过上限 $1+\varepsilon$ 后，不再为该 token 提供推高的梯度。

(1) 对称裁剪 $\varepsilon=0.2$ 时，三个 token 的概率最多被推到多少？绝对涨幅各是多少？
(2) 改用 DAPO 的 $\varepsilon_{\text{high}}=0.28$ 呢？
(3) 据此说明对称裁剪为什么容易导致熵坍塌。

<details>
<summary>答案与解析</summary>

**答案：(1) 0.024、0.24，涨幅 0.004、0.04；0.9 的上限 1.08 超过 1，裁剪等于不起作用；(2) 0.0256、0.256，涨幅 0.0056、0.056；(3) 可涨幅度与 π_old 成正比，低概率的探索性 token 被卡得最死**

**解析：**

**(1)** 上限概率 $=\pi_{\text{old}}\times(1+\varepsilon)$：
- $0.02\times1.2=0.024$，最多涨 0.004；
- $0.2\times1.2=0.24$，最多涨 0.04；
- $0.9\times1.2=1.08>1$，裁剪对它不起作用，概率可以一路涨向 1。

**(2)** $\varepsilon_{\text{high}}=0.28$：$0.02\to0.0256$（涨 0.0056），$0.2\to0.256$（涨 0.056），$0.9$ 仍不受限。

**(3)** 裁剪约束的是**比率**，所以概率的可涨幅度与 $\pi_{\text{old}}$ 成正比：高概率 token 几乎随便涨，低概率的「探索性」token（往往是「换一种思路」「回头检查」这类分叉点）一步只能挪动千分之几。多步之后，概率质量不断集中到已经占优的 token 上，策略熵持续下降，同一题的 $G$ 个回答越来越像，组内差异消失，探索停止。

Clip-Higher 放宽上界，给低概率 token 更多上涨空间；下界保持 0.2，避免把 token 概率一步压到接近 0、进一步收窄采样空间。

### ALN-GRPO-017　进阶 · 考频 ★★

二值奖励、组大小 $G=8$。若某题单次采样的正确率为 $p$，则一组「全对或全错」（优势全为 0，没有策略梯度）的概率为 $p^G+(1-p)^G$。

(1) 分别计算 $p=0.05$、$0.5$、$0.9$ 时的零方差概率；
(2) 若一个 batch 中这三类题各占 1/3，平均有多大比例的组没有梯度？
(3) 用 DAPO 的动态采样凑满 32 个有效组，期望大约要采样多少个组？

<details>
<summary>答案与解析</summary>

**答案：(1) 约 0.663、0.008、0.430；(2) 约 36.7%；(3) 约 51 组（32 ÷ 0.633）**

**解析：**

**(2)** $(0.6634+0.0078+0.4305)/3\approx0.367$，约 36.7% 的组白采。

### ALN-GRPO-042　进阶 · 考频 ★★

一条回答的 4 个 token，推理引擎采样时给出的概率 $\mu$，以及训练引擎（同一份权重）重新计算的概率 $\pi$ 如下：

| token | $\mu$（推理端） | $\pi$（训练端） |
|---|---|---|
| 1 | 0.50 | 0.50 |
| 2 | 0.25 | 0.20 |
| 3 | 0.01 | 0.03 |
| 4 | 0.05 | 0.01 |

记 $\rho_t=\pi/\mu$。

(1) 求各 token 的 $\rho_t$，以及 token 级截断重要性采样（TIS，$C=2$）的权重 $\min(\rho_t,C)$；
(2) 若改用 IcePop 式的掩码：$\rho_t\in[0.5,5]$ 时权重为 $\rho_t$，否则为 0，各 token 的权重是多少？
(3) 求序列级比率 $\prod_t\rho_t$ 及其几何平均 $(\prod_t\rho_t)^{1/4}$（保留 3 位小数），并说明长回答为什么不宜直接用连乘的序列级比率做修正。

<details>
<summary>答案与解析</summary>

**答案：(1) ρ = [1, 0.8, 3, 0.2]，TIS 权重为 [1, 0.8, 2, 0.2]；(2) [1, 0.8, 3, 0]；(3) 连乘为 0.480，几何平均约 0.832**

**解析：**

**(1)** $\rho=[0.50/0.50,\ 0.20/0.25,\ 0.03/0.01,\ 0.01/0.05]=[1,\ 0.8,\ 3,\ 0.2]$。TIS 只截断上端：$[1,\ 0.8,\ \min(3,2)=2,\ 0.2]$。

**(2)** IcePop 把区间外的 token 整个屏蔽：token 4 的 $\rho=0.2<0.5$，权重为 0；token 3 的 $\rho=3$ 在区间内，保留原值。权重为 $[1,\ 0.8,\ 3,\ 0]$。

两者的区别：TIS 对异常 token「降权但保留梯度」（token 4 仍以 0.2 的权重参与更新）；IcePop 认为区间外的 token 噪声太大，直接丢弃它的梯度。Ring-1T 在推理 RL 阶段取 $[\alpha,\beta]=[0.5,5]$。

**(3)** $\prod_t\rho_t=1\times0.8\times3\times0.2=$ **0.480**；几何平均 $0.48^{1/4}\approx$ **0.832**。

连乘比率随长度指数级地放大或缩小：每个 token 只偏 1%，1000 个 token 后就是 $1.01^{1000}\approx2.1\times10^4$ 或 $0.99^{1000}\approx4.3\times10^{-5}$，几条样本就能主导整个 batch 的梯度。所以序列级修正通常改用按长度归一化的几何平均（与 GSPO 的思路一致），再配合阈值屏蔽整条序列（如 Geo-MIS），而不是直接乘连乘比率。

**注意**：
- 这些权重在 stop-gradient 下计算，乘在 PPO / GRPO 的裁剪目标外面；裁剪目标内部的比率仍是 $\pi_\theta/\pi_{\text{old}}$，分母用训练端的概率。
- 本例中差异最大的是 token 3、4，它们在推理端的概率都很低。实践中训推差异正是集中在低概率 token 上。

### ALN-GRPO-046　挑战 · 考频 ★★

(2) 按 AReaL 的解耦 PPO 目标 $\frac{\pi_{\text{prox}}}{\pi_{\text{behav}}}\cdot\min\big(uA,\ \mathrm{clip}(u,1-\varepsilon,1+\varepsilon)A\big)$，其中 $u=\pi_\theta/\pi_{\text{prox}}$，求重要性权重、$u$、目标值，并判断有没有梯度；
(3) 简述为什么信赖域应以近端策略而不是行为策略为中心。

<details>
<summary>答案与解析</summary>

**解析：**

**(1)** 比率 $0.22/0.10=2.2>1+\varepsilon=1.2$，$A>0$ 时取 $\min(2.2,\ 1.2)\times1=$ **1.2**，是常数，**梯度为 0**。

而且本轮更新一开始（$\theta=\theta_{\text{prox}}$）比率就已经是 $0.20/0.10=2.0$，超出了裁剪范围，这个 token 从头到尾贡献不了梯度。陈旧样本里这样的 token 很多，信号被白白浪费。反过来，若 $A<0$ 而比率很大，裁剪不起作用，$\rho A$ 会带来过大的更新。

**(2)** 重要性权重 $\pi_{\text{prox}}/\pi_{\text{behav}}=0.20/0.10=$ **2.0**（在 stop-gradient 下计算）；$u=0.22/0.20=$ **1.1**，落在 $[0.8,1.2]$ 内，取未裁剪项：目标值 $2.0\times1.1\times1=$ **2.2**，**有梯度**（对 $u$ 的导数为 $2.0$）。

**(3)** 解耦目标把两件事分开：
- **分布修正**：样本来自 $\pi_{\text{behav}}$，用 $\pi_{\text{prox}}/\pi_{\text{behav}}$ 做重要性修正；
- **限制步长**：裁剪约束的是「这一次更新走多远」，应以最近的策略 $\pi_{\text{prox}}$ 为中心。若以几个版本之前的 $\pi_{\text{behav}}$ 为中心，要么大量 token 被直接裁掉，要么更新被拉向过时的策略。

AReaL 中 $\pi_{\text{prox}}$ 取每次更新前的参数，在 batch 到达时重算概率；「把近端策略与行为策略解耦」的思路来自 Hilton 等（2021）。实践中重要性权重往往还会再做截断，防止个别极端样本带飞梯度。

<sub>考点：异步RL与陈旧度　｜　出处：AReaL 论文 arXiv:2505.24298；Hilton 等 Batch size-invariance for policy optimization arXiv:2110.00641</sub>

</details>

## 代码输出题

<a name="ALN-GRPO-020"></a>

### ALN-GRPO-020　进阶 · 考频 ★★

一组两个回答：回答 0 答对、长 2 个 token；回答 1 答错、长 6 个 token；不除以标准差时，优势分别为 +0.5 和 −0.5。下面的代码在比率为 1（首个更新步）时，比较三种 loss 聚合方式下每个 token 的 $\log\pi$ 被推动的大小。输出是什么？

```python
import torch

mask = torch.zeros(2, 6)
mask[0, :2] = 1                      # 回答 0：答对，2 个 token
mask[1, :] = 1                       # 回答 1：答错，6 个 token
adv = torch.tensor([[0.5], [-0.5]])  # 不除以 std 的组内优势

for agg in ["seq-mean", "token-mean", "const-norm"]:
    logp = torch.zeros(2, 6, requires_grad=True)
    per_tok = -adv * logp * mask     # 比率为 1 时的策略梯度 loss
    if agg == "seq-mean":            # GRPO 原版：先序列内平均，再对回答平均
        loss = (per_tok.sum(-1) / mask.sum(-1)).mean()
    elif agg == "token-mean":        # DAPO：全部有效 token 一起平均
        loss = per_tok.sum() / mask.sum()
    else:                            # Dr. GRPO：除以固定常数（回答数 × 最大长度）
        loss = per_tok.sum() / (2 * 6)
    loss.backward()
    g = -logp.grad                   # 每个 token 的 log π 被推高多少
    print(agg, round(g[0, 0].item(), 4), round(g[1, 0].item(), 4))
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
seq-mean 0.125 -0.0417
token-mean 0.0625 -0.0625
const-norm 0.0417 -0.0417
```

**解析：**

比率为 1 时，策略梯度 loss 对 $\log\pi$ 的梯度就是 $-A\times$（聚合权重），取负号即「被推高多少」。

- **seq-mean（GRPO 原版）**：每 token 权重 $\frac12\cdot\frac{1}{|y_i|}$。短的正确回答每 token $+0.5/(2\times2)=0.125$，长的错误回答每 token $-0.5/(2\times6)\approx-0.0417$，只有前者的 1/3。错误回答写得越长，每个 token 挨的罚越轻，这就是 Dr. GRPO 指出的**长度偏差**。
- **token-mean（DAPO）**：分母是有效 token 总数 8，每个 token 都是 $\pm0.5/8=\pm0.0625$，等权；长的错误回答整体受罚 $6\times0.0625=0.375$，多于短回答整体所得的 0.125。
- **const-norm（Dr. GRPO）**：分母是固定常数 $2\times6=12$，每个 token 都是 $\pm0.5/12\approx\pm0.0417$，只取决于优势，与回答长度无关。

token-mean 的分母随 batch 内的总 token 数变化，不同 batch 的梯度尺度会随回答长度浮动；Dr. GRPO 用固定常数，彻底与长度脱钩。两者都消除了「按样本长度平均」带来的长度偏差。

<sub>考点：Token级损失、Dr.GRPO　｜　出处：DAPO 论文 arXiv:2503.14476；Dr. GRPO 论文 arXiv:2503.20783</sub>

    """logp、old_logp、mask 形状均为 (N, T)；返回每条回答的序列级比率 s_i，形状 (N,)"""
    log_ratio = (logp - old_logp) * mask

def gspo_loss(logp, old_logp, adv, mask, eps_low=3e-4, eps_high=4e-4):

## 代码改错题

<a name="ALN-GRPO-034"></a>

### ALN-GRPO-034　挑战 · 考频 ★★

下面是 GRPO 逐 token loss 的实现，其中 `k3_kl` 应计算 $\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$ 的 k3 估计 $r-1-\log r$，$r=\pi_{\text{ref}}(y)/\pi_\theta(y)$，样本 $y$ 来自当前策略。代码能运行，KL 值也恒非负，但训练中记录的 KL 数值明显偏离预期。请找出 bug 并修正。

```python
import torch

def k3_kl(logp, ref_logp):
    """逐 token 的 k3 估计，样本来自当前策略 π_θ；logp、ref_logp 为采样 token 的对数概率"""
    log_r = logp - ref_logp
    return torch.exp(log_r) - 1 - log_r

def grpo_token_loss(logp, old_logp, ref_logp, adv, clip=0.2, beta=0.04):
    ratio = torch.exp(logp - old_logp)
    pg = -torch.min(ratio * adv, ratio.clamp(1 - clip, 1 + clip) * adv)
    return pg + beta * k3_kl(logp, ref_logp)
```

<details>
<summary>答案与解析</summary>

**答案：**

**问题**：第 5 行把对数比写反了。`log_r = logp - ref_logp` 算的是 $\log(\pi_\theta/\pi_{\text{ref}})$，函数实际计算的是 $\frac{\pi_\theta}{\pi_{\text{ref}}}-1-\log\frac{\pi_\theta}{\pi_{\text{ref}}}$。它仍然恒非负，看起来「像个 KL」，但在 $y\sim\pi_\theta$ 下的期望不等于 $\mathbb{D}_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$，是有偏的估计。

**修正**：

```python
log_r = ref_logp - logp
return torch.exp(log_r) - 1 - log_r
```

**修正后的代码：**

```python
import torch

def k3_kl(logp, ref_logp):
    """逐 token 的 k3 估计，样本来自当前策略 π_θ；logp、ref_logp 为采样 token 的对数概率"""
    log_r = ref_logp - logp
    return torch.exp(log_r) - 1 - log_r

def grpo_token_loss(logp, old_logp, ref_logp, adv, clip=0.2, beta=0.04):
    ratio = torch.exp(logp - old_logp)
    pg = -torch.min(ratio * adv, ratio.clamp(1 - clip, 1 + clip) * adv)
    return pg + beta * k3_kl(logp, ref_logp)
```

**解析：**

k3 无偏的关键在于 $\mathbb{E}_{y\sim\pi_\theta}[r]=\sum_y\pi_\theta(y)\frac{\pi_{\text{ref}}(y)}{\pi_\theta(y)}=1$，所以 $\mathbb{E}[r-1]=0$，剩下的 $\mathbb{E}[-\log r]$ 正好是 KL。比率写反后，$\mathbb{E}_{\pi_\theta}[\pi_\theta/\pi_{\text{ref}}]=\sum_y\pi_\theta^2/\pi_{\text{ref}}\ge1$，多出的部分让估计系统性偏大（测试的例子中，错误实现的精确期望为 1.345，真实 KL 为 0.574），而且 $\pi_{\text{ref}}$ 很小的 token 会让它爆炸。

测试在小词表上**精确**计算估计量在 $\pi_\theta$ 下的期望，并与真实 KL 对比，比采样检验更灵敏。这类 bug 的危险在于：值恒非负、曲线看起来正常，只有与精确值对拍才能发现。手写 KL 估计器时，先写清 $r$ 的定义以及样本来自哪个分布。

<sub>考点：KL估计器</sub>

</details>

## 编程题

<a name="ALN-GRPO-033"></a>

### ALN-GRPO-033　进阶 · 考频 ★★★

实现 GRPO 的组内相对优势，并顺带返回监控指标「零方差组比例」：

```python
def group_advantages(rewards, G, scale_std=True, eps=1e-6) -> tuple[np.ndarray, float]: ...
```

- `rewards`：长度为 $B\cdot G$ 的一维序列，同一提示词的 $G$ 个回答相邻存放；
- 优势 $=(r_i-\text{组均值})/(\text{组内无偏标准差}+\text{eps})$；`scale_std=False` 时只减组均值（Dr. GRPO 的做法）；
- 组内奖励全相同时优势必须为 0，不能出现 NaN；
- 第二个返回值是「组内奖励全相同」的组所占的比例；
- `G < 2` 或奖励个数不是 `G` 的整数倍时抛出 `ValueError`；
- 只能使用 numpy。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
import numpy as np

def group_advantages(rewards, G, scale_std=True, eps=1e-6):
    r = np.asarray(rewards, dtype=float)
    if G < 2 or r.size % G != 0:
        raise ValueError("G 必须 >= 2，且奖励个数必须是 G 的整数倍")
    r = r.reshape(-1, G)                                   # 每行是同一提示词的 G 个回答
    adv = r - r.mean(axis=1, keepdims=True)
    if scale_std:
        adv = adv / (r.std(axis=1, ddof=1, keepdims=True) + eps)
    zero_frac = float(np.mean(r.max(axis=1) == r.min(axis=1)))   # 组内奖励全相同的比例
    return adv.reshape(-1), zero_frac
```

**测试用例：**

```python
a, z = group_advantages([1, 0, 0, 1, 1, 1, 1, 1], G=4)
assert np.allclose(a, [0.866, -0.866, -0.866, 0.866, 0, 0, 0, 0], atol=1e-3)
assert not np.isnan(a).any() and z == 0.5
b, z = group_advantages([1.0, 0.6, 0.0, -0.5], G=4, scale_std=False)
assert np.allclose(b, [0.725, 0.325, -0.275, -0.775]) and z == 0.0
c, _ = group_advantages([0.3, 0.9, 5.0, 2.0], G=2)                # G=2 时恒为 ±0.707
assert np.allclose(c, [-0.7071, 0.7071, 0.7071, -0.7071], atol=1e-3)
d, z = group_advantages(np.arange(9) % 4, G=3)
assert np.allclose(d.reshape(3, 3).sum(axis=1), 0, atol=1e-9) and z == 0.0
e, z = group_advantages([0, 0, 0, 0, 0, 0], G=3)                   # 全错：优势为 0，不是 NaN
assert np.all(e == 0) and z == 1.0
for bad in (([1, 0, 1], 2), ([1, 0], 1)):
    try:
        group_advantages(*bad)
        raise AssertionError("应抛出 ValueError")
    except ValueError:
        pass
```

**解析：**

**思路**：
1. `reshape(-1, G)`：同一提示词的回答相邻存放，每行就是一组；
2. 按行求均值与无偏标准差（`ddof=1`，与 `torch.std` 的默认口径一致）；
3. 分母加 eps：全同组的 std 为 0、偏差也为 0，结果是 0 而不是 NaN；
4. 零方差组比例用「每行最大值是否等于最小值」判断。它是训练中要盯的关键指标：过高说明题太易或太难，应开动态采样或调整数据难度。

**易错点**：把整批奖励一起求均值和标准差（不同提示词的难度混在一起，全对的简单题也拿到正优势）；写成 `reshape(G, -1)`（与「相邻存放」的布局不符，组被打乱）；忘了 eps；混用无偏与总体标准差。

**复杂度**：时间、空间均为 $O(BG)$。

<sub>考点：GRPO组内优势、动态采样</sub>

</details>

## 简答题

<a name="ALN-GRPO-005"></a>

### ALN-GRPO-005　进阶 · 考频 ★★★

面试官问：「GRPO 相对 PPO 做了哪些简化？每一处简化付出了什么代价？什么样的任务适合用 GRPO？」请回答。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **去掉 critic**：对同一提示词采样 $G$ 个回答，用组均值（再除以组标准差）作基线。只有结果奖励时，组均值就是 $V(x)$ 的蒙特卡洛估计。省掉一个与策略同规模、且在稀疏奖励下很难训准的价值模型（7B 训练态约 112 GB）。**代价**：每题生成 $G$ 次；组内全对或全错时优势全为 0，样本白采。
2. **序列级优势**：一个回答的所有 token 共享同一个优势，不再有逐 token 的 GAE。**代价**：信用分配粗，分不出关键步骤；回答越长方差越大。DeepSeekMath 也给了过程监督版本，用 PRM 的逐步分数缓解这一点。
3. **KL 从奖励挪进 loss**：不再把 $\beta\cdot$KL 拆进逐 token 奖励，而是在 loss 中直接加 k3 估计 $r-1-\log r$（$r=\pi_{\text{ref}}/\pi_\theta$）。好处是优势只反映任务奖励，组内归一化不受 KL 干扰。**代价**：k3 当 loss 时梯度期望对应的是正向 KL $\mathbb{D}_{\mathrm{KL}}(\pi_{\text{ref}}\|\pi_\theta)$；策略远离参考模型时 k3 的方差会变大。
4. **没变的部分**：仍是在线、同策略；仍用 token 级重要性比率和裁剪；原版仍需要参考模型。
5. **随之出现的新问题**：长度偏差与难度偏差（Dr. GRPO）、熵坍塌与零方差组（DAPO）、长序列与 MoE 下 token 级比率不稳（GSPO）。
6. **适用场景**：结果可以自动验证（数学、代码、可检查的指令约束），奖励只在结尾，同一提示词能便宜地多次采样。需要细粒度信用分配的长程任务，或环境无法重置、不能从同一初始状态重复采样时，带 critic 的方法更合适。

**评分要点（共 10 分）：**

- 说清三处简化：去 critic 用组内基线、序列级优势、KL 进 loss 并用 k3（3 分）
- 逐条说出代价：G 倍生成、零方差组、信用分配粗、k3 的方向与方差问题（3 分）
- 指出随之出现的偏差与稳定性问题及对应的改进方法（2 分）
- 能结合任务特点判断何时适合用 GRPO（2 分）

**讲解：**

**常见失分点**：说 GRPO「没有基线」（基线是组均值）；说 GRPO「不需要参考模型」（原版需要，DAPO 去掉 KL 项后才可以不要）；把 GRPO 说成离线算法；只列简化不讲代价；把 KL 的位置说反（PPO 在奖励里用 k1，GRPO 在 loss 里用 k3）。

<sub>考点：去掉价值模型、GRPO组内优势、KL估计器　｜　出处：DeepSeekMath 论文 arXiv:2402.03300</sub>

</details>

<a name="ALN-GRPO-013"></a>

### ALN-GRPO-013　进阶 · 考频 ★★★

DAPO 对 GRPO 做了哪些改进？每一项解决什么问题、具体怎么做？DAPO 还去掉了 KL 项，这样做的理由和前提是什么？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **Clip-Higher**：对称裁剪下，比率上限 $1+\varepsilon$ 让概率的可涨幅度与 $\pi_{\text{old}}$ 成正比，低概率的「探索性」token 几乎涨不动，高概率 token 却几乎不受限，熵迅速坍塌。做法是上下界解耦，$\varepsilon_{\text{low}}=0.2$、$\varepsilon_{\text{high}}=0.28$；下界不放宽，以免把 token 概率一步压向 0。
2. **动态采样**：组内全对或全错时优势全为 0，训练越往后这样的组越多，有效 batch 变小、梯度噪声变大。做法是过采样，丢掉准确率为 0 或 1 的提示词，直到凑满 batch。代价是更多生成。
3. **token 级 loss**：GRPO 原版先在每个样本内按长度平均，长回答中每个 token 的权重被稀释：长回答里的好模式学得慢，重复、乱码等坏模式罚得轻。做法是把整个 batch 的有效 token 放在一起平均，每个 token 等权。
4. **超长奖励整形**：被截断的回答可能推理正确，一律判 0 会引入奖励噪声。做法是截断样本不计 loss（overlong filtering）；再加软超长惩罚：长度进入上限前的缓冲区后线性扣分，到达上限扣满 1 分。
5. **去掉 KL**：长思维链训练中，策略本来就需要显著偏离初始模型；奖励来自可靠的规则验证器，被钻空子的风险小，不再需要 KL 把策略拴在参考模型附近，也顺带省掉参考模型的前向计算。**前提**是奖励可靠；若用神经奖励模型或 LLM 评审，贸然去掉 KL 很容易被钻空子。
6. **效果**：DAPO 在 Qwen2.5-32B 基座上 AIME 2024 达到 50 分，超过 DeepSeek-R1-Zero-Qwen-32B 的 47 分，训练步数约为后者的一半。

**评分要点（共 10 分）：**

- Clip-Higher 的原因与做法，含上下界取值或「只放宽上界」的理由（2 分）
- 动态采样的原因、做法与代价（2 分）
- token 级 loss 针对的稀释问题（2 分）
- 超长奖励整形：截断样本不计 loss + 软超长惩罚（2 分）
- 去掉 KL 的理由，以及「需要可靠的规则奖励」这一前提（2 分）

**讲解：**

**常见失分点**：把 DAPO 说成一种新的优势估计方法（优势仍是组内归一化）；把动态采样说成「删掉难题」；不知道下界为什么不放宽；只说「去掉 KL 训得更快」而不讲前提；把 GSPO 的序列级比率也算进 DAPO。

<a name="ALN-GRPO-024"></a>

### ALN-GRPO-024　进阶 · 考频 ★★

Dr. GRPO（论文 Understanding R1-Zero-Like Training: A Critical Perspective）认为 GRPO 的目标函数中有两处归一化会引入偏差。请说明是哪两处、分别造成什么偏差、在训练中有什么表现，以及 Dr. GRPO 如何修正。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **长度归一化 $1/|y_i|$（回答级的长度偏差）**：每个回答先在自身内部按长度平均。$A>0$ 时越短的回答每个 token 奖励越大；$A<0$ 时越长的回答每个 token 罚得越轻。表现：错误回答越写越长，平均长度上涨被误读为「学会了深度思考」，token 效率差。
2. **除以组内标准差（问题级的难度偏差）**：几乎全对或几乎全错的题组内 std 小，优势被放大，这些题在梯度中权重过高。例如 $G=8$ 时，只对 1 个的难题中答对样本的优势约 2.47，对一半的题只有约 0.94。
3. **修正**：去掉 $1/|y_i|$，改为除以与样本无关的常数（如最大生成长度）；不再除以 std，只减组均值，优势变为 $r_i-\mathrm{mean}(r)$，目标回到无偏的策略梯度形式。
4. **效果**：论文报告在相近的准确率下 token 效率更高，错误回答不再越写越长。
5. **相关结论**：DAPO 的 token 级平均也缓解了长度偏差，但分母随 batch 的总 token 数变化，Dr. GRPO 用的是固定常数。该论文还发现一些基座模型在 RL 之前就已表现出自我反思，提醒我们不要把长度增长和「顿悟时刻」都归功于 RL。

**评分要点（共 10 分）：**

- 指出 1/|y_i| 造成的长度偏差及其方向：正确回答偏短、错误回答偏长（3 分）
- 指出除以 std 造成的难度偏差（2 分）
- 说明训练中的表现，如错误回答变长、长度增长被误读（2 分）
- 说明 Dr. GRPO 的修正方法（2 分）
- 能联系 DAPO 的 token 级 loss 或「基座已有自我反思」等相关结论（1 分）

**讲解：**

**常见失分点**：只说「Dr. GRPO 去掉了归一化」却讲不出偏差的方向；把长度偏差说成「鼓励所有回答变长」（实际是正确回答偏短、错误回答偏长）；把难度偏差和长度偏差混为一谈；认为回答变长一定代表推理能力提升。

<a name="ALN-GRPO-027"></a>

### ALN-GRPO-027　挑战 · 考频 ★★

GSPO 的作者认为 GRPO 的 token 级重要性比率「更像噪声而不是修正」。请解释这一论点；说明 GSPO 如何改写比率与裁剪；并解释为什么它在 MoE 模型上更稳定，以及 Routing Replay 是什么。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **论点**：重要性采样要靠「同一分布下的大量样本」取平均才能起到修正作用。GRPO 在每个 token 位置只有一个样本，token 级比率 $\pi_\theta(y_{i,t})/\pi_{\text{old}}(y_{i,t})$ 更像高方差的噪声；这些噪声随回答长度累积，再经裁剪机制放大，长回答训练时可能出现难以恢复的崩溃。奖励是按整条回答给的，修正也应该按整条回答做。
2. **改写**：序列级比率 $s_i=(\pi_\theta(y_i)/\pi_{\text{old}}(y_i))^{1/|y_i|}$，即 token 对数比的平均再取指数；开 $1/|y_i|$ 次方让长短回答处于同一量级。目标为 $\frac1G\sum_i\min(s_i\hat A_i,\mathrm{clip}(s_i,1-\varepsilon,1+\varepsilon)\hat A_i)$，整条回答要么一起被裁、要么一起保留；同一回答内所有 token 梯度等权。裁剪范围很小（论文取 $3\times10^{-4}$ 和 $4\times10^{-4}$）。需要逐 token 优势时（如多轮场景），有 GSPO-token 变体。
3. **MoE 的问题**：每次参数更新后，同一条样本在新旧策略下激活的专家会变化。论文观察到 Qwen3-30B-A3B 每次梯度更新后约有 10% 的激活专家不同，于是一批 token 的比率剧烈跳动，GRPO 难以收敛。
4. **Routing Replay**：缓存旧策略前向时的路由结果，计算新策略概率时强制沿用同样的专家，使 token 比率可比。它能让 GRPO 在 MoE 上收敛，但增加了显存与通信开销，也限制了模型的真实路由。
5. **GSPO 为什么不需要它**：序列级比率只看整条回答的平均对数比，个别 token 因路由变化产生的跳动被平均掉；论文还认为序列级似然对数值精度不那么敏感，有望直接使用推理引擎返回的概率，减少训练端的重算。
6. **一个反直觉的现象**：GSPO 被裁剪的比例比 GRPO 高约两个数量级，训练效率却更高，说明 token 级梯度本身噪声很大。

**评分要点（共 10 分）：**

- 解释 token 级比率「单样本、高方差、随长度累积」的论点（3 分）
- 写出序列级比率的定义、长度归一化的作用与裁剪范围的量级（3 分）
- 说明 MoE 路由变化导致比率跳动，以及 Routing Replay 的做法与代价（3 分）
- 提到 GSPO-token、裁剪比例高但效率更高等细节之一（1 分）

**讲解：**

**常见失分点**：说 GSPO 不做组内优势归一化（它只改了比率和裁剪的粒度）；把序列级比率写成 token 比率的连乘而不做长度归一化；照搬 0.2 的裁剪范围；说不清 MoE 不稳的根源是路由在新旧策略之间变化。

<sub>考点：GSPO　｜　出处：GSPO 论文 arXiv:2507.18071</sub>

</details>

<a name="ALN-GRPO-040"></a>

### ALN-GRPO-040　进阶 · 考频 ★★

设计 GRPO 训练时，组大小 $G$ 怎么选？请从基线质量、零方差组概率、生成成本、与每步提示词数量的关系等方面分析，并说明有哪些按题目难度动态调整采样的做法。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **基线质量**：组均值是 $V(x)$ 的蒙特卡洛估计，标准差也在组内估计。$G$ 太小时两者都很噪：$G=2$ 时只要两条奖励不同，标准化后永远是 $\pm0.71$，「好多少」的信息全部丢失。
2. **零方差组概率**：一组全对或全错的概率为 $p^G+(1-p)^G$。难题（$p$ 小）要足够大的 $G$ 才能采到成功样本：$p=0.1$ 时，$G=4$ 约 66% 的组没有信号，$G=16$ 约 19%。
3. **生成成本**：生成开销随 $G$ 线性增长，长思维链下生成是最慢的环节；同一提示词的 $G$ 个回答共享前缀，推理引擎的前缀缓存可以省掉重复的 prefill。
4. **与每步提示词数的关系**：每步回答总数 = 提示词数 × $G$。算力固定时，增大 $G$ 就要减少每步的提示词数，题目多样性下降。常见取值：DeepSeekMath 每题采 64 个；后来的推理 RL 常用 8～16。
5. **动态调整**：训练前按通过率筛题（去掉 0 和 1）；训练中用动态采样过滤零方差组并补采；对难题追加采样，或先用较小的 $G$ 探测、只对「有成功迹象」的题扩采；按难度做课程学习。若为提速采用「多发请求、先完成先用」，会系统性偏向短回答和简单题，要补采或加权。
6. **监控**：零方差组比例、每题通过率分布、生成耗时占比，据此调整 $G$ 与提示词数的配比。

**评分要点（共 10 分）：**

- 说明 G 对基线与标准差估计的影响，含 G 过小的问题（2 分）
- 用 p^G + (1-p)^G 说明 G 与零方差组的关系（3 分）
- 说明生成成本、固定算力下 G 与提示词数的取舍，并给出常见取值（2 分）
- 给出按难度动态采样的具体做法与监控指标（3 分）

**讲解：**

**常见失分点**：只说「越大越好」或「8 就够」而不讲代价；不会计算零方差组的概率；忽略固定算力下 $G$ 与题目数之间的取舍；不提难度筛选与动态采样。

<sub>考点：组大小与采样、动态采样</sub>

</details>

<a name="ALN-GRPO-047"></a>

### ALN-GRPO-047　挑战 · 考频 ★★

长思维链 RL 中，rollout 占了每一步的大部分时间，回答长度的长尾也很严重。团队打算把同步共卡（colocate）训练改成异步训练。请说明：
(1) 共卡同步与分离异步各自的优缺点，什么情况下值得改成异步；
(2) 陈旧度上限怎样确定，样本太旧时怎样处理；
(3) partial rollout（未生成完的轨迹跨轮续写）怎么做，需要怎样的 off-policy 修正；
(4) 改造后要监控哪些指标。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **共卡同步与分离异步**
   - 共卡同步：同一组 GPU 轮流生成与训练，除训推不一致外是严格同策略，实现简单，权重同步几乎免费；缺点是长尾时整组 GPU 空等最慢的回答，生成与训练不能重叠，GPU 还要同时容纳训练状态与 KV Cache（或频繁卸载、重切分）。
   - 分离异步：推理与训练用两组 GPU 并行，推理端持续接收新请求，长尾不再阻塞；代价是样本变成 off-policy、需要显式的权重同步（如 NCCL 广播）、要配平两侧资源，系统更复杂。
   - 注意：若两侧都理想线性扩展，单纯把 GPU 拆成两组并行并不提高总吞吐，收益主要来自消除长尾空等、省掉模式切换开销、两侧各用更合适的并行配置。生成占比高、长尾严重（长思维链、多轮 Agent）、规模较大时最值得改。
2. **陈旧度上限**
   - 以「生成样本的权重落后几个版本」计；可以先从 1（one-step off-policy）起步，再按生成与训练的耗时比、长尾程度逐步放宽。AReaL 的实验中，数学任务取 8、代码任务取 4，适度的陈旧度对最终效果影响很小。
   - 实现：每条样本带上权重版本号；限制推理端在途请求的数量；组 batch 时优先消费旧样本；超过上限的样本丢弃或降权。
   - 用小规模消融确定上限：比较不同上限下的奖励曲线和评测结果。
3. **partial rollout 与修正**
   - 给每轮生成设 token 预算，没写完的轨迹存入缓冲区，下一轮由新权重续写（Kimi k1.5 的 partial rollout、Ring-1T 的 C3PO++）；AReaL 论文中的可中断生成则在权重更新时打断解码，用新权重重算 KV Cache 后继续。
   - 一条轨迹的不同片段来自不同版本，必须在生成时逐 token 记录行为策略的 log-prob，不能事后用新权重重算。
   - 修正：解耦 PPO（以近端策略为信赖域中心，用 $\pi_{\text{prox}}/\pi_{\text{behav}}$ 做重要性修正）、截断重要性权重；跨轮次太多的片段可以丢弃（C3PO++ 设置了保留期限），或不计入 loss。
4. **监控指标**：每个 batch 的版本差分布（均值、最大值）；重要性权重的分布与截断比例；PPO 裁剪比例；训推 mismatch-KL；生成吞吐、GPU 利用率、缓冲区长度；样本的长度与难度分布（「先完成先用」会偏向短回答和简单题）；奖励与评测曲线，并与同步基线对比。

**评分要点（共 10 分）：**

- 说清共卡同步与分离异步的取舍和适用场景，指出收益的真正来源（3 分）
- 说明陈旧度的定义、上限的确定方法与超限样本的处理（2 分）
- 说明 partial rollout 的做法，以及逐 token 记录行为 log-prob、解耦目标或截断重要性权重等修正（3 分）
- 给出合理的监控指标（2 分）

**讲解：**

**常见失分点**：以为「异步 = 更快」，忽略长尾这一收益来源和陈旧样本的代价；不限制陈旧度、直接用旧样本跑 PPO；partial rollout 之后用新权重重算行为概率；只监控奖励，不看版本差与重要性权重的分布；忽略「先完成先用」带来的样本偏差。

<sub>考点：异步RL与陈旧度　｜　出处：AReaL 论文 arXiv:2505.24298；Kimi k1.5 技术报告 arXiv:2501.12599；Ring-1T 技术报告 arXiv:2510.18855；Hugging Face 博客 Keep the Tokens Flowing: Lessons from 16 Open-Source RL Libraries（2026-03）</sub>

</details>

### ALN-GRPO-048　进阶 · 考频 ★★

你维护一个 GRPO 训练框架，一步训练的数据流是：取提示词 → 每题采样 $G$ 个回答 → 奖励打分 → 计算组内优势 → 计算 loss 并更新 → 同步权重。现在要接入 DAPO 的四项改进（Clip-Higher、动态采样、token 级 loss、超长奖励塑形）。请按数据流说明每项改进要改哪个环节、实现时要注意什么，以及上线前怎样验证实现正确、改进有效。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **打分之后：动态采样**
   - 按组检查奖励，去掉全对或全错（组内方差为 0）的组；凑不满一个 batch 时继续采样补齐。
   - 注意：设置补采的轮数上限，避免题目太难或太易时无限补采；记录过滤比例，它本身就是难度分布的监控指标；过滤后 batch 偏向中等难度的题，评估训练集表现时要考虑这一点。
2. **奖励环节：超长塑形**
   - 软超长惩罚按回答长度分段计算：长度不超过 $L_{\max}-L_{\text{cache}}$ 时为 0，进入缓冲区后线性减到 $-1$，加到正确性奖励上；或者对被截断的样本做超长过滤（不计 loss）。
   - 注意：长度按回答 token 数计算（不含提示词），与生成长度上限保持一致；截断样本不能被当作「答错」来学。
3. **优势环节**：仍是组内标准化，分母加 eps；如果同时引入 Dr. GRPO 式的「不除以标准差」，要在配置中统一，避免两套逻辑混用。
4. **loss 环节**
   - Clip-Higher：裁剪的上下界分开配置（如 $\varepsilon_{\text{low}}=0.2$、$\varepsilon_{\text{high}}=0.28$），只放宽上界。
   - token 级聚合：所有回答的有效 token 损失求和，除以整个 batch 的有效 token 总数，而不是先在每条回答内平均。梯度累积或数据并行时，分母必须是全局的有效 token 数；各个 micro-batch 各自平均再求平均，又会退回按样本加权。
   - DAPO 去掉了 KL 项：可以不加载参考模型，省下显存与计算。
5. **验证**
   - 单元测试：构造两条长度不同的回答，手算 token 级 loss 与梯度，与实现对拍；构造 $A>0$、比率在 $(1.2,1.28]$ 之间的 token，确认放宽上界后它有梯度；动态采样之后，batch 中零方差组的比例应为 0；改变 micro-batch 的切分方式，loss 应保持不变。
   - 端到端：用小模型短训练，与原版 GRPO 对比熵曲线（Clip-Higher 应减缓熵的下降）、零方差组比例、长度与截断率、验证集准确率；逐项消融，确认每项改动的收益。

**评分要点（共 10 分）：**

- 动态采样放在打分之后，说明补采上限与过滤比例的监控（2 分）
- 超长惩罚或超长过滤放在奖励或 loss mask 环节，并说明长度口径（2 分）
- 在 loss 环节实现 Clip-Higher 与 token 级聚合，指出梯度累积和数据并行下的分母问题（3 分）
- 给出对拍、不变性检查与消融等验证方法（3 分）

**讲解：**

**常见失分点**：只罗列 DAPO 的四个名字，说不清各自落在数据流的哪个环节；token 级聚合只在 micro-batch 内做，忽略全局分母；动态采样不设补采上限；只看训练奖励就宣布「接入成功」，没有对拍与消融。面试中这类题考的是「把论文翻译成代码改动」的能力，按数据流组织答案最清楚。

### ALN-GRPO-036　挑战 · 考频 ★★

团队在 7B 基座上用 GRPO 原版目标训练数学推理：$G=8$，对称裁剪 $\varepsilon=0.2$，$\beta=0.04$，样本级平均（先在回答内按长度平均），最大生成长度 8K，训练集是 2 万道题，未做难度筛选。训练 300 步后：

请分析原因，并给出按优先级排列的改进方案和验证方法。

<details>
<summary>答案与解析</summary>

**参考答案：**

**原因分析**：
1. **熵坍塌**：对称裁剪让低概率 token 涨不动，概率集中到少数高频路径；熵跌到 0.05、pass@8 下降，说明模型丢掉了多样性，同一题的 8 个回答几乎一样。
2. **零方差组过多**：72% 的组全对或全错，优势全为 0，有效 batch 只剩约四分之一，梯度噪声大。一部分是题太简单（训练奖励已到 0.8，大量题全对），一部分是熵坍塌后「错也错得一样」。训练集未做难度筛选加剧了这一点。
3. **长度偏差**：样本级平均下，错误回答越长每个 token 受罚越轻（Dr. GRPO 指出的偏差），于是错误回答越写越长、顶到上限。
4. **截断处理不当**：截断样本直接判 0，其中可能有推理正确只是没写完的回答，被当成错误来学，给奖励加了噪声。

**改进（按优先级）**：
1. **数据与采样**：用当前模型对训练题采样 8～16 次，去掉通过率为 0 或 1 的题，补充更难的题；开启动态采样，过滤零方差组并补采。
2. **防熵坍塌**：Clip-Higher（$\varepsilon_{\text{high}}=0.28$，下界保持 0.2）；适当降低学习率或减少每批数据的更新轮数；必要时提高采样温度。
3. **修长度偏差**：改为 token 级平均（DAPO）或除以固定常数（Dr. GRPO）。
4. **截断处理**：截断样本不计 loss（超长过滤），并加软超长惩罚；视情况调大长度上限。
5. **KL**：规则奖励可靠时可以减小 $\beta$ 或去掉 KL，给策略更多探索空间，同时加强监控。

**验证**：熵是否稳定在合理区间而不是贴近 0；零方差组比例是否降到中等水平；按对错拆开的长度分布与截断率；验证集 pass@1 与 pass@k 是否同时上升；抽检高奖励样本，排除奖励黑客。每项改动单独做消融，确认收益来源。

**评分要点（共 10 分）：**

- 识别熵坍塌及其与对称裁剪、pass@k 下降的关系，并给出 Clip-Higher 等对策（3 分）
- 识别零方差组过多与数据难度问题，给出难度筛选与动态采样（2 分）
- 识别样本级平均造成的长度偏差和截断判 0 的奖励噪声，给出 token 级 loss 或 Dr. GRPO、超长过滤与软惩罚（3 分）
- 给出可执行的验证指标与消融思路（2 分）

**讲解：**

**常见失分点**：只说「调学习率」「加数据」；把错误回答变长解读成「模型在努力思考」；忽略截断样本的处理；只看训练奖励，不看 pass@k、熵和零方差组比例；一次改动多处却不做消融。

<sub>考点：Clip-Higher与熵坍塌、动态采样、Dr.GRPO　｜　出处：DAPO 论文 arXiv:2503.14476；Dr. GRPO 论文 arXiv:2503.20783</sub>

</details>

<a name="ALN-GRPO-037"></a>

### ALN-GRPO-037　挑战 · 考频 ★★

你负责数学 RLVR 的验证器。训练两周后，训练奖励持续上涨，但留出的人工评测集准确率不涨。抽检高奖励样本和部分低奖励样本，发现三类现象：

1. 有的回答在 `\boxed{}` 之外又写了「也可能是 12 或 15」，验证器在全文中搜到了正确答案，判为正确；
2. 有的回答给出 `\boxed{0.5}`，标准答案写作 `\frac{1}{2}`，被判为错误；
3. 有的回答推理过程明显错误，最终答案却碰巧正确。

请分析每类现象对训练的影响，并给出验证器和训练流程上的改进方案。

<details>
<summary>答案与解析</summary>

**参考答案：**

**影响分析**：
1. **多答案碰运气（假阳性）**：验证器在全文中搜答案，罗列候选就能得分，RL 会持续放大这种投机行为，训练奖励虚高而真实准确率不涨。这是典型的奖励黑客，说明奖励的**定义**有漏洞。
2. **等价答案被判错（假阴性）**：正确回答拿不到奖励，等于给奖励加噪声，还可能让模型去迎合某种书写格式而不是把题做对；假阴性往往集中在分数、根式、区间、带单位的题型上，会系统性地压低这些题的学习信号。
3. **过程错、答案对**：结果奖励只看最终答案，这类样本拿到正优势，错误推理被强化；答案空间小的题（选择题、是非题）尤其常见。

**改进方案**：
1. **严格抽取**：只认最后一个 `\boxed{}`（或约定的答案标签）；出现多个不一致的最终答案，或在答案区之外罗列候选，直接判 0；抽取失败单独统计。
2. **等价判断**：用符号计算库做代数等价，数值题允许容差；统一单位、大小写、空格、千分位；为验证器建立单元测试集（正例、反例、对抗样例），每次修改都回归。
3. **数据侧**：减少或改写答案空间很小的题，降低蒙对概率；核查标准答案本身是否有错。
4. **过程信号作辅助**：用独立模型或 PRM 抽检高奖励样本的推理过程，用于发现问题、筛选数据，而不是直接作为主奖励（PRM 自身也会被钻空子）。
5. **流程**：验证器版本化；训练中持续抽检高奖励样本；保留不参与训练的人工评测集作为锚点；发现漏洞后修复验证器、清洗受影响的数据，必要时回退到漏洞被利用之前的检查点。

**评分要点（共 10 分）：**

- 指出全文搜索导致多答案投机，属于奖励黑客，并给出严格抽取与多答案判 0（3 分）
- 指出等价答案判错是假阴性噪声，并给出等价比较与验证器测试集（2 分）
- 指出结果奖励无法区分过程对错，给出减少蒙对与过程抽检等措施（3 分）
- 给出版本化、抽检、留出评测与回退等流程措施（2 分）

**讲解：**

**常见失分点**：只说「换成奖励模型」（神经奖励模型更容易被钻空子）；只修假阳性而忽视假阴性；把「过程错、答案对」归咎于模型而不是奖励设计；没有为验证器本身建立测试。

<sub>考点：规则奖励设计、RLVR</sub>

</details>

<a name="ALN-GRPO-043"></a>

### ALN-GRPO-043　挑战 · 考频 ★★

团队用同一套 GRPO 流水线（vLLM 采样、FSDP 训练、BF16）训练两个模型：8B 稠密模型一直很稳定；30B-A3B 的 MoE 模型却在第 250 步左右崩溃：训练奖励骤降，熵和梯度范数同时出现尖峰。日志显示：

- 衡量两端差异的指标 mismatch-KL（在推理端采样的 token 上，用 k3 估计 $\mathrm{KL}(\mu\|\pi)$，$\mu$、$\pi$ 分别为推理端与训练端的概率）从训练初期的约 $10^{-3}$ 逐步升到 $10^{-1}$，尖峰集中在少数 batch；
- 按 token 统计，两端差异最大的大多是推理端概率很低的 token；
- PPO 比率 $\pi_\theta/\pi_{\text{old}}$ 的裁剪比例一直正常。

请分析原因，给出排查步骤、按优先级排列的修正方案，以及验证方法。

<details>
<summary>答案与解析</summary>

**参考答案：**

**原因分析**
1. **训推不一致造成的隐性 off-policy**：样本来自推理端的 $\mu$，梯度按训练端的 $\pi$ 计算。PPO 比率的分母 $\pi_{\text{old}}$ 是训练端重算的，看不到 $\mu$ 与 $\pi_{\text{old}}$ 的差距，所以裁剪比例正常，偏差却一直没有被修正。
2. **MoE 把差异放大**：路由的 top-k 选择对微小的数值差异敏感，两端可能选中不同的专家，相当于用了不同的参数子空间。稠密模型没有这一层放大，所以同一套流水线下表现稳定。
3. **低概率 token 是重灾区**：$\mu$ 很小的 token 上比率最极端，这些 token 的 $\nabla\log\pi$ 也大，少数样本就能造成梯度尖峰。
4. **可能存在正反馈**：有偏的梯度把策略推向两端差异更大的区域，差异继续变大，直至崩溃。mismatch-KL 逐步上升正是这一过程的信号（Ring-1T 报告对此给出过理论分析，Liu、Li 等也观察到类似现象）。

**排查步骤**
1. 固定一批样本，分别用推理引擎和训练引擎计算 log-prob，逐层比对隐藏状态，找出差异最大的层（MiniMax-M1 由此定位到 LM head 的高幅激活）。
2. 记录推理端的路由结果并在训练端回放，看 mismatch-KL 下降多少，判断路由不一致的贡献。
3. 检查采样设置：两端是否使用同一组 token id（直接复用推理端返回的 id，不要解码再重新编码）、同样的模板与温度；top-p / top-k 截断是否被训练端忽略。
4. 检查数值与内核：KV Cache 或权重是否量化、推理端的特殊注意力内核（如 cascade attention、chunked prefill）、不同 GPU 型号。
5. 把 mismatch 按 token 概率分桶、按 batch 统计，找出高 mismatch batch 的共同特征（超长回答、多轮工具返回、特定语言等）。

**修正方案（按优先级）**
1. **路由一致**：采用 R3 / Keep Routing，训练时使用推理端记录的专家路由。
2. **在损失中修正**：token 级截断重要性采样 $\min(\pi_{\text{old}}/\mu,\,C)$，或屏蔽比率超出区间的 token（MIS、IcePop）；也可以做序列级修正：按几何平均比率屏蔽整条序列，或像 DeepSeek-V3.2 那样屏蔽「优势为负、且与采样策略偏离过大」的序列。
3. **对齐采样空间**：保存 top-p / top-k 的截断掩码，训练时对 $\pi$ 施加同样的掩码。
4. **数值手段**：LM head 用 FP32（MiniMax-M1 报告有效，但并非对所有设置都有效，需实测）；改用 FP16 以减小舍入误差（Qi 等, 2025）；使用 batch-invariant 内核（逐位一致，代价是推理吞吐下降）。
5. **兜底**：mismatch-KL 超过阈值的 batch 跳过或降权并告警；从崩溃前的检查点回滚后，带着上述修正重启。

**验证**
- mismatch-KL 回到 $10^{-3}$ 量级，且不再随训练上升；熵和梯度范数没有尖峰；
- 与稠密模型、与「小学习率 + 严格同步」的基线对比奖励曲线和评测指标；
- 逐项消融，确认是哪一项修正起了作用，避免把多项改动的效果混为一谈。

**评分要点（共 10 分）：**

- 指出崩溃源于训推不一致造成的 off-policy，并解释为什么 PPO 裁剪比例正常却没有修正这层偏差（3 分）
- 解释 MoE 路由的放大作用，以及差异集中在低概率 token 的影响（2 分）
- 给出可操作的排查步骤：逐层或逐 token 比对、路由回放对照、采样设置与数值内核检查（2 分）
- 给出路由回放、TIS / MIS 或序列级屏蔽、数值精度等修正方案，并说明代价（2 分）
- 给出验证方法，包括监控 mismatch-KL 与消融（1 分）

**讲解：**

**常见失分点**：只调小学习率或加大 KL 系数；认为「同步训练就是严格同策略」；把 PPO 的裁剪当成训推修正；只给出一种手段，不做排查就下结论；把「LM head 改 FP32」当作万能解。高分回答要先说清 $\mu$、$\pi_{\text{old}}$、$\pi_\theta$ 三个分布的关系，再解释为什么 MoE 更脆弱。

<sub>考点：训推不一致与修正、GSPO　｜　出处：Liu、Li 等博客 When Speed Kills Stability（2025-09）；MiniMax-M1 技术报告 arXiv:2506.13585；R3 论文 arXiv:2510.11370；Ring-1T 技术报告 arXiv:2510.18855；DeepSeek-V3.2 技术报告 arXiv:2512.02556；Qi 等 arXiv:2510.26788</sub>

</details>
