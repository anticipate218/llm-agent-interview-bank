<a name="TRN-PT-001"></a>

### TRN-PT-001　基础 · 考频 ★★★

关于 Decoder-only 因果语言模型的预训练目标，下列说法正确的是：

- **A.** 训练时把模型上一步自己生成的 token 作为下一步输入，使训练条件与推理时保持一致，避免暴露偏差
- **B.** 长度为 $T$ 的序列只在最后一个位置计算损失，前面的 token 只提供上下文，以免重复计算梯度
- **C.** 最小化各位置预测下一个 token 的平均交叉熵，即最大化文本的对数似然，各位置可并行计算
- **D.** 损失是模型最后一层输出向量与真实下一个 token 的 Embedding 向量之间的均方误差

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：预训练就是对文本做最大似然估计，损失是逐位置的下一个 token 交叉熵。

按链式法则 $p(x_1,\dots,x_T)=\prod_t p_\theta(x_t\mid x_{<t})$，取负对数再按位置平均，就得到损失 $\mathcal{L}=-\frac{1}{T}\sum_t\log p_\theta(x_t\mid x_{<t})$。训练采用教师强制（teacher forcing）：每个位置的输入都是真实前文，因果掩码保证位置 $t$ 看不到它之后的 token，所以一次前向就能得到全部位置的预测与损失。

- A 错：这叫自由运行（free running），预训练一般不这样做：只能串行生成、速度慢，早期的错误还会不断累积。教师强制与推理条件之间的差异被称为暴露偏差（exposure bias）。
- B 错：每个位置都提供一个监督信号，这正是自回归目标数据利用率高的原因；各位置的损失在同一次前向、反向中算出，不存在重复计算的问题。
- D 错：模型输出的是词表上的概率分布，用交叉熵衡量，而不是去回归一个 Embedding 向量。

<sub>考点：自回归预训练目标</sub>

</details>

<a name="TRN-PT-003"></a>

### TRN-PT-003　基础 · 考频 ★★

代码模型常在预训练中加入 FIM（Fill-in-the-Middle）目标，以支持编辑器里的「中间补全」。关于 FIM，下列说法正确的是：

- **A.** FIM 需要额外的双向编码器来读取光标之后的代码，因此不能直接用于 Decoder-only 的代码模型
- **B.** FIM 训练时只对后缀部分计算损失，前缀和中间部分作为条件输入，不计入损失，以突出右侧上下文
- **C.** FIM 会明显损害从左到右的生成能力，所以代码模型通常只在 SFT 阶段少量加入 FIM 数据
- **D.** 把文档切成前缀、中间、后缀三段，用哨兵 token 重排为「前缀+后缀+中间」，仍按下一个 token 预测训练

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：FIM 只是一种数据变换，不改模型结构，也不改损失函数。

Bavarian 等（2022）的做法：随机选一段作为「中间」，挪到文档末尾，并用 `<PRE>`、`<SUF>`、`<MID>` 等哨兵 token 标出各段。模型读完前缀和后缀之后再生成中间，于是学会了利用光标两侧的上下文。推理时把前缀、后缀按同样格式拼好，让模型生成到「中间结束」标记为止。

- A 错：重排之后后缀已经出现在中间段之前，普通的因果注意力就能看到它，不需要编码器。
- B 错：变换后的序列仍按普通语言模型损失训练，关键在于中间段被放到了最后，以前后文为条件生成。
- C 错：论文的一个重要结论是「FIM for free」：即使相当大比例的训练数据做了 FIM 变换，从左到右的生成能力也基本不受影响。StarCoder、Code Llama、DeepSeek-Coder 等代码模型都在预训练中使用了 FIM。

延伸：另一类辅助目标是多 token 预测（MTP），如 DeepSeek-V3 在训练时额外预测后续 token，增加训练信号，推理时还可用于投机解码。

<sub>考点：自回归预训练目标　｜　出处：Efficient Training of Language Models to Fill in the Middle（Bavarian 等, 2022）arXiv:2207.14255</sub>

</details>

<a name="TRN-PT-006"></a>

### TRN-PT-006　挑战 · 考频 ★★

在同一份中文验证集（共 100 万个汉字）上评测两个基座模型：模型 A 的分词器把它切成 150 万个 token，困惑度为 6.0；模型 B 的词表更大，只切出 100 万个 token，困惑度为 12.0。关于两者的语言建模能力，下列判断正确的是：

- **A.** 模型 A 更强：同一份验证集上困惑度越低越好，A 的困惑度只有 B 的一半，优势明显
- **B.** 模型 B 更强：折算到每个汉字，B 的负对数似然更低（约 2.48 对 2.69 nat/字）
- **C.** 两者大致相当：困惑度之比为 2，而 token 数之比为 1.5，折算到每个汉字后差距基本抵消
- **D.** 无法比较：困惑度依赖分词方式，只有词表完全相同的两个模型之间才能比较语言建模能力

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：跨分词器比较要把损失换算到与分词无关的单位（每字、每字节），不能直接比较困惑度。

全文的总负对数似然 = token 数 × 每 token 平均 loss = token 数 × $\ln\mathrm{PPL}$：
- A：$1.5\times10^6\times\ln6\approx1.5\times10^6\times1.792\approx2.69\times10^6$ nat，即约 2.69 nat/字；
- B：$1.0\times10^6\times\ln12\approx1.0\times10^6\times2.485\approx2.48\times10^6$ nat，即约 2.48 nat/字。

同样的 100 万字，B 用更少的总信息量就「编码」了全文，压缩得更好，语言建模能力更强。B 的每个 token 承载的文字更多、本身更难预测，所以按 token 算的困惑度更高，这并不说明它更差。

- A 错：困惑度只在同一分词器、同一数据上可比。
- C 错：困惑度是指数尺度，抵消关系要在对数上算：$1.5\ln6\approx2.69$ 与 $\ln12\approx2.48$ 并不相等。
- D 错：换算成每字或每字节的比特数（BPB）后就可以比较，这正是 BPB 的用途。

<sub>考点：交叉熵与困惑度、基座模型评估</sub>

</details>

<a name="TRN-PT-008"></a>

### TRN-PT-008　进阶 · 考频 ★★★

Kaplan 等（2020）认为算力增加时应优先放大模型（$N_{opt}\propto C^{0.73}$），而 Chinchilla（Hoffmann 等, 2022）得出参数量与数据量应同比例增长。对于两者的分歧，Chinchilla 论文给出的最主要解释是：

- **A.** Kaplan 使用的网页数据质量较低，在低质量数据上多喂数据收益小，所以得出「重模型、轻数据」的结论
- **B.** Kaplan 估算算力时漏掉了反向传播，用 $2ND$ 代替了 $6ND$，导致最优分配的指数偏大
- **C.** Chinchilla 把推理成本也计入了优化目标：小模型部署更便宜，因此最优解偏向小模型、多数据
- **D.** Kaplan 让不同训练长度共用同一套学习率调度，余弦周期与训练 token 数不匹配，低估了多喂数据的收益

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：学习率调度没有与训练长度匹配，是 Chinchilla 指出的关键原因。

余弦调度在训练中途学习率仍然较高、尚未退火，此时的 loss 明显高于「按这个 token 数设定周期、完整训完」的模型。Kaplan 的实验让不同训练长度共用一套调度，「数据少」的配置因此被系统性高估了 loss，看起来多喂数据收益很小，结论便偏向大模型。Chinchilla 为每个训练长度单独匹配余弦周期，论文附录还显示周期比实际训练长度长出 25% 以上时效果会明显变差。后续研究还指出，Kaplan 只统计非 Embedding 参数、实验模型偏小（最大约 15 亿参数）等因素也影响了外推。

- A 错：数据质量会影响拟合常数，但不是论文给出的分歧原因。
- B 错：两篇论文都用 $C\approx6ND$ 估算训练算力。
- C 错：Chinchilla 只优化训练算力，不含推理成本；把推理成本算进来的是后来的 Beyond Chinchilla-Optimal 等工作。

<sub>考点：Kaplan缩放律、Chinchilla缩放律　｜　出处：Training Compute-Optimal Large Language Models（Hoffmann 等, 2022）arXiv:2203.15556</sub>

</details>

<a name="TRN-PT-014"></a>

### TRN-PT-014　基础 · 考频 ★★

Gopher 有 280B 参数、训练了 300B token；Chinchilla 有 70B 参数、训练了 1.4T token。两者的训练算力相近，Chinchilla 却在大多数评测上超过了 Gopher。对这一结果最合理的解释是：

- **A.** Gopher 每个参数只训练了约 1 个 token，远没训够；同样算力挪给数据更接近算力最优
- **B.** Chinchilla 实际使用的训练算力约是 Gopher 的 4 倍，效果更好主要来自更多的算力
- **C.** 参数量越大越容易过拟合，280B 的 Gopher 在 300B token 上已经严重过拟合
- **D.** Chinchilla 采用了 MoE 结构，每个 token 只激活一小部分参数，同样算力下能处理更多数据

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：同样的算力，Chinchilla 的分配更接近最优。

按 $6ND$：Gopher 约 $6\times280\times10^9\times300\times10^9\approx5.0\times10^{23}$ FLOPs，Chinchilla 约 $6\times70\times10^9\times1.4\times10^{12}\approx5.9\times10^{23}$ FLOPs，相差不到 20%。Gopher 约 1.1 token/参数，Chinchilla 为 20 token/参数。按缩放律，Gopher 的「数据不足」项很大，把算力挪给数据后总 loss 更低。而且 Chinchilla 参数只有 Gopher 的四分之一，推理和微调都便宜得多。

- B 错：两者算力只差约 17%，不是 4 倍。
- C 错：数据只过一遍左右，谈不上过拟合；问题恰恰是没训够，loss 还在下降。
- D 错：Chinchilla 是稠密模型。

<sub>考点：Chinchilla缩放律</sub>

</details>

<a name="TRN-PT-015"></a>

### TRN-PT-015　进阶 · 考频 ★★★

以下哪种情况**最适合**远超 20 token/参数地「过训练」一个较小的模型，而不是按 Chinchilla 最优配比训练一个更大的模型？

- **A.** 研究团队只想在固定的训练预算内得到验证集 loss 最低的模型，训完写论文即可，不打算部署
- **B.** 模型上线后要服务海量请求，还要部署到手机等端侧设备，推理成本和显存是主要约束
- **C.** 高质量训练数据非常有限，现有数据连按 Chinchilla 配比训练更大模型都不够用
- **D.** 希望尽可能提高模型能力的上限，而且推理成本不是问题

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：过训练是用更多的训练算力换更低的推理成本。

Chinchilla 只最小化训练算力，而每生成一个 token 的推理算力约为 $2N$，模型越小推理越便宜，显存与延迟也越低。上线后推理量巨大时，「多花一些训练算力、换一个小一半的模型」很快就能回本。Beyond Chinchilla-Optimal（Sardana 等, 2023）把推理需求纳入目标后，最优解明显偏向更小的模型、更多的数据；Llama 3 8B 训了约 15T token（约 1875 token/参数）就是典型例子。

- A 错：只看训练算力下的 loss，Chinchilla 配比正是最优解。
- C 错：过训练小模型需要**更多**的数据（每参数上千 token），数据稀缺时只会更缺；此时应考虑重复数据（4 个 epoch 以内损失不大）、放宽过滤或合成数据。
- D 错：追求上限且不在乎推理成本时，同样的算力训练更大的模型效果更好。

<sub>考点：过训练小模型　｜　出处：Beyond Chinchilla-Optimal（Sardana 等, 2023）arXiv:2401.00448</sub>

</details>

<a name="TRN-PT-022"></a>

### TRN-PT-022　基础 · 考频 ★★

Wei 等（2022）在 Emergent Abilities of Large Language Models 中对「涌现能力」的定义是：

- **A.** 模型训练到某一步时预训练 loss 曲线出现的突然下降，此后多项能力同时提升
- **B.** 预训练模型本身不具备、只有经过指令微调和 RLHF 之后才会出现的能力
- **C.** 小模型上不存在、大模型上才出现，且无法由小模型的表现外推预测的能力
- **D.** 随参数量增加而平滑、可预测地提升，并且可以用幂律外推到更大规模的能力

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：涌现是针对**下游任务表现**随规模的变化定义的：小模型接近随机，超过某个规模后明显高于随机，无法从小模型的趋势外推出来。论文中的例子有少样本多位数算术、多步推理，以及思维链提示只在足够大的模型上才带来收益等，横轴可以是训练算力或参数量。

- A 错：预训练 loss 随规模基本是平滑下降的，涌现讨论的是任务指标。
- B 错：论文中的很多例子来自预训练模型的少样本提示，并不依赖后训练。
- D 错：这恰恰是涌现的反面，即可预测的平滑缩放。

后续 Schaeffer 等（2023）指出，很多涌现现象与所选指标是否连续有关，这一争论至今仍在继续。

<sub>考点：涌现能力　｜　出处：Emergent Abilities of Large Language Models（Wei 等, 2022）arXiv:2206.07682</sub>

</details>

<a name="TRN-PT-027"></a>

### TRN-PT-027　基础 · 考频 ★★

GPT-3 系列从 125M 到 175B 的训练配置中，随着模型变大，峰值学习率与 batch size 的变化趋势是：

- **A.** 学习率增大、batch 减小：大模型容量大、损失曲面更平坦，可以承受更大的步长和更多的更新次数
- **B.** 学习率与 batch 都保持不变，只增加训练步数，这样不同规模模型的结果才便于直接比较
- **C.** 学习率减小、batch 增大：175B 的峰值学习率约为 125M 的 1/10，batch 是其 6 倍多
- **D.** 学习率减小、batch 也减小：大模型的单卡显存紧张，能放下的序列变少，全局 batch 只能随之减小

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：模型越大，峰值学习率越小，batch 越大。GPT-3 论文中，125M 模型的峰值学习率为 $6\times10^{-4}$、batch 为 0.5M token；175B 模型为 $0.6\times10^{-4}$、3.2M token。

- 学习率：大模型对更新更敏感，过大的步长容易引起 loss spike 甚至发散，所以峰值学习率随规模下降（Llama 2 的 7B 用 $3\times10^{-4}$，70B 用 $1.5\times10^{-4}$）。
- batch：随着 loss 降低，梯度噪声相对变大，「临界 batch size」随之增大，大 batch 不再浪费数据，还能提高并行效率。DeepSeek LLM 也拟合出算力越大、最优 batch 越大、最优学习率越小的幂律。

- A 错：方向反了，大模型反而要用更小的学习率。
- B 错：学习率和 batch 都需要随规模调整。
- D 错：全局 batch 由数据并行和梯度累积凑出，不受单卡显存限制；单卡显存只限制 micro-batch。

<sub>考点：学习率与批大小　｜　出处：Language Models are Few-Shot Learners（GPT-3）arXiv:2005.14165</sub>

</details>

<a name="TRN-PT-030"></a>

### TRN-PT-030　进阶 · 考频 ★★

WSD（Warmup-Stable-Decay）学习率调度相对于余弦退火，最主要的工程优势是：

- **A.** 不再需要 warmup：稳定阶段的恒定学习率本身就足够温和，训练一开始即可使用峰值学习率
- **B.** 学习率在 warmup 后始终保持恒定直到训练结束，避免了退火阶段 loss 的突然下降与波动
- **C.** 在同样的训练步数下，WSD 的最终 loss 通常显著低于余弦调度，这是它取代余弦的主要原因
- **D.** 稳定阶段的任意检查点都能接一段衰减得到可用模型，不必事先确定总步数，便于续训

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：WSD 把「训练多久」与「学习率曲线的形状」解耦了。

余弦调度的形状由总步数决定，中途的检查点学习率还没降下来，既不能直接用，也难以延长训练。WSD 由三段组成：warmup 后长时间保持恒定学习率，最后用约 10% 的步数快速衰减。稳定阶段的任何检查点都可以分出一支、做一小段衰减得到可用模型，主线则继续以恒定学习率训练。MiniCPM（Hu 等, 2024）推广了这种调度；Hägele 等（2024）的实验表明，配合适当的衰减段，WSD 的效果可以与余弦相当，并且一次训练就能得到多个算力预算下的结果，降低了缩放律实验的成本。DeepSeek LLM 的多阶段阶梯式调度也是类似的思路。

- A 错：W 就是 warmup。
- B 错：衰减段必不可少，loss 在衰减段明显下降正是期望的效果。
- C 错：配合适当的衰减段，两者效果大致相当，WSD 的优势在灵活性，而不是显著更低的 loss。

<sub>考点：学习率调度与退火　｜　出处：MiniCPM（Hu 等, 2024）arXiv:2404.06395；Scaling Laws and Compute-Optimal Training Beyond Fixed Training Durations（Hägele 等, 2024）arXiv:2405.18392；DeepSeek LLM arXiv:2401.02954</sub>

</details>

<a name="TRN-PT-035"></a>

### TRN-PT-035　进阶 · 考频 ★★

现代大模型的训练流程常被划分为「预训练 → 中期训练（mid-training）→ 后训练」。关于中期训练，下列说法最准确的是：

- **A.** 仍以下一个 token 预测为目标，但会上采样数学、代码等高质量数据，常同时扩展上下文并退火学习率
- **B.** 中期训练就是 SFT 的另一个名字：使用对话模板与 loss mask，只对回答部分计算损失
- **C.** 中期训练使用的 token 数通常超过初始预训练阶段，是整个训练流程中最主要的算力消耗
- **D.** 中期训练只调整学习率等超参数（如重新 warmup 再衰减），数据配比与初始预训练阶段保持一致

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：中期训练是「换了数据配方的预训练」，夹在通用预训练和后训练之间。

例如 Qwen3 的预训练分为三个阶段：通用阶段（30T 以上 token，序列长度 4K）；推理阶段（约 5T 高质量 token，提高 STEM、代码、推理与合成数据的比例）；长上下文阶段（数千亿 token，把序列长度扩展到 32K）。Llama 3 在末期退火并上采样高质量数据；OLMo 2 也设有专门的中期训练配比。这一阶段的目标是用相对少的算力拔高数学、代码和推理能力，补上长上下文，为后训练打好底子。

- B 错：中期训练仍按普通语言模型损失在大规模数据上训练；有些配比中会混入指令式数据，但并不是 SFT。
- C 错：初始预训练占绝大部分 token 和算力，如 Qwen3 的 30T 以上对比约 5T。
- D 错：改变数据分布正是中期训练的核心。

<sub>考点：预训练阶段划分</sub>

</details>

<a name="TRN-PT-037"></a>

### TRN-PT-037　进阶 · 考频 ★★

PaLM 在训练中加入了辅助损失 z-loss：$10^{-4}\cdot\log^2 Z$，其中 $Z=\sum_i e^{z_i}$ 是输出层 softmax 的归一化项。它的主要作用是：

- **A.** 让 $\log Z$ 保持在 0 附近，防止输出 logits 整体漂移、绝对值变得过大，从而提高训练稳定性
- **B.** 替代 label smoothing，鼓励模型输出更平滑的概率分布，以提高生成的多样性
- **C.** 惩罚注意力打分过大，作用与 QK-Norm 完全相同，两者只能二选一
- **D.** 作为正则项减少过拟合，主要用于提高下游任务的泛化能力

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：z-loss 约束的是输出 softmax 的归一化项，防止 logits 漂移。

softmax 对所有 logits 同时加一个常数时结果不变，交叉熵无法约束 logits 的「整体位置」，于是 logits 可能慢慢漂移、绝对值越来越大。在 BF16 等低精度下，这会带来精度损失和溢出风险，甚至引发发散。加上 $10^{-4}\log^2Z$ 后，logits 被锚定在 $\log Z\approx0$ 附近，此时 logits 直接近似于对数概率。Wortsman 等（2023）研究训练不稳定性时，也把「输出 logits 发散」列为主要类型之一，并用 z-loss 缓解。

- B 错：label smoothing 改变的是目标分布；z-loss 不改变最优的预测分布，只约束 logits 的整体平移。
- C 错：QK-Norm 作用于注意力 logits，z-loss 作用于输出层 logits，位置不同，可以同时使用。
- D 错：主要目的是数值稳定，而不是正则化。

<sub>考点：训练稳定性</sub>

</details>

<a name="TRN-PT-041"></a>

### TRN-PT-041　基础 · 考频 ★★

评测一个未经指令微调的 Base 模型在多项选择基准（如 HellaSwag、ARC）上的能力，下列做法中最常用、也最合理的是：

- **A.** 用聊天模板包装题目，要求模型「只回答 A、B、C 或 D」，再用正则表达式抽取答案
- **B.** 用少样本续写式提示，分别计算各候选答案文本的对数似然（常按长度归一化），取最高者
- **C.** 让模型为每道题先生成一段推理过程，再由人工或更强的模型判断推理和结论是否正确
- **D.** 计算模型在这些题目文本上的困惑度，困惑度越低，说明模型对题目理解越深、选择题做得越好

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：Base 模型的选择题通常用「似然打分」，而不是让它生成答案。

做法：用若干条少样本示例拼成续写式提示，把每个选项的答案文本接在后面，计算其对数似然（按 token 数或字符数归一化，避免偏向短选项），取最高者。lm-evaluation-harness 等框架默认这样做。它不依赖模型遵循格式，训练早期的小模型也能给出有区分度的信号。

- A 错：Base 模型不能稳定地遵循对话格式，答案抽取失败会被算错，严重低估能力。模型较强时也可以用「输出选项字母」的格式，但那是另一种评测口径。
- C 错：成本高、难以复现，而且 Base 模型未必能按要求写出推理过程，评的更多是格式遵循而不是知识。
- D 错：题目文本上困惑度低更可能说明「见过这些题」（数据污染），而不是会做题。

<sub>考点：基座模型评估</sub>

</details>

### TRN-PT-010　进阶 · 考频 ★★

关于大模型的缩放律（Scaling Law），下列说法**正确**的有：

- **A.** 按 Chinchilla 的结论，训练算力增加到原来的 4 倍时，最优参数量也应增加到原来的 4 倍
- **B.** Kaplan 给出 $L(C)\propto C^{-0.050}$：训练算力每增加到原来的 2 倍，loss 大约降为原来的一半
- **C.** 缩放律的拟合常数与数据分布无关，换了数据配方后可以直接沿用之前拟合的结果
- **D.** loss 与参数量、数据量、算力之间近似呈幂律，因此可以先训一系列小模型拟合曲线，再外推大模型的 loss
- **E.** Chinchilla 拟合式 $L=E+A/N^{\alpha}+B/D^{\beta}$ 中，$E$ 表示模型再大、数据再多也消除不了的不可约损失

<details>
<summary>答案与解析</summary>

**答案：DE**

**解析：**

**结论**：D、E 正确。

- A 错：Chinchilla 中 $N_{opt}\propto C^{0.5}$，算力变为 4 倍时参数量和 token 数各变为 2 倍。
- B 错：这是把幂律指数当成了 1。指数只有 0.05，算力翻倍时 loss 只变为原来的 $2^{-0.05}\approx0.966$，约下降 3.4%；反过来，loss 降低 10% 需要算力变为 $(1/0.9)^{20}\approx8.2$ 倍。这也是大模型越往后训练、越显得「小数点后的进步也来之不易」的原因。
- C 错：拟合常数依赖数据分布、分词器和模型结构，换了数据配方或架构要重新拟合；MoE 模型估算算力时还要用激活参数。
- D 对：这是缩放律最重要的工程价值。GPT-4 技术报告称，用不超过其万分之一算力的小模型就较准确地预测了最终 loss。
- E 对：$E$ 是数据本身的熵，后两项分别是模型容量不足和训练数据不足带来的损失。

<sub>考点：Kaplan缩放律、Chinchilla缩放律　｜　出处：Scaling Laws for Neural Language Models（Kaplan 等, 2020）arXiv:2001.08361；Chinchilla arXiv:2203.15556</sub>

</details>

<a name="TRN-PT-021"></a>

### TRN-PT-021　进阶 · 考频 ★★

用 $6ND$ 除以「集群峰值算力 × 预期 MFU」估算出的训练时长，往往比项目实际消耗的 GPU 时间短。下列原因中**合理**的有：

- **A.** 混合精度让每个 token 的计算量从 $6N$ 降到 $3N$，估算时本应减半
- **B.** 正式训练之外的小规模消融、超参搜索、数据实验与评测也要消耗大量算力
- **C.** 硬件故障导致的中断与重启，以及回滚到检查点后重复计算的步数
- **D.** 长上下文阶段注意力打分的计算量明显增加，而 $6ND$ 不含这部分；沿用短序列阶段测得的 MFU 会过于乐观
- **E.** 开启激活重计算后，模型本身的 FLOPs（$6ND$）变为原来的 2 倍

<details>
<summary>答案与解析</summary>

**答案：BCD**

**解析：**

- B 对：缩放律拟合、配比消融、退火实验、定期评测，加起来可能占到正式训练相当大的比例，预算时要单独列出。
- C 对：万卡规模几乎每天都有故障。Llama 3 405B 在 54 天的统计期内出现了 466 次作业中断，其中大部分是意外中断；每次中断还要回滚到最近的检查点重算。
- D 对：注意力打分的 FLOPs 与上下文长度成正比，长上下文阶段占比显著上升；按短序列阶段测得的「$6N$ 口径 MFU」去估算会偏乐观。
- E 错：重计算多做一次前向，硬件实际执行的计算约为 $8ND$（多约 33%，不是 2 倍）；模型 FLOPs 仍按 $6ND$ 统计，表现为 MFU 下降。

<a name="TRN-PT-028"></a>

### TRN-PT-028　进阶 · 考频 ★★

关于预训练的学习率与 batch size，下列说法**正确**的有：

- **A.** 增大 batch 时通常要相应提高学习率，Adam 类优化器经验上按平方根到线性的规则放大，再小范围验证
- **B.** 超过临界 batch size 之后，继续增大 batch 时所需步数减少得越来越少，达到同样 loss 所需的总 token 数却明显增加
- **C.** μP（最大更新参数化）让在小宽度模型上调好的学习率等超参数，可以较好地迁移到更宽的模型
- **D.** 梯度累积会改变优化器看到的有效 batch，因此即使损失归一化处理正确，也与一次性大 batch 训练不等价
- **E.** DeepSeek LLM 拟合的规律是：训练算力越大，最优 batch 越大、最优学习率越小

<details>
<summary>答案与解析</summary>

**答案：ABCE**

**解析：**

**结论**：A、B、C、E 正确，只有 D 错。

- A 对：SGD 常用线性缩放规则；对 Adam 类优化器，理论分析与经验都更支持平方根缩放，实际中在两者之间取值，再做小范围扫描。
- B 对：McCandlish 等（2018）给出步数 $S$ 与样本数 $E$ 的权衡 $(S/S_{min}-1)(E/E_{min}-1)=1$。batch 远小于临界值时，加大 batch 几乎线性地减少所需步数，总 token 数基本不变；超过临界值后，步数逼近下限 $S_{min}$、几乎不再减少，多出来的 token 基本被浪费，达到同样 loss 的总 token 数（算力）随 batch 近似线性增加。
- C 对：μP 调整了初始化和各层学习率的缩放方式，使最优超参数在宽度变化时基本不变，Cerebras-GPT、MiniCPM 等都用它在小模型上调参。
- D 错：每个 micro-batch 的 loss 按整个累积窗口正确归一化后，累积得到的梯度与一次性大 batch 的梯度在数学上相同（只差浮点误差），优化器看到的就是大 batch。
- E 对：DeepSeek LLM 用小规模实验拟合了最优 batch 与学习率随算力变化的幂律，再外推到大模型。

<sub>考点：学习率与批大小　｜　出处：An Empirical Model of Large-Batch Training（McCandlish 等, 2018）arXiv:1812.06162；DeepSeek LLM arXiv:2401.02954；Tensor Programs V（μP）arXiv:2203.03466</sub>

</details>

<a name="TRN-PT-036"></a>

### TRN-PT-036　挑战 · 考频 ★★

预训练中观察到下列 loss 曲线现象，对应的解释**合理**的有：

- **A.** 某数据源重复到第 8 个 epoch 后，训练 loss 仍降、验证 loss 却上升——说明出现了过拟合
- **B.** 训练最初几百步 loss 从约 $\ln V$ 迅速下降，之后越降越慢——这是正常现象
- **C.** 进入中期训练、提高数学与代码比例时，总 loss 出现台阶式跳变——可能只是数据分布变化所致
- **D.** warmup 结束后 loss 的下降速度明显变慢——说明峰值学习率设置过低，应立即调大学习率
- **E.** loss 突然跳高、梯度范数同时暴涨，几百步后 loss 又自己回落——属于正常波动，继续训练即可

<details>
<summary>答案与解析</summary>

**答案：ABC**

**解析：**

- A 对：训练与验证 loss 分叉是典型的过拟合（记忆）信号，应减少该数据源的重复次数；重复超过约 4 个 epoch 后收益本就迅速递减，还会增加原样背诵训练数据的风险。
- B 对：随机初始化时 loss 约为 $\ln V$；模型很快学会 unigram、bigram 等简单统计，loss 迅速下降；之后的提升需要学习更难的规律，下降速度按幂律放缓。
- C 对：总 loss 是各数据源 loss 的加权平均，而不同数据源的 loss 水平差别很大（例如代码通常比网页文本更容易预测、loss 更低），配比一变总 loss 就会跳一下，并不说明模型变好或变坏。应该看各数据源各自的验证 loss 和下游指标。
- D 错：warmup 后下降变慢是幂律的自然表现，高学习率下的优化噪声也会掩盖进展；是否调学习率要靠对照实验判断，不能凭这一现象立即调大。
- E 错：伴随梯度范数暴涨的 spike 是训练不稳定的信号。即使 loss 回落，Adam 的状态和模型能力也可能已受损；频繁出现说明学习率或数值稳定性有问题。应定位原因，必要时回滚并跳过相关数据。

<sub>考点：学习率调度与退火、预训练阶段划分、训练稳定性</sub>

</details>

<a name="TRN-PT-038"></a>

### TRN-PT-038　进阶 · 考频 ★★★

下列措施中，有助于**预防**大模型预训练出现 loss spike 的有：

- **A.** 适当降低峰值学习率，或加长 warmup 的步数
- **B.** 把 BF16 换成 FP16，利用 FP16 更多的尾数位提高数值精度
- **C.** 像 GLM-130B 那样把 Embedding 层的梯度缩小（乘以 0.1）
- **D.** 把 AdamW 的 $\beta_2$ 从 0.999 调到 0.95，让二阶矩更快跟上梯度幅度的变化
- **E.** 引入 QK-Norm，约束注意力 logits 的增长

<details>
<summary>答案与解析</summary>

**答案：ACDE**

**解析：**

- A 对：学习率过大、warmup 过短是 spike 的常见原因；降低峰值学习率、加长 warmup 都能提高稳定性，代价是收敛可能变慢。反过来「提高学习率、缩短 warmup 以尽快越过不稳定期」是错误的思路。
- B 错：FP16 只有 5 位指数，最大值约 65504，更容易溢出；BF16 范围与 FP32 相同，才是大模型训练更稳的选择。
- C 对：GLM-130B 发现 Embedding 层的梯度异常是 spike 的重要来源，用梯度缩小（EGS）稳定了训练。
- D 对：罕见 token 的参数长期梯度很小，$v$ 也很小；一旦梯度突然变大，$\beta_2=0.999$ 时 $v$ 跟得太慢，更新量 $m/\sqrt v$ 会异常偏大。$\beta_2=0.95$ 让 $v$ 更快适应，GPT-3、Llama 等都用 0.95。
- E 对：注意力 logits 随训练持续增长会导致注意力熵塌缩、训练发散；对每个头的 $q$、$k$ 先做归一化可以抑制这种增长，Qwen3、Gemma 3 等模型都采用了 QK-Norm。

<sub>考点：训练稳定性　｜　出处：GLM-130B arXiv:2210.02414；Small-scale proxies for large-scale Transformer training instabilities（Wortsman 等, 2023）arXiv:2309.14322；Qwen3 技术报告 arXiv:2505.09388；Gemma 3 技术报告 arXiv:2503.19786；GPT-3 arXiv:2005.14165</sub>

</details>

### TRN-PT-042　进阶 · 考频 ★★

关于在预训练过程中评测 Base 模型及其中间检查点，下列说法**正确**的有：

- **A.** 基准分数随训练持续上涨，就足以说明模型能力在提升，不必再专门检查训练数据中的污染
- **B.** 训练早期的小模型用选项字母格式往往接近随机，按答案文本算似然的完形填空格式更早有区分度
- **C.** 不同分词器的模型，可以直接比较它们在同一验证集上的困惑度，困惑度低者语言建模能力更强
- **D.** Base 模型通常不擅长遵循指令，评测时多用少样本提示和续写式格式
- **E.** 余弦调度下未退火的中间检查点，得分通常低于同等 token 数下完整退火的模型

- C 错：词表和切分不同，每个 token 的难度不同，要换算成每字节比特数（BPB）等与分词无关的单位再比较。
- D 对：Base 模型是续写模型，少样本示例让它从上下文里「看懂」任务格式。
- E 对：中途检查点的学习率仍然较高，loss 和下游得分都被低估；比较不同配置时要注意这一偏差，应都做一段退火，或只比较同一阶段的检查点。

<sub>考点：基座模型评估</sub>

## 判断题

<a name="TRN-PT-004"></a>

### TRN-PT-004　基础 · 考频 ★★

按 Chinchilla 论文拟合的缩放律，模型参数量与训练数据量同时趋于无穷时，自然语言文本上的预训练交叉熵损失趋于 0，困惑度趋于 1。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。自然文本本身存在不确定性：同样的前文后面可以合理地接很多不同的词，这部分熵是任何模型都消除不了的，称为不可约损失。

Chinchilla 的拟合式 $L(N,D)=E+A/N^{\alpha}+B/D^{\beta}$ 中，$E$ 就是这一项，论文在其数据上拟合得 $E\approx1.69$ nat/token（数值依赖数据分布与分词器）。$N$、$D$ 趋于无穷时损失只趋于 $E$，困惑度趋于 $e^{1.69}\approx5.4$，而不是 1。

如果训练集 loss 降到接近 0，通常说明模型把训练文本背了下来（数据重复、过拟合或标签泄漏），并不代表它对新文本的预测能力更强。判断模型好坏要看留出验证集上的 loss。

<sub>考点：交叉熵与困惑度、Chinchilla缩放律　｜　出处：Chinchilla 论文（Hoffmann 等, 2022）arXiv:2203.15556</sub>

</details>

<a name="TRN-PT-009"></a>

### TRN-PT-009　进阶 · 考频 ★★

Kaplan 等（2020）认为「训练到收敛」在算力上是低效的：给定算力预算，更好的做法是训练一个很大的模型，并在它远未收敛时就停止训练。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。Kaplan 的论文明确提出「收敛是低效的」：大模型的样本效率更高，用同样多的 token 能把 loss 降得更低，所以给定算力时，应把大部分算力投给参数（$N_{opt}\propto C^{0.73}$），数据只需缓慢增加（$D_{opt}\propto C^{0.27}$），并在远未收敛时停止。GPT-3 175B 只训练了约 300B token（不到 2 token/参数），体现的正是这种思路。

Chinchilla 修正的是分配比例（$N$、$D$ 同比例增长、约 20 token/参数），并没有主张训练到收敛：按 Chinchilla 最优配比训完的模型，继续训练 loss 仍会下降。今天远超 20 token/参数的「过训练」是出于推理成本的考虑，优化的是另一个目标。

<sub>考点：Kaplan缩放律　｜　出处：Scaling Laws for Neural Language Models（Kaplan 等, 2020）arXiv:2001.08361</sub>

</details>

<a name="TRN-PT-018"></a>

### TRN-PT-018　进阶 · 考频 ★★

Scaling Data-Constrained Language Models（Muennighoff 等, 2023）发现：高质量数据不够用时，把同一份数据重复训练至多约 4 个 epoch，效果与使用同等数量的全新数据相差不大；重复次数再多，增加算力带来的收益会迅速递减。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。论文在数据受限的设定下系统地训练了大量模型，发现在固定算力下重复至多约 4 个 epoch，loss 与全新数据几乎没有差别；重复次数继续增加，重复 token 的价值快速衰减，最终再加算力也几乎没有收益。论文据此提出了考虑数据重复的缩放律，并发现混入代码数据、放宽常用的过滤规则也能缓解数据不足。

这对「过训练小模型」很重要：把 8B 模型训到 15T token 以上，高质量数据往往不够，只能在重复、放宽过滤、合成数据之间权衡。实践中高质量来源本来就会被多遍使用，例如 GPT-3 中维基百科重复了约 3.4 遍。

<sub>考点：过训练小模型　｜　出处：Scaling Data-Constrained Language Models（Muennighoff 等, 2023）arXiv:2305.16264</sub>

</details>

<a name="TRN-PT-024"></a>

### TRN-PT-024　进阶 · 考频 ★★

Are Emergent Abilities of Large Language Models a Mirage?（Schaeffer 等, 2023）证明了大模型根本不存在涌现能力：只要换成连续指标，所有任务上的能力都会随规模平滑、可预测地提升。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。该论文的论点是：**很多**被报道的涌现现象可以由研究者的指标选择来解释。精确匹配、多选准确率这类非线性或不连续的指标，会把平滑的提升放大成「突变」；换成 token 编辑距离、Brier 分数等连续指标，或增加测试样本提高分辨率后，曲线往往变得平滑。

但它并没有证明不存在任何涌现：
- 很多实际关心的能力本身就是「全对才有用」的（如代码能否通过测试），对使用者来说突变是真实的；
- Du 等（2024）从预训练 loss 的角度重新刻画涌现，发现某些任务上的能力在预训练 loss 降到一定阈值以下才出现，且与指标是否连续无关。

更稳妥的说法是：涌现与「能否预测」高度依赖指标，评测时应同时看离散指标与连续指标。

<sub>考点：涌现能力　｜　出处：Are Emergent Abilities of Large Language Models a Mirage?（Schaeffer 等, 2023）arXiv:2304.15004；Understanding Emergent Abilities of Language Models from the Loss Perspective（Du 等, 2024）arXiv:2403.15796</sub>

</details>

<a name="TRN-PT-032"></a>

### TRN-PT-032　进阶 · 考频 ★★

学习率衰减阶段 loss 明显加速下降，一个主要原因是：高学习率下参数在损失面「山谷」的两侧来回震荡，loss 被优化噪声抬高；学习率降低后震荡变小，参数更接近谷底，loss 随之下降。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。高学习率阶段，参数沿着「谷底方向」不断取得进展，同时在垂直方向上大幅震荡，测到的 loss 被这部分噪声抬高，看起来下降缓慢；一旦降低学习率，震荡幅度变小，此前积累的进展就显现出来，loss 在短时间内明显下降。这也是 WSD 稳定阶段的 loss 高于同期余弦调度、但衰减之后能追平的原因。

由此得到几条实践经验：
- 衰减段的下降主要来自「降噪」，并不意味着模型在这一小段数据上学到了大量新知识，但衰减段的数据分布确实会对最终模型产生较大影响，所以常在此时上采样高质量数据；
- 比较不同配置时，要在学习率都已衰减之后比较，不能拿高学习率阶段的 loss 去比；
- 训练早期 loss 下降慢并不一定说明学习率太低，可能只是噪声掩盖了进展。

<sub>考点：学习率调度与退火</sub>

</details>

<a name="TRN-PT-039"></a>

### TRN-PT-039　挑战 · 考频 ★★

开启全局梯度裁剪（如阈值 1.0）后，AdamW 对每个参数的更新量也会随梯度一起按比例缩小，因此单个异常 batch 造成的参数更新被限制在安全范围内，大规模预训练可以省去回滚与跳过数据的机制。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。梯度裁剪限制的是梯度的范数，但 AdamW 的更新量是 $\eta\,\hat m/(\sqrt{\hat v}+\epsilon)$，分子、分母随梯度同步缩放，对梯度的整体缩放近似不敏感：一个长期梯度很小（$m$、$v$ 都接近 0）的参数突然收到梯度 $g$ 时，即使 $g$ 已经被裁剪，更新量仍约为
$\eta\cdot\dfrac{(1-\beta_1)g}{\sqrt{(1-\beta_2)g^2}}=\eta\cdot\dfrac{0.1}{\sqrt{0.05}}\approx0.45\eta$（$\beta_1=0.9$、$\beta_2=0.95$），远大于它平时的更新幅度。

此外，很多 spike 并非来自单个坏 batch，而是注意力或输出 logits 逐渐增长、数值逐步失控的结果，裁剪只能延缓不能根治；硬件的静默错误也会产生异常梯度。PaLM 在使用梯度裁剪的同时，仍多次需要「回滚约 100 步、跳过 200～500 个 batch」。裁剪是标配，但裁剪前的梯度范数更是需要监控的关键信号，回滚机制不可省。

<sub>考点：训练稳定性</sub>

</details>

## 填空题

<a name="TRN-PT-011"></a>

### TRN-PT-011　基础 · 考频 ★★★

Chinchilla 的结论：给定训练算力 $C$，最优参数量 $N_{opt}$ 与最优训练 token 数 $D_{opt}$ 都约正比于 $C$ 的 ____ 次方；折算下来，训练算力最优时约每个参数对应 ____ 个训练 token。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0.5 / 1/2 / 二分之一；(2) 20

**解析：**

Chinchilla 训练了 400 多个模型（7000 万到 160 多亿参数、50 亿到 5000 亿 token），用三种方法估计最优分配，结论都接近 $N_{opt}\propto C^{0.5}$、$D_{opt}\propto C^{0.5}$，即模型和数据同比例扩大，折算约 **20 token/参数**。对比 Kaplan 的 $C^{0.73}$ 与 $C^{0.27}$，Chinchilla 明显更「重数据」。

代入 $C\approx6ND$、$D=20N$ 得 $C=120N^2$，即 $N_{opt}=\sqrt{C/120}$。例如 Chinchilla 本身是 70B 参数、1.4T token。

注意：20 token/参数是**训练算力最优**，不是推理最优，也不是效果上限；继续多训，loss 仍会下降。

<sub>考点：Chinchilla缩放律</sub>

</details>

### TRN-PT-020　进阶 · 考频 ★★

用 $C\approx6ND$ 估算 MoE 模型的训练算力时，$N$ 应取 ____（填「总参数」或「激活参数」）。DeepSeek-V3 总参数 671B、每个 token 激活 37B，预训练 14.8T token，据此估算预训练算力约为 ____ $\times10^{24}$ FLOPs（保留两位有效数字）。

**解析：**

每个 token 只经过被路由到的少数专家，计算量由激活参数决定：
$C\approx6\times37\times10^9\times14.8\times10^{12}\approx3.3\times10^{24}$ FLOPs。若误用总参数 671B，会得到约 $6.0\times10^{25}$，高估约 18 倍。

<a name="TRN-PT-026"></a>

### TRN-PT-026　基础 · 考频 ★★

预训练的全局 batch 为 4M（4,194,304）个 token，序列长度为 4096。若使用 64 路数据并行、每张卡的 micro-batch 为 2 条序列，则每次参数更新需要梯度累积 ____ 步；若每卡 micro-batch 改为 1（全局 batch 不变），累积步数变为 ____ 步。

<details>
<summary>答案与解析</summary>

**答案：** (1) 8；(2) 16

**解析：**

全局 batch（token 数）= 数据并行路数 × micro-batch × 累积步数 × 序列长度：
- $4194304=64\times2\times k\times4096$，得 $k=8$；
- micro-batch 改为 1 时，$k=16$。

全局 batch 才是影响优化的超参数，它怎样由「卡数 × micro-batch × 累积步数」凑出来，理想情况下不改变训练结果。micro-batch 减半会让每卡的激活显存约减半（模型状态不变），代价是串行的 micro-step 变多、GPU 利用率可能下降。变长样本做累积时，loss 要用整个累积窗口的有效 token 总数归一化，否则与大 batch 不等价。

<sub>考点：学习率与批大小</sub>

</details>

## 计算题

<a name="TRN-PT-005"></a>

### TRN-PT-005　基础 · 考频 ★★★

某模型在一份英文验证集上的平均交叉熵损失为 2.0 nat/token（自然对数），它的分词器在这份数据上平均每个 token 对应 4.0 个 UTF-8 字节。求：
(1) 困惑度；
(2) 每个 token 的比特数；
(3) 每字节比特数（bits per byte，BPB）；
(4) 继续训练后 loss 降到 1.9（同一分词器、同一验证集），困惑度下降了约百分之多少？

<details>
<summary>答案与解析</summary>

**答案：(1) 约 7.39；(2) 约 2.885 bit/token；(3) 约 0.721 bit/byte；(4) 约 9.5%**

**解析：**

1. **困惑度**：$\mathrm{PPL}=e^{\mathcal{L}}=e^{2.0}\approx7.39$，相当于模型每一步平均在约 7.4 个候选之间等概率地犹豫。
2. **比特数**：nat 换算成 bit 要除以 $\ln2$：$2.0/0.6931\approx2.885$ bit/token。
3. **BPB**：$2.885/4.0\approx0.721$ bit/byte。BPB 与分词方式无关，可以用来比较不同分词器的模型。
4. **困惑度变化**：$e^{1.9}\approx6.69$，比值 $e^{-0.1}\approx0.905$，即下降约 **9.5%**。

loss 只降了 0.1，困惑度却降了近一成：困惑度是 loss 的指数，大模型训练后期的进步常常体现为 loss 小数点后的变化。若 loss 用以 2 为底的对数计算，困惑度应写成 $2^{\mathcal{L}}$，两种写法结果相同。

<sub>考点：交叉熵与困惑度</sub>

</details>

### TRN-PT-012　进阶 · 考频 ★★★

团队有 1000 张 H100（BF16 稠密峰值约 989 TFLOPS），可以连续训练 30 天，预计模型算力利用率（MFU）为 40%。
(1) 总训练算力约多少 FLOPs？
(2) 按 Chinchilla 约 20 token/参数的经验，算力最优的参数量与训练 token 数各约多少？
(3) 若出于部署考虑改训 8B 模型，同样的算力能训练多少 token？约多少 token/参数？

<details>
<summary>答案与解析</summary>

**答案：(1) 约 1.03×10^24 FLOPs；(2) 约 92B 参数、1.85T token；(3) 约 21T token，约 2670 token/参数**

**解析：**

**(1) 总算力**：$C=1000\times989\times10^{12}\times0.4\times(30\times86400)\approx1.03\times10^{24}$ FLOPs。

</details>

<a name="TRN-PT-013"></a>

### TRN-PT-013　挑战 · 考频 ★

Chinchilla 用参数化损失 $L(N,D)=E+\dfrac{A}{N^{\alpha}}+\dfrac{B}{D^{\beta}}$ 拟合实验数据，算力约束为 $C=6ND$。
(1) 推导给定 $C$ 时，$N_{opt}$ 与 $D_{opt}$ 分别正比于 $C$ 的多少次方；
(2) 代入论文的拟合值 $\alpha=0.34$、$\beta=0.28$，求两个指数，并说明算力增加时参数和数据谁增长得更快。

<details>
<summary>答案与解析</summary>

**答案：(1) N_opt ∝ C^{β/(α+β)}，D_opt ∝ C^{α/(α+β)}；(2) 约 0.45 与 0.55，数据增长略快于参数**

**解析：**

**(1) 推导**：把 $D=C/(6N)$ 代入，只需最小化
$f(N)=AN^{-\alpha}+B\left(\frac{6N}{C}\right)^{\beta}$。
令导数为 0：$-\alpha AN^{-\alpha-1}+\beta B\left(\frac{6}{C}\right)^{\beta}N^{\beta-1}=0$，整理得
$N^{\alpha+\beta}=\frac{\alpha A}{\beta B}\left(\frac{C}{6}\right)^{\beta}$，
所以 $N_{opt}=G\left(\frac{C}{6}\right)^{\frac{\beta}{\alpha+\beta}}$，其中 $G=\left(\frac{\alpha A}{\beta B}\right)^{\frac{1}{\alpha+\beta}}$；
$D_{opt}=\frac{C}{6N_{opt}}=G^{-1}\left(\frac{C}{6}\right)^{\frac{\alpha}{\alpha+\beta}}$。两个指数之和为 1，与 $C=6ND$ 一致。

**(2) 代入**：$\frac{\beta}{\alpha+\beta}=\frac{0.28}{0.62}\approx0.45$，$\frac{\alpha}{\alpha+\beta}\approx0.55$。论文中这种方法给出的是 0.46 与 0.54，差别来自 $\alpha$、$\beta$ 的四舍五入。

**直觉**：$D$ 的指数 $\beta$ 更小，数据项随 $D$ 下降得更慢，「更难压」，所以要把更多的新增算力分给数据。另外两种方法（固定模型大小看训练曲线的包络、IsoFLOP 曲线）给出的指数都约为 0.5，这也是「同比例增长、约 20 token/参数」的来源。2024 年 Epoch AI 的复现工作（Besiroglu 等）认为这种参数化拟合存在问题，重新拟合后的结果与另外两种方法更一致。

<sub>考点：Chinchilla缩放律　｜　出处：Training Compute-Optimal Large Language Models（Hoffmann 等, 2022）arXiv:2203.15556</sub>

</details>

<a name="TRN-PT-016"></a>

### TRN-PT-016　挑战 · 考频 ★★

假设实验表明下面两个方案能达到相同的模型质量：方案 A 为 70B 参数、训练 1.4T token；方案 B 为 30B 参数、训练 5T token。训练算力按 $6ND$ 估算，推理算力按每处理一个 token 约 $2N$ FLOPs 估算（忽略注意力与 KV Cache 的开销）。
(1) 两个方案的训练算力各是多少？
(2) 上线后累计推理多少 token 时，方案 B 的「训练 + 推理」总算力开始低于方案 A？
(3) 若服务每天处理 1000 亿（$10^{11}$）个 token，大约多少天后方案 B 开始更划算？

<details>
<summary>答案与解析</summary>

**答案：(1) A 约 5.88×10^23 FLOPs，B 约 9.0×10^23 FLOPs；(2) 约 3.9T token；(3) 约 39 天**

**解析：**

**(1) 训练算力**：
- A：$6\times70\times10^9\times1.4\times10^{12}=5.88\times10^{23}$ FLOPs；
- B：$6\times30\times10^9\times5\times10^{12}=9.0\times10^{23}$ FLOPs，比 A 多 $3.12\times10^{23}$（约 53%）。

**(2) 回本点**：每处理一个 token，B 比 A 少 $2\times(70-30)\times10^9=8\times10^{10}$ FLOPs。
回本所需推理量 $=3.12\times10^{23}/(8\times10^{10})=3.9\times10^{12}$，即约 **3.9T** token。

**(3) 天数**：$3.9\times10^{12}/10^{11}=39$ 天。

**讨论**：热门服务一年处理的 token 往往远超训练 token 数，总成本由推理主导，这就是「过训练小模型」的经济学依据（Sardana 等, 2023）。除了 FLOPs，小模型的好处还有：权重显存小（30B 的 BF16 权重约 60 GB，单张 80 GB 卡可放下；70B 约 140 GB，至少要两张）、延迟低、能支撑更高并发。代价是：前提「质量相同」必须靠实验验证，而且方案 B 需要 5T token 的高质量数据。

### TRN-PT-007　基础 · 考频 ★★

下面的代码分别从「真实 token 的概率」和「均匀分布的 logits」计算交叉熵与困惑度。输出是什么？

```python
import math
import torch
import torch.nn.functional as F

p = torch.tensor([0.5, 0.25, 0.5, 0.125])   # 模型给 4 个真实 token 的概率
loss = -p.log().mean()
print(round(loss.item(), 4), round(math.exp(loss.item()), 4))

logits = torch.zeros(4, 1000)                # 全零 logits：均匀分布，词表大小 1000
target = torch.tensor([1, 2, 3, 4])
ce = F.cross_entropy(logits, target)
print(round(ce.item(), 4), round(math.exp(ce.item()), 1))
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
1.213 3.3636
6.9078 1000.0
```

**解析：**

**第一行**：$\mathcal{L}=-\frac14(\ln0.5+\ln0.25+\ln0.5+\ln0.125)=\frac{(1+2+1+3)\ln2}{4}=1.75\ln2\approx1.213$。困惑度 $e^{\mathcal{L}}=2^{1.75}\approx3.3636$，也就是各 token 概率倒数 $(2,4,2,8)$ 的几何平均：$(2\times4\times2\times8)^{1/4}=128^{1/4}$。

**第二行**：全零 logits 经过 softmax 是均匀分布，每个真实 token 的概率都是 $1/1000$，交叉熵为 $\ln1000\approx6.9078$，困惑度恰好等于词表大小 1000。这也是随机初始化模型的初始 loss 应接近 $\ln V$ 的原因：若初始 loss 远大于 $\ln V$，多半是初始化尺度过大。

注意 `F.cross_entropy` 接收的是未归一化的 logits，内部先做 `log_softmax`；把已经过 softmax 的概率传进去会得到错误结果。

<sub>考点：交叉熵与困惑度</sub>

ps = [0.5, 0.6, 0.7, 0.8, 0.9, 0.95]   # 不同规模模型的单 token 正确率
L = 10                                  # 答案长度
exact = [round(p ** L, 3) for p in ps]  # 精确匹配：10 个 token 全对

**答案（程序输出）：**

[5.0, 6.0, 7.0, 8.0, 9.0, 9.5]

## 代码改错题

<a name="TRN-PT-002"></a>

### TRN-PT-002　进阶 · 考频 ★★★

下面是预训练代码中计算语言模型损失的函数。用它训练时，训练 loss 很快降到接近 0，但模型生成的文本完全不可用。请指出 bug 并修正。

```python
import torch
import torch.nn.functional as F

def lm_loss(logits, input_ids):
    # logits: (B, T, V)，由因果语言模型对 input_ids 前向得到
    B, T, V = logits.shape
    return F.cross_entropy(logits.reshape(B * T, V), input_ids.reshape(B * T))
```

<details>
<summary>答案与解析</summary>

**答案：**

**问题**：logits 与标签没有错开一位。位置 $t$ 的输出应该预测第 $t+1$ 个 token，原代码却让它去预测第 $t$ 个 token，也就是输入里它自己。

**修正**：logits 去掉最后一个位置，标签去掉第一个位置，再计算交叉熵：

```python
shift_logits = logits[:, :-1, :].reshape(-1, V)
shift_labels = input_ids[:, 1:].reshape(-1)
loss = F.cross_entropy(shift_logits, shift_labels)
```

**修正后的代码：**

```python
import torch
import torch.nn.functional as F

def lm_loss(logits, input_ids):
    # 位置 t 的输出预测第 t+1 个 token：logits 去掉最后一位，标签去掉第一位
    B, T, V = logits.shape
    shift_logits = logits[:, :-1, :].reshape(-1, V)
    shift_labels = input_ids[:, 1:].reshape(-1)
    return F.cross_entropy(shift_logits, shift_labels)
```

**解析：**

因果掩码允许位置 $t$ 看到第 $t$ 个 token 本身，所以「预测自己」只需把输入原样复制到输出。模型很快学会这种恒等映射，训练 loss 接近 0，却完全没有学到「预测下一个 token」，生成时自然不可用。这是从零写训练代码时最常见的 bug 之一。

错开一位后，长度为 $T$ 的序列产生 $T-1$ 个监督信号。Hugging Face 的 `LlamaForCausalLM` 等实现在模型内部完成这次错位，所以调用时传入的 `labels` 与 `input_ids` 相同即可；自己写损失时则必须手动错位，而且不能在两处重复错位。

排查经验：训练 loss 低得不合常理（如小模型几百步就接近 0）时，先检查标签是否错位、掩码是否泄漏了未来信息，再考虑数据重复等原因。

<sub>考点：自回归预训练目标</sub>

</details>

<a name="TRN-PT-017"></a>

### TRN-PT-017　进阶 · 考频 ★★★

Chinchilla 认为每个参数约训练 20 个 token 最划算，但 Llama 3 8B 训练了约 15T token（约 1875 token/参数）。请回答：(1) 两者为什么并不矛盾？(2) 「过训练」小模型的动机有哪些？(3) 它有哪些代价与限制？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **目标不同**：Chinchilla 回答的是「固定训练算力下怎样让 loss 最低」，不考虑推理。20 token/参数是训练算力最优点，不是效果上限：继续训练 loss 仍在下降，Meta 报告 8B 和 70B 训到 15T token 时效果仍在按对数线性提升。
2. **动机**：
   - 推理成本：每 token 推理约 $2N$ FLOPs，显存、延迟、并发都与模型大小相关；上线后的累计推理量远大于训练量，总成本由推理主导。Beyond Chinchilla-Optimal（Sardana 等, 2023）把推理需求纳入后，最优解偏向小模型、多数据。
   - 部署约束：端侧、单卡、低延迟场景只放得下小模型，只能靠多喂数据把它训强。
   - 生态：小模型便于社区微调、量化和二次开发。
3. **代价与限制**：
   - 训练算力不是最省的：达到同样的 loss，小模型要多花训练算力，而且越往后边际收益越低（小模型的 loss 下限更高）。
   - 数据需求大：15T 级的高质量数据很难获得；重复训练 4 个 epoch 以内损失不大，再多收益迅速递减（Muennighoff 等, 2023）。
   - 能力上限低于同等算力下的更大模型，知识容量和复杂推理受参数量限制。
   - 有研究（Kumar 等, 2024, Scaling Laws for Precision）发现训练 token 越多，训练后量化带来的损失越大，过训练的模型可能更难压缩。

**评分要点（共 10 分）：**

- 指出 Chinchilla 只优化训练算力，20 token/参数不是效果上限（3 分）
- 说明推理成本、部署约束等动机，最好给出 2N 推理算力或具体案例（4 分）
- 说明训练算力、数据需求、能力上限等代价（3 分）

**讲解：**

**常见失分点**：说「Chinchilla 已经被推翻」（在它的目标下结论依然成立）；只说「小模型更快」，却说不清省的是推理算力而不是训练算力；忽视数据瓶颈；把 20 token/参数理解为「训练到收敛」。

<a name="TRN-PT-025"></a>

### TRN-PT-025　挑战 · 考频 ★★

有人说「大模型的涌现能力只是评测指标制造的错觉」。请谈谈你的看法：(1) 指标选择如何制造「突变」；(2) 这一争论对预训练团队有什么实际意义；(3) 在预训练过程中，你会如何设计评测，以便更早、更平滑地预测下游能力？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **指标如何制造突变**：
   - 非线性指标：设每个 token 的正确率 $p$ 随规模平滑提升，长度为 $L$ 的答案全对的概率约为 $p^L$。$L=10$ 时，$p$ 从 0.7 升到 0.9，精确匹配从 2.8% 跳到 35%，看起来像突然「开窍」。
   - 不连续指标：多选题只有正确选项的概率超过其他选项才得分，概率的连续变化被阈值化。
   - 分辨率不足：小模型准确率接近 0，测试集太小时测不出差别；模型尺寸采样稀疏、横轴取对数，也会放大「突然」的观感。
   - 换用 token 编辑距离、Brier 分数等连续指标后，很多「涌现」变得平滑（Schaeffer 等, 2023）；但也有研究（Du 等, 2024）发现某些能力要在预训练 loss 降到一定阈值以下才出现，不能一概而论。
2. **实际意义**：缩放律预测的是 loss，而不是下游能力。若能找到与目标能力平滑相关的连续指标，就能用小模型可靠地预测大模型，从而决定模型规模、数据配比和训练时长；只看离散指标，小规模实验会「看不到信号」，导致误判数据或配方无效。另一方面，很多能力对用户确实是「全对才有用」的，离散指标反映真实体验，两类指标都要看。
3. **评测设计**：
   - 同时记录连续指标：正确答案的对数似然、按长度归一化的似然排序（完形填空格式）、各领域验证集的 BPB；
   - 训练早期用完形填空格式，模型变强后再加选项字母格式与生成式评测；代码等生成任务用较大 $k$ 的 pass@k 获得更细的信号；
   - 扩大评测集并报告置信区间；用多个尺寸、多个检查点画「指标—loss」或「指标—算力」曲线；
   - 中间检查点先接一小段退火再评测，避免未退火带来的偏差；评测集要与训练数据去污染。

**评分要点（共 10 分）：**

- 用 p^L、阈值化等例子说明非线性或不连续指标如何制造突变（3 分）
- 说明争论的实际意义（可预测性、规模与数据决策），并指出离散指标仍有用户意义（3 分）
- 给出具体的连续指标与评测设计，如似然、BPB、pass@k、置信区间、指标对 loss 作图（4 分）

**讲解：**

**常见失分点**：一边倒地断言「涌现是假的」或「涌现是真的」；只复述论文标题，举不出 $p^L$ 这样的数字例子；评测设计只说「多跑几个基准」，没有连续指标、置信区间和对 loss 作图的思路。

<a name="TRN-PT-029"></a>

### TRN-PT-029　进阶 · 考频 ★★★

预训练为什么需要学习率 warmup？峰值学习率和全局 batch size 一般怎样确定？模型变大时它们通常怎样变化？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **warmup 的作用**：初始化时参数是随机的，梯度大而且方向不稳定；Adam 的二阶矩 $v$ 在最初几步只基于很少的梯度估计，方差很大，自适应步长不可靠。直接用峰值学习率，容易一步跳出好的区域甚至发散（Post-Norm 结构更明显）。线性 warmup 让 $m$、$v$ 先积累起稳定的估计，常见几百到几千步（Llama 2 为 2000 步）。
2. **峰值学习率**：在小规模代理模型上做网格搜索，再按经验规律外推。DeepSeek LLM 拟合了最优学习率和 batch 随算力变化的幂律；μP 让小宽度模型上调好的超参数可以迁移到大模型。经验值：7B 级约 $3\times10^{-4}$，70B 约 $1.5\times10^{-4}$（Llama 2）。
3. **batch size**：通常为数百万 token（Llama 2 为 4M）。上限由「临界 batch size」决定：在它以内，加大 batch 几乎线性地减少所需步数、提高并行效率；超过后收益递减，浪费数据。训练早期临界 batch 较小，GPT-3 采用了 batch 从小逐步增大的做法。改 batch 时学习率要联动调整（平方根到线性放大）。
4. **随规模的变化**：模型越大，峰值学习率越小、batch 越大。GPT-3 的 125M 模型用 $6\times10^{-4}$、0.5M token，175B 模型用 $0.6\times10^{-4}$、3.2M token。

**评分要点（共 10 分）：**

- 解释 warmup 的原因：初期梯度与 Adam 二阶矩估计不稳定（3 分）
- 给出确定峰值学习率的方法：小模型搜索、超参数缩放律、μP（3 分）

<a name="TRN-PT-033"></a>

### TRN-PT-033　进阶 · 考频 ★★

什么是预训练的「退火阶段」？为什么常在这一阶段上采样高质量数据？Llama 3 是如何借助退火来评估一个新数据集的价值的？这种评估方法有什么局限？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **定义**：训练末期把学习率降到很小（线性降到 0，或余弦降到峰值的约 10%），同时提高高质量数据（数学、代码、精选网页、教材式与指令式数据）的比例，常与长上下文扩展一起进行，也被视为中期训练（mid-training）的一部分。Llama 3 在最后 4000 万 token 把学习率线性降到 0，并上采样最高质量的数据源。
2. **为什么上采样高质量数据**：低学习率阶段 loss 下降快、模型逐渐「定型」，此时的数据分布对最终能力影响最大；高质量数据量少，放在末期集中使用，既能多遍利用，又不会在高学习率阶段被后续数据冲淡或过早过拟合。Llama 3 报告：退火让 8B 模型在 GSM8K、MATH 验证集上明显提升，但对 405B 的提升可以忽略。
3. **用退火评估数据**：取训练到约 50% 的 Llama 3 8B 检查点，在 400 亿 token 上把学习率线性退火到 0，其中新数据集占 30%、默认配比占 70%，与不加新数据的退火对比指标变化。这比从头训练做消融便宜得多，对小规模、高质量的数据也足够敏感。
4. **局限**：只测了「末期加入」的效果，不等于全程混入的效果；小模型上的结论未必能迁移到大模型（405B 收益可忽略就是例子）；新数据若与评测集相似会造成分数虚高，必须先去污染；单次实验有噪声，需要对照组和重复实验。

**评分要点（共 10 分）：**

- 说清退火阶段的定义：学习率降到很小，同时上采样高质量数据（3 分）
- 解释为何在这一阶段上采样高质量数据（3 分）
- 说出用退火评估数据的具体做法（2 分）
- 指出至少两点局限（2 分）

**讲解：**

**常见失分点**：把退火说成优化算法里的「模拟退火」；只提学习率、不提数据配比的变化；说不出用退火评估数据的做法；忽视评测污染和小模型结论能否迁移的问题。

<sub>考点：学习率调度与退火、预训练阶段划分　｜　出处：The Llama 3 Herd of Models arXiv:2407.21783（3.1.3 节用退火评估数据、3.4.3 节退火）</sub>

</details>

## 场景分析题

<a name="TRN-PT-034"></a>

### TRN-PT-034　进阶 · 考频 ★★

团队准备训练一个 3B 模型。目前的算力只够训练 1T token，但下季度可能追加预算再训 1T～2T；同时下游团队希望在训练过程中随时能拿到一个「可用版本」先行试用。请选择学习率调度方案，说明检查点与发布策略；如果最后真的追加了预算，训练要怎样接上？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **选型**：用 WSD（或类似的多阶段阶梯式调度），不用按 1T 设定的余弦。余弦的形状由总步数决定：中途的检查点学习率还高、没有退火，拿出去效果偏差；训完 1T 后学习率已降到很低，追加训练只能重新 warmup，loss 会先上升，效率也不如一开始就按更长的总量规划。
2. **训练主线**：warmup（如 2000 步）后保持恒定的峰值学习率；定期保存完整检查点，包括优化器状态和数据加载的位置。
3. **发布策略**：需要可用版本时，从最近的主线检查点分出一支，做一段衰减（约为已训 token 数的 10%，或固定几十 B token），衰减段可上采样高质量数据，得到的模型交给下游；主线不受影响，继续以恒定学习率训练。每个分支额外消耗约 10% 的算力，发布频率要权衡。
4. **追加预算后**：从主线（未衰减）的最新检查点继续以峰值学习率训练，到新的终点前再做最终的衰减与退火；不要从已经衰减的分支接着训。如果只剩衰减后的检查点，就要重新 warmup 到适中的学习率再衰减，并接受短暂的 loss 上升。
5. **注意事项**：按新的总量重新规划数据，避免高质量数据提前用尽或重复过多；只在「衰减后」的模型之间比较效果，稳定阶段的 loss 偏高是正常的；续训一定要加载优化器状态，否则 Adam 的 $m$、$v$ 需要重新积累，等于重新开始一段不稳定期。

**评分要点（共 10 分）：**

- 选择 WSD 并说明余弦在训练长度不确定时的问题（3 分）
- 给出从稳定阶段分支衰减、得到可用版本的策略（3 分）
- 说明追加预算时从未衰减的主线续训，以及只剩衰减检查点时需重新 warmup（2 分）
- 提到数据规划、比较口径、保存优化器状态等细节（2 分）

**讲解：**

**常见失分点**：直接按 1T 设计余弦，「追加时再说」；从已衰减的分支续训却不处理学习率；只说「用 WSD」却讲不清分支衰减的具体做法；忽略续训时的数据重复和优化器状态。

<sub>考点：学习率调度与退火、学习率与批大小</sub>

</details>

<a name="TRN-PT-040"></a>

### TRN-PT-040　挑战 · 考频 ★★★

你负责一个 70B 稠密模型的预训练（BF16 混合精度，AdamW，$\beta_2=0.95$，峰值学习率 $1.5\times10^{-4}$，余弦调度，全局梯度裁剪阈值 1.0）。训练到第 12 万步时，loss 从 1.92 突然跳到 2.6，同一时刻梯度范数从约 0.3 暴涨到 40 以上；之后几百步 loss 缓慢回落，但仍高于跳变前。过去一周还出现过两次较小的 spike。请给出处理与排查方案，并说明如何降低后续 spike 的概率。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 立即止损**
- 暂停训练，回滚到 spike 前的检查点（如提前 100～200 步，确认该检查点的 loss 与梯度范数都正常）；
- 跳过 spike 附近的若干个 batch 后重启（PaLM 的做法是回退约 100 步、跳过 200～500 个 batch）；若重启后仍在附近出现 spike，再适当降低学习率。
- 不要「等它自己降回来」：spike 后 loss 仍高于跳变前，说明模型状态（包括 Adam 的 $m$、$v$）已被扰乱，下游能力可能受损。

**2. 定位原因**
- **数据**：数据加载要可复现（记录每步的样本索引）。取出 spike 前后的 batch 检查是否有乱码、超长重复片段、base64、表格、语种识别错误、某个来源占比异常等。用回滚的检查点**重放**这些 batch，若能复现梯度暴涨，基本可以确定是数据问题。
- **数值**：查看分层梯度范数、各层激活与注意力 logits 的最大值、输出层的 $\log Z$、Embedding 的梯度（罕见 token）。若 logits 在 spike 之前就持续增长，属于数值逐步失控，不是单个坏 batch。
- **硬件**：对比各数据并行组的 loss 与梯度，排查掉卡、慢节点和静默数据错误，必要时下线可疑节点。
- 三次 spike 若间隔缩短、幅度增大，说明学习率相对当前状态偏大或数值问题在累积。

**3. 预防措施**
- 本次训练中可以改的：适当调低学习率；加入 z-loss；对 Embedding 梯度做缩放（GLM-130B 乘 0.1）；梯度范数超过阈值时自动跳过该步更新；清洗被定位出的坏数据源。
- 下一轮再改的：QK-Norm 等架构改动（训练中途加入会改变模型函数，需要谨慎）、更长的 warmup、更保守的初始化。

**4. 监控与自动化**：loss、梯度范数、更新量与参数之比、logits 最大值的实时看板；spike 自动检测与告警；高频异步保存检查点以缩短回滚距离；回滚与跳数据流程脚本化。

**5. 决策依据**：对比「回滚跳数据」与「继续训练」两个分支在下游小评测上的表现，选择更好的路径。

**评分要点（共 10 分）：**

- 给出回滚到 spike 前检查点并跳过相关数据的止损方案（3 分）
- 从数据、数值、硬件三方面给出具体的排查手段，如重放 batch、查看 logits 与分层梯度（3 分）
- 给出预防措施，并区分本次可改与下一轮再改的项（3 分）
- 提到监控、告警与自动化（1 分）

**讲解：**

**常见失分点**：只说「调小学习率」；没有可复现的数据定位手段；认为 loss 回落就万事大吉；建议改用 FP16「提高精度」；忽视硬件故障。高分回答要体现「先止损、再定位、后预防」的顺序，并能说出重放 batch 这样可验证的排查方法。

<sub>考点：训练稳定性</sub>

<a name="TRN-PT-044"></a>

### TRN-PT-044　挑战 · 考频 ★★

你负责一个 13B 模型的预训练（256 张 H800，BF16 混合精度，AdamW，序列长度 8K）。周末发生了两件事：

1. 第 41,200 步时 loss 突然变成 NaN；在此之前 loss 和梯度范数都正常，没有出现 spike 之类的先兆；
2. 从第 41,000 步的检查点恢复、并跳过出事的那批数据后，loss 恢复正常，但每步耗时从约 9.8 秒变成约 19 秒，MFU 从 42% 掉到 21%；GPU 利用率曲线呈周期性的锯齿状，每隔一段时间就掉到接近 0。

请分别给出两个问题的排查顺序与处理方案。

<details>
<summary>答案与解析</summary>

**参考答案：**

**问题 1：没有先兆的 NaN**
1. **先定位第一个非有限值**：每步检查 loss 与梯度范数是否有限，出现 NaN / Inf 时跳过本次更新并保存现场；找出最先出现非有限值的 rank 和张量（前向的某层激活、loss、梯度还是优化器状态）。
2. **数据**（突然出现、没有先兆，首先怀疑单个 batch）：用同一个检查点在同一个 rank 上重放这批数据，看能否复现。重点检查：空样本或整条样本都被掩码，有效 token 数为 0，loss 变成 0/0；超长的重复片段或异常字符；越界的 token id。
3. **数值**：自定义算子中的 log(0)、除以 0（归一化层的 eps、loss 归一化的分母）、对负数开方；注意力中某一行被全部掩码，softmax 的输入全是 −∞，输出 NaN。BF16 的动态范围与 FP32 相当，真正溢出的情况较少，更常见的是 0/0、∞−∞ 这类运算。
4. **硬件**：同一 batch 换到其他节点重放不再复现，就怀疑某张卡的静默数据错误，检查 Xid、ECC 日志并隔离该节点。
5. **预防**：在数据管线中断言「有效 token 数 > 0」「token id 在词表范围内」；loss 分母加保护；遇到非有限梯度自动跳过并告警；记录每步的样本索引，方便定位。

**问题 2：恢复后 MFU 减半、利用率呈锯齿状**

锯齿状、周期性掉到 0，说明 GPU 在等待，应优先排查计算之外的环节：
1. **逐阶段计时**：用 profiler 或计时器把一步拆成数据等待、前向、反向、通信、优化器、检查点保存，与事故前的记录对比，先找变化最大的环节。
2. **数据加载与存储**：恢复时数据集要「快进」到断点或重建索引；本地缓存失效，开始从远端存储读取；恢复脚本改动了数据加载进程数或预取设置。
3. **配置差异**：对比恢复前后的启动配置：micro-batch、梯度累积步数、激活重计算（为排查 NaN 临时打开了全量重计算，或打开了异常检测、同步执行 CUDA 等调试开关）、packing 是否被关闭、检查点间隔是否被调小且改成了同步保存。每一项都可能让耗时翻倍。
4. **通信与节点**：恢复后调度到了不同的节点或机架；NCCL 是否没有识别到 InfiniBand 网卡、退回到 TCP Socket（查看 NCCL 初始化日志）；对比各 rank 的耗时，找出拖慢全体的慢节点。
5. **硬件状态**：GPU 降频、温度过高、ECC 错误。

**处理与长期措施**：恢复数据预取与缓存、改为异步保存检查点、关闭调试开关、剔除慢节点、修复网络配置；在恢复流程中自动对比配置差异；对每步耗时与 MFU 设置告警，偏离基线时立即通知。

**评分要点（共 10 分）：**

- 对 NaN 给出「先定位首个非有限值，再查数据、数值、硬件」的合理顺序，并使用重放 batch 等可验证的手段（3 分）
- 指出 0/0、整行被掩码、log(0) 等具体的数值成因，并给出预防措施（2 分）
- 对 MFU 减半以逐阶段计时为核心排查，覆盖数据与存储、检查点、配置差异、通信（含 NCCL 退回 Socket）、慢节点（3 分）
- 给出长期防护措施：非有限值自动跳过、配置差异检查、MFU 告警（2 分）

**讲解：**

**常见失分点**：看到 NaN 就降低学习率或改用 FP32，没有先定位是哪个张量、哪批数据；把恢复后的变慢归因于「模型变大」或「数据变难」；不知道 GPU 利用率周期性掉到 0 意味着在等数据、等 I/O 或等某个 rank；没有对比恢复前后的配置；只给一次性的修复，没有告警与自动化。

<sub>考点：训练稳定性、训练算力估算</sub>

### TRN-PT-043　挑战 · 考频 ★★

你负责一个 7B 模型的从零预训练（计划 8T token，含末期退火与长上下文阶段，约训练一个月）。请设计训练过程中的评测与监控体系：监控哪些训练指标、多久评测一次、用哪些评测集和评测方式，以及如何用这些信号做决策（例如是否回滚、是否调整数据配比、是否进入下一阶段）。

**参考答案：**

**1. 目标与原则**：尽早发现问题（训练不稳定、数据缺陷），并给出与最终能力相关、可横向比较的信号；评测要便宜、稳定、可复现，并与训练数据去污染。

**2. 训练过程监控（实时，每步或每几十步）**
- loss：总 loss 与按数据源拆分的 loss；

**评分要点（共 10 分）：**

- 列出训练过程的关键监控指标，如分数据源的 loss、梯度范数、logits 统计（2 分）
- 给出评测频率、内在指标与下游评测集，评测方式适合 Base 模型（3 分）
