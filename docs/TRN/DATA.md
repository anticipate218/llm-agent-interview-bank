<a name="TRN-DATA-001"></a>

### TRN-DATA-001　基础 · 考频 ★★

关于大模型预训练数据的来源，下列说法正确的是：

- **A.** Common Crawl 的原始网页已经过抓取方的去重与质量筛选，抽取正文后即可直接用于训练
- **B.** 网页通常是预训练数据中占比最大的来源，但要经过正文抽取、过滤和去重才能使用
- **C.** 书籍和学术论文的 token 总量最大，是预训练的主体；网页主要用来补充口语化和时效性内容
- **D.** 代码数据只对编程任务有帮助，通用对话模型的预训练中通常会去掉代码，以免影响语言能力

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：网页是预训练数据的「大头」，也是最需要清洗的来源。

以 Llama 1 为例，Common Crawl 与 C4（同样来自网页）合计约占训练数据的 82%，其余是 GitHub 代码、维基百科、书籍、arXiv 论文和 StackExchange。Common Crawl 每次抓取有数十亿网页，原始内容充斥导航栏、广告、乱码和重复页，开源社区因此发布了 RefinedWeb、FineWeb（约 15T token）、DCLM 等清洗版本。

- A 错：Common Crawl 只负责抓取与存档，不做质量筛选；原始网页必须经过抽取、过滤、去重才能使用，最终留下的只是一小部分。
- C 错：书籍、论文质量高但总量远小于网页，通常被上采样。
- D 错：代码数据有助于推理与结构化输出，主流通用模型都包含相当比例的代码（如 Llama 3 约 17%）。

<sub>考点：数据来源</sub>

</details>

<a name="TRN-DATA-003"></a>

### TRN-DATA-003　进阶 · 考频 ★★

C4 数据集的清洗规则之一是：丢弃包含花括号「{」的网页，初衷是去掉 JavaScript 等代码片段。这条规则最主要的副作用是：

- **A.** 含颜文字和表情符号的社交媒体帖子被大量误删，数据集中的口语化表达明显减少
- **B.** 很多非英文网页的模板中带有花括号，非英文内容因此被系统性地过滤，数据集变成纯英文
- **C.** 代码和含 LaTeX 公式的数学内容几乎被清空，用它训练的模型代码与数学能力先天不足
- **D.** 被删的多为短小的代码片段页，剩余文档的平均长度大幅增加，训练时需要更长的上下文窗口

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：一条看似合理的规则，会让整类内容从数据中消失。

花括号在绝大多数编程语言中都会出现，LaTeX 公式（如 `\frac{a}{b}`）也离不开它，所以这条规则几乎清空了代码和带公式的数学内容。C4 的其他规则还包括：只保留以句末标点结尾的行、丢弃句子太少的页面、删除含「脏词表」中词语的页面等。后续研究（Dodge 等, 2021）发现，脏词表过滤还不成比例地删除了涉及少数群体的文本。

- A 错：表情符号与花括号无关，这条规则对社交媒体文本的影响很小。
- B 错：C4 确实只保留英文，但那是另一条语种识别规则（langdetect）的结果，不是花括号规则造成的。
- D 错：被删的是含花括号的整页，长短都有，不会让平均长度大幅增加；而且预训练把文档拼接成定长序列，文档长短并不决定上下文窗口。

启示：每条过滤规则都要抽样检查被删内容，按领域统计删除比例，避免「误伤」整类数据。

<sub>考点：文本清洗、代码与数学数据</sub>

</details>

<a name="TRN-DATA-006"></a>

### TRN-DATA-006　基础 · 考频 ★★★

两篇网页的正文完全相同，只有页脚的发布日期不同（「2023-05-01」与「2023-05-02」）。对规范化后的全文计算 SHA-1 哈希做精确去重，结果是：

- **A.** 两者哈希值截然不同，精确去重发现不了这对近重复，需要 MinHash 等近似去重方法
- **B.** 两者的哈希值只有少数几位不同，按汉明距离设一个阈值（如不超过 3 位）就能识别为重复
- **C.** 规范化会统一日期、数字等易变字段，两篇规范化后的文本相同、哈希一致，会被判为重复
- **D.** SHA-1 对长文档分块计算，页脚的改动只影响最后一块，整体哈希的大部分位保持不变

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：精确哈希只能识别「一字不差」的重复。

SHA-1、MD5 等哈希具有雪崩效应：输入改动一个字符，输出约一半的位都会变化，哈希值之间的距离不反映文本的相似程度。所以精确去重适合做第一道关（URL 去重、整篇去重、行级去重），近重复要交给 MinHash-LSH 或 SimHash 这类局部敏感哈希。

- B 错：「相似的输入得到汉明距离小的签名」是 SimHash 的性质，SHA-1 没有。
- C 错：常见的规范化是统一大小写、合并空白、Unicode 规范化等，不会改写或去掉日期这类内容。
- D 错：SHA-1 虽然按块迭代计算，但最终摘要依赖全部输入，任何一块的改动都会经雪崩效应改变约一半的输出位，与文档长度无关。

<sub>考点：精确去重　｜　出处：Deduplicating Training Data Makes Language Models Better（Lee 等, 2022）arXiv:2107.06499；MinHash（Broder, 1997）；SimHash（Charikar, 2002）</sub>

</details>

<a name="TRN-DATA-009"></a>

### TRN-DATA-009　进阶 · 考频 ★★

MinHash 用「对集合做一次随机哈希后取最小值」来估计两个集合的 Jaccard 相似度 $J(A,B)=|A\cap B|/|A\cup B|$。两个集合的 MinHash 值相等的概率恰好等于 $J(A,B)$，原因是：

- **A.** 哈希函数把集合映射成高维向量，最小值相等的概率等于两向量的余弦相似度，而对集合而言余弦相似度与 Jaccard 相等
- **B.** 根据生日悖论，两个集合中任意一对元素发生哈希碰撞的概率约为 $|A\cap B|/|A\cup B|$
- **C.** 最小哈希值主要由集合大小决定：元素越多最小值越小，两个集合大小越接近，最小值相等的概率越大
- **D.** 随机哈希等价于随机排列 $A\cup B$，排在最前的元素落在 $A\cap B$ 的概率就是 $J$，此时两者最小值相同

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：关键是看 $A\cup B$ 中哈希值最小的那个元素落在哪里。

$A\cup B$ 中每个元素成为最小值的机会均等。如果它属于 $A\cap B$，它同时是 $A$ 和 $B$ 的最小值，两个签名相等；如果它只属于其中一个集合，两个最小值必然不同。所以 $P(\min h(A)=\min h(B))=|A\cap B|/|A\cup B|=J$。用 $k$ 个独立的哈希函数得到长度为 $k$ 的签名，逐位相等的比例就是 $J$ 的无偏估计，标准差约 $\sqrt{J(1-J)/k}$。

- A 错：余弦相似度与 Jaccard 是不同的量，对 0/1 向量余弦为 $|A\cap B|/\sqrt{|A||B|}$，一般不等于 $J$；用随机超平面估计向量夹角的是 SimHash。
- B 错：与生日悖论无关，这里讨论的不是任意两个元素之间的哈希碰撞。
- C 错：集合越大，最小值确实倾向于越小，但两个最小值是否相等取决于重叠程度，而不是大小是否接近；两个等大但不相交的集合，最小值不可能相等。

<sub>考点：MinHash近似去重</sub>

</details>

<a name="TRN-DATA-012"></a>

### TRN-DATA-012　挑战 · 考频 ★

近似去重的最后一步，常把「被判为近重复的文档对」用并查集合并成簇，每簇只保留一篇。已知文档 A 与 B 的 Jaccard 相似度为 0.8，B 与 C 为 0.8，而 A 与 C 只有 0.6，去重阈值为 0.7。关于这一步，下列说法正确的是：

- **A.** 并查集只合并直接相似的文档对：A 与 B、B 与 C 各成一组，A 与 C 未达阈值，最终保留两篇
- **B.** 并查集求的是连通分量，A、B、C 会被并成一簇只留一篇，链式相似可能误删差异较大的文档
- **C.** A 与 C 的相似度低于阈值，并查集会检测到这一矛盾，自动把 B 拆出来单独成簇以保留更多文档
- **D.** 这种情况不可能出现：Jaccard 距离满足三角不等式，A、B 和 B、C 都是 0.8 时，A、C 至少也是 0.8

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：并查集做的是传递闭包，「A 像 B、B 像 C」就会把 A、B、C 并成一簇。

近重复关系本身不可传递：A、C 只有 0.6，单看它们并不算重复，但通过 B 连在了一起，最终只保留一篇。在高阈值下这种链很少，影响有限；若担心误删，可以检查簇的「直径」（簇内最不相似的一对），或改用以某篇文档为中心、只合并与中心足够相似的文档的聚类方式，并在每簇中保留质量最高的一篇。

- A 错：并查集合并的是连通分量，不是只看直接相连的边，A、B、C 最终只保留一篇。
- C 错：并查集不会根据相似度拆分已合并的簇。
- D 错：Jaccard 距离 $1-J$ 确实满足三角不等式，但它给出的是 $1-J(A,C)\le0.2+0.2$，即 $J(A,C)\ge0.6$，而不是 0.8。例如 $B=\{1,\dots,10\}$，$A=B\setminus\{1,2\}$，$C=B\setminus\{9,10\}$，恰好得到 0.8、0.8 和 0.6。

<sub>考点：MinHash近似去重</sub>

</details>

<a name="TRN-DATA-015"></a>

### TRN-DATA-015　进阶 · 考频 ★★

FineWeb-Edu 先让 Llama-3-70B-Instruct 给数十万篇网页的「教育价值」打 0～5 分，再用这些标注训练一个小分类器，给全部约 15T token 的网页打分，保留 3 分及以上的部分。不直接用 70B 模型给全部网页打分，最主要的原因是：

- **A.** 70B 模型对同一篇网页多次打分波动较大，训练后的小分类器打分更稳定，也比大模型更准确
- **B.** Llama-3-70B 只能较好地理解英文，小分类器基于多语言 Embedding，可以给各种语言的网页统一打分
- **C.** 对数十亿篇网页逐篇调用 70B 模型成本过高，用它标注少量样本再蒸馏到小分类器才能覆盖全量
- **D.** 大模型打分只看正文内容，小分类器还能利用 URL、域名等元数据，对教育价值的判断更全面

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：「大模型标注 + 小模型推理」是把昂贵的判断能力扩展到海量数据的标准做法。

小分类器（在文本 Embedding 上训练的回归头）每篇只需一次轻量前向，可以在合理成本内处理数十亿篇网页。按 3 分阈值过滤后保留约 1.3T token，用它训练的模型在 MMLU、ARC 等知识与推理基准上明显好于未过滤的 FineWeb。

- A 错：小分类器是从大模型的标注中学来的，一般不会比「老师」更准，换来的是成本。
- B 错：语言覆盖不是这里的主要考虑，FineWeb-Edu 本身面向英文网页。
- D 错：FineWeb-Edu 的小分类器同样只看网页文本（在文本 Embedding 上训练回归头），并不使用 URL 等元数据。

注意：这种过滤把「教育价值」当作质量标准，会偏向教材、百科风格，对话、创作类内容会被大量去掉，使用时要结合配比考虑。

<sub>考点：质量过滤　｜　出处：FineWeb 技术报告（Penedo 等, 2024）arXiv:2406.17557</sub>

</details>

<a name="TRN-DATA-020"></a>

### TRN-DATA-020　基础 · 考频 ★★

对预训练数据中的个人可识别信息（PII，如邮箱、电话号码、身份证号），下列处理方式最合理的是：

- **A.** 删除含有连续 6 位以上数字的文档，电话号码和证件号由此一并去除，规则简单且召回率高
- **B.** 不做处理：模型参数量远小于数据量，单条个人信息在训练中出现的次数太少，模型记不住
- **C.** 训练数据保持原样，上线后用输出过滤器拦截个人信息，这样既不损失数据，又能保护隐私
- **D.** 用正则和命名实体识别检测 PII，替换成 `<EMAIL>` 等类型占位符并保留上下文

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：在数据源头检测并替换 PII，既保护隐私，又保留文本的其余价值。

邮箱、电话、证件号、IP 地址、银行卡号等格式固定的信息用正则匹配（可加校验位减少误报），人名、住址等用命名实体识别；替换成带类型的占位符，句子结构仍然完整。上线前要抽样评估检测的精确率与召回率。

- A 错：会误删大量含数字的数学、代码、表格和正常文本，代价过大；邮箱、住址等不含长串数字的 PII 仍会漏掉。
- B 错：Carlini 等（2021）从 GPT-2 中抽取出了训练数据里的姓名、电话、邮箱等信息；在数据中重复出现的内容尤其容易被记住。
- C 错：输出过滤是有用的补充防线，但可能被绕过，也无法消除模型已经记住的信息，源头清洗仍然必要。

<sub>考点：毒性与PII过滤</sub>

</details>

<a name="TRN-DATA-023"></a>

### TRN-DATA-023　基础 · 考频 ★★

GPT-3 的训练配比中，过滤后的 Common Crawl 占采样权重的 60%，但整个训练只过了约 0.44 遍；维基百科只占 3%，却重复了约 3.4 遍。这反映的配比原则是：

- **A.** 高质量数据宁可多训几遍，海量低质数据宁可用不完：权重按质量而非数据量设定
- **B.** 每个数据源都应恰好训练一遍，CC 只过 0.44 遍是受算力所限，重复数据容易导致过拟合
- **C.** 数据量越大的来源越可靠，采样权重应随 token 数等比例提高，CC 权重最高正体现了这一点
- **D.** 按各数据源的 token 数自然混合，再对小数据源少量上采样以防被淹没，与数据质量无关

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：配比的核心是「每个来源占多少采样权重、因此训几遍」，而不是简单按数据量混合。

GPT-3 的五个数据源中，Common Crawl 约 410B token，权重 60%、只过 0.44 遍；WebText2 权重 22%、约 2.9 遍；维基百科约 3B token，权重 3%、约 3.4 遍。高质量的小数据源被上采样多遍，海量但质量一般的网页用不完也没关系。

- B 错：适度重复高质量数据是常见做法，Muennighoff 等（2023）发现重复 4 遍以内的损失很小。
- C 错：按数据量等比例提高权重就是按自然比例混合，会让网页淹没少量高质量数据；Common Crawl 按 token 数约占 82%，实际权重只给了 60%。
- D 错：GPT-3 论文明确说明，被视为更高质量的数据集采样更频繁，权重是按质量设定的。

<sub>考点：数据配比</sub>

</details>

<a name="TRN-DATA-027"></a>

### TRN-DATA-027　进阶 · 考频 ★★

Llama 3 用「退火实验」评估新数据集：取训练到约 50% 的 8B 检查点，在 400 亿 token 上把学习率线性退火到 0，其中新数据集占 30%、默认配比占 70%，再与对照组比较指标。相比「用新数据从头训练小模型做消融」，这种方法的主要优势是：

- **A.** 退火实验能完整反映新数据全程混入时的效果，在 8B 上看到的增益可以直接外推到 405B 模型
- **B.** 成本低得多，且对数学、代码等小规模高质量数据更敏感，增益在已有一定能力的模型上更易显现
- **C.** 不必另设对照组：直接比较同一检查点退火前后的分数变化，就能量化新数据带来的增益
- **D.** 退火阶段学习率很小，参数几乎不再变化，新数据中混入少量低质量内容也不会影响最终模型

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：退火实验是一种便宜而灵敏的数据评估手段。

40B token 的退火只占从头训练的一小部分算力；而且很多高质量数据（如数学题解）量不大，从头训练的小模型能力太弱，往往看不出差别，在已经训练过半的检查点上做退火，增益更容易显现。

- A 错：退火实验只评估「末期加入」的效果；Llama 3 自己也发现，退火对 8B 的数学指标提升明显，对 405B 的提升却可以忽略，结论不能直接外推。
- C 错：必须与「用默认配比做同样退火」的对照组比较，否则无法区分退火本身带来的提升与新数据带来的提升。
- D 错：末期学习率虽小，但这一阶段的数据分布对最终模型影响很大，低质量数据同样会造成损害。

<sub>考点：课程学习</sub>

</details>

<a name="TRN-DATA-029"></a>

### TRN-DATA-029　基础 · 考频 ★★

Shumailov 等（2024, Nature）研究了「模型坍塌」（model collapse）现象。它指的是：

- **A.** 大模型训练中途 loss 突然飙升、权重出现 NaN 的数值不稳定现象，规模越大越容易发生
- **B.** 模型对不同输入输出几乎相同的表示或 token，即表示坍塌，主要由学习率过高引起
- **C.** 一代代用模型生成的数据训练下一代，分布尾部（罕见事件、少见表达）逐渐消失、偏离真实分布
- **D.** 合成数据占训练数据的比例超过 50% 后，模型训练会无法收敛，这个阈值与合成方式、质量关系不大

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：模型坍塌是「递归地用生成数据训练」带来的分布退化。

每一代模型只能从上一代模型的输出中学习：有限的采样很难覆盖低概率事件，模型本身的近似误差也会叠加，于是分布的尾部一代代被削掉，方差变小、内容趋同；继续迭代，模型会收敛到一个与原始分布相去甚远的窄分布。论文在语言模型、变分自编码器、高斯混合模型上都观察到了这一现象。

- A 错：那是训练不稳定（发散），属于数值问题。
- B 错：描述的是另一种退化，与递归训练无关。
- D 错：没有这样固定的比例阈值。风险取决于合成数据是否替代了真实数据、是否经过验证、多样性如何。

应对：保留并持续混入真实数据；能验证的合成数据必须验证；提高生成多样性；记录数据来源，避免不知不觉地用模型数据训练模型。

<sub>考点：合成数据　｜　出处：AI models collapse when trained on recursively generated data（Shumailov 等, 2024, Nature）</sub>

</details>

<a name="TRN-DATA-032"></a>

### TRN-DATA-032　进阶 · 考频 ★★

用 n-gram 重叠检测训练数据与评测集之间的污染（如 GPT-3 使用 13-gram）。关于 $n$ 的选择，下列说法正确的是：

- **A.** $n$ 太小会把常见短语也判为重叠而误删正常数据，太大又会漏掉只改了几个词的近似泄漏
- **B.** $n$ 越小越稳妥：哪怕只有一两个词重叠也可能是泄漏，宁可多删训练数据也不能漏检
- **C.** $n$ 越大越好：长 n-gram 不仅能抓住原样泄漏，也能抓住换了说法、改了数字的改写泄漏
- **D.** $n$ 的取值只影响哈希表的大小和计算速度，对误报率和漏报率的影响可以忽略

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：$n$ 在误报与漏报之间权衡。

$n$ 很小时（如 3-gram），「in order to」「the number of」这类常见搭配在评测集和训练集中都大量出现，几乎所有文档都会被判为污染；$n$ 很大时，只要评测题被改了几个词、换了数字格式，长 n-gram 就对不上了。13-gram 是 GPT-3 选择的折中值。实践中还会配合：文本规范化（小写、去标点和多余空白）；按样本统计「重叠 n-gram 占比」并设阈值；对选择题这类短文本单独处理。

- B 错：单个词重叠毫无意义，会把整个训练集都判为污染。
- C 错：改写后的泄漏无论 $n$ 取多大都难以用 n-gram 抓到，需要 Embedding 相似度或大模型判别。
- D 错：$n$ 直接决定误报和漏报的多少。

<sub>考点：数据污染</sub>

</details>

### TRN-DATA-036　基础 · 考频 ★★

即使目标是通用对话模型而不是代码模型，主流预训练配比中通常也包含相当比例的代码数据（如 Llama 3 约 17%）。最主要的原因是：

- **A.** 代码文件普遍较长，能提高平均序列长度、减少 padding 浪费，从而提高预训练的吞吐
- **B.** 代码数据重复少、噪声低，几乎不必去重和过滤，单位 token 的处理成本远低于网页
- **C.** 让模型在对话中更倾向于用代码和伪代码来组织回答，使输出更精确、更容易被程序解析
- **D.** 加入代码不只提升编程能力，还有助于推理、结构化输出和遵循格式等非代码能力

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：代码是一种「高密度的逻辑训练材料」，收益会迁移到非代码任务。

- A 错：预训练通常把文档拼接成定长序列，本来就几乎没有 padding。
- B 错：代码需要大量处理：fork 与复制带来的大规模重复、自动生成文件、许可证、密钥等敏感信息都要处理。
- C 错：混入代码不是为了改变回答方式，回答风格主要由后训练决定。

<sub>考点：代码与数学数据　｜　出处：The Llama 3 Herd of Models arXiv:2407.21783（代码约 17%）；To Code, or Not To Code?（Aryabumi 等, 2024）arXiv:2408.10914；Scaling Data-Constrained Language Models（Muennighoff 等, 2023）arXiv:2305.16264</sub>

</details>

### TRN-DATA-016　挑战 · 考频 ★★

关于预训练数据的质量过滤，下列说法**正确**的有：

- **A.** CCNet 用在维基百科上训练的 n-gram 语言模型计算网页的困惑度，按困惑度分档过滤
- **B.** GPT-3 的质量分类器按固定阈值一刀切：低于阈值的文档丢弃、高于阈值的保留，阈值由验证集确定
- **C.** 阈值越严越好：DCLM 的消融表明只保留得分最高的 1% 效果最佳，数据量的损失可以靠多轮重复弥补
- **D.** DCLM 以指令数据和 ELI5 高分帖子为正例训练 fastText 分类器，效果优于困惑度过滤等方法
- **E.** 质量分类器主要去掉乱码、广告等明显垃圾，对保留数据的主题、文体与地域分布影响很小

<details>
<summary>答案与解析</summary>

**答案：AD**

**解析：**

**结论**：A、D 正确。

- A 对：CCNet（Wenzek 等, 2020）用维基百科上训练的 KenLM 模型给网页打困惑度，困惑度越低越像维基百科，并据此分成 head / middle / tail 三档。
- B 错：GPT-3 并没有按阈值一刀切。它用逻辑回归分类器打分后，按「`np.random.pareto(9) > 1 - score`」随机保留：高分文档几乎都保留，低分文档也有小概率留下，以保留一些分布外的内容、避免数据过于单一。
- C 错：过严会让数据量骤减、多样性下降；训练 token 数固定时，保留的数据要重复更多遍，而重复过多时收益会迅速递减。阈值要通过消融确定，DCLM 最终保留的是得分前 10% 左右。
- D 对：DCLM 的实验发现，用「像高质量指令回答」的文本作为正例训练的 fastText 分类器，比困惑度过滤、其他分类器方案效果更好。
- E 错：分类器带有「品味」，会系统性地改变数据的文体、主题和人群分布，例如偏向正式书面语、冷落口语和方言。

<sub>考点：质量过滤　｜　出处：GPT-3 论文附录 A arXiv:2005.14165；CCNet（Wenzek 等）arXiv:1911.00359；DataComp-LM（Li 等, 2024）arXiv:2406.11794</sub>

### TRN-DATA-026　进阶 · 考频 ★★

关于如何确定预训练的数据配比，下列说法**正确**的有：

- **A.** 提高代码比例往往有利于推理与结构化输出，但可能削弱纯文本写作，需要分领域评测
- **B.** 固定总 token 数，用几种配比各训一个小模型，比较验证 loss 与下游指标，再按趋势外推
- **C.** 各数据源按去重后 token 数的自然比例混合即可，每条数据恰好训一遍，不会因重复而过拟合
- **D.** 配比可以分阶段调整，例如在训练末期的退火阶段提高数学、代码等高质量数据的比例
- **E.** DoReMi 先用小代理模型通过分布鲁棒优化学出各领域的权重，再用这组权重训练大模型

<details>
<summary>答案与解析</summary>

**答案：ABDE**

**解析：**

**结论**：A、B、D、E 正确，只有 C 错。

- A 对：配比是多目标权衡，不同能力的指标可能此消彼长，评测要覆盖目标能力的各个维度。
- B 对：小模型消融加趋势外推是最常用的方法，Llama 3 也用小模型实验来确定配比；还有工作用大量小模型的结果拟合「配比 → 效果」的回归模型（如 RegMix）。
- C 错：自然比例会让海量网页淹没少量高质量数据；适度重复高质量数据（如 4 遍以内）损失很小，GPT-3 就按质量上采样。
- D 对：配比并非一成不变。Llama 3 在最后的退火阶段上采样极高质量的数据源，MiniCPM、OLMo 2 等也在学习率衰减阶段（中期训练）换用以高质量数据为主的配比；阶段切换时总 loss 出现跳变是数据分布变化所致，不会因此发散。
- E 对：DoReMi（Xie 等, 2023）用分布鲁棒优化在小代理模型上自动学出领域权重，再用于训练大模型。

<a name="TRN-DATA-039"></a>

### TRN-DATA-039　进阶 · 考频 ★★

关于多语言预训练数据，下列说法**正确**的有：

- **A.** 温度采样（$\alpha<1$）会提高低资源语言的采样比例，但可能导致它们被重复很多遍
- **B.** 把英文高质量数据机器翻译成其他语言，可以完全替代该语言的原生数据，而且不会引入任何偏差
- **C.** 在模型容量固定时，加入的语言越多，起初能提升低资源语言的表现，但超过一定数量后，各语言的平均表现会下降（「多语言的诅咒」）
- **D.** 对 mC4、OSCAR 等公开多语言网页语料的人工审计发现，不少低资源语言子集质量很差，语种标注错误也很多
- **E.** 分词器对某种语言的压缩率低（同样的内容切出更多 token），会让这种语言的训练和推理成本更高、有效上下文更短

<details>
<summary>答案与解析</summary>

**答案：ACDE**

**解析：**

**结论**：A、C、D、E 正确，只有 B 错。

- A 对：温度采样是公平性与过拟合之间的权衡，要同时监控每种语言的重复遍数。
- B 错：机器翻译数据带有「翻译腔」，缺少该语言特有的文化背景与表达，还可能引入翻译错误，只能作为补充。
- C 对：XLM-R（Conneau 等, 2020）把这一现象称为「多语言的诅咒」：容量固定时，语言之间争夺参数，增加模型容量可以缓解。
- D 对：Kreutzer 等（2022）人工审计了 CCAligned、ParaCrawl、WikiMatrix、OSCAR、mC4 五个语料中的 205 个语言子集，发现至少 15 个子集几乎没有可用文本，相当一部分低资源语言子集中合格句子不到一半，语种标错或使用不规范语言代码的情况也很普遍。根源在于语种识别在低资源语言上错误率高，对相近语言、混合语言、短文本尤其不可靠，因此低资源语言的数据需要额外抽检。
- E 对：同样的内容需要更多 token，意味着训练算力、推理成本更高，相同长度的上下文窗口能容纳的内容更少；这是多语言模型设计词表时要考虑的因素。

<sub>考点：多语言数据　｜　出处：XLM-R：Unsupervised Cross-lingual Representation Learning at Scale（Conneau 等, 2020）arXiv:1911.02116；Quality at a Glance: An Audit of Web-Crawled Multilingual Datasets（Kreutzer 等, 2022）arXiv:2103.12028</sub>

### TRN-DATA-042　进阶 · 考频 ★★

为数学推理的 RLVR（基于可验证奖励的强化学习）准备训练题目时，下列做法**合理**的有：

- **A.** 多选题和判断题的答案最容易验证、奖励最干净，应当尽量多保留，甚至可以专门扩充这类题目

- **C.** 把答案形式复杂、难以用规则可靠比对的题目，改写成答案为整数等便于验证的形式，以减少验证器的误判
- **D.** 训练前用当前模型对每道题采样多次，暂时去掉全部答对或全部答错的题，让训练集集中在模型「有时对、有时错」的难度区间
- **E.** 证明题直接把「回答中是否出现了正确的最终结论」作为奖励即可，不需要做任何特殊处理

<summary>答案与解析</summary>

**答案：BCD**

**解析：**

**结论**：B、C、D 正确。RLVR 的数据要同时满足「可验证」「有学习信号」「不污染评测」。

- A 错：选择题、判断题可以靠猜：四选一随机作答也有 25% 的概率拿到奖励，推理过程错误、碰巧蒙对的回答同样会被强化。常见做法是把它们改写成开放作答（Big-Math 由多选题改写出约 4.7 万道开放题），或者直接过滤。

- C 对：DAPO 把 DAPO-Math-17K 中各种形式的答案改写为整数。例如答案形如 $\frac{a+\sqrt{b}}{c}$ 时，把问题改成求 $a+b+c$，从而减少公式解析器带来的误判。

- E 错：证明的正确性在于推理过程，只检查结论等于奖励「抄出结论」的回答。证明题通常被排除在规则奖励之外，或改用专门的证明验证器、评审模型。

## 判断题

<a name="TRN-DATA-007"></a>

### TRN-DATA-007　进阶 · 考频 ★

用 Bloom 过滤器对海量文档做精确去重时，可能把一篇从未出现过的文档误判为「已出现」而删掉，但绝不会把真正重复的文档误判为「未出现」而漏掉。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。Bloom 过滤器用一个位数组和 $k$ 个哈希函数：插入时把 $k$ 个位置置 1；查询时只有 $k$ 个位置全为 1 才判为「可能存在」。这些位可能是被其他元素置上的，所以存在**假阳性**；而已经插入过的元素，它的 $k$ 个位一定都是 1，不会出现假阴性。

用于去重时，假阳性意味着少量独特文档被误删（数据损失），误判率约为 $(1-e^{-kn/m})^k$（$n$ 为元素数，$m$ 为位数），可以通过加大位数组控制在很低的水平。它的好处是内存远小于保存全部哈希值，适合在单机或流式处理中做 URL、段落级别的精确去重，Dolma 等开源数据工具就采用了这种做法。

<sub>考点：精确去重</sub>

</details>

### TRN-DATA-022　基础 · 考频 ★★

Longpre 等（2023）的实验发现，对预训练数据做毒性过滤，既能减少模型生成有害文本，也能提升模型识别有毒内容的能力。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。该研究发现的是一种取舍：毒性过滤减少了有害生成，但同时削弱了模型**识别**有毒内容的能力（在 C4 与 the Pile 上都观察到）；模型没见过某类内容，就很难判断它、拒绝它。过滤还有别的代价：基于词表的过滤会误伤方言、少数群体相关的正常文本（Dodge 等, 2021 对 C4 的分析），引入偏见。所以有害内容并不是过滤得越干净越好。

<a name="TRN-DATA-030"></a>

### TRN-DATA-030　进阶 · 考频 ★

有研究发现：如果每一代训练都在保留全部真实数据的基础上**累加**新生成的合成数据，而不是用合成数据**替换**真实数据，模型坍塌在很大程度上可以避免，测试误差会保持有界。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。Is Model Collapse Inevitable?（Gerstgrasser 等, 2024）对比了两种设定：每一代都用新生成的数据**替换**旧数据时，误差随代数持续增长，出现坍塌；每一代都把新数据**累加**到包含原始真实数据的数据集中时，误差存在与代数无关的上界。论文在线性模型上给出了理论分析，并在语言模型、扩散模型等上做了实验验证。

这对实践的启示是：真实数据要作为「锚点」一直保留，不能让合成数据逐步取代它；同时要记录每条数据的来源，控制合成数据的比例。注意这只说明坍塌可以避免，合成数据本身的错误、风格趋同、评测污染等问题仍需单独处理。

<sub>考点：合成数据　｜　出处：Is Model Collapse Inevitable?（Gerstgrasser 等, 2024）arXiv:2404.01413</sub>

</details>

### TRN-DATA-034　进阶 · 考频 ★★

对训练数据和评测集做 13-gram 重叠去污染，能检出评测题被换说法、换数字格式或翻译成其他语言后的改写版本；因此去污染之后，评测分数不会因为这类泄漏而虚高。

**解析：**

**错误**。n-gram 重叠只能抓住「字面相同」的泄漏：题目被改写、换数字格式或翻译之后，与原题往往找不到连续 13 个相同的 token。Yang 等（2023）的实验表明，把 MMLU、GSM8K、HumanEval 的测试题改写或翻译后加入训练数据，就能绕过 n-gram 去污染，一个 13B 模型在这些基准上的分数被抬高到与 GPT-4 相当的水平。

- 用 Embedding 相似度召回疑似样本，再用大模型判断是否为同一道题；
- 特别检查合成数据与 SFT 数据：生成它们的教师模型可能见过评测题；
- 使用训练截止日期之后发布的新题目或私有评测集作为对照；
- 对比模型在原题与重新出题版本上的表现差异。

### TRN-DATA-040　进阶 · 考频 ★

某低资源语言只有约 1B token 的可用数据。在一次 2T token 的预训练中，把它的采样比例提高到 2%（约重复 40 遍），只会带来好处：该语言的能力会显著提升，而且没有任何副作用。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。$2\%\times2\text{T}=40\text{B}$ token，相当于把 1B 数据重复 40 遍：
- 重复超过约 4 遍后收益迅速递减，继续重复几乎是在浪费算力（Muennighoff 等, 2023）；
- 大量重复会导致记忆与过拟合，模型可能原样背诵这部分文本，泛化反而变差；
- 这 2% 的份额挤占了其他数据，可能损害整体能力。

更合理的做法：用温度采样适度上采样，同时设定最大重复遍数；尽量扩充原始数据（更多网页快照、OCR 书籍、政府与新闻文本）；借助相近语言的跨语言迁移；谨慎地用翻译或合成数据补充；检查分词器对该语言的压缩率。

<sub>考点：多语言数据</sub>

</details>

### TRN-DATA-010　进阶 · 考频 ★★

两篇文档切成字符 5-gram 后，集合大小分别为 80 和 100，交集大小为 60。它们的 Jaccard 相似度为 ____；若用 $k=200$ 个哈希函数的 MinHash 签名来估计，估计值的标准差约为 ____（保留两位有效数字）。

<details>
<summary>答案与解析</summary>

**答案：** (1) 0.5；(2) 0.035 / 0.0354

**解析：**

- 并集大小 $=80+100-60=120$，$J=60/120=$ **0.5**。
- 签名每一位相等是概率为 $J$ 的伯努利事件，$k$ 位取平均，标准差 $=\sqrt{J(1-J)/k}=\sqrt{0.25/200}\approx$ **0.035**。

标准差与 $\sqrt{k}$ 成反比：想把误差减半，哈希函数要增加到 4 倍。$k=200$ 时，真实相似度为 0.5 的文档对，估计值大致落在 $0.5\pm0.07$ 之内，远低于常用的 0.7～0.8 去重阈值，不会被误判；阈值附近的文档对才需要更大的 $k$ 或用真实 Jaccard 复核。

<sub>考点：MinHash近似去重</sub>

</details>

<a name="TRN-DATA-025"></a>

### TRN-DATA-025　基础 · 考频 ★★

多语言预训练常用温度采样：语言 $i$ 的采样概率 $p_i\propto n_i^{\alpha}$（$n_i$ 为该语言的数据量）。$\alpha=$ ____ 时，等价于按数据量的原始比例采样；$\alpha$ 趋于 0 时，各语言的采样概率趋于 ____。

<details>
<summary>答案与解析</summary>

**答案：** (1) 1；(2) 均匀分布 / 均匀 / 相等 / 相同

**解析：**

- $\alpha=1$ 时 $p_i\propto n_i$，就是原始比例，英文等高资源语言会淹没低资源语言；
- $\alpha\to0$ 时 $n_i^{\alpha}\to1$，所有语言等概率采样，低资源语言会被重复非常多遍。

$0<\alpha<1$ 是两者之间的折中：压缩高资源语言的比例、放大低资源语言的比例。mT5、XLM-R 等多语言模型都取 $\alpha=0.3$。取值时要同时算一下低资源语言的重复遍数，避免为了「公平」把少量数据重复几十遍。

<sub>考点：多语言数据、数据配比</sub>

</details>

## 计算题

<a name="TRN-DATA-011"></a>

### TRN-DATA-011　挑战 · 考频 ★★★

FineWeb 的 MinHash 去重使用 5-gram、共 112 个哈希函数，分成 $b=14$ 个 band、每个 band $r=8$ 行；只要有一个 band 的签名完全相同，两篇文档就成为候选对。
(1) 写出 Jaccard 相似度为 $s$ 的两篇文档成为候选对的概率，并估算 S 曲线的陡峭点 $(1/b)^{1/r}$；
(2) 分别计算 $s=0.5$、$0.75$、$0.9$ 时成为候选对的概率；
(3) 若希望相似度 0.75 的文档对被召回的概率更高，可以怎样调整 $b$、$r$？代价是什么？

<details>
<summary>答案与解析</summary>

**答案：(1) P(s)=1-(1-s^8)^14，陡峭点约 0.72；(2) 约 5.3%、77%、99.96%；(3) 增加 band 数或减少每个 band 的行数，召回提高，但候选对增多、误报与复核成本上升**

**解析：**

**(1)** 某个 band 的 8 行全部相同的概率为 $s^8$；14 个 band 都不相同的概率为 $(1-s^8)^{14}$，所以
$P(s)=1-(1-s^8)^{14}$。陡峭点 $(1/14)^{1/8}\approx0.72$。

**(2)**
- $s=0.5$：$0.5^8\approx0.0039$，$P=1-0.9961^{14}\approx$ **5.3%**；
- $s=0.75$：$0.75^8\approx0.100$，$P=1-0.900^{14}\approx$ **77%**；
- $s=0.9$：$0.9^8\approx0.430$，$P=1-0.570^{14}\approx$ **99.96%**。

**(3)** 哈希总数不变时改成 $b=16$、$r=7$：陡峭点降到约 0.67，$P(0.75)\approx90\%$，但 $P(0.5)$ 也从 5.3% 升到约 12%；或者增加哈希函数，如 $b=20$、$r=8$（共 160 个），$P(0.75)\approx88\%$，$P(0.5)\approx7.5\%$。代价分别是候选对（含误报）增多、复核计算量和分桶 shuffle 的数据量增加，以及签名计算成本增加。

**调参原则**：band 多、行少 → 召回高、误报多；band 少、行多 → 更严格、可能漏掉近重复。一般让陡峭点略低于目标阈值，先保召回，再用签名估计或真实 Jaccard 复核候选对，过滤误报。

<sub>考点：MinHash近似去重　｜　出处：FineWeb 技术报告（Penedo 等, 2024）arXiv:2406.17557</sub>

</details>

```text
1.0 [0.9, 0.09, 0.01]

0.3 [0.568, 0.285, 0.147]
```

**解析：**

- $\alpha=1$：就是原始比例 90%、9%、1%。
- $\alpha=0.5$：权重为 $\sqrt{900}=30$、$\sqrt{90}\approx9.49$、$\sqrt{10}\approx3.16$，归一化得 0.703、0.222、0.074。
- $\alpha=0.3$：分布更平，斯瓦希里语的比例从 1% 提高到约 14.7%。

要同时算一算重复遍数：若总共训练 1T token，$\alpha=0.3$ 时斯瓦希里语采样约 147B token，相当于把 10B 数据重复约 14.7 遍，远超「4 遍以内」的经验值，容易过拟合；英文只用到 568B，约 0.63 遍。实践中常在温度采样之外再给每种语言设置最大重复遍数，并尽量扩充低资源语言的原始数据。

<sub>考点：多语言数据、数据配比</sub>

### TRN-DATA-021　进阶 · 考频 ★★

下面的函数用于把中文文本中的手机号和 18 位身份证号替换成占位符。测试发现它会把身份证号的一部分错误地识别为手机号，还会误伤较长的订单号。请指出问题并修正。

```python
import re

PHONE = re.compile(r"1[3-9]\d{9}")          # 11 位手机号
ID_CARD = re.compile(r"\d{17}[\dXx]")       # 18 位身份证号

def mask_pii(text):
    text = PHONE.sub("<PHONE>", text)
    text = ID_CARD.sub("<ID>", text)
    return text
```

<details>
<summary>答案与解析</summary>

**答案：**

**问题 1：替换顺序**。先替换手机号，而身份证号中间很容易出现「1 + [3-9] + 9 位数字」的片段。例如 `110105199003071234` 中的 `19900307123` 会先被替换成 `<PHONE>`，剩下的部分再也匹配不上身份证规则，结果变成 `110105<PHONE>4`。

**问题 2：没有数字边界**。两个正则都能匹配更长数字串的一部分：21 位的订单号前 18 位会被当成身份证号。

**修正**：给两个模式加上前后不是数字的断言 `(?<!\d)`、`(?!\d)`，并先替换更长、更具体的身份证模式：

```python
PHONE = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")
ID_CARD = re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)")
text = ID_CARD.sub("<ID>", text)
text = PHONE.sub("<PHONE>", text)
```

**修正后的代码：**

```python
import re

PHONE = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")
ID_CARD = re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)")

def mask_pii(text):
    text = ID_CARD.sub("<ID>", text)       # 先处理更长的模式
    text = PHONE.sub("<PHONE>", text)
    return text
```

**解析：**

多个 PII 规则串联时，先执行的规则会改写文本，影响后面的规则，所以要先处理更长、更具体的模式；同时用边界断言保证只匹配「完整的」号码，避免误伤订单号、时间戳等长数字串。

实际系统还要考虑：身份证号可以用校验位（GB 11643 的加权求和模 11）进一步降低误报；手机号可能带 `+86`、空格或短横线，需要扩展规则提高召回；最终在标注样本上同时评估精确率与召回率。过度替换会损伤数学、代码等含大量数字的数据，漏检则带来隐私风险，两者要权衡。

<sub>考点：毒性与PII过滤</sub>

### TRN-DATA-005　进阶 · 考频 ★★

网页正文里常混有在大量页面中重复出现的模板行（如「版权所有 © 2024」「点击关注我们」）。实现：

```python
def remove_boilerplate_lines(docs: list[str], min_docs: int) -> list[str]: ...
```

- 每篇文档按 `\n` 分行，每行先做 `strip()`，空行直接丢弃；
- 若某行（strip 之后）出现在至少 `min_docs` 篇**不同**的文档中，就从所有文档中删除这一行；同一篇文档里重复出现只按 1 篇计；
- 返回新的文档列表，每篇保留的行（strip 之后的内容）按原顺序用 `\n` 连接；没有保留任何行时返回空字符串。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
from collections import Counter

def remove_boilerplate_lines(docs, min_docs):
    split = [[l.strip() for l in d.split("\n") if l.strip()] for d in docs]
    df = Counter()                      # 文档频率：每行出现在多少篇文档中
    for lines in split:
        df.update(set(lines))           # 同一篇内重复只计一次
    return ["\n".join(l for l in lines if df[l] < min_docs) for lines in split]
```

**测试用例：**

```python
docs = [
    "点击关注我们\n大模型的预训练数据需要清洗\n版权所有 © 2024",
    "  点击关注我们  \n去重可以节省算力\n去重可以节省算力",
    "MinHash 用来做近似去重\n\n版权所有 © 2024",
    "",
]
out = remove_boilerplate_lines(docs, min_docs=2)
assert out[0] == "大模型的预训练数据需要清洗"
assert out[1] == "去重可以节省算力\n去重可以节省算力"   # 只在一篇中重复，不删
assert out[2] == "MinHash 用来做近似去重"
assert out[3] == ""
assert remove_boilerplate_lines(docs, min_docs=3)[0] == "点击关注我们\n大模型的预训练数据需要清洗\n版权所有 © 2024"
assert remove_boilerplate_lines([], 2) == []
```

**解析：**

**思路**：两遍扫描。第一遍统计每行的「文档频率」（出现在多少篇不同的文档中，用 `set` 保证同一篇只计一次）；第二遍删除文档频率达到阈值的行。时间复杂度与总行数成线性关系。

**易错点**：
- 按出现次数而不是文档数计数，会误删某一篇内部的正常重复（如诗歌的叠句、代码里重复的语句）；
- 比较前没有 `strip()`，首尾空白不同的同一行会被当成不同的行。

**工程化**：上亿篇文档时，把每行映射成 64 位哈希再计数，按哈希分片做分布式统计；阈值要结合抽样检查来定，太低会误删「目录」「参考文献」这类正常的常见行。这属于行级（或段落级）的精确去重，与文档级去重互补。

<sub>考点：文本清洗、精确去重</sub>

</details>

<a name="TRN-DATA-013"></a>

### TRN-DATA-013　挑战 · 考频 ★★

实现 MinHash 签名与 LSH 分桶：

```python
def minhash_signature(shingles: set[str], a: list[int], b: list[int], p: int) -> list[int]: ...
def lsh_candidates(signatures: list[list[int]], bands: int) -> set[tuple[int, int]]: ...
```

- `minhash_signature`：`shingles` 为非空字符串集合。先用 `zlib.crc32(s.encode())` 把每个元素映射成整数 $x$；第 $i$ 个哈希函数为 $h_i(x)=(a_ix+b_i)\bmod p$，签名的第 $i$ 位是集合内所有元素 $h_i$ 的最小值。返回长度为 `len(a)` 的整数列表。
- `lsh_candidates`：`signatures` 是若干等长签名，长度能被 `bands` 整除。把每个签名切成 `bands` 段，**同一段位置上**内容完全相同的文档互为候选对。返回所有候选对 `(i, j)`（$i<j$）组成的集合；输入为空时返回空集合。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
import zlib
from collections import defaultdict
from itertools import combinations

def minhash_signature(shingles, a, b, p):
    xs = [zlib.crc32(s.encode()) for s in shingles]
    return [min((ai * x + bi) % p for x in xs) for ai, bi in zip(a, b)]

def lsh_candidates(signatures, bands):
    if not signatures:
        return set()
    r = len(signatures[0]) // bands
    buckets = defaultdict(list)                 # (段号, 段内容) -> 文档号列表
    for doc_id, sig in enumerate(signatures):
        for k in range(bands):
            buckets[(k, tuple(sig[k * r:(k + 1) * r]))].append(doc_id)
    pairs = set()
    for ids in buckets.values():
        pairs.update(combinations(ids, 2))      # ids 按文档号递增，保证 i < j
    return pairs
```

**测试用例：**

```python
import random
rng = random.Random(0)
P = (1 << 61) - 1
K = 128
a = [rng.randrange(1, P) for _ in range(K)]
b = [rng.randrange(0, P) for _ in range(K)]

def grams(t, n=5):
    return {t[i:i + n] for i in range(len(t) - n + 1)}

letters = "abcdefghijklmnopqrstuvwxyz "
base = "".join(rng.choice(letters) for _ in range(600))
chars = list(base)
for i in (100, 250, 400):                       # 改 3 个字符并加一段尾巴：近重复
    chars[i] = "#"
near = "".join(chars) + " -- reposted"
other = "".join(rng.choice(letters) for _ in range(600))
docs = [base, near, other, base]
sh = [grams(d) for d in docs]
sigs = [minhash_signature(s, a, b, P) for s in sh]

assert len(sigs[0]) == K and sigs[0] == sigs[3]          # 相同集合，签名相同
true_j = len(sh[0] & sh[1]) / len(sh[0] | sh[1])
est_j = sum(x == y for x, y in zip(sigs[0], sigs[1])) / K
assert abs(est_j - true_j) < 0.1                         # 签名可估计 Jaccard
cands = lsh_candidates(sigs, bands=32)                    # 每段 4 行
assert {(0, 1), (0, 3), (1, 3)} <= cands
assert (0, 2) not in cands and (1, 2) not in cands
assert all(i < j for i, j in cands)
assert lsh_candidates([], 4) == set()
```

**解析：**

**思路**：
1. 签名：每个哈希函数对集合中所有元素取最小值，$k$ 个哈希函数得到长度为 $k$ 的签名；两个签名逐位相等的比例估计 Jaccard。
2. 分桶：签名切成 $b$ 段、每段 $r=k/b$ 行，以「(段号, 段内容)」为键分桶。段号必须放进键里，否则不同位置上碰巧相同的片段也会被当成候选。
3. 同一个桶里的文档两两成为候选对；用集合去重，因为一对文档可能在多个段上都相同。

**复杂度**：签名 $O(n\cdot|S|\cdot k)$；分桶 $O(nb)$；只对候选对复核，避免 $O(n^2)$ 的两两比较。

**易错点**：键里漏掉段号；用 Python 内置 `hash()` 处理字符串（每次启动进程的随机种子不同，结果不可复现，分布式时各机器也不一致）；系数 $a$ 取 0 会让该哈希函数退化为常数。上亿文档的实现中，以段签名为键做 shuffle，同键文档在同一个 reducer 中产生候选对，最后用分布式连通分量聚类。

<sub>考点：MinHash近似去重</sub>

</details>

### TRN-DATA-033　进阶 · 考频 ★★

实现一个简单的 n-gram 污染检测工具：

```python
def build_ngram_index(train_docs: list[str], n: int) -> set[tuple[str, ...]]: ...
def contamination_ratio(example: str, index: set, n: int) -> float: ...
```

- 文本先转小写，再按空白切分成词（`text.lower().split()`）；
- `build_ngram_index` 返回训练文档中出现过的所有词级 n-gram（用 tuple 表示）组成的集合；
- `contamination_ratio` 返回评测样本的 n-gram 中「在索引里出现过」的比例；样本不足 $n$ 个词时返回 `0.0`。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
def _ngrams(text, n):
    words = text.lower().split()
    return [tuple(words[i:i + n]) for i in range(len(words) - n + 1)]

def build_ngram_index(train_docs, n):
    index = set()
    for doc in train_docs:
        index.update(_ngrams(doc, n))
    return index

def contamination_ratio(example, index, n):
    grams = _ngrams(example, n)
    if not grams:                       # 不足 n 个词
        return 0.0
    return sum(g in index for g in grams) / len(grams)
```

**测试用例：**

```python
train = ["The quick brown fox jumps over the lazy dog near the river bank",
         "Large language models are trained on web data"]
idx = build_ngram_index(train, 3)
assert ("quick", "brown", "fox") in idx and ("on", "web", "data") in idx
assert contamination_ratio("the QUICK brown fox jumps", idx, 3) == 1.0
assert abs(contamination_ratio("a quick brown fox sleeps", idx, 3) - 1 / 3) < 1e-12
assert contamination_ratio("completely unrelated sentence here", idx, 3) == 0.0
assert contamination_ratio("too short", idx, 3) == 0.0
assert build_ngram_index([], 3) == set()
```

**解析：**

**思路**：把文本规范化后切成词级 n-gram，训练侧建集合索引，评测样本逐个 n-gram 查询，统计命中比例。比例超过阈值（如 0.5）就把样本标记为污染；也可以反过来，删除与评测集重叠的训练文档。

**边界**：样本不足 $n$ 个词时没有任何 n-gram，直接返回 0，避免除零。

**工程化**：真实场景中训练数据有万亿 token，应把索引建在**规模小的一侧**（全部评测集），再流式扫描训练数据；n-gram 用 64 位哈希代替字符串元组以节省内存，必要时用 Bloom 过滤器。规范化还应去掉标点、统一空白与全半角，中文可按字符级 n-gram 处理。注意这种方法抓不到改写和翻译后的泄漏。

<sub>考点：数据污染</sub>

</details>

## 简答题

<a name="TRN-DATA-008"></a>

### TRN-DATA-008　进阶 · 考频 ★★★

预训练数据为什么要去重？通常按哪些粒度、用哪些方法来做？去重是不是越彻底越好？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **为什么去重**：
   - 节省算力：重复内容浪费训练 token；
   - 减少死记硬背：重复越多越容易原样输出训练文本，带来隐私与版权风险。Lee 等（2022）在 C4 中发现一句 61 个词的句子重复了 6 万多次，去重后模型原样输出训练文本的频率降到约十分之一；
   - 避免少数内容被过度加权、扭曲数据分布；减少训练集与评测集的重叠。
2. **粒度与方法**：
   - URL 去重、全文精确哈希：$O(n)$，第一道关；
   - 行 / 段落级精确去重：删掉模板行、导航栏、版权声明；
   - 子串去重：用后缀数组找出跨文档重复的长片段（如 50 个 token 以上）；
   - 近似去重：MinHash-LSH（n-gram 集合的 Jaccard 相似度）或 SimHash（签名的汉明距离），抓「改了几个字」的近重复；
   - 语义去重：Embedding 聚类（如 SemDeDup），抓改写类重复，成本最高，多用于精选子集或 SFT 数据。
3. **不是越彻底越好**：
   - FineWeb 发现跨所有快照的全局去重，效果反而不如每个快照内部去重：全局去重后幸存的旧数据中低质量内容的比例更高；
   - 阈值过低会把只是主题相近的文档误判为重复；
   - 高质量数据本来就会被有意重复多遍，去重的目标是去掉「无意义的重复」，而不是让数据集最小。
4. **工程实践**：签名并行计算，按 band 分桶后分布式找候选，用连通分量聚类，每簇保留质量最高的一篇；每种去重策略都用小模型消融验证。

**评分要点（共 10 分）：**

- 说明去重的收益：省算力、减少记忆与隐私风险、减少评测重叠（3 分）
- 列出精确、子串、近似、语义等不同粒度的方法（3 分）
- 指出去重不是越彻底越好并给出依据（如 FineWeb 的全局去重实验）（3 分）
- 提到分布式实现或用消融验证（1 分）

**讲解：**

**常见失分点**：只会说「算哈希去重」，说不出近重复和子串重复；认为去重越狠越好；不知道去污染本质上也是一种「训练集与评测集之间的去重」；没有任何数字或案例支撑。

<sub>考点：精确去重、MinHash近似去重</sub>

</details>

### TRN-DATA-018　进阶 · 考频 ★★

如果让你为预训练数据训练一个质量分类器，你会如何选择正负样本、选择模型、确定过滤阈值？又如何验证这个分类器真的有用？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **正负样本**：
   - 正例：维基百科、教材、被高质量网站引用的网页、精选问答（DCLM 用 OpenHermes 2.5 指令数据和 ELI5 高分帖子），或让大模型按明确的评分标准标注（FineWeb-Edu 用 Llama-3-70B 给「教育价值」打 0～5 分）；
   - 负例：随机抽取的网页；
   - 注意正例来源带来的偏差，按语言、领域分别构建。
2. **模型**：要能在数十亿篇文档上跑得动，常用 fastText（n-gram 特征，CPU 上就很快），或「小型 Embedding 模型 + 线性头」；大模型只用于标注少量样本。

   - 抽查被保留和被丢弃的样本，检查语言、领域、地域分布的变化；
   - 警惕分类器偏好与评测集「长得像」的文本，造成类似污染的虚高。
5. **迭代**：针对不同目标（教育价值、代码质量、数学）用多个分类器组合，定期复核。

**评分要点（共 10 分）：**

- 说明正负样本的来源与偏差（3 分）
- 说明模型选择需兼顾成本，如 fastText 或 Embedding 加线性头（2 分）
- 说明阈值策略：分档、随机保留、与训练 token 数联动（2 分）
- 给出以小模型消融为核心的验证方法（3 分）

**讲解：**

**常见失分点**：只看分类器准确率、不做下游消融；阈值一刀切；忽略品味偏见与多样性；建议直接用大模型给全量数据打分而不估算成本。

### TRN-DATA-028　进阶 · 考频 ★★

什么是预训练中的课程学习（curriculum learning）？请列举大模型预训练中实际使用的「课程」做法，说明为什么「把全部数据按难度由易到难排序」的做法并不常见，以及课程设计的主要风险。

**参考答案：**

1. **定义**：不再从固定分布中均匀随机采样，而是按某种顺序或阶段安排数据（难度、质量、领域、长度），希望收敛更快或最终效果更好。
2. **实际做法**：
   - **阶段式配比**：主体阶段以通用网页为主，后期（中期训练、退火）提高数学、代码、推理与高质量数据的比例，如 Llama 3、Qwen3、OLMo 2；
   - **长度课程**：主体阶段用较短的序列，最后再扩展上下文；也有工作（Li 等, 2022）在训练初期逐步增加序列长度来提高稳定性；
   - **batch 课程**：GPT-3 的 batch 从小逐步增大；
   - **领域 / 语言的阶段性调整**：如后期加大低资源语言或特定领域的比重（需谨慎控制重复）。
3. **为什么「全局按难度排序」少见**：
   - 万亿 token 规模下很难定义可靠的「难度」；
   - 数据大多只过一遍，严格排序会让各阶段的分布差异很大，早期学到的内容可能被遗忘；
   - 随机打乱已经很有效，相关研究中按难度排序的收益不稳定；
   - 工程上排序与流式处理也更复杂。
4. **风险**：
   - 遗忘：前期数据在后期不再出现，相关能力下降；
   - 过拟合：末期高质量数据量少、重复多；
   - 评测污染：末期上采样的数据若与评测集相似，分数虚高；
   - 效果与学习率调度耦合（末期低学习率时数据影响更大），必须用退火实验和消融来验证。

**评分要点（共 10 分）：**

- 给出课程学习的定义（2 分）
- 列举至少两种实际使用的课程做法，如阶段式配比与退火、长度课程（3 分）
- 解释全局按难度排序少见的原因（3 分）
- 指出遗忘、过拟合、污染等风险（2 分）

**讲解：**

**常见失分点**：只会说「先易后难」；不知道退火与中期训练就是当前最常见的「课程」；忽视遗忘与污染；把课程学习与学习率调度混为一谈，说不清二者的耦合关系。

<sub>考点：课程学习、数据配比　｜　出处：The Llama 3 Herd of Models arXiv:2407.21783；2 OLMo 2 Furious arXiv:2501.00656；Qwen3 技术报告 arXiv:2505.09388；The Stability-Efficiency Dilemma: Investigating Sequence Length Warmup（Li 等, 2022）arXiv:2108.06084；GPT-3 arXiv:2005.14165</sub>

### TRN-DATA-035　进阶 · 考频 ★★

如果你负责一个预训练项目的数据去污染，你会如何设计这套流程？请说明要保护哪些评测集、用什么方法检测、发现重叠后怎么处理，以及如何验证去污染是否有效。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **保护范围**：所有计划使用的公开基准（测试集、验证集、各语言版本）、内部业务评测集，以及近期可能使用的基准；检测对象不只是网页数据，还包括代码、书籍、SFT 数据和合成数据。
2. **检测方法**：
   - 文本规范化（小写、去标点与多余空白、Unicode 规范化）后做 n-gram 重叠，如 13-gram，或按样本统计重叠 n-gram 的比例再设阈值；
   - 选择题等短文本用较小的 n 或整题字符串匹配；
   - 改写、翻译类泄漏：Embedding 相似度召回 + 大模型判别；
   - 利用评测集中的 canary 字符串（如 BIG-bench 的 canary GUID）：在训练数据中出现即报警。

4. **验证**：
   - 抽查命中与未命中的样本，估计误报率与漏报率；
   - 比较模型在干净子集与污染子集上的表现差异；
   - 用训练截止日期之后发布的题目或私有评测集作为对照；
   - 检查合成数据的生成提示中是否使用过评测题。
5. **工程**：索引建在评测集一侧（规模小），流式扫描训练数据；n-gram 用哈希表示；流程版本化、可复现，每次新增评测集都重跑。

**评分要点（共 10 分）：**

- 明确保护范围，并覆盖 SFT 与合成数据（2 分）
- 给出规范化、n-gram 阈值与改写检测等方法（3 分）
- 说明发现重叠后的处理方式（2 分）
- 给出验证方法，如干净/污染子集对比、时间切分对照（2 分）
- 提到索引建在评测集一侧等工程要点（1 分）

**讲解：**

**常见失分点**：只说「做 n-gram 去重」，不讲规范化和阈值；忽视改写泄漏以及 SFT、合成数据中的污染；没有验证与对照；把索引建在万亿 token 的训练数据一侧，导致方案不可行。

## 场景分析题

<a name="TRN-DATA-014"></a>

### TRN-DATA-014　挑战 · 考频 ★★

团队处理了 90 个 Common Crawl 快照。第一版按快照分别做 MinHash 去重（每个快照内部去重）；第二版把 90 个快照放在一起做全局去重，数据量减少了一大半。用同样的训练 token 数训练 1B 的消融模型后，第二版在多数基准上反而更差。请分析可能的原因，并给出验证思路和改进方案。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 原因分析**
- FineWeb 观察到了同样的现象。全局去重删掉的主要是在多个快照中反复出现的文档，它们往往是长期存在、被反复抓取的页面（百科、文档、经典文章），整体质量较高；全局去重之后**幸存**的大多是只出现过一次的页面，其中低质量、垃圾内容的比例更高。全局去重在客观上做了一次「反向质量筛选」。
- FineWeb 在一个较早的快照上做过对比：用被全局去重**删掉**的数据训练的模型，反而好于用保留下来的数据训练的模型。
- 在训练 token 数固定时，第一版中被多次抓取的高质量页面相当于被自然上采样；第二版数据量变少，为凑够 token 可能要重复更多遍，而重复的恰恰是质量偏低的那部分。

**2. 验证思路**
- 抽样对比「被删除的数据」与「被保留的数据」：用质量分类器打分、人工评估、统计来源与领域分布；
- 分别用这两部分数据训练小模型，比较下游指标；
- 统计文档的重复次数与质量分之间的相关性。

**3. 改进方案**
- 回到按快照去重，或按来源、时间分组去重；
- 若要全局去重，每簇保留质量分最高（或最新）的一篇，并把「被多次抓取」作为质量信号用于采样加权；
- 去重后再做质量过滤（如分类器打分、分档采样），弥补幸存数据质量偏低的问题；
- 任何去重策略的阈值与粒度都通过小模型消融来确定。

**4. 原则**：去重的目标是去掉「无意义的重复」，而不是把数据集压到最小；它与质量过滤、配比是联动的，不能孤立地优化。

**评分要点（共 10 分）：**

- 指出全局去重后幸存数据的质量更差、相当于反向质量筛选（4 分）
- 给出可操作的验证方法，如对比被删与被保留数据训练的小模型（3 分）
- 给出改进方案：按快照去重、簇内保留高质量文档、去重后再做质量过滤（3 分）

**讲解：**

**常见失分点**：只归因于「数据量变少」就结束；默认「去重一定有益」；没有提出能验证假设的实验；改进方案只是「把阈值调高一点」，没有触及质量与去重的联动关系。

<sub>考点：MinHash近似去重、精确去重、质量过滤　｜　出处：FineWeb 技术报告（Penedo 等, 2024）arXiv:2406.17557</sub>

</details>

### TRN-DATA-019　挑战 · 考频 ★★

**3. 补充**：部分能力可以在 SFT 阶段补救，但预训练阶段损失的语言多样性很难只靠少量 SFT 数据完全弥补。

- 指出分类器偏好导致文体、领域、语言分布偏移（3 分）
- 指出过滤过严导致多样性下降、重复增加，以及评测集本身的偏向（2 分）

- 给出扩展评测与消融验证的方案（2 分）

## 系统设计题

<a name="TRN-DATA-041"></a>

### TRN-DATA-041　挑战 · 考频 ★★★

请为一个中英双语、约 7B 参数的基座模型设计预训练数据流水线，目标是产出约 3T token 的训练数据（含代码与数学）。请说明：数据来源；处理流程的各个阶段（清洗、去重、质量与安全过滤、去污染）；配比与采样策略；规模与工程实现；如何验证每个环节的效果，以及主要风险。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 需求与来源**
- 目标 3T token，约 430 token/参数，属于「过训练」，换取更低的推理成本；中英为主，代码约 10%～15%，数学约 5%～10%。
- 来源：Common Crawl 多个快照（中英网页）；许可合规的开源清洗数据集；中文百科、新闻、问答社区；许可合规的书籍与论文；GitHub 宽松许可证代码；数学网页与题解；经过验证的合成数据（改写、教材式、可验证的题目）。

**2. 处理流程**
- **抽取**：从 WARC 原始文件用 trafilatura 等工具抽正文；数学和代码页面用能保留公式、代码块的专用抽取器。
- **语种识别**：fastText 语种识别，中英分流，低置信度的丢弃或单独处理。
- **规则过滤**：长度、符号与数字比例、重复行与 n-gram 比例、停用词、乱码；中文特有规则（繁简转换、全半角统一、广告与 SEO 关键词）。
- **去重**：URL 去重 → 文档精确哈希 → 行 / 段落级模板去重 → MinHash-LSH（5-gram、约一两百个哈希函数、阈值 0.7～0.8，按快照或按来源去重）。
- **质量过滤**：中英分别训练分类器（大模型标注几十万条 + 蒸馏成 fastText 或小模型），按分数分档采样而非一刀切。
- **安全**：PII 替换为占位符；URL 黑名单与毒性分类器去掉严重有害内容。
- **去污染**：对全部评测集建 n-gram 索引，删除重叠的训练文档，并检查合成数据。

**3. 配比与采样**
- 用约 1B 的小模型（训练几十 B token）做配比消融，再结合趋势外推确定比例；
- 高质量来源按质量分档上采样，但每个来源重复不超过约 4 遍；
- 退火阶段上采样数学、代码与精选数据，并用退火实验评估新数据源。

**4. 规模与工程**
- 原始网页经过抽取、过滤、去重后通常只剩一小部分，要得到数 T token 的干净网页数据，需要处理几十个快照级别的原始数据；
- 用 Spark、Ray 或 datatrove 等框架在 CPU 集群上分布式处理；MinHash 以「(段号, 段签名)」为键 shuffle 分桶，用分布式连通分量聚类；
- 大模型只用于标注少量样本，全量打分用小模型。

**5. 验证**
- 每个环节（换抽取器、调去重阈值、换质量分类器）都用小模型对照，在相同 token 数下比较下游指标；
- 抽样人工审查被删除与被保留的样本；
- 统计每一步前后的数据量与语言、领域、来源分布；
- 去污染的命中率与抽查；记录数据血缘与版本，保证可复现。

**6. 主要风险**：版权、许可与隐私合规；质量分类器的偏见误伤口语、方言与小众领域；全局去重的副作用；中文高质量数据稀缺，翻译与合成数据比例过高的风险；评测污染导致虚高。

**评分要点（共 10 分）：**

- 来源覆盖中英网页、代码、数学、书籍等，并考虑许可合规（2 分）
- 处理流程完整：抽取、语种识别、规则过滤、精确与近似去重、质量过滤、PII 与毒性处理、去污染（3 分）
- 配比与采样策略合理：小模型消融、重复上限、退火上采样（2 分）
- 给出规模估计与分布式工程实现思路（1 分）
- 给出每个环节的验证方法与主要风险（2 分）
