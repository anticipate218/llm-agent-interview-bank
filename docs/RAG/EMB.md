<a name="RAG-EMB-001"></a>

### RAG-EMB-001　基础 · 考频 ★★★

双塔（Bi-encoder）向量检索能在千万级文档上做到在线毫秒级响应，**根本原因**是：

- **A.** 双塔模型的参数量比 Cross-Encoder 小一个数量级，单次前向的计算量也就小得多
- **B.** 双塔在编码时让问题与文档的 token 做交叉注意力，一次前向就能完成匹配打分
- **C.** 文档向量与问题无关，可离线算好并建 ANN 索引，在线只需编码问题再做近邻搜索
- **D.** 双塔模型的向量运算可以在 CPU 上用 SIMD 指令完成，不需要 GPU 参与推理

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：双塔的关键在「分开编码」：$s(q,d)=f(q)\cdot g(d)$，文档表示 $g(d)$ 不依赖问题，可以离线批量计算并建 ANN 索引。在线只需对问题做一次前向，再在索引里找最近邻；ANN 只访问很少一部分向量，耗时随文档数增长得很慢。

- A 错：双塔与 Cross-Encoder 可以用同样大小的 BERT 骨干，快慢的差别来自计算方式，而不是参数量。
- B 错：这描述的是 Cross-Encoder。双塔的问题和文档在编码时互相看不见，这正是它能预计算的前提，也是它不如 Cross-Encoder 精细的原因。
- D 错：运行设备与此无关，线上通常仍用 GPU（或优化过的 CPU 推理）来编码问题。

<sub>考点：双塔模型</sub>

</details>

<a name="RAG-EMB-004"></a>

### RAG-EMB-004　基础 · 考频 ★★★

带批内负例（in-batch negatives）的 InfoNCE 损失中，batch 大小为 $B$。对 batch 中的第 $i$ 个问题而言，这个损失相当于：

- **A.** 对 batch 内每篇文档单独做一次二分类（是否为正例），分别计算 sigmoid 交叉熵后求和
- **B.** 在 batch 内的 $B$ 篇文档上做一次 $B$ 分类：正确类别是 $d_i$，其余 $B-1$ 篇当负例
- **C.** 只计算它与正例 $d_i$ 的相似度，把负的相似度直接作为损失来最小化，其他文档不参与
- **D.** 只与一个随机抽取的负例比较，做成对的 margin 损失，负例个数与 batch 大小无关

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：InfoNCE 的本质是 Softmax 分类：

$$\mathcal{L}_i=-\log\frac{\exp(s(q_i,d_i)/\tau)}{\sum_{j=1}^{B}\exp(s(q_i,d_j)/\tau)}$$

相似度矩阵 $QD^\top/\tau$ 的每一行是一个 $B$ 分类问题，正确答案在对角线上，所以代码里就是一行 `cross_entropy(logits, arange(B))`。同一批中其他样本的正例被「顺手」拿来当负例，不需要额外编码，这就是批内负例的妙处。

- A 错：这更像 SigLIP 式的成对 sigmoid 损失，与 Softmax 形式的 InfoNCE 不同。
- C 错：只拉近正例而不推远负例，模型会把所有向量压到一起（表示坍缩），失去区分能力。
- D 错：批内负例的个数是 $B-1$，随 batch 增大而增加；还可以额外加入难负例。

<sub>考点：对比学习InfoNCE</sub>

</details>

<a name="RAG-EMB-007"></a>

### RAG-EMB-007　进阶 · 考频 ★★

InfoNCE 的温度 $\tau$ 取得过小（例如 0.001）时，最可能带来的问题是：

- **A.** Softmax 变得平坦，难负例和易负例得到的梯度差不多，模型学不会区分难负例
- **B.** 正例的 logit 被放大到远超各个负例，损失恒为 0，模型参数从此不再更新
- **C.** 除以极小的温度后，余弦相似度会超出 $[-1, 1]$ 的范围，导致浮点溢出和数值错误
- **D.** Softmax 接近 one-hot，梯度压在最难的几个负例上，混入的假负例被放大，训练不稳

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：温度控制 Softmax 的尖锐程度。$\tau$ 越小，越「只盯着最难的负例」，梯度几乎全部压在少数难负例上；若其中混有未标注的假负例，错误信号会被放大。过小时，模型对假负例和标注噪声极其敏感，梯度大小还随 $1/\tau$ 放大，训练容易震荡。

- A 错：这是温度**过大**时的现象：Softmax 趋于平坦，难负例与易负例得到的梯度差不多。
- B 错：只要正例没有以绝对优势胜出，损失就不为 0；即使损失很小，难负例仍然提供梯度。
- C 错：余弦相似度本身始终在 $[-1, 1]$ 内，温度只是把它除以一个常数作为 logits；logits 最大约 1,000，配合 log-sum-exp 的稳定实现，也不会溢出。

实践中温度常取 0.01～0.1 量级；CLIP 等工作把温度设为可学习参数，并限制它的下界。

<sub>考点：对比学习InfoNCE　｜　出处：Radford 等, CLIP 论文 arXiv:2103.00020（温度为可学习参数，并限制 logits 的缩放不超过 100 倍）</sub>

</details>

<a name="RAG-EMB-009"></a>

### RAG-EMB-009　挑战 · 考频 ★

对单个问题，InfoNCE 损失为 $\mathcal{L}=-\log\dfrac{e^{s_{+}/\tau}}{\sum_{k}e^{s_k/\tau}}$（求和包括正例），记 $p_j=\dfrac{e^{s_j/\tau}}{\sum_k e^{s_k/\tau}}$。对某个负例的相似度 $s_j$，梯度 $\partial\mathcal{L}/\partial s_j$ 等于：

- **A.** $p_j/\tau$
- **B.** $(p_j-1)/\tau$
- **C.** $-1/\tau$，对所有负例都相同
- **D.** $p_j\cdot\tau$

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**推导**：$\mathcal{L}=-\dfrac{s_{+}}{\tau}+\log\sum_k e^{s_k/\tau}$。对负例 $s_j$ 求导，第一项与它无关，第二项的导数是 $\dfrac{1}{\tau}\cdot\dfrac{e^{s_j/\tau}}{\sum_k e^{s_k/\tau}}=\dfrac{p_j}{\tau}$。

**含义**：每个负例受到的「推开」力度与它在 Softmax 中的概率 $p_j$ 成正比：越像正例的难负例，$p_j$ 越大，被推得越狠；易负例的 $p_j$ 接近 0，几乎不贡献梯度。温度越低，概率越集中在难负例上，这就是「低温聚焦难负例」的数学来源。

- B 错：$(p_{+}-1)/\tau$ 是对**正例**相似度的梯度（为负，表示要增大正例相似度）。
- C 错：梯度与各负例的概率有关，不是常数。
- D 错：温度在分母上，求导得到的系数是 $1/\tau$ 而不是 $\tau$。

<sub>考点：对比学习InfoNCE</sub>

</details>

<a name="RAG-EMB-013"></a>

### RAG-EMB-013　基础 · 考频 ★★★

问题向量 $q$ 与文档向量 $d$ 都做了 L2 归一化。关于余弦相似度、内积与 L2 距离，下列说法正确的是：

- **A.** 余弦与内积等价，但 L2 距离还受向量长度影响，会给出不同的近邻集合
- **B.** 三者的数值相同，所以相关性阈值（如 0.8）可以在三种度量之间直接互换
- **C.** 三者给出的近邻排序相同，因为此时 L2 距离是余弦的单调递减函数
- **D.** 只有在向量**不**归一化时，三者才给出相同的排序，归一化会改变距离关系

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**推导**：$\lVert q-d\rVert^2=\lVert q\rVert^2+\lVert d\rVert^2-2\,q\cdot d$。归一化后 $\lVert q\rVert=\lVert d\rVert=1$，且 $q\cdot d=\cos(q,d)$，所以 $\lVert q-d\rVert^2=2-2\cos(q,d)$。L2 距离是余弦的单调递减函数：余弦最大的，L2 距离就最小。

- A 错：归一化后向量长度都是 1，L2 距离不再受长度影响；如上，排序完全一致。
- B 错：排序相同不代表数值相同。余弦 0.9 对应的 L2 距离是 $\sqrt{0.2}\approx0.447$，阈值必须换算。
- D 错：恰好相反，不归一化时内积会受向量长度影响，三者的排序一般不同。

工程结论：向量归一化之后，向量库选「内积」最省事；但距离类型要与模型训练时使用的相似度一致。

<sub>考点：相似度度量</sub>

</details>

### RAG-EMB-018　基础 · 考频 ★★

BGE-M3 名字中的「M3」指的是它的三个特点。下列描述正确的是：

- **A.** 三种模型尺寸（Mini、Medium、Max），分别面向端侧、服务端和离线批处理，共享同一套词表和训练数据
- **B.** 多语言（100 多种）、多功能（稠密、稀疏、多向量三种表示）、多粒度（最长 8,192 token 输入）
- **C.** 三阶段训练（预训练、对比学习、指令微调），每个阶段分别对应名字里的一个「M」
- **D.** 三种距离度量（余弦、内积、L2）都经过联合训练，部署时可以按向量库的支持任选其一

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：BGE-M3（智源，2024）= Multi-Linguality + Multi-Functionality + Multi-Granularity：支持 100 多种语言；同时输出稠密、稀疏和多向量三种表示；输入可以从短句到最长 8,192 token 的长文档。

- 多功能是它最有特色的地方：一次前向同时产出稠密向量、稀疏的词权重（可以建倒排索引，类似学习型稀疏检索）和多向量表示（类似 ColBERT 的 token 级向量），一个模型就能支撑混合检索与重排。
- 多粒度让它可以直接编码较长的块，不受 512 token 的限制。

A、C、D 都不是名字的含义：BGE-M3 没有按 Mini/Medium/Max 划分尺寸；训练流程与名字无关；距离度量应与训练方式一致（稠密向量归一化后用内积），不是「任选」。

<sub>考点：Embedding模型选型　｜　出处：Chen 等, M3-Embedding（BGE-M3）, arXiv:2402.03216；BGE-M3 模型卡 https://huggingface.co/BAAI/bge-m3</sub>

</details>

<a name="RAG-EMB-020"></a>

### RAG-EMB-020　进阶 · 考频 ★★

某模型用 Matryoshka 表示学习（MRL）训练，输出 1,024 维、已 L2 归一化的向量。部署时只取前 256 维用于检索。下列说法正确的是：

- **A.** 截断后可以直接用内积检索，不必重新归一化：MRL 训练保证了前 256 维的范数仍然为 1
- **B.** 应该截取后 256 维：MRL 先训练低维部分、再逐步补充，越靠后的维度信息量越大
- **C.** 普通对比学习训练的 Embedding 模型也可以这样截断，效果与 MRL 模型相当，只是维度利用率略低
- **D.** 训练时对多个前缀维度同时计算损失，前 256 维本身就是可用的表示；截断后要重新做 L2 归一化

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：MRL（Kusupati 等, 2022）在训练时把多个前缀长度（如 64、128、256……）上的损失加在一起，迫使信息「由粗到细」地排在前面：前 64 维就能粗略表达语义，越往后补充越多细节。所以截取前缀仍然是一个好的低维表示。

- A 错：MRL 只约束前缀维度的检索效果，不约束范数。完整向量的范数为 1，但它前 256 维的平方和小于 1，且各向量截断后的范数各不相同；不重新归一化，内积就不等于余弦，排序会受范数影响。
- B 错：信息集中在前面，截取前缀才是正确用法。
- C 错：普通模型没有经过这种训练，信息分散在所有维度上，随意截断会显著掉点。

OpenAI text-embedding-3 系列的 `dimensions` 参数，就是这种截断思路的产品化。

<sub>考点：Matryoshka表示　｜　出处：Kusupati 等, Matryoshka Representation Learning, arXiv:2205.13147；OpenAI: New embedding models and API updates（2024-01-25，dimensions 参数）https://openai.com/index/new-embedding-models-and-api-updates/</sub>

</details>

<a name="RAG-EMB-024"></a>

### RAG-EMB-024　基础 · 考频 ★★

团队对 Embedding 模型（问题与文档共用同一个编码器）做了常规的领域微调，准备上线。下列做法中**正确**的是：

- **A.** 用新模型对全部文档重新编码、建立新索引，验证通过后整体切换
- **B.** 只用新模型编码新增文档，旧文档沿用旧向量：维度相同，可以放在同一个索引里
- **C.** 把同一文档的新旧向量取平均后写回原索引，平滑过渡到新模型
- **D.** 只更新在线的查询编码，文档向量保持不变，微调后的查询向量更贴近文档

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：微调会改变整个向量空间，新模型的查询向量只能和新模型的文档向量比较。

- A 对：全量重新编码 → 建新索引 → 在评测集上验证 → 通过别名切换等方式整体上线（蓝绿发布），出问题可以快速回滚。
- B 错：维度相同不代表可比，新旧向量处在不同的空间，混在一个索引里，旧文档的相似度失去意义，会被系统性地错排。
- C 错：两个不同空间的向量取平均没有意义。
- D 错：查询用新空间、文档用旧空间，两者不可比。（学术界有专门训练「向后兼容」表示的方法，但常规微调不具备这种性质。）

同理，相似度阈值也要在新模型上重新标定。

<sub>考点：领域微调</sub>

</details>

<a name="RAG-EMB-026"></a>

### RAG-EMB-026　基础 · 考频 ★★

关于暴力检索（Flat 索引，逐一计算查询与全部向量的相似度），下列说法正确的是：

- **A.** 无论数据规模多大，它都比 HNSW 更快，因为没有建图开销
- **B.** 召回率为 100%，常作为评估 ANN 索引召回率的标准答案
- **C.** 使用前必须先用 k-means 训练聚类中心
- **D.** 只支持 L2 距离，不支持内积

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：暴力检索是精确检索，代价为 $O(N\cdot d)$。它的价值有二：数据量小（如十万级以内）时简单够用；在任何规模下，它都是 ANN 索引的「标准答案」，上线前要用它来测 HNSW、IVF 的 Recall@k。

- A 错：查询代价随 $N$ 线性增长，千万级以上很难支撑高并发，这正是 ANN 存在的原因。
- C 错：需要 k-means 训练的是 IVF、PQ 这类索引。
- D 错：暴力检索支持任意可计算的度量。

另外，批量查询时暴力检索可以写成矩阵乘法，在 GPU 上效率很高，适合离线的批量检索与评测。

<sub>考点：暴力检索</sub>

</details>

<a name="RAG-EMB-032"></a>

### RAG-EMB-032　挑战 · 考频 ★★

PQ 检索时常用「非对称距离计算」（ADC，Asymmetric Distance Computation）。它的做法是：

- **A.** 查询保持原精度：先算出它每一段到各码字的距离表，再按库向量的码字编号查表累加
- **B.** 把查询向量也量化成码字，再查预先算好的「码字 × 码字」距离表，查询与库向量同等对待
- **C.** 先把每个库向量解码还原成 float32 向量，再逐一与查询精确计算距离，保证结果精确
- **D.** 只比较查询与库向量在每一段上的码字编号是否相同，编号相同的段计 1 分，按总分排序

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：ADC 的「非对称」指查询保持原始精度、库向量用压缩码表示。每个查询只需构建一次 $m\times256$ 的距离表（查询每一段到该段 256 个码字的距离），之后每个库向量的距离只是 $m$ 次查表加法，比原始的 $d$ 维浮点计算快得多，也不需要解码。

- B 错：这是对称距离计算（SDC）。查询也被量化，多引入一份量化误差，精度不如 ADC。
- C 错：解码还原后再计算，既慢，又没有利用 PQ 的查表加速；还原出的也只是近似向量，结果并不精确。
- D 错：码字编号只是索引，编号不同的码字之间也有远近之分，「相同计 1 分」丢掉了距离信息。

例：$d=768$、$m=96$ 时，距离表有 $96\times256=24576$ 项（每项是一次 8 维子向量的距离），之后每个库向量只需 96 次查表累加，而原始计算要 768 次乘加。

<sub>考点：乘积量化PQ　｜　出处：Jégou 等, Product Quantization for Nearest Neighbor Search, IEEE TPAMI 2011（ADC 与 SDC）</sub>

</details>

<a name="RAG-EMB-034"></a>

### RAG-EMB-034　基础 · 考频 ★★★

关于 HNSW 的参数，下列说法正确的是：

- **A.** efConstruction 是查询时的候选队列长度，调大后查询更快、召回更高
- **B.** efSearch 在建索引时设定并写入索引文件，之后要改就得重建索引
- **C.** M 越大，每个节点的边越多，召回通常越高，但内存占用和建图时间也会增加
- **D.** efSearch 可以小于 k，返回结果不足 k 个时，索引会自动从上层补齐

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**三个参数的分工**：
- **M**：每个节点在每层最多连接的邻居数（底层通常放宽到 2M）。M 越大，图越稠密、越不容易「走不通」，召回越高，但邻接表越大，建图也越慢。常见取值 16～64。
- **efConstruction**：建图时搜索邻居用的候选队列长度。越大，选出的邻居越好、图质量越高，但建图越慢；它不是查询参数。
- **efSearch**：查询时候选队列的长度，可以按请求动态调整：越大，探索越充分，召回越高，延迟也越高。

逐项点评：
- A 错：efConstruction 是建图参数，主要影响建图时间和图质量，并不直接让查询变快；查询时的候选队列长度是 efSearch，调大它召回更高、查询更慢。
- B 错：efSearch 是查询时参数，可以随时修改，甚至每个请求设不同的值。
- D 错：结果集最多只有 ef 个元素，efSearch 小于 k 没有意义；常见实现会取 max(ef, k)。

<sub>考点：HNSW　｜　出处：Malkov & Yashunin, HNSW 论文 arXiv:1603.09320；hnswlib 参数说明 https://github.com/nmslib/hnswlib/blob/master/ALGO_PARAMS.md</sub>

</details>

### RAG-EMB-002　进阶 · 考频 ★★★

关于双塔（Bi-encoder）Embedding 模型，下列说法**正确**的有：

- **A.** 文档的全部信息被压缩进一个向量，否定、数字等细粒度信息容易丢失
- **B.** 问题和文档各自独立编码，编码时互相看不到对方的 token
- **C.** 打分函数可以换成任意复杂的神经网络（如 MLP），ANN 索引照样能用来加速检索
- **D.** 问题塔和文档塔必须使用两套不同的参数，共享参数会让问题和文档向量无法区分
- **E.** 句向量常取 [CLS] 或 mean pooling；decoder-only 模型常取最后一个 token

<details>
<summary>答案与解析</summary>

**答案：ABE**

**解析：**

**结论**：A、B、E 正确。

- A 对：单向量是一种强压缩，「支持甲而不支持乙」「价格是 199 而不是 299」这类细节容易丢失，因此需要 Cross-Encoder 重排来补偿。
- B 对：这是双塔的定义，也是文档向量可以离线预计算的前提。
- C 错：ANN 索引依赖内积、余弦、L2 这类简单度量在向量空间里做几何搜索；换成复杂的神经网络打分，就只能逐一计算，失去了双塔的效率优势。
- D 错：两塔可以不共享（如 DPR 用两个独立的 BERT），也可以共享同一个编码器（如 Sentence-BERT 的孪生结构）。很多现代模型共享编码器，靠查询前缀或指令区分问题与文档。
- E 对：常见池化方式有取 [CLS] 位置的输出与 mean pooling（所有 token 输出取平均）；decoder-only 模型用因果注意力，只有最后一个 token 能看到全部输入，所以取最后一个 token（常是 EOS）的隐状态。之后一般再做 L2 归一化。

<a name="RAG-EMB-010"></a>

### RAG-EMB-010　进阶 · 考频 ★★★

关于 Embedding 训练中的难负例（hard negatives），下列说法**正确**的有：

- **A.** 难负例常与批内负例一起使用：批内负例数量多、几乎不增加计算，难负例补充细粒度信号
- **B.** 难负例只能来自 BM25 等稀疏检索，不能取自正在训练的稠密模型自身的检索结果
- **C.** 与随机负例相比，难负例能提供更大的梯度信号，帮助模型学会细粒度区分
- **D.** 难负例中可能混有未被标注的真正相关文档（假负例），需要用 Cross-Encoder 打分过滤，或跳过排名最靠前的若干个
- **E.** 常用 BM25 或当前模型召回结果中排名靠前、但未被标注为正例的文档作为难负例

<details>
<summary>答案与解析</summary>

**答案：ACDE**

**解析：**

**结论**：A、C、D、E 正确。

- A 对：两者是叠加关系。DPR 效果最好的设置就是「批内负例 + 每个问题 1 个 BM25 难负例」：批内负例直接复用同一 batch 里其他问题的段落向量，数量多、几乎零成本；难负例提供关键的细粒度信号。有了难负例就丢掉批内负例，是常见误解。
- B 错：两种来源都常用。DPR（Karpukhin 等, 2020）为每个问题加入 BM25 难负例；ANCE 等方法用正在训练的稠密模型自己检索难负例，并定期刷新索引。
- C 对：随机负例往往「一眼就能区分」，Softmax 概率接近 0，几乎不产生梯度；难负例的概率高，梯度大。
- D 对：标注通常不完整，排名最靠前的「负例」里常有其实也能回答问题的文档。RocketQA 等工作用 Cross-Encoder 给候选打分，去掉高分的疑似假负例。
- E 对：这是最常见的两种挖掘方式。

<a name="RAG-EMB-015"></a>

### RAG-EMB-015　进阶 · 考频 ★★

关于向量检索中相似度度量的工程选择，下列说法**正确**的有：

- **A.** 向量未归一化却用内积检索时，范数大的文档可能被系统性地排到前面
- **B.** 余弦相似度对向量长度敏感，所以长文档的余弦分数天然更高
- **C.** 不同 Embedding 模型的相似度分数分布差别很大，相关性阈值不能跨模型照搬
- **D.** 向量库的距离类型应与 Embedding 模型训练时使用的相似度保持一致

<details>
<summary>答案与解析</summary>

**答案：ACD**

**解析：**

**结论**：A、C、D 正确。

- A 对：内积 $=\lVert d\rVert\cos\theta$（$q$ 固定时），长度大的向量占便宜。有些模型的向量范数与文本长度、词频相关，未归一化时会出现「某类文档总排在前面」的现象。
- B 错：余弦只看方向、与长度无关，这正是使用余弦的原因。长文档得分高不高，取决于模型怎么编码它，与余弦公式无关。
- C 对：有的模型给无关文档也打 0.6 以上的余弦，有的模型分数整体分布在 0.2～0.6。换模型或微调后，阈值必须在评测集上重新标定。
- D 对：模型在训练时按某种相似度优化（多数是归一化后的余弦或内积），检索时换成别的度量，排序就不再是模型学到的那一种。

<a name="RAG-EMB-030"></a>

### RAG-EMB-030　挑战 · 考频 ★★

关于 IVF 索引，下列说法**正确**的有：

- **A.** IVF 与 HNSW 一样不需要训练，可以在空索引上直接逐条插入向量
- **B.** 近邻常落在相邻的簇里（边界效应），所以 nprobe = 1 时召回率往往明显低于 1
- **C.** 簇中心由建索引时的数据训练得到，数据分布漂移后召回可能下降，需定期重训
- **D.** nlist 越大越好：每个簇更小，扫描量一定更少，召回也更高
- **E.** 对 IVF-PQ 来说，只要 nprobe 等于 nlist，检索结果就与暴力检索完全相同

<details>
<summary>答案与解析</summary>

**答案：BC**

**解析：**

**结论**：B、C 正确。

- A 错：IVF 必须先用一批有代表性的样本训练出簇中心，之后才能插入向量；不需要训练、可以从空索引开始逐条插入的是 HNSW 这类图索引。
- B 对：查询离所在簇的边界较近时，真正的近邻可能被分到隔壁的簇里；多探查几个簇能显著改善召回。例如在一次 2 万个 64 维向量、nlist = 64 的实验中，nprobe 从 1 增到 8，Recall@10 从约 0.73 升到约 0.92，扫描比例从约 1.7% 升到约 12.6%。
- C 对：簇中心反映的是建索引时的数据分布；新增数据的分布变化后，簇会越来越不均衡、边界越来越不合理，召回下降，需要定期重训并重建。
- D 错：nlist 增大，每个簇变小，但簇的边界变多，近邻更容易分散到多个簇中，要达到同样的召回需要更大的 nprobe；与簇中心比较的开销也随 nlist 线性增长。nlist 常取 $\sqrt{N}$ 的若干倍，再按评测调 nprobe。
- E 错：nprobe = nlist 只保证扫描了全部簇；IVF-PQ 比较的是量化后的近似距离（ADC 查表），存在量化误差，排序仍可能与暴力检索不同。只有簇内保存原始向量的 IVF-Flat，在 nprobe = nlist 时才与暴力检索一致。工程上常在 IVF-PQ 粗排后用原始向量对前若干名重排（refine）来弥补。

<a name="RAG-EMB-035"></a>

### RAG-EMB-035　进阶 · 考频 ★★★

关于 HNSW 的原理与特性，下列说法**正确**的有：

- **A.** 原论文选邻居时用启发式，优先选方向分散的邻居，而非简单取最近的 M 个
- **B.** HNSW 天然支持高效的物理删除：删除节点后，邻居之间会自动重连，图结构不受影响
- **C.** HNSW 在 efSearch 不小于 k 时等价于精确检索，召回率为 100%
- **D.** 查询从最高层入口逐层贪心下降，在最底层用长度为 efSearch 的候选队列做束搜索
- **E.** 每个节点的最高层号按指数衰减的分布随机抽取，越往上层节点越少

<details>
<summary>答案与解析</summary>

**答案：ADE**

**解析：**

**结论**：A、D、E 正确。

- A 对：这个启发式会跳过与已选邻居挨得太近的候选（以改善图的连通性），让边指向不同的方向，在聚簇明显的数据上能避免图被分割成孤岛。
- B 错：删除节点会破坏它周围的连通性，图不会自动重连，常见实现只做标记删除（查询时跳过），积累多了要重建或修复。
- C 错：HNSW 是近似最近邻（ANN）索引，召回率随 efSearch 等参数变化，通常在 0.9～0.99 之间调。上线前要用暴力检索的结果测召回。
- D 对：高层用贪心（候选队列长度为 1）找到下一层的入口，底层用 efSearch 做束搜索，好比「先坐飞机、再换高铁、最后步行」。
- E 对：层号取 $\lfloor-\ln U\cdot m_L\rfloor$，$m_L=1/\ln M$，每往上一层，节点数约缩小为 $1/M$。高层稀疏、边跨度大，用来快速跨越区域；底层包含全部节点，用来精细搜索。

<sub>考点：HNSW　｜　出处：Malkov & Yashunin, HNSW 论文 arXiv:1603.09320（层号分布 m_L = 1/ln M、启发式选邻居）</sub>

</details>

**答案：✅ 正确**

**解析：**

**正确**。因果注意力下，第 $t$ 个 token 只能看到前 $t$ 个 token；取前面的位置或做平均，都会让一部分 token 缺少后文信息。最后一个 token 看到了全部输入，自然成为句向量的选择。E5-mistral、Qwen3-Embedding 等基于 decoder-only 大模型的向量模型都采用这类「最后 token 池化」，再用对比学习训练；也有工作（如 LLM2Vec）把注意力改成双向后再做 mean pooling。

这类模型的优势是语义理解与多语言能力强、可以接受任务指令；代价是参数量大（常达数十亿），编码的延迟和成本明显高于 BERT 系小模型，选型时要权衡。

<sub>考点：双塔模型、Embedding模型选型　｜　出处：Wang 等, Improving Text Embeddings with Large Language Models（E5-mistral，最后 token 池化）, arXiv:2401.00368；Qwen3 Embedding 技术报告 arXiv:2506.05176；BehnamGhader 等, LLM2Vec, arXiv:2404.05961</sub>

</details>

### RAG-EMB-008　基础 · 考频 ★★

使用批内负例的 InfoNCE 时，batch 越大，每个问题对比的负例越多，效果通常越好；这也是很多 Embedding 模型训练时采用大 batch，或在多卡之间汇总负例的原因。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。批内负例的个数是 $B-1$，batch 越大：

1. 负例越多，其中越可能出现「难」的负例，学习信号更强；
2. 理论上，InfoNCE 给出互信息的下界 $I(q;d)\ge\log B-\mathcal{L}$，$B$ 越大，这个下界可以越紧（CPC，van den Oord 等, 2018）。

## 填空题

<a name="RAG-EMB-031"></a>

### RAG-EMB-031　基础 · 考频 ★★★

用乘积量化（PQ）压缩 1,024 维 float32 向量：切成 $m=64$ 段，每段用 256 个码字的码本量化（每段只存 1 字节的码字编号）。每个向量编码后占 ____ 字节，相对原始 float32 向量压缩了 ____ 倍。

<details>
<summary>答案与解析</summary>

**答案：** (1) 64；(2) 64

**解析：**

- 原始：$1024\times4=4096$ 字节；
- PQ：每段 1 字节（$256=2^8$ 个码字，正好 8 bit），共 $m=64$ 字节；
- 压缩比：$4096/64=64$ 倍。

码本本身的开销：64 段 × 256 个码字 × 每个码字 16 维 × 4 字节 = 1 MiB，由所有向量共享，可以忽略。

PQ 的表达能力来自「乘积」：每段 256 个码字，64 段组合起来相当于 $256^{64}$ 个不同的量化中心，而存储只要 64 字节。代价是量化误差，通常要用原始向量对候选重排来找回精度。

<sub>考点：乘积量化PQ</sub>

</details>

<a name="RAG-EMB-037"></a>

### RAG-EMB-037　挑战 · 考频 ★

HNSW 为每个新节点随机抽取层号 $l=\lfloor-\ln U\cdot m_L\rfloor$，其中 $U$ 在 $(0,1]$ 上均匀分布，$m_L=1/\ln M$。则一个节点出现在第 $l$ 层及以上的概率为 ____（用 $M$ 和 $l$ 表示）；当 $M=16$、共 100 万个节点时，第 2 层及以上约有 ____ 个节点（取整数）。

<details>
<summary>答案与解析</summary>

**答案：** (1) M^{-l} / M^(-l) / 1/M^l / $M^{-l}$ / M的-l次方；(2) 3906 / 约3906 / 3,906 / 3906.25

**解析：**

- 层号 $\ge l$ 等价于 $-\ln U\cdot m_L\ge l$，即 $-\ln U\ge l\ln M$，即 $U\le M^{-l}$，概率为 $M^{-l}$。
- $M=16$、$l=2$：$16^{-2}=1/256$，$10^6/256\approx3906$ 个。

**含义**：每往上一层，节点数约缩小为 $1/M$：第 1 层及以上约 62,500 个，第 2 层及以上约 3,906 个，第 3 层及以上约 244 个……总层数约为 $\log_M N$（本例约 5 层）。这种结构类似跳表：高层节点稀疏、边跨度大，查询先在高层快速逼近目标区域，再逐层下降，访问的节点数随规模近似对数增长。

<sub>考点：HNSW　｜　出处：Malkov & Yashunin, HNSW 论文 arXiv:1603.09320（m_L = 1/ln M）</sub>

</details>

<a name="RAG-EMB-006"></a>

### RAG-EMB-006　进阶 · 考频 ★★

某个问题与 4 个候选文档的余弦相似度为：正例 0.70，难负例 0.65，两个易负例 0.20 和 0.10。在这 4 个候选上计算 InfoNCE：对 $s/\tau$ 做 Softmax，损失为 $-\ln p_{\text{正例}}$。分别求 $\tau=0.5$ 与 $\tau=0.02$ 时的损失，以及难负例在「负例梯度」中所占的比例（负例 $j$ 的梯度为 $\partial\mathcal{L}/\partial s_j=p_j/\tau$，占比按 $p_{\text{难}}/\sum_{j\in\text{负例}}p_j$ 计算）。

<details>
<summary>答案与解析</summary>

**答案：τ=0.5 时损失约 0.945，难负例约占负例梯度的 57%；τ=0.02 时损失约 0.079，难负例占比几乎为 100%（约 1 − 1.7×10⁻¹⁰）**

**解析：**

**τ = 0.5**：logits 为 $[1.4,\ 1.3,\ 0.4,\ 0.2]$。
- $e^{1.4}=4.055$，$e^{1.3}=3.669$，$e^{0.4}=1.492$，$e^{0.2}=1.221$，和为 $10.438$；
- $p=[0.389,\ 0.352,\ 0.143,\ 0.117]$，损失 $=-\ln0.389\approx0.945$；
- 难负例占比 $=0.352/(0.352+0.143+0.117)\approx57\%$。

**τ = 0.02**：logits 为 $[35,\ 32.5,\ 10,\ 5]$，以 35 为基准：
- 相对指数为 $[1,\ e^{-2.5}\approx0.0821,\ e^{-25}\approx1.4\times10^{-11},\ e^{-30}\approx9.4\times10^{-14}]$；
- $p_{\text{正例}}=1/1.0821\approx0.924$，损失 $=\ln1.0821\approx0.079$；
- 难负例占比 $\approx1-1.7\times10^{-10}$，几乎 100%。

**解读**：温度越低，Softmax 越尖锐，易负例的概率被压到几乎为 0，负例方向的梯度几乎全部集中在最难的负例上，模型会专注于区分「0.70 与 0.65」这种细微差别，这正是检索需要的能力。代价是：如果难负例其实是没被标注的正例（假负例），错误信号也会被同样放大，所以低温训练更需要清洗难负例。

<sub>考点：对比学习InfoNCE、难负例</sub>

</details>

<a name="RAG-EMB-021"></a>

### RAG-EMB-021　进阶 · 考频 ★★

知识库有 5,000 万个块。方案一：使用 3,072 维 float32 向量；方案二：使用同一个支持 Matryoshka 的模型，截断到前 512 维并改用 float16 存储。求两种方案的向量存储量与压缩倍数；暴力检索时，每次查询的乘加次数分别是多少？

<details>
<summary>答案与解析</summary>

**答案：方案一约 614.4 GB，方案二约 51.2 GB，压缩 12 倍；每次查询的乘加次数从 1.536×10¹¹ 降到 2.56×10¹⁰，减少到 1/6**

**解析：**

- 方案一：$5\times10^7\times3072\times4$ 字节 $=6.144\times10^{11}$ 字节，约 614.4 GB；
- 方案二：$5\times10^7\times512\times2$ 字节 $=5.12\times10^{10}$ 字节，约 51.2 GB；

<a name="RAG-EMB-027"></a>

### RAG-EMB-027　挑战 · 考频 ★★

对 1,000 万个 1,024 维 float32 向量做暴力内积检索。(1) 单次查询需要多少次乘加？(2) 若机器的有效算力为 1 TFLOPS（一次乘加按 2 次浮点运算计），只考虑计算时，单次查询需要多少时间？(3) 若每次查询都要把全部向量从内存读一遍，内存带宽为 100 GB/s，单次查询又需要多少时间？瓶颈在哪里，如何缓解？

<details>
<summary>答案与解析</summary>

**答案：(1) 约 1.02×10¹⁰ 次乘加；(2) 约 20 ms；(3) 约 410 ms，瓶颈是内存带宽，可通过批量查询、降低精度或改用 ANN 索引缓解**

**解析：**

1. 乘加次数：$10^7\times1024=1.024\times10^{10}$。
2. 计算时间：$2\times1.024\times10^{10}$ FLOP $\div10^{12}$ FLOPS $\approx20.5$ ms。
3. 读内存：数据量 $10^7\times1024\times4$ 字节 $\approx40.96$ GB，$40.96\div100\approx0.41$ s。

**分析**：单个查询每读 4 字节只做 1 次乘加（约 0.5 FLOP/字节），算术强度很低，是典型的**访存受限**：读数据比计算慢约 20 倍。

**缓解**：
- 批量查询：一次读入的向量同时与 $b$ 个查询计算（矩阵乘法），读内存的开销被摊薄约 $b$ 倍，这也是离线批量检索常在 GPU 上用矩阵乘完成的原因；
- 降低精度：float16、int8 让读取量减半或减到 1/4，PQ 压缩得更多；
- 少读数据：用 IVF、HNSW 等 ANN 索引，只访问一小部分向量；
- 多机分片：把向量分到多台机器上并行扫描。

<sub>考点：暴力检索、召回与延迟权衡</sub>

</details>

### RAG-EMB-033　挑战 · 考频 ★★

1 亿个 768 维 float32 向量，用 PQ 压缩：$m=96$ 段（每段 8 维），每段 256 个码字。求：(1) 原始向量与 PQ 编码各占多少内存，压缩多少倍；(2) 所有码本共占多少内存；(3) 一次查询构建 ADC 距离表需要计算多少个子向量距离，之后每扫描一个库向量需要几次查表累加？

<details>
<summary>答案与解析</summary>

**答案：(1) 原始约 307.2 GB，PQ 编码约 9.6 GB，压缩 32 倍；(2) 码本约 768 KiB；(3) 距离表需 24,576 个 8 维子距离，每个库向量 96 次查表累加**

**解析：**

1. 原始：$10^8\times768\times4=3.072\times10^{11}$ 字节，约 307.2 GB；PQ：每个向量 96 字节，$10^8\times96=9.6\times10^9$ 字节，约 9.6 GB；压缩比 $3072/96=32$。
2. 码本：$96\times256\times8\times4=786432$ 字节 $=768$ KiB，与编码相比可以忽略。
3. 距离表：$96\times256=24576$ 个子距离（每个是 8 维向量的距离，合计约 $2\times10^5$ 次乘加，每个查询只做一次）；之后每个库向量只需 96 次查表与累加，而原始计算要 768 次乘加。

**工程结论**：PQ 让亿级向量能放进单机内存（约 10 GB 而不是 300 GB），扫描也更快；代价是量化误差。常见做法是 IVF-PQ（先用 IVF 缩小扫描范围），再用原始向量（可以放在 SSD 上）对 top 候选重排，找回精度。

<sub>考点：乘积量化PQ、召回与延迟权衡</sub>

**解析：**

- 每个节点：向量 $768\times4=3072$ 字节 + 邻接表 $2\times16\times4=128$ 字节 $=3200$ 字节；
- 总计：$10^7\times3200=3.2\times10^{10}$ 字节，约 32 GB；
- M = 48：邻接表 $2\times48\times4=384$ 字节，每个节点 3456 字节，共约 34.56 GB，增加 2.56 GB（8%）。

**结论**：
1. 对 768 维这类高维向量，原始向量占了内存的绝大部分。想大幅省内存，应该压缩向量本身（float16、int8 标量量化、PQ）或改用磁盘索引（如 DiskANN），而不是减小 M。
2. M 的主要代价不在内存，而在建图时间和查询计算量（每扩展一个节点，要计算它所有邻居的距离）；M 带来的召回收益要在评测中权衡。
3. 高层节点很少（约占 1/M），它们的邻接表可以忽略。

<sub>考点：HNSW、召回与延迟权衡</sub>

</details>

## 代码输出题

<a name="RAG-EMB-014"></a>

### RAG-EMB-014　进阶 · 考频 ★★

下面的代码对比向量**未归一化**与**归一化**时，内积、余弦、L2 距离给出的排序。输出是什么？

```python
import numpy as np

q = np.array([1.0, 0.0])
docs = np.array([[0.9, 0.1], [3.0, 3.0], [0.3, 0.0]])

ip = docs @ q
cos = ip / np.linalg.norm(docs, axis=1)
l2 = np.linalg.norm(docs - q, axis=1)
print(np.argsort(-ip).tolist())
print(np.argsort(-cos).tolist())
print(np.argsort(l2).tolist())

n = docs / np.linalg.norm(docs, axis=1, keepdims=True)
print(np.argsort(-(n @ q)).tolist(), np.argsort(np.linalg.norm(n - q, axis=1)).tolist())
```

<details>
<summary>答案与解析</summary>

**答案（程序输出）：**

```text
[1, 0, 2]
[2, 0, 1]
[0, 2, 1]
[2, 0, 1] [2, 0, 1]
```

**解析：**

**未归一化**（$q$ 是单位向量，文档不是）：
- 内积为 $[0.9,\ 3.0,\ 0.3]$，降序得 `[1, 0, 2]`：文档 1 与 $q$ 的夹角有 45°，但长度大（约 4.24），内积反而最高；
- 余弦为 $[0.994,\ 0.707,\ 1.0]$，降序得 `[2, 0, 1]`：文档 2 与 $q$ 方向完全相同；
- L2 距离为 $[0.141,\ 3.606,\ 0.7]$，升序得 `[0, 2, 1]`：文档 2 方向虽然相同，但长度只有 0.3，离 $q$ 反而比文档 0 远。

三种度量给出三种不同的排序。

**归一化后**：所有文档都落在单位圆上，$\lVert q-d\rVert^2=2-2\cos$，内积与 L2 的排序都等于余弦的排序 `[2, 0, 1]`。

结论：度量的选择只在向量未归一化时才影响排序。用内积检索未归一化的向量，范数大的文档会被系统性地排到前面；L2 则同时受方向和长度影响。向量库的距离类型应与模型训练时一致，常见做法是归一化后用内积。

<sub>考点：相似度度量</sub>

</details>

<a name="RAG-EMB-011"></a>

### RAG-EMB-011　进阶 · 考频 ★★

训练或微调 Embedding 模型时，为什么要用难负例？难负例从哪里来？如何处理其中的假负例？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **为什么**：
   - 随机负例和批内负例大多与问题毫不相关，模型很快就能区分，它们在 Softmax 中的概率接近 0，几乎不贡献梯度；
   - 线上真正难分的是「字面或话题很像、但不能回答问题」的文档（如同一产品的不同型号、新旧版本），只有拿这类负例训练，模型才能学会细粒度区分。
2. **来源**：
   - BM25 检索结果中排名靠前的非正例（字面相似）；
   - 当前（或上一轮）稠密模型的检索结果（语义相似），ANCE 等方法还会在训练中定期刷新，让负例始终「够难」；
   - 业务规则构造：同类目的不同条目、同一文档的其他段落、旧版本内容。
3. **假负例处理**：
   - 标注往往不完整，排名最靠前的候选里常有其实也相关的文档；
   - 用 Cross-Encoder 或 LLM 给候选打分，去掉高分的疑似正例；
   - 跳过排名最前的若干个，从中间排名段（如第 10～100 名）采样；
   - 同一批次内避免出现同主题样本，防止批内负例变成假负例。
4. **注意**：温度越低，梯度越集中在难负例上，假负例的伤害也越大；难负例的比例要适中，并与批内负例搭配使用。

**评分要点（共 10 分）：**

- 说明难负例提供更大的梯度、帮助模型做细粒度区分（3 分）
- 给出至少两种难负例来源（BM25、模型自身检索、业务规则）（3 分）
- 说明假负例的成因与处理方法（过滤、跳过头部、批内去重）（3 分）
- 提到温度或难负例比例与假负例风险的关系（1 分）

**讲解：**

**常见失分点**：只说「难负例更难所以更好」，讲不出梯度上的原因；把排名第 1 的非正例直接当负例，不考虑假负例；不知道难负例需要随模型更新而刷新。

<sub>考点：难负例、领域微调</sub>

</details>

<a name="RAG-EMB-028"></a>

### RAG-EMB-028　进阶 · 考频 ★★★

请比较 IVF（及 IVF-PQ）与 HNSW 两类 ANN 索引：原理、可调参数、内存、召回与延迟、更新与删除，并说明在什么场景下选哪一种。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **原理**：
   - IVF：用 k-means 把向量聚成 nlist 个簇，每个向量挂在最近的簇中心下（倒排表）；查询时找最近的 nprobe 个簇，只在这些簇内精确比较。IVF-PQ 再用乘积量化压缩簇内向量（通常编码的是向量与簇中心的残差）。
   - HNSW：分层的近邻图。查询从最高层的入口贪心下降，在底层用候选队列做束搜索。
2. **参数**：IVF 有 nlist（建索引时确定）与 nprobe（查询时可调）；PQ 有分段数 m 与每段码本大小；HNSW 有 M（每个节点的邻居数）、efConstruction（建图质量）与 efSearch（查询时可调）。
3. **内存**：HNSW 要存原始向量加邻接表，内存最大；IVF-Flat 存原始向量加少量簇中心；IVF-PQ 只存压缩码（每个向量几十字节），内存可以降低一两个数量级。
4. **召回与延迟**：内存充足时，HNSW 通常能以很低的延迟达到很高的召回；IVF 在 nprobe 较小时受簇边界影响（近邻落在相邻的簇里）；PQ 有量化误差，常需要用原始向量对候选重排。
5. **更新与删除**：IVF 新增向量直接挂到最近的簇，但数据分布漂移后要重新训练簇中心；HNSW 支持增量插入，但删除通常只能打标记，积累多了要重建。
6. **选型**：
   - 千万级以内、内存充足、要求低延迟高召回：HNSW；
   - 亿级以上或内存受限：IVF-PQ 加原始向量重排，或 DiskANN 这类磁盘图索引；
   - 十万级以内或需要精确结果：暴力检索；
   - 无论选哪种，都要以暴力检索的结果为标准答案，按召回目标调 nprobe 或 efSearch。

**评分要点（共 10 分）：**

- 正确说明 IVF 与 HNSW 的原理（3 分）
- 说出两者的关键参数及其对召回、延迟的影响（2 分）
- 比较内存占用，并说明 PQ 的压缩作用（2 分）
- 说明更新、删除、数据漂移等运维差异（1 分）
- 给出合理的选型结论（2 分）

**讲解：**

**常见失分点**：把 HNSW 说成精确检索；不知道 IVF 需要训练、数据漂移后要重训；只说「HNSW 最好」，忽略它的内存代价；混淆 nlist 与 nprobe、efConstruction 与 efSearch。

<sub>考点：IVF、HNSW、召回与延迟权衡</sub>

</details>

## 场景分析题

<a name="RAG-EMB-040"></a>

### RAG-EMB-040　挑战 · 考频 ★★

某平台的向量检索目前用单机 HNSW（768 维 float32，M = 16），500 万个向量，P99 延迟 15 ms，Recall@10 = 0.97。业务预计一年内增长到 5 亿个向量，要求 P99 延迟 < 50 ms、Recall@10 ≥ 0.95，机器内存为每台 256 GB。请估算增长后的内存需求，给出可行的索引与部署方案，并说明如何调参和验证。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 内存估算**
- 原始向量：$5\times10^8\times768\times4\approx1.54$ TB；
- HNSW 邻接表（底层 2M = 32 个 4 字节 id）：$5\times10^8\times128$ 字节，约 64 GB；
- 合计约 1.6 TB，单机 256 GB 远远放不下，必须压缩、分片或改用磁盘索引。

**2. 候选方案**
- **方案 A：分片 + HNSW + 标量量化**。int8 标量量化把向量压到 1/4（约 384 GB），加上邻接表约 450 GB，至少分到 3 台机器（留出余量通常要 4 台以上）；查询并行发往各分片，各取 top-k 后合并。召回损失小，但机器多、成本高。
- **方案 B：IVF-PQ + 原始向量重排**。PQ（如 $m=96$，每个向量 96 字节）编码共约 48 GB，可以放进单台或少量机器；用 nprobe 控制扫描量，先取 top-200 候选，再从 SSD 读取原始向量精确重排得到 top-10。成本低，但量化损失要靠重排补回，参数需要仔细调。
- **方案 C：DiskANN 类磁盘图索引**。图和原始向量放在 SSD 上，内存中只放 PQ 压缩向量（约 48 GB），单机即可支撑十亿级规模；延迟受 SSD 随机读影响，通常在几毫秒到几十毫秒。
- 选型：预算充足、延迟要求最严时选 A；成本敏感时在 B、C 中按团队技术栈选择。很多向量数据库（如 Milvus）内置了 IVF-PQ、DiskANN、分片与副本，可以减少自研工作量。

**3. 调参与验证**
- 从线上采样查询，用暴力检索（可以离线在 GPU 上批量计算）生成标准答案；
- 扫描 nprobe、efSearch、重排候选数等参数，画出 Recall@10 与 P99 延迟的曲线，选出满足 Recall ≥ 0.95 且 P99 < 50 ms 的最便宜配置；
- 压测高并发与带过滤条件的查询；上线后定期抽样对比暴力检索、监控召回；簇中心与量化码本随数据分布漂移要定期重训。

**评分要点（共 10 分）：**

- 正确估算原始向量与邻接表的内存量级，指出单机放不下（2 分）
- 给出分片、量化、IVF-PQ 加重排或磁盘索引等至少两种可行方案（3 分）
- 说明各方案在召回、延迟、成本上的取舍（2 分）
- 给出以暴力检索为标准答案、扫参绘制召回—延迟曲线的验证方法（2 分）
- 提到过滤查询、码本或簇中心重训、线上召回监控等运维要点（1 分）

**讲解：**

**常见失分点**：不做内存估算就说「换成向量数据库」；只说「加机器」，不考虑量化与压缩；用了 PQ 却不做重排，召回不达标；没有以暴力检索为标准答案的召回评估。
