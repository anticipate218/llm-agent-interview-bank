## 单选题

<a name="SEC-REL-001"></a>

### SEC-REL-001　进阶 · 考频 ★★★

某 RAG 问答系统检索到的产品文档写着「标准版月费 99 元」（这份文档已经过时）。模型没有采用文档，而是凭自己的参数知识回答「标准版月费 129 元」，而 129 元恰好是现行的真实价格。按「事实性幻觉 / 忠实性幻觉」的划分（Huang 等的幻觉综述），对这个回答最准确的判断是：

- **A.** 答案与现实一致，模型只是用更新的参数知识纠正了过时文档，既不算事实性问题，也不算忠实性问题
- **B.** 与给定上下文不一致，属于忠实性问题；事实上虽然对，在要求依据资料作答的系统里仍是缺陷
- **C.** 答案与检索到的文档不符，说明模型在资料之外编造了内容，属于事实性幻觉中的事实捏造
- **D.** 属于逻辑不一致：模型先检索了写着 99 元的资料，最终却给出 129 元，前后互相矛盾

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：事实性与忠实性是两个独立的维度。事实性看输出与真实世界是否一致；忠实性看输出与用户指令、给定上下文是否一致，以及自身是否前后一致。这个回答「事实上对、但不忠实」。

**为什么仍是缺陷**：RAG 系统的价值在于「凭资料答、可溯源」。模型绕开资料、凭记忆作答，这次碰巧对了，下次参数知识出错时同样会绕开资料，而且引用无法为它作证。正确的处理是：更新过时的文档（数据新鲜度问题）；当参数知识与资料冲突时，按资料作答并提示「资料可能已过时」，而不是悄悄替换。

- A 错：只看最终对错，忽略了与上下文不一致这一可靠性问题。
- C 错：事实捏造指编造无法核实的内容（如不存在的论文）；这里的问题是与上下文不一致，而且答案本身符合事实。
- D 错：逻辑不一致指模型自己的推理步骤之间、或步骤与结论之间的矛盾，例如推出 2x = 8 后写出 x = 3；与给定资料矛盾属于上下文不一致。

<sub>考点：幻觉类型　｜　出处：A Survey on Hallucination in Large Language Models arXiv:2311.05232</sub>

</details>

<a name="SEC-REL-003"></a>

### SEC-REL-003　挑战 · 考频 ★

Kalai 等（OpenAI，2025）在《Why Language Models Hallucinate》中把幻觉看作一种「二分类错误」，并给出了预训练阶段的一个下界：对于生日这类没有规律可循的「任意事实」，在一定假设下，基础模型在这类问题上的幻觉率大致不低于：

- **A.** 这类事实在训练数据中只出现过一次的比例（singleton rate）
- **B.** 训练语料中错误或相互矛盾的陈述所占的比例（即「垃圾进、垃圾出」）
- **C.** 模型参数量与训练 token 数之比（参数相对数据越少，越记不住任意事实）
- **D.** 评测集与训练集发生重叠（数据污染）的比例，重叠越多测得的幻觉率越低

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：论文的直观结论是，预训练后的幻觉率至少约等于「只在训练数据中出现过一次的事实」所占的比例。例如若 20% 的生日事实在训练数据中只出现过一次，基础模型在这类问题上预计至少有约 20% 会出错。

**直觉**：只见过一次的事实，在统计上与从未见过的事实很难区分（这与估计「未见过的概率质量」的 Good-Turing 方法同源）。生成一个正确答案比判断一个答案对不对更难：如果模型连「是否有效」都分不清，生成时必然会产出一部分看似合理、实则错误的内容。

- B 错：论文特别强调，即使训练数据完全没有错误，这个下界依然存在；数据中的错误只会让情况更糟。
- C、D 错：与论文给出的下界无关。

论文的第二个论点是：后训练之后幻觉仍然顽固，是因为主流评测按「答对得分、答错与不答都不得分」计分，奖励的是猜测而不是承认不确定。

<sub>考点：幻觉成因　｜　出处：Why Language Models Hallucinate arXiv:2509.04664</sub>

</details>

<a name="SEC-REL-007"></a>

### SEC-REL-007　基础 · 考频 ★★

SelfCheckGPT（Manakul 等，2023）不需要外部知识库，也不需要读取模型的输出概率，就能检测生成内容中的幻觉。它依据的基本假设是：

- **A.** 模型会给自己确信的内容赋予更高的 token 概率，所以逐句检查概率，概率低的句子就是幻觉
- **B.** 只要回答中给出了引用来源，就可以认为其中没有幻觉，无需再做一致性检查
- **C.** 温度设为 0 时得到的回答一定符合事实，可以作为判断其他采样回答是否幻觉的参照
- **D.** 对模型真正知道的事实，多次采样的回答会彼此一致；编造的内容在采样之间容易互相矛盾

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：SelfCheckGPT 用「自洽性」代替外部知识：对同一个问题多次采样，检查主回答中的每个句子能否得到其他采样的支持。

它是「零资源」的（不需要外部数据库）、「黑盒」的（不需要 token 概率，适合只能调 API 的场景）。衡量一致性的方式有多种：BERTScore、基于问答的比对、n-gram、NLI，或直接让 LLM 判断。

- A 错：利用 token 概率属于「灰盒」方法，SelfCheckGPT 恰恰不依赖它；而且低概率不等于错误。
- B 错：引用可能是编造的，被引资料也未必支持该说法，必须核验。
- C 错：贪心解码只是选概率最高的路径，模型照样可能稳定地答错。

**局限**：要多次采样，成本成倍增加；对模型「每次都一致地答错」的情况（如训练数据中普遍存在的误解）无能为力。

<sub>考点：幻觉检测　｜　出处：SelfCheckGPT arXiv:2303.08896（EMNLP 2023）</sub>

</details>

<a name="SEC-REL-011"></a>

### SEC-REL-011　基础 · 考频 ★★

某数据分析 Agent 根据用户的问题查询销售数据库，再用自然语言写出分析结论。抽检发现，结论里的数字时常与查询结果不一致：把 12.4% 写成 14.2%，或者凭空给出一个同比增幅。下列改进中最能从根本上解决问题的是：

- **A.** 数字全由代码计算，结论用占位符引用、由程序填入，输出前核对每个数字都有出处
- **B.** 把采样温度调到 0 消除随机性，并在提示词中强调「务必逐个核对数字，不得自行估算」
- **C.** 换一个参数量更大、数学推理能力更强的模型来撰写结论，并让它在结论后附上计算过程
- **D.** 在结论末尾加上免责声明「以上数字仅供参考，请以系统数据为准」，并附上原始查询结果的链接

<details>
<summary>答案与解析</summary>

**答案：A**

**解析：**

**结论**：让模型「抄写」或「心算」数字本身就容易出错，根本的办法是让数字不经过模型的自由生成。计算交给确定性的工具，模型只负责组织语言并引用计算结果，最后再用程序核对。这是「受约束生成」与「工具落地」的思路。

- B 错：温度为 0 只消除采样的随机性，消除不了系统性的抄错、算错；提示词强调属于概率性措施。
- C 错：更大的模型出错更少，但没有保证，成本也更高；附上的「计算过程」同样由模型生成，未必可靠。
- D 错：免责声明不减少任何错误，还把核对的负担推给了用户。

**延伸**：核对时还要识别「派生数字」（如增幅、占比），它们也必须由代码算出，不能让模型根据两个数字自己去算。

<sub>考点：幻觉缓解</sub>

</details>

<a name="SEC-REL-012"></a>

### SEC-REL-012　基础 · 考频 ★★

说一个模型「校准良好」（well-calibrated），指的是：

- **A.** 模型在测试集上的准确率很高，并且在不同子集、不同分布上的准确率也都很接近
- **B.** 对同一个问题多次采样，模型给出的答案总是彼此一致，不会出现前后矛盾
- **C.** 模型给出约 80% 置信度的预测中，大约 80% 是对的；其他置信度区间同理
- **D.** 模型对绝大多数预测都给出 0.9 以上的置信度，回答果断、从不犹豫

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：校准描述的是「置信度与实际正确率是否一致」，与准确率高低是两回事。

一个准确率只有 60% 的模型，如果每次都诚实地给出约 60% 的置信度，它就是校准良好的；一个准确率 90% 的模型，若总是报 99% 的置信度，就是过度自信。校准良好的意义在于置信度可以直接用来做决策：低于阈值就拒答、转人工或调用检索。

常用的检查方法是可靠性图（按置信度分箱，画每箱的平均置信度与实际正确率）和期望校准误差（ECE）。

- A 错：准确率高、跨分布稳定说的是准确率与鲁棒性，不代表置信度可信。
- B 错：那是一致性，与校准有关联，但不是同一个概念；模型可能稳定地、自信地答错。
- D 错：校准看的是置信度与正确率是否匹配，而不是置信度高不高；准确率达不到 90% 的模型这样做，恰恰是过度自信。

<sub>考点：不确定性与校准　｜　出处：On Calibration of Modern Neural Networks arXiv:1706.04599</sub>

</details>

<a name="SEC-REL-019"></a>

### SEC-REL-019　基础 · 考频 ★★

公司想把客服对话发给第三方大模型 API 生成摘要。对话中含有客户的手机号和身份证号；摘要需要保留「哪句话是哪位客户说的」这种指代关系，事后还要能对应回具体客户。下列方案中最合适的是：

- **A.** 原样发送：第三方已在协议中承诺不会用 API 数据训练模型，数据在传输中也有 TLS 加密
- **B.** 把整段对话做 base64 编码后再发送：模型照样能解码读懂，第三方的日志和监控里却不会再出现明文
- **C.** 用一致的占位符替换敏感字段（同一号码始终换成同一个 <PHONE_1>），映射表留在本地，摘要返回后还原
- **D.** 用正则把对话中所有手机号、身份证号替换成统一的「***」后再发送，摘要返回后直接使用

<details>
<summary>答案与解析</summary>

**答案：C**

**解析：**

**结论**：这是「假名化」：用一致的占位符替换敏感字段，第三方看不到真实信息，指代关系又得以保留，映射表不出本系统，结果可以在本地还原。

- A 错：不训练不等于不处理，TLS 也只保护传输过程。数据仍被第三方处理，可能被日志保留；按数据最小化原则，第三方不需要的个人信息就不该发出去。
- B 错：base64 只是编码，不是加密，任何人都能还原；模型要理解内容就必须解码，第三方照样拿到全部信息，日志里的 base64 串也等同于明文。
- D 错：统一换成「***」会丢掉「哪句话是哪位客户说的」这种指代关系，事后也无法对应回具体客户；姓名、地址等也不是正则能找全的。

**注意**：假名化后的数据在 GDPR 下仍属于个人数据（借助映射表可以重新识别），仍需合法依据、数据处理协议等安排；姓名、地址等要用实体识别模型找出；高度敏感的数据宜用私有化部署的模型处理。

<sub>考点：隐私与PII　｜　出处：GDPR Recital 26</sub>

</details>

<a name="SEC-REL-023"></a>

### SEC-REL-023　进阶 · 考频 ★★

某公司用客服对话（其中含用户的个人信息）微调了自有模型，并已上线。一位用户依法要求删除其个人信息。下列说法最准确的是：

- **A.** 从原始数据库中删除该用户的对话即可：微调只是更新了权重，并不保存原文，删除义务到原始数据为止
- **B.** 模型权重只是一堆浮点参数，无法从中直接读出任何一条训练样本，因此不构成个人信息，无需考虑模型
- **C.** 删除原始对话，并在模型输出端加一个过滤器屏蔽该用户的姓名和手机号，即可视为删除完成
- **D.** 删除原始与派生数据，评估模型是否记住了该用户的信息，必要时剔除后重训或回退版本；机器遗忘多为近似

<details>
<summary>答案与解析</summary>

**答案：D**

**解析：**

**结论**：删除权要求「删干净」，这对训练进了模型的数据尤其困难。

- A 错：派生数据也要删，索引、缓存、评测集、分析报表中用到的这个人的信息同样在删除范围内；而且模型可能已经记住了这些数据，不能一删了之。
- B 错：模型可能记住训练数据。研究表明，大模型能逐字复现训练数据中的部分内容（包括姓名、电话等），用合适的提示就能抽取出来。
- C 错：输出过滤不等于删除。信息仍在模型和派生数据中，换种问法、换个字段就可能被引出。
- D 对：覆盖了原始数据、派生数据和模型三个层面，并如实说明了机器遗忘的局限。

对模型的处理方式：评估是否记住（用该用户的特有信息做探测）；能重训就在剔除数据后重训，或回退到未包含该数据的版本；机器遗忘可以作为补充，但多为近似方法，很难证明已彻底遗忘。我国《个人信息保护法》第四十七条第二款还规定：删除从技术上难以实现的，应当停止除存储和采取必要的安全保护措施之外的处理。

**更好的设计**：个人信息尽量不进训练数据（训练前去标识化），需要个性化的信息放在可删除的检索库或记忆里；记录数据血缘，知道每个模型版本用了哪些数据。

<sub>考点：数据合规　｜　出处：《个人信息保护法》第四十七条；Extracting Training Data from Large Language Models arXiv:2012.07805</sub>

</details>

### SEC-REL-026　进阶 · 考频 ★★

团队计划基于 DeepSeek-R1-Distill-Llama-8B 开发并商用一款产品。下列判断正确的是：

- **A.** DeepSeek-R1 以 MIT 许可发布并允许蒸馏等衍生使用，所以由它蒸馏出的 Distill-Llama-8B 也只受 MIT 许可约束
- **B.** 它以 Llama 3.1 8B 为基座，还需遵守 Llama 3.1 社区许可，如标注「Built with Llama」、遵守可接受使用政策
- **C.** 只要权重公开可下载，就属于 OSI 定义的开源软件，可以像 Apache 2.0 项目一样不受附加条件地商用
- **D.** 只做推理部署、不修改也不再分发权重时，许可证中的标注义务和使用政策都不适用

<details>
<summary>答案与解析</summary>

**答案：B**

**解析：**

**结论**：派生模型要同时满足上游基座模型的许可条件。DeepSeek-R1 的模型卡写明：R1 本身（代码与权重）采用 MIT 许可；基于 Qwen2.5 蒸馏的版本源自 Apache 2.0 许可的模型；Distill-Llama-8B 源自 Llama 3.1 8B Base，受 Llama 3.1 许可约束（Distill-Llama-70B 则对应 Llama 3.3 许可）。

Llama 3.1 社区许可的几项关键条件：分发时附上许可文本并显著标注「Built with Llama」；在版本发布时，产品月活超过 7 亿的企业须向 Meta 另行申请许可；用 Llama 或其输出训练并发布新模型时，名称开头要带「Llama」；使用须遵守可接受使用政策。

- A 错：MIT 只覆盖 DeepSeek 自己的权利，改变不了基座模型的许可。
- C 错：开放权重不等于开源。Llama 许可附有用途限制和月活门槛，开放源代码促进会（OSI）不认为它符合开源定义。
- D 错：可接受使用政策约束的正是「怎么用」；对外提供服务或分发产品时，标注等义务也随之产生。

<sub>考点：版权与许可　｜　出处：DeepSeek-R1 模型卡（https://huggingface.co/deepseek-ai/DeepSeek-R1）；Llama 3.1 Community License</sub>

</details>

<a name="SEC-REL-002"></a>

### SEC-REL-002　基础 · 考频 ★★

下列模型输出中，属于**忠实性幻觉**（与用户指令、给定上下文不一致，或自身前后矛盾）的有：

- **A.** 基于用户提供的保修条款回答问题，条款写着「整机保修 2 年」，模型却回答「整机保修 1 年」
- **B.** 用户请模型推荐几篇相关论文，模型列出了一篇并不存在的论文，连作者、期刊和年份都写得有模有样
- **C.** 用户要求「把这段英文翻译成中文」，模型没有翻译，而是直接回答了这段英文里提出的问题
- **D.** 解方程时，模型前一步已经推出 2x = 8，下一步却写出 x = 3，并以此作为最终答案
- **E.** 用户问「电话是谁发明的」，模型自信地回答「电话是爱迪生在 1876 年发明的」

<details>
<summary>答案与解析</summary>

**答案：ACD**

**解析：**

**结论**：A、C、D 属于忠实性幻觉，B、E 属于事实性幻觉。

Huang 等的综述把幻觉分为两大类：**事实性幻觉**与可核实的现实知识不符，又分为事实矛盾（实体或关系错误）和事实捏造（编造无法核实的内容）；**忠实性幻觉**与用户输入或上下文不一致，或自相矛盾，又分为指令不一致、上下文不一致和逻辑不一致。

- A 对：与用户提供的条款矛盾，属于上下文不一致。
- B 错：编造不存在的论文属于事实捏造，是事实性幻觉；模型并没有违背「推荐论文」这一指令。
- C 对：没有执行「翻译」这一指令，偏离了用户的要求，属于指令不一致。
- D 对：前后推理步骤互相矛盾，属于逻辑不一致。
- E 错：电话通常归功于贝尔（1876 年获得专利），说成爱迪生是与现实知识不符的事实矛盾，属于事实性幻觉。

区分两类的意义在于对症下药：事实性幻觉多与知识边界有关（长尾、过时、错误知识），常用检索增强、引用与拒答来缓解；忠实性幻觉多与指令遵循、对上下文的利用有关，常用约束生成、引用核验、改进提示与训练来缓解。

<sub>考点：幻觉类型　｜　出处：A Survey on Hallucination in Large Language Models arXiv:2311.05232</sub>

</details>

<a name="SEC-REL-010"></a>

### SEC-REL-010　进阶 · 考频 ★★★

下列做法中，**能够**缓解大模型幻觉的有：

- **A.** 调高采样温度、增加采样的多样性，让模型「自由发挥」，以覆盖更多可能正确的答案
- **B.** 要求回答为每个关键陈述给出引用，并用 NLI 或规则核对引用是否真的支持该陈述
- **C.** 收集几千条包含最新事实的问答对做 SFT，把模型原本不知道的新知识直接灌进参数里
- **D.** 在评测与奖励中，对「自信地答错」的扣分高于「回答不知道」，鼓励模型在没把握时拒答
- **E.** 对实体 ID、枚举值这类字段使用受约束解码，只允许生成数据库中真实存在的取值

<details>
<summary>答案与解析</summary>

**答案：BDE**

**解析：**

**结论**：B、D、E 正确。

- A 错：温度越高越容易采到低概率 token，事实类任务通常应降低温度。
- B 对：引用让答案可追溯，核验让「编造的引用」「引用不支持说法」这两类问题现形。只给引用、不做核验，作用有限。
- C 错：Gekhman 等（2024）发现，模型原本不掌握的新知识在 SFT 中学得慢，学会之后反而会提高幻觉倾向。注入新知识应交给检索或继续预训练。
- D 对：Kalai 等（2025）指出，只按对错计分的评测会奖励猜测；给「不知道」留分、对答错扣分，模型才有动力在没把握时拒答。
- E 对：受约束解码（如基于语法或枚举的约束）从机制上排除了「编出一个不存在的 ID」这类幻觉，适合结构化输出。

<a name="SEC-REL-015"></a>

### SEC-REL-015　挑战 · 考频 ★

关于大模型的不确定性估计，下列说法**正确**的有：

- **A.** 语义熵先按语义等价（如双向蕴含）把多次采样的回答聚类，再在簇上计算熵；簇越分散，越可能是在编造
- **B.** 让模型用文字报告置信度（如「我有 90% 的把握」）通常就是校准良好的，可以直接当作概率使用
- **C.** GPT-4 技术报告显示，预训练模型在 MMLU 子集上校准良好，而经过后训练之后校准明显变差
- **D.** 语义熵擅长发现模型「每次说法都不一样」的编造，但对模型稳定地、一致地答错（例如训练数据中普遍存在的误解）无能为力
- **E.** 对自由文本回答，直接用整句的 token 概率衡量不确定性有缺陷：同一个意思有多种说法，概率会被分散到不同措辞上

<details>
<summary>答案与解析</summary>

**答案：ACDE**

**解析：**

**结论**：A、C、D、E 正确。

- A 对：这是 Farquhar 等（Nature，2024）的方法，可用任何 NLI 模型或 LLM 判断双向蕴含。
- B 错：研究普遍发现，模型口头报告的置信度往往偏高（过度自信），而且对提示措辞敏感，需要校准或结合采样一致性等其他信号才能使用。
- C 对：GPT-4 技术报告的校准图显示，预训练模型的置信度与正确率高度一致，后训练（报告中标注为 PPO 模型）后校准明显变差。这也是 RLHF 后的模型「说得很自信」的原因之一。
- D 对：熵衡量的是回答的分散程度；模型稳定地给出同一个错误答案时熵很低，需要靠检索核验等外部手段发现。
- E 对：「巴黎」「是巴黎」「法国首都巴黎」意思相同，概率却分散在不同序列上，单看序列概率会高估不确定性。这正是语义熵要解决的问题。

<a name="SEC-REL-021"></a>

### SEC-REL-021　进阶 · 考频 ★★

关于大模型应用中的个人信息（PII）保护，下列做法或说法**正确**的有：

- **A.** 需要保留还原能力时可以用令牌化：敏感值换成随机令牌，映射表单独加密保存，只在受控环境中按权限还原
- **B.** 日志、Trace、评测样本与向量库同样会保存个人信息，脱敏和访问控制不能只做在模型输入这一处
- **C.** 为了方便排障，可以在提示词和日志中保留完整的身份证号，只在最终回答里打码
- **D.** 脱敏应尽量在数据进入系统的最早环节完成，并在模型输出和工具参数处再做一次出口检测
- **E.** 文本嵌入在相当程度上可以被反推出原文，向量应与原文按同等级别保护

<details>
<summary>答案与解析</summary>

**答案：ABDE**

**解析：**

**结论**：A、B、D、E 正确。

- A 对：令牌化（tokenization）是可逆的假名化：日志、分析、第三方模型看到的都是令牌，真实值只存在于加密的映射表中，排障、对账等确需原值时按权限申请还原，还原操作本身也要审计。注意令牌化后的数据仍属于个人数据。
- B 对：大模型应用里，个人信息会沿着日志、Trace、缓存、评测集、向量库、长期记忆一路扩散；每一处都要脱敏、控制访问、设定保留期。
- C 错：提示词和日志恰恰是最容易外流的地方（第三方模型服务、日志平台、排障人员）；排障需要原值时，应走令牌化后按权限还原的流程，而不是留着明文。
- D 对：越早脱敏，扩散面越小；出口检测则防止模型把上下文中的个人信息写进回答或外发的工具参数（对应 OWASP LLM02 敏感信息泄露）。
- E 对：Morris 等（2023）的研究表明，文本嵌入能在相当程度上被还原成原文，向量库不能当作「已脱敏」的存储。

**识别手段**：正则适合格式固定的号码（配合校验位减少误报），对姓名、地址、自由描述的身份信息几乎无能为力；生产中通常是「规则 + 实体识别模型 + 校验 + 人工抽检」的组合，召回率要单独评估。

<sub>考点：隐私与PII、审计与可解释　｜　出处：Text Embeddings Reveal (Almost) As Much As Text arXiv:2310.06816；OWASP LLM02:2025</sub>

</details>

## 判断题

<a name="SEC-REL-004"></a>

### SEC-REL-004　进阶 · 考频 ★★

即使预训练语料中的每一条陈述都是正确的，按标准的预训练目标训练出来的语言模型仍然会产生幻觉。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。Kalai 等（2025）明确指出：即使训练数据没有错误，语言模型训练所优化的目标也会导致模型生成错误。原因包括：

- **任意事实无规律可学**：像个人生日这样只出现一两次的事实，模型无法从模式中推出，只能在若干看似合理的答案之间分配概率，生成时就会说出错误的那个；
- **能力与容量的限制**：模型表示不了某些规律，或推理能力不足（如多跳推理、「A 是 B」学会后推不出「B 是 A」的逆转诅咒）；
- **生成比判别更难**：分不清对错的地方，生成时必然会出错。

所以清洗数据只能去掉「照抄错误知识」这一类成因。要真正压低幻觉，还需要让模型学会在没把握时拒答（后训练与评测的激励要配合）、用检索补齐知识、用引用和校验兜底。

<sub>考点：幻觉成因　｜　出处：Why Language Models Hallucinate arXiv:2509.04664</sub>

</details>

<a name="SEC-REL-014"></a>

### SEC-REL-014　进阶 · 考频 ★★

温度缩放（temperature scaling）在验证集上学习一个标量 $T$，把 logits 除以 $T$ 后再做 Softmax。它在改善校准的同时，也会改变模型的 Top-1 预测，从而改变分类准确率。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。所有 logits 都除以同一个正数 $T$，它们之间的大小顺序不变，argmax 不变，所以 Top-1 预测和准确率都不变。变化的只是概率分布的「尖锐程度」：$T>1$ 让分布更平，降低置信度，用来纠正过度自信；$T<1$ 则相反。

正因为不影响准确率、只需在验证集上拟合一个参数，温度缩放成了最常用的事后校准方法（Guo 等，2017）。它的局限是只有一个全局参数，修正不了「某些区间过度自信、另一些区间自信不足」这类方向不一致的偏差。

注意区分：生成式模型做**采样**时，温度会改变采样分布，从而改变采样到的文本；但贪心解码（每步取 argmax）的结果不受温度影响。

<sub>考点：不确定性与校准　｜　出处：On Calibration of Modern Neural Networks arXiv:1706.04599</sub>

</details>

<a name="SEC-REL-017"></a>

### SEC-REL-017　基础 · 考频 ★★

XSTest 用一批措辞上像有害请求、实际完全无害的提示（例如「怎么杀掉一个 Python 进程」），来检测模型的「夸大安全」（exaggerated safety）行为，也就是过度拒答。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。XSTest（Röttger 等，NAACL 2024）包含 250 条安全提示，分属同形异义词、比喻说法、安全语境、定义类问题等 10 种类型，校准良好的模型不应拒绝它们；另有 200 条不安全的对照提示，模型应当拒绝。两组一起看，才能同时衡量「该拒的拒了没有」和「不该拒的有没有乱拒」。

过度拒答不是无害的保守：它直接损害有用性和用户信任，用户还可能转向更不安全的渠道。它的常见成因是安全训练依赖表面关键词（「杀」「攻击」「炸」），而不是理解真实意图。所以发布安全更新时，要把有害请求拒答率与过度拒答率放在一起报告。

</details>

<a name="SEC-REL-024"></a>

### SEC-REL-024　基础 · 考频 ★★

从向量库中删除某份文档对应的全部向量之后，这份文档的内容就不可能再出现在系统的回答中。

<details>
<summary>答案与解析</summary>

**答案：❌ 错误**

**解析：**

**错误**。向量库只是这份文档的一个落脚点，它的内容还可能存在于：

- **其他副本**：同一内容被多次入库、转载进别的文档，或存在近似重复的版本；
- **缓存**：语义缓存中已有的答案、检索结果缓存；
- **派生数据**：从文档中抽取的摘要、知识图谱、长期记忆、FAQ；
- **日志与评测集**：历史问答记录中带着原文片段；
- **存储层**：许多存储引擎的删除先是逻辑删除（打墓碑），物理清除要等段合并或压缩；备份与快照中仍有旧数据；
- **模型参数**：如果这份文档曾用于微调，模型可能记住了其中的内容。

所以删除要依靠数据血缘：从源头文档出发找到所有副本与派生物，一并删除或重建，并用检索与问答做验证。

<sub>考点：数据合规</sub>

</details>

<a name="SEC-REL-030"></a>

### SEC-REL-030　进阶 · 考频 ★★

研究发现，推理模型在思维链中常常不会提及实际影响其答案的因素（例如提示中暗含的线索），因此不能把模型输出的思维链直接当作其决策依据的可靠审计证据。

<details>
<summary>答案与解析</summary>

**答案：✅ 正确**

**解析：**

**正确**。Turpin 等（2023）发现，在少样本提示中把正确答案都排在选项 A 等「偏置特征」会明显影响模型的答案，而模型的思维链几乎从不提到这些特征，反而给出看似合理的另一套理由。Anthropic 的 Chen 等（2025）在推理模型上做了类似实验：在提示中埋入线索后，模型确实利用了线索，但思维链提到线索的比例常常低于 20%。思维链监控有助于发现问题，但不足以排除问题。

**对审计的启示**：
- 可审计的依据应当是可核对的事实：输入、检索到的文档及版本、工具调用的参数与结果、触发的规则与策略、审批记录；
- 关键决策尽量由确定性规则做出（「模型提建议，规则做决定」），解释由规则与证据生成；
- 思维链可以作为辅助材料保存，但不能当作「模型为什么这样做」的权威说明。

<sub>考点：审计与可解释　｜　出处：Language Models Don't Always Say What They Think arXiv:2305.04388；Reasoning Models Don't Always Say What They Think arXiv:2505.05410</sub>

</details>

## 填空题

<a name="SEC-REL-022"></a>

### SEC-REL-022　进阶 · 考频 ★

按 GDPR 第 26 条叙述（Recital 26）：借助单独保存的额外信息（如映射表）仍能识别到具体个人的数据，即经过 ____ 处理的数据，仍然属于个人数据；只有经过 ____ 处理、用合理可能的手段都无法再识别到个人的数据，才不再受 GDPR 约束。

<details>
<summary>答案与解析</summary>

**答案：** (1) 假名化 / 去标识化 / pseudonymisation / pseudonymization；(2) 匿名化 / anonymisation / anonymization

**解析：**

- **假名化**：用占位符或令牌替换直接标识符，映射关系另行保存。它能降低风险，但持有映射表的一方（或能拿到其他辅助信息的人）仍可重新识别，所以数据仍是个人数据，处理依然要有合法依据。
- **匿名化**：处理后无法再识别到个人，判断标准是「考虑所有合理可能使用的手段」，包括成本、时间和现有技术。

我国《个人信息保护法》有对应的概念：第七十三条把「去标识化」定义为在不借助额外信息的情况下无法识别特定自然人，把「匿名化」定义为无法识别特定自然人且不能复原；第四条规定个人信息不包括匿名化处理后的信息。

## 计算题

<a name="SEC-REL-013"></a>

### SEC-REL-013　挑战 · 考频 ★★

某多分类模型在 20 条验证样本上的预测，按最高类别的置信度分到 5 个等宽箱中（另外两个箱为空）：

| 置信度区间 | 样本数 | 平均置信度 | 预测正确数 |
|---|---|---|---|
| (0.8, 1.0] | 10 | 0.90 | 7 |
| (0.6, 0.8] | 6 | 0.70 | 3 |
| (0.2, 0.4] | 4 | 0.30 | 3 |

(1) 计算期望校准误差 ECE。
(2) 如果只用 1 个箱计算（即整体平均置信度与整体准确率之差的绝对值），结果是多少？为什么与 (1) 相差这么大？
(3) 若用温度缩放（统一把 logits 除以 $T>1$）来校准，对各箱分别会产生什么影响？准确率会变吗？

<details>
<summary>答案与解析</summary>

**答案：(1) ECE = 0.25；(2) 0.07，高置信箱的过度自信与低置信箱的自信不足相互抵消；(3) 高置信箱的过度自信缓解，低置信箱的自信不足反而加剧，准确率不变**

**解析：**

**(1)** $\mathrm{ECE}=\sum_m\dfrac{|B_m|}{N}\big|\mathrm{acc}(B_m)-\mathrm{conf}(B_m)\big|$：
- (0.8, 1.0]：准确率 $7/10=0.70$，与 0.90 差 0.20，权重 $10/20$，贡献 0.10；
- (0.6, 0.8]：准确率 $3/6=0.50$，与 0.70 差 0.20，权重 $6/20$，贡献 0.06；
- (0.2, 0.4]：准确率 $3/4=0.75$，与 0.30 差 0.45，权重 $4/20$，贡献 0.09。

$\mathrm{ECE}=0.10+0.06+0.09=$ **0.25**。

**(2)** 整体准确率 $13/20=0.65$；整体平均置信度 $(10\times0.9+6\times0.7+4\times0.3)/20=14.4/20=0.72$，差 **0.07**。前两个箱过度自信（置信度高于准确率），最后一个箱自信不足（置信度低于准确率），合在一起时正负抵消。所以 ECE 必须分箱计算；分箱数、分箱方式（等宽或等频）也会影响结果，报告时要写明。

**(3)** 温度缩放用一个全局标量 $T$。$T>1$ 让每条预测的最高概率向均匀分布 $1/K$ 靠拢：高置信箱的置信度下降，过度自信得到缓解；低置信箱的置信度也会进一步下降，而它原本就自信不足，误差反而加大。一个标量无法同时修正方向相反的偏差，需要直方图分箱、保序回归等更灵活的方法。

所有 logits 除以同一个正数不改变它们的大小顺序，Top-1 预测不变，所以**准确率不变**，变的只是置信度。

<sub>考点：不确定性与校准　｜　出处：On Calibration of Modern Neural Networks arXiv:1706.04599</sub>

</details>

<a name="SEC-REL-016"></a>

### SEC-REL-016　进阶 · 考频 ★★

在同一份 100 题的知识问答评测上：
- 模型 A 从不拒答：答对 60 题，答错 40 题；
- 模型 B 在没把握时会回答「不知道」：拒答 30 题，答对 58 题，答错 12 题。

(1) 按「答对得 1 分，答错和不知道都得 0 分」计分，两个模型各得多少分？
(2) 改为「答对 +1，答错 −1，不知道 0」，各得多少分？
(3) 一般地，若答错扣 $k$ 分、答对得 1 分、不知道得 0 分，模型对某题的把握（答对概率）为 $p$ 时，什么条件下作答比拒答更划算？$k=3$ 时阈值是多少？
(4) 结合 (1)～(3) 说明，为什么只按准确率排名的评测会助长幻觉。

<details>
<summary>答案与解析</summary>

**答案：(1) A 60 分，B 58 分；(2) A 20 分，B 46 分；(3) p > k/(1+k)，k = 3 时为 0.75；(4) 只按对错计分时，猜测的期望得分总不低于拒答，模型被训练成「宁可猜也不说不知道」**

**解析：**

**(1)** A：60 分；B：58 分。按准确率排名 A 更好，尽管 A 的回答里有 40% 是错的，B 只有 $12/70\approx17\%$。

**(2)** A：$60-40=20$ 分；B：$58-12=46$ 分。名次反转。

**(3)** 作答的期望得分为 $p\cdot1-(1-p)\cdot k$，拒答为 0。作答更划算当且仅当
$$p-(1-p)k>0\iff p>\frac{k}{1+k}$$
$k=1$ 时阈值 0.5，$k=3$ 时 0.75，$k=9$ 时 0.9。反过来，想让模型「把握超过 $t$ 才回答」，就把答错的扣分设为 $t/(1-t)$。Kalai 等（2025）正是建议在评测说明中明确写出这样的置信度目标与扣分规则。

**(4)** $k=0$ 时阈值为 0：哪怕只有 1% 的把握，猜一下的期望得分也比拒答高。例如若 B 对拒答的 30 题各有 30% 的把握，按 (1) 的规则全部去猜，期望多得 $0.3\times30=9$ 分，总分 67，反超 A。以排行榜为目标优化的模型，自然学会「不确定也要给出一个像样的答案」，这就是幻觉在后训练之后依然顽固的一个重要原因。评测应同时报告准确率、错误率与拒答率，或使用对错误扣分的计分方式。

<sub>考点：拒答与过度拒答、幻觉成因　｜　出处：Why Language Models Hallucinate arXiv:2509.04664</sub>

</details>

<a name="SEC-REL-031"></a>

### SEC-REL-031　进阶 · 考频 ★★

某 Agent 平台把每次工具调用写入审计日志。每条记录保存上一条的哈希 `prev` 和本条的哈希 `hash`，用来发现篡改。安全评审发现：有人直接从日志中删掉了一条退款记录，`verify` 却报告日志完好。请找出 bug 并修正。

```python
import hashlib
import json

GENESIS = "0" * 64


def entry_hash(prev_hash, record):
    data = json.dumps(record, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256((prev_hash + data).encode("utf-8")).hexdigest()


def append(log, record):
    prev = log[-1]["hash"] if log else GENESIS
    log.append({"record": record, "prev": prev, "hash": entry_hash(prev, record)})


def verify(log):
    """返回第一条有问题的记录下标；全部完好时返回 -1"""
    for i, e in enumerate(log):
        if e["hash"] != entry_hash(e["prev"], e["record"]):
            return i
    return -1
```

<details>
<summary>答案与解析</summary>

**答案：**

**问题**：`verify` 只检查每条记录「自己的哈希是否与自己的 prev 和内容相符」，从不检查 `prev` 是否等于**前一条记录**的哈希（第一条应等于 `GENESIS`）。删除中间一条后，剩下的每条记录各自仍然自洽，链条断了却检查不出来；交换顺序、删除开头、修改内容后重算本条哈希也都发现不了。

**修正**：遍历时维护「期望的前驱哈希」，同时检查链接关系与本条哈希：

```python
prev = GENESIS
for i, e in enumerate(log):
    if e["prev"] != prev or e["hash"] != entry_hash(prev, e["record"]):
        return i
    prev = e["hash"]
return -1
```

**修正后的代码：**

```python
import hashlib
import json

GENESIS = "0" * 64


def entry_hash(prev_hash, record):
    data = json.dumps(record, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256((prev_hash + data).encode("utf-8")).hexdigest()


def append(log, record):
    prev = log[-1]["hash"] if log else GENESIS
    log.append({"record": record, "prev": prev, "hash": entry_hash(prev, record)})


def verify(log):
    """返回第一条有问题的记录下标；全部完好时返回 -1"""
    prev = GENESIS
    for i, e in enumerate(log):
        if e["prev"] != prev or e["hash"] != entry_hash(prev, e["record"]):
            return i
        prev = e["hash"]
    return -1
```

**解析：**

哈希链的防篡改能力来自「每条记录都绑定了前一条」：改动、删除或重排任何一条，后面的链接就对不上。只校验单条记录，等于把链拆成了互不相关的散点。

**局限与加固**：如果攻击者能改写某条记录及其之后的**全部**记录并重算哈希，整条链依然自洽。所以还需要：
- 定期把最新的链头哈希锚定到攻击者改不了的地方（另一套系统、只追加的 WORM 存储、可信时间戳服务）；
- 或用只有审计服务掌握密钥的 HMAC 代替普通哈希；
- 存储层开启只追加、对象锁定，并对审计日志本身的访问做审计。

<sub>考点：审计与可解释</sub>

## 编程题

<a name="SEC-REL-008"></a>

### SEC-REL-008　进阶 · 考频 ★★

实现离散版的**语义熵**（semantic entropy），用于判断一个问题的多次采样回答是否「众说纷纭」：

```python
def semantic_entropy(answers: list, equivalent) -> tuple[int, float]: ...
```

- `answers`：对同一问题多次采样得到的回答（非空列表）；`equivalent(a, b)`：判断两条回答语义等价，返回布尔值（实际系统中用双向蕴含判断，本题直接给出）。
- 聚类规则：按顺序处理每条回答，依次与已有各簇的**代表元**（该簇的第一条回答）比较，加入第一个等价的簇；都不等价则新建一个簇。
- 返回 `(簇数, 熵)`：熵按各簇回答数的占比计算，$H=-\sum_k p_k\ln p_k$（自然对数）。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
import math


def semantic_entropy(answers, equivalent):
    clusters = []                                  # 每个簇：[代表元, 成员数]
    for a in answers:
        for c in clusters:
            if equivalent(c[0], a):                # 只与簇的代表元比较
                c[1] += 1
                break
        else:
            clusters.append([a, 1])
    n = len(answers)
    entropy = -sum(k / n * math.log(k / n) for _, k in clusters)
    return len(clusters), entropy
```

**测试用例：**

```python
import math

def same_year(a, b):                               # 玩具版「语义等价」：只比较其中的数字
    digits = lambda s: "".join(ch for ch in s if ch.isdigit())
    return digits(a) == digits(b)

k, h = semantic_entropy(["1969 年", "公元1969年", "是1969年"], same_year)
assert k == 1 and h == 0.0                         # 说法不同、意思相同：熵为 0
k, h = semantic_entropy(["1969", "1971", "1968", "1972"], same_year)
assert k == 4 and math.isclose(h, math.log(4))     # 每次都不一样：熵最大
k, h = semantic_entropy(["1969", "1969年", "1971", "1971 年"], same_year)
assert k == 2 and math.isclose(h, math.log(2))
k, h = semantic_entropy(["a1", "a1", "a1", "b2"], same_year)
assert k == 2 and math.isclose(h, -(0.75 * math.log(0.75) + 0.25 * math.log(0.25)))
close = lambda a, b: abs(a - b) <= 1                # 非传递的判断：必须只和代表元比较
k, h = semantic_entropy([1, 2, 3], close)
assert k == 2 and math.isclose(h, -(2 / 3 * math.log(2 / 3) + 1 / 3 * math.log(1 / 3)))
k, h = semantic_entropy(["x"], same_year)
assert k == 1 and h == 0.0
```

**解析：**

**思路**：语义熵（Farquhar 等，Nature 2024）的出发点是：同一个意思可以有很多种说法，直接在 token 序列上算不确定性，会把「措辞不同」误当成「答案不同」。所以先按语义把采样结果聚类，再在簇上计算熵：
- 所有回答意思相同（「1969 年」「公元 1969 年」），熵为 0，模型很确定；
- 每次答案都不同，熵接近 $\ln n$，提示模型可能在编造（论文称之为 confabulation），可以据此拒答或转人工。

本题是「离散」版本：用各簇的频率估计概率，不需要 token 概率，适合只能调用 API 的场景。原论文也有用序列概率加权的版本。

**易错点**：
- 聚类时与簇里的每个成员都比较：等价判断不一定满足传递性（测试中 1≈2、2≈3，但 1 与 3 不等价），结果会依赖比较方式；题目约定只和代表元比较；
- 用 `math.log2` 或忘了负号；
- 把熵算在原始回答字符串上，而不是簇上。

**局限**：语义熵发现的是「回答不稳定」型的幻觉；模型若每次都一致地答错，熵很低，它检测不出来。

<sub>考点：幻觉检测、不确定性与校准　｜　出处：Detecting hallucinations in large language models using semantic entropy（Nature 630, 2024）</sub>

</details>

<a name="SEC-REL-020"></a>

### SEC-REL-020　进阶 · 考频 ★★★

实现写日志前的个人信息脱敏函数：

```python
def mask_pii(text: str) -> tuple[str, dict]: ...
```

- **身份证号**：18 位，前 17 位是数字，最后一位是数字或 X（大小写均可）；前后都不能紧邻数字或英文字母；还必须通过 GB 11643 的校验：前 17 位依次乘以权重 7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2 后求和，和对 11 取余，余数 0～10 依次对应校验码 1, 0, X, 9, 8, 7, 6, 5, 4, 3, 2。通过校验的整体替换为 `[ID]`；不通过的保持原样（多半是订单号之类的长数字）。
- **手机号**：11 位，第 1 位是 1、第 2 位是 3～9，前后不能紧邻数字；替换为「前 3 位 + `****` + 后 4 位」。
- 返回 `(脱敏后的文本, {"id": 身份证号替换次数, "phone": 手机号替换次数})`。

<details>
<summary>答案与解析</summary>

**参考实现：**

```python
import re

WEIGHTS = [7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2]
CHECK = "10X98765432"
ID_RE = re.compile(r"(?<![0-9A-Za-z])\d{17}[0-9Xx](?![0-9A-Za-z])")
PHONE_RE = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")


def id_valid(s):
    total = sum(int(c) * w for c, w in zip(s[:17], WEIGHTS))
    return CHECK[total % 11] == s[17].upper()


def mask_pii(text):
    counts = {"id": 0, "phone": 0}

    def mask_id(m):
        if not id_valid(m.group()):
            return m.group()                     # 校验不通过：保持原样
        counts["id"] += 1
        return "[ID]"

    def mask_phone(m):
        counts["phone"] += 1
        s = m.group()
        return s[:3] + "****" + s[-4:]

    text = ID_RE.sub(mask_id, text)              # 先处理更长的身份证号
    text = PHONE_RE.sub(mask_phone, text)
    return text, counts
```

**测试用例：**

```python
t, c = mask_pii("身份证11010519491231002X，手机13800138000。")
assert t == "身份证[ID]，手机138****8000。" and c == {"id": 1, "phone": 1}
t, c = mask_pii("证件号 11010519491231002x 已登记")            # 小写 x
assert t == "证件号 [ID] 已登记" and c["id"] == 1
t, c = mask_pii("订单号 999999199001011239 已发货")             # 校验位不对：不是身份证
assert t == "订单号 999999199001011239 已发货" and c == {"id": 0, "phone": 0}
t, c = mask_pii("号码 999999199001011238")
assert t == "号码 [ID]"
t, c = mask_pii("流水号2025138001380001234")                     # 手机号形态嵌在更长的数字串里
assert t == "流水号2025138001380001234" and c["phone"] == 0
t, c = mask_pii("电话:15000000000,备用15000000001")
assert t == "电话:150****0000,备用150****0001" and c["phone"] == 2
t, c = mask_pii("12800138000 不是手机号")                         # 第二位不在 3～9
assert c["phone"] == 0
t, c = mask_pii("ID:A11010519491231002X")                         # 前面紧邻字母
assert c["id"] == 0
assert mask_pii("") == ("", {"id": 0, "phone": 0})
```

**解析：**

**思路**：
1. 用前后环视（lookaround）表达「前后不能紧邻数字或字母」，避免从更长的数字串中截出一段误判；
2. 身份证号先按格式匹配，再用校验码过滤，大幅减少把订单号、流水号误当成身份证号的情况；
3. 先处理 18 位的身份证号，再处理 11 位的手机号；
4. 替换函数里顺便计数，便于监控「日志里出现了多少个人信息」。

**易错点**：不加边界，导致长数字串中间的 11 位被当成手机号；忘了校验码可能是小写 x；用 `\b` 做边界（中文字符在 Python 中属于单词字符，`手机13800138000` 里的号码前面没有 `\b`）。

**工程上**：随机的 18 位数字也有约 1/11 的概率碰巧通过校验，规则只能兜底；姓名、地址等要用实体识别模型；脱敏应在写日志、写 Trace、进入评测集之前完成，而不是事后清理；需要还原时用可逆的映射（令牌化），映射表单独加密保存。

<sub>考点：隐私与PII　｜　出处：GB 11643-1999《公民身份号码》</sub>

</details>

## 简答题

<a name="SEC-REL-005"></a>

### SEC-REL-005　进阶 · 考频 ★★★

大模型为什么会产生幻觉？请从数据、训练、推理（解码）三个阶段分析成因，并为每个阶段给出至少一种对应的缓解思路。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **数据阶段**：
   - 训练语料中的错误与偏见被模型照学（模仿性错误）；
   - 长尾知识出现次数太少，模型记不牢（只出现一次的事实几乎等同于没见过）；
   - 知识有截止时间，过时后无法自行更新。
   - 缓解：数据清洗与去重；长尾与时效性知识交给检索增强（RAG）和工具查询。
2. **训练阶段**：
   - 预训练目标只奖励「像样的续写」，没有「我不知道」这个选项；教师强制训练与自回归推理之间的暴露偏差，让早期错误在生成时滚雪球；
   - SFT 用模型本不掌握的新知识做训练，会教会它在知识边界之外照样作答，提高幻觉倾向；
   - RLHF 中人类偏好自信、详尽的回答，可能带来谄媚和过度自信；主流评测按「答错与不答同分」计分，奖励猜测。
   - 缓解：为模型不知道的问题构造拒答样本（如 R-Tuning 的思路）；奖励与评测中对「自信地答错」扣分、给「不知道」留分；知识注入交给预训练或 RAG，SFT 主要教行为。
3. **推理阶段**：
   - 随机采样、较高的温度会采到低概率的错误 token；
   - 一旦开头写错，后文会自洽地延续错误；
   - 长上下文中注意力分散（中间位置的信息被忽略），多跳推理失败。
   - 缓解：事实类任务降低温度或用受约束解码；先起草再验证（如 Chain-of-Verification）；要求引用并核验；用多次采样的一致性或语义熵检测，没把握就拒答。
4. **与类型的对应**：事实性幻觉多源于知识边界（数据与预训练）；忠实性幻觉多源于指令遵循与上下文利用不足（训练与推理）。

**评分要点（共 10 分）：**

- 数据阶段：说出错误知识、长尾、过时中的至少两项（2 分）
- 训练阶段：说出预训练目标或暴露偏差、SFT 引入新知识、RLHF 或评测激励中的至少两项（3 分）
- 推理阶段：说出采样随机性、错误累积、长上下文或推理失败中的至少两项（2 分）
- 每个阶段都给出对应的缓解思路（3 分）

**讲解：**

**常见失分点**：只会说「训练数据有错」；认为「把数据洗干净、温度设为 0 就没有幻觉」；说「用 SFT 把新知识灌进去就能减少幻觉」（恰恰相反）；只罗列成因，不给对应的缓解手段。

<sub>考点：幻觉成因、幻觉类型　｜　出处：A Survey on Hallucination in Large Language Models arXiv:2311.05232；Why Language Models Hallucinate arXiv:2509.04664</sub>

</details>

<a name="SEC-REL-006"></a>

### SEC-REL-006　进阶 · 考频 ★★

用户问「某开源框架最新版本里的 X 接口怎么用」，模型自信地给出了一个已被废弃的旧写法，还声称这就是「最新版本」的用法。请解释为什么会出现这种情况，并给出工程上的解决方案。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **原因**：
   - **知识截止**：训练数据只到某个时间点，之后的版本变化模型不知道；
   - **不知道「现在」是什么时候**：没有当前日期的信息，「最新」只能按训练时的认知理解；
   - **频率偏差**：旧写法存在时间长，教程、问答、代码积累得多，在训练数据中远比新写法常见，模型更倾向于输出它；
   - **不会表达不确定**：模型不知道自己的知识对应哪个版本，训练和评测又鼓励给出确定的答案。
2. **解决方案**：
   - 在系统提示中注入当前日期，并说明模型的知识截止时间，要求回答时写明所针对的版本；
   - 检索官方文档、变更日志或迁移指南（RAG），优先依据检索结果作答并附链接；
   - 让 Agent 先查清用户环境里实际安装的版本（如读取依赖锁文件、查询包管理器），再读该版本的源码或文档；
   - 生成的代码交给工具验证：运行、类型检查、跑测试，用执行结果纠错；
   - 无法确定版本时，先询问或明确说明不确定，而不是假装知道；
   - 建立时效性评测集（版本敏感的问题），并监控用户的纠错反馈。

**评分要点（共 10 分）：**

- 指出知识截止与缺少当前日期信息（2 分）
- 指出旧写法在训练数据中更常见的频率偏差（2 分）
- 给出检索官方文档、查询实际安装版本等补充最新知识的方案（3 分）
- 给出执行验证、注明版本或在不确定时拒答等兜底手段（3 分）

**讲解：**

**常见失分点**：只说「模型知识过时，换个新模型就好」（新模型同样有截止时间）；不提频率偏差，解释不了「明明见过新写法却还是给旧的」；方案只有改提示词，没有检索与执行验证。

<sub>考点：幻觉成因、幻觉缓解</sub>

</details>

### SEC-REL-029　进阶 · 考频 ★★

请为一个面向公众的对话产品设计内容安全审核体系：审核放在哪些环节、用什么手段、命中后如何处置、如何衡量效果、如何持续迭代？

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **先定政策与分类体系**：按类别（暴力、色情、自伤、仇恨、违法活动、隐私、未成年人保护，以及本地法规要求的类别）和严重程度（安全、有争议、不安全）分级，每一级对应明确的处置方式；政策版本化管理。
2. **审核环节**：
   - 输入侧：用户文本、上传的图片与文件；

6. **持续迭代**：线上抽样标注、误判样本回流训练与调阈值；定期红队；回归集作为发布门禁；多语言、多模态单独评估。

**评分要点（共 10 分）：**

- 先定政策、分类与严重程度分级（2 分）
- 覆盖输入、输出（含流式）、外部内容与会话层等环节（2 分）
- 规则、护栏模型、LLM 复核与人工审核的组合及分工（2 分）
- 给出分级处置方式（2 分）
- 给出按类别的精确率与召回率、漏出率、过度拒答率等指标，以及迭代闭环（2 分）

**讲解：**

**常见失分点**：只做输出审核或只做关键词过滤；命中后一律拒答，不区分严重程度；只看拦截率，不看过度拒答；不处理多轮诱导和多语言绕过；没有人工复核与申诉渠道。

<a name="SEC-REL-032"></a>

### SEC-REL-032　进阶 · 考频 ★

一家金融客户要求你们的 Agent 产品满足审计要求：「任何一次自动化决策都要能说清依据、能追溯到责任人」。团队担心这会拖慢上线。请说明：审计日志应记录哪些内容；如何保证不可篡改与隐私合规；如何提供可解释性；以及如何让这些要求不拖慢交付。

<details>
<summary>答案与解析</summary>

**参考答案：**

1. **记录什么**：
   - 谁：发起人、代谁操作（委托身份）、Agent 实例与版本；
   - 何时、在哪个会话：时间戳、trace ID；
   - 依据：输入（或其摘要与哈希）、检索到的文档 ID 与版本、工具调用的参数与返回、触发的规则与策略、审批人和审批结果；
   - 结果：最终决策、输出内容、模型版本、提示词版本、策略版本。
2. **不可篡改**：只追加的存储（WORM、对象锁定）；哈希链或分批签名，并把链头定期锚定到外部系统；审计日志的写入与读取权限分离，对审计日志的访问本身也要审计；设定保留期限。
3. **隐私合规**：只记录必要的字段；个人信息脱敏或令牌化；按角色控制访问；到期删除，有法定留存要求的转入受限存储。
4. **可解释**：不依赖模型自述的推理过程（思维链未必反映真实依据）；用结构化证据解释决策：引用了哪些文档、哪条规则命中、哪个工具返回了什么；高风险决策由确定性规则或人工做最终决定，模型只提供建议；面向审计员的说明由结构化轨迹自动生成。
5. **不拖慢交付**：
   - 做成平台能力：在网关和中间件层自动采集 trace（参考 OpenTelemetry 的 span 模型），业务方无需逐个埋点；
   - 统一的审计数据结构与合规检查清单，设计评审阶段就让合规参与；
   - 按风险分级：高风险决策全量审计并加人工审批，低风险操作轻量记录与抽样；
   - 自动生成审计材料（证据包、报表），减少临时人工整理。

**评分要点（共 10 分）：**

- 记录内容完整：身份与委托、时间与 trace、依据（检索、工具、规则、审批）、结果与各类版本（3 分）
- 不可篡改的手段：只追加存储、哈希链或签名、外部锚定、权限分离（2 分）
- 隐私合规：最小化、脱敏、访问控制与保留期限（2 分）
- 可解释性基于结构化证据与确定性规则，并说明为何不能依赖思维链（2 分）
- 给出平台化、分级等不拖慢交付的做法（1 分）

**讲解：**

**常见失分点**：只记录模型的最终回答；审计日志里明文保存身份证号等敏感信息；把思维链当成决策解释；每个业务方各自埋点、格式不一；把合规当成上线前最后一步，而不是在设计阶段就纳入。

<sub>考点：审计与可解释、数据合规　｜　出处：Reasoning Models Don't Always Say What They Think arXiv:2505.05410</sub>

</details>

## 场景分析题

<a name="SEC-REL-009"></a>

### SEC-REL-009　挑战 · 考频 ★★★

某企业知识问答助手（RAG + 引用）上线后，经人工抽检，幻觉率已降到约 2%，剩下的主要是：数字、日期写错，以及引用的段落其实并不支持答案中的说法。线上每天约 5 万次问答，没有现成的标注。请设计一套方案，持续发现并压降这部分剩余的幻觉：如何定义与度量幻觉率；没有标注时如何自动发现；发现后如何处置；如何形成闭环。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 定义与度量**
- 以「陈述」为单位：把回答拆成原子陈述，幻觉率 = 无依据或与依据矛盾的陈述数 ÷ 陈述总数；同时统计「至少含一处幻觉的回答」占比。
- 按错误类型（数字与日期、实体、引用不支持、无引用的断言）和问题类别、知识库来源分别统计，避免平均数掩盖问题。

**2. 没有标注时的自动发现**
- **引用核验**：对每条陈述与它引用的段落做支持判断（NLI 模型或 LLM 裁判，结论为支持、矛盾或无关）。
- **数字精确比对**：用规则抽取回答中的数字、日期、金额，与被引原文逐一比对，不一致直接标记。这一步确定、便宜，正好针对最主要的错误类型。
- **一致性信号**：对高风险问题多次采样或换一组检索结果重答，答案不一致就标记（SelfCheckGPT、语义熵的思路）。
- **检索信号**：最高相关度很低、被引段落与问题明显不匹配。
- **用户信号**：点踩、追问「你确定吗」、复制后大量修改、转人工。
- **探针**：定期混入已知答案的问题，监测检测器和系统本身。

**3. 处置**
- 在线：数字、日期在输出前校验，不一致时改用原文中的数值或删去该陈述；引用不支持时降级为「资料中没有明确说明」，或拒答并给出相关文档链接；价格、合同、合规等高风险问题启用严格模式（每句必须有引用且通过核验）。
- 离线：按风险分数抽取样本做人工审核，标注结果沉淀为评测集。

**4. 根因治理与闭环**
- 按根因分流：文档本身错误或过时 → 修文档；没检索到 → 改切块、召回与重排；检索到了但没用好 → 改提示词、要求逐字引用数字、换模型或微调。
- 指标看板：分类型的幻觉率、自动检测的准确率与召回率（定期用人工标注校准检测器本身）、拒答率与过度拒答率。
- 发布门禁：改模型、提示词、检索参数前，跑幻觉回归集，指标不得变差。

**评分要点（共 10 分）：**

- 给出以陈述为单位、按类型分层的幻觉率定义（2 分）
- 给出无标注的自动检测手段，至少包含引用核验与数字比对（3 分）
- 给出在线处置（校验改写、降级或拒答、严格模式）与离线人工抽检（2 分）
- 按根因分流治理，并有检测器校准、看板与发布门禁等闭环（3 分）

**讲解：**

**常见失分点**：只说「换更强的模型」或「再加一个 LLM 裁判」；没有可计算的幻觉率定义；忽略数字比对这种确定、便宜的手段；检测器本身的准确率不做校准；只发现、不处置，或者处置时一律拒答，导致过度拒答。

<sub>考点：幻觉检测、幻觉缓解　｜　出处：SelfCheckGPT arXiv:2303.08896</sub>

</details>

<a name="SEC-REL-018"></a>

### SEC-REL-018　进阶 · 考频 ★★

某面向开发者的编程助手做了一次安全对齐更新。之后，「如何 kill 掉僵尸进程」「怎样 purge 掉 CDN 缓存」「写一个端口扫描脚本检查自家服务器暴露了哪些端口」这类请求的拒答率明显上升，用户开始流失。安全团队则要求真正有害请求的拒答率不能下降。请分析可能的原因，并给出改进与评估方案。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 原因分析**
- 安全数据与奖励过度依赖表面线索：含「kill」「purge」「扫描」等词的请求被成批标为拒答，模型学到的是关键词而不是意图；
- 安全策略没有区分场景：面向大众的聊天策略直接套用到开发者工具上，系统提示里「这是编程助手」的上下文没有被利用；
- 两用（dual-use）请求缺少细粒度政策：扫描自有服务器是正常的运维需求，政策里却只有「允许 / 禁止」两档；
- 输入或输出护栏的阈值按通用场景调校，在技术领域误报偏高。

**2. 改进方案**
- 先写清政策：按类别列出「允许」「允许但附带安全提示」「拒绝」，对两用请求给出判断标准（例如针对自有资产、防御目的可以协助）；
- 补充对比数据：成对构造「看起来危险、实际安全」与「看起来安全、实际危险」的样本，加入 SFT 与偏好数据，让模型学习意图而不是关键词；
- 用「安全地完成」代替一刀切的拒答：帮助完成合理部分，只拒绝真正危险的细节，并说明原因；
- 护栏按领域与类别分别设阈值，利用系统提示与对话上下文；处于灰区的请求交给更强的判别模型复核，而不是直接拦截。

**3. 评估与发布**
- 两组评测一起跑：过度拒答集（XSTest 一类的公开集，加上从线上日志挖出的被误拒的开发者请求）与有害请求集，按类别报告两边的拒答率；
- 发布门禁：有害请求拒答率不得下降，过度拒答率降到目标以下；
- 线上灰度 A/B，监控拒答率、重新生成率、点踩与流失，并持续回流误拒样本。

**评分要点（共 10 分）：**

- 指出依赖表面关键词、场景与政策缺乏细分、护栏阈值不当等成因（3 分）
- 给出政策细化、对比数据、安全地完成等模型侧改进（3 分）
- 给出护栏分领域阈值与灰区复核等系统侧改进（2 分）
- 同时评估过度拒答与有害拒答，并有发布门禁与线上监控（2 分）

**讲解：**

**常见失分点**：只想到「放松安全策略」，导致有害请求的拒答率一起下降；只报一个总拒答率；不区分两用请求；把问题全归因于模型，忽略护栏阈值与产品场景。

<sub>考点：拒答与过度拒答、内容安全　｜　出处：XSTest arXiv:2308.01263</sub>

</details>

<a name="SEC-REL-025"></a>

### SEC-REL-025　挑战 · 考频 ★★

公司内部的 HR 助手 Agent 有长期记忆，能检索员工手册以及员工本人提交过的材料；对话日志会进入评测集和数据分析平台；每季度还会用去标识化后的对话微调一次模型。一位已离职的员工依法要求删除其全部个人信息。请设计删除流程：需要覆盖哪些数据，如何做到「删干净且可证明」，哪些情况可以暂不删除，以及系统应当提前做好哪些设计。

<details>
<summary>答案与解析</summary>

**参考答案：**

**1. 覆盖范围（按数据地图逐一列出）**
- 原始对话日志、长期记忆条目（含从对话中抽取的事实、偏好）；
- 员工提交的材料及其切块、嵌入向量、关键词索引；
- 派生数据：摘要、反思、知识图谱中的节点与边，以及仍能识别到个人的统计结果；
- 缓存：语义缓存、检索缓存；
- 评测集、标注平台、数据分析平台中的样本；
- 备份与快照；
- 第三方处理方：外部模型服务、日志服务按协议同步删除；
- 微调数据与模型：检查该员工的数据是否进入过训练集。

**2. 流程**
- 核验身份 → 按员工 ID 和数据血缘索引定位全部记录 → 删除或不可逆地处理 → 重建受影响的索引 → 通知第三方处理方；
- 备份：登记删除，备份过期时自然清除；若需从备份恢复，必须重新执行删除；
- 模型：若下个训练周期还会用到这些数据，先从训练集中剔除；对已上线的模型，用该员工的特有信息做记忆探测，确有记忆时回退版本或剔除后重训。

**3. 可证明**
- 删除工单与审计记录：删了什么类别、何时、由谁执行（不保留被删内容本身）；
- 删除后的验证查询（按 ID、姓名、工号检索各存储都无结果）；在法定期限内答复。

**4. 可以暂不删除的情况**
- 法律、行政法规规定的保存期限未满（如劳动法规要求保存的工资、劳动合同记录）；删除从技术上难以实现时，按《个人信息保护法》第四十七条第二款，停止除存储和必要的安全保护措施之外的处理，转入受限存储并控制访问。

**5. 提前做好的设计**
- 数据地图与血缘：每条记录带数据主体 ID 与来源，派生数据记录上游；
- 每个存储都提供按主体删除的接口；默认设置保留期限与自动过期；
- 个人数据与共享知识分开存放；训练只用去标识化的数据，并保留可重训的流水线与检查点；
- 定期做删除演练。

**评分要点（共 10 分）：**

- 覆盖范围完整：日志、记忆、向量与索引、派生数据、缓存、评测与分析、备份、第三方、模型（3 分）
- 流程中包含按血缘定位、重建索引、备份与模型的处理（2 分）
- 能证明已删除：审计记录与验证查询，且审计不保留被删内容（2 分）
- 说明法定保存期限与技术上难以删除时的处理（1 分）
- 给出血缘、按主体删除接口、保留期限、训练数据去标识化等前置设计（2 分）

**讲解：**

**常见失分点**：只删原始对话；忘了向量、缓存、评测集与备份；把模型简单说成「不受影响」或「必须立刻重训」；审计记录里又把被删内容完整存了一份；不知道法定保存期限等例外情形。

<sub>考点：数据合规、隐私与PII、审计与可解释　｜　出处：《个人信息保护法》第四十七条</sub>

</details>
