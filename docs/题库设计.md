# 题库设计说明

## 1. 目标与定位

本题库服务于准备**大模型算法、Agent 应用开发、大模型工程**等岗位的求职者，也可用于团队内部培训与能力评估。设计目标：

1. **考试级**：每道题都有唯一明确的答案（主观题有评分标准），可以直接组成试卷；
2. **覆盖广**：知识面覆盖从机器学习基础到 Agent 前沿的完整链条，不留明显盲区；
3. **讲解透**：做错的人看完讲解就能弄懂，而不是只知道正确选项；
4. **可验证**：能自动验证的部分全部自动化，代码题必须真正运行；
5. **可演进**：数据与展示分离，便于社区持续贡献、纠错和扩充。

## 2. 分类体系：大类 → 小类 → 考点

题库采用三级分类，定义在仓库根目录的 `taxonomy.yaml`：

| 层级 | 数量 | 作用 | 示例 |
|---|---|---|---|
| 大类（domain） | 11 | 知识领域，决定组卷范围 | `AGT` 智能体 |
| 小类（subcategory） | 70 | 一个题目文件、一个练习页 | `AGT-PROTO` 智能体协议 |
| 考点（point） | 861 | 最细的知识单元，用于统计覆盖度 | `MCP传输方式` |

**划分原则**：

- 每个考点只归属一个小类（例如注意力的计算细节归 `LLM-ATTN`，推理服务里的 KV Cache 管理归 `INF-KV`），避免重复出题；
- 小类的粒度以「一次面试中会被连续追问的一组知识」为准，每类 25～70 题；
- 考点粒度以「一道题能考透」为准，每个考点至少 2 道题，从不同角度考查。

## 3. 题型设计

| 题型 | 考查目的 | 答案形式 | 自动验证 |
|---|---|---|---|
| 单选 `single` | 概念辨析，区分易混概念 | 一个字母 | 答案在选项内 |
| 多选 `multiple` | 全面理解，一题考多个知识点 | 字母列表（至少 2 个） | 答案合法、不全选 |
| 判断 `judge` | 识别常见误解 | true / false | 类型检查 |
| 填空 `fill` | 关键术语与数值 | 每空一个答案，可列等价写法 | 空位数与答案数一致 |
| 计算 `calc` | 量化估算能力 | 带单位的结果 + 计算过程 | 出题时用 Python 验算 |
| 代码输出 `code_output` | 读代码、理解 API 行为 | 程序的标准输出 | **运行代码逐字比对** |
| 代码填空 `code_fill` | 关键实现细节 | 每空的代码片段 | **填回后运行测试** |
| 代码改错 `code_debug` | 定位与修复 bug | 说明 + 修正代码 | **修正版通过测试，原版不通过** |
| 编程 `coding` | 手撕实现 | 参考实现 + 测试 | **运行参考实现与测试** |
| 简答 `short` | 原理阐述、方案比较 | 分点参考答案 + 评分要点 | 评分要点合计 10 分 |
| 场景分析 `scenario` | 线上排障、方案取舍 | 参考答案 + 评分要点 | 同上 |
| 系统设计 `design` | 端到端设计能力 | 参考设计 + 评分要点 | 同上 |

**每个小类的参考配比**：单选约 30%、多选约 15%、判断约 12%、填空约 8%、简答约 15%、计算与代码约 12%、场景与设计约 8%。偏数学的小类多出计算题，偏编程的小类多出代码题。

## 4. 难度与考频

| 维度 | 取值 | 定义 | 目标占比 |
|---|---|---|---|
| 难度 | 1 基础 | 概念、定义、直接结论 | 约 30% |
| | 2 进阶 | 理解原理、比较权衡、简单计算或读代码 | 约 50% |
| | 3 挑战 | 推导、多步计算、细节陷阱、复杂场景、前沿 | 约 20% |
| 考频 | ★ | 偶尔考或加分项 | — |
| | ★★ | 常考 | — |
| | ★★★ | 高频必考 | — |

难度描述的是题目本身的难易，考频描述的是这个知识点在面试中出现的频率，两者独立标注。例如「为什么 Attention 要除以 √d」难度低、考频高；「GSPO 的序列级重要性比」难度高、考频中等。

## 5. 编号与数据格式

- 题目 ID：`大类-小类-三位序号`，如 `RAG-RETR-017`。ID 发布后不再改变，删除的编号不复用。
- 源数据：`questions/<大类>/<小类>.yaml`，一个小类一个文件。YAML 的长文本用 `|` 块写法，选项用单引号，方便直接书写 LaTeX 与代码。
- 字段：`id`、`type`、`difficulty`、`frequency`、`points`、`question`、`options`、`answer`、`explanation`、`rubric`（主观题）、`code` / `fixed_code` / `test`（代码题）、`tags`、`source`。完整定义与每种题型的模板见 [出题规范](../CONTRIBUTING.md)。

## 6. 质量保障

```text
面经调研 ──→ 出题规范 ──→ 自动校验 ──→ 出题人复核 ──→ 联网核实 ──→ 盲答复核 ──→ 社区纠错
```

1. **面经调研**：整理公开的大模型与 Agent 面经、题单和课程中的高频考点，与分类体系逐项对照，找出未覆盖的考点后补题。只借鉴「考什么」，题目与讲解全部原创。
2. **出题规范**：统一的题型模板、干扰项要求、讲解结构与禁止事项（见 CONTRIBUTING.md）。
3. **自动校验**（`scripts/validate.py`，CI 中强制执行）：
   - 格式：必填字段、ID 规则与唯一性、考点是否在分类体系内、乱码字符检测；
   - 答案合法性：选项存在、多选至少两个正确项且不全选、填空空位数一致、主观题评分要点合计 10 分；
   - **代码真实运行**：输出题逐字比对、编程题跑测试、改错题双向验证（修正版通过且原版失败）；
   - 查重：题干、代码与选项的 4-gram 相似度过高时告警；
   - 统计：题量、题型与难度配比、考点覆盖、单选答案字母分布、多选正确项数分布、判断题正误比例。
4. **出题人复核**：每批题写完后，出题人把每道客观题当作第一次见到，独立重做一遍；计算题用程序验算。
5. **联网核实**：涉及产品、协议、框架版本、默认配置、基准成绩和论文数字的题目，对照官方文档或原始论文核实，出处写入 `source` 字段；拿不准的细节改写成原理辨析，不写具体数字。代码输出题还要用不同的哈希种子重复运行，确认输出与运行环境无关。
6. **盲答复核**：把客观题的题干和选项（不含答案）交给独立的作答者重新作答，答案不一致的题目逐一裁定：答案键错误的修正答案与讲解，题目有歧义的收紧题干，等价写法补进填空备选答案。
7. **消除表面线索**：考生不读懂题目、只凭表面特征就能猜对的题是无效的。逐项统计并消除这类规律：
   - 长度：正确选项不能系统性地更长、更具体；
   - 位置：多选题的正确项在各字母上均匀分布，单选答案字母大致均匀；
   - 个数：多选题的正确项个数在 2、3、4 之间变化；
   - 措辞：错误选项和错误陈述不能只靠「一定」「总是」等绝对化用语出错；
   - 判断题正误各半。
8. **社区纠错**：开源后通过 Issue 与 PR 持续修正，每道题都有稳定 ID，方便引用。

### 首轮质检结果（2026 年 11 月）

| 项目 | 结果 |
|---|---|
| 盲答复核 | 1750 道客观题（单选、多选、判断、填空）由独立复核者重做，与答案键一致 1747 道；3 道分歧中 2 道是填空的等价写法，1 道是选项有歧义 |
| 修正 | 复核与核实中修正了约 50 道题的事实错误、过时信息或不严谨的表述；按 MCP 2026-07-28 版规范对齐了 30 余道协议题 |
| 代码题 | 全部代码题实际运行通过；代码输出题在 5 组不同的哈希种子下输出一致 |
| 单选「正确项为唯一最长」 | 81% → 27%（随机约 25%）；正确项与干扰项的平均长度比 2.00 → 1.05 |
| 多选正确项的位置 | 处理前 A 选项 74% 是正确项、E 选项只有 42%；处理后五个字母均为 60% |
| 多选正确项个数 | 处理前 90% 是「5 选 3」；处理后 2、3、4 个正确约为 25%、50%、25% |
| 判断题 | 正确陈述约占 49% |

## 7. 生成产物

| 产物 | 生成方式 | 用途 |
|---|---|---|
| `site/data/` | `build_site.py`（部署时由 GitHub Actions 生成） | 在线刷题网站的数据：索引、单题文件、搜索索引 |
| `docs/<大类>/<小类>.md` | `build.py` | 在 GitHub 上直接阅读的练习页，答案默认折叠 |
| `docs/by-type/*.md` | `build.py` | 按题型浏览的索引 |
| `docs/taxonomy.md` | `build.py` | 分类体系与考点覆盖全表 |
| `dist/questions.json`、`.csv` | `build.py` | 结构化数据，可用于刷题工具、Anki |
| `exams/*.md` | `make_exam.py` | 模拟卷与参考答案 |

在线刷题网站（`site/`）是纯静态单页应用，不依赖前端框架：题目按需逐题加载，做题记录只保存在浏览器本地；选择题即时判分，主观题对照评分要点自评，模拟考试的组卷算法与 `make_exam.py` 相同（按难度 3 : 5 : 2 抽题、小类之间轮转）。

## 8. 组卷策略

- **预设**：大模型算法岗、Agent 应用开发岗、大模型工程岗、编程基础、综合卷，每套预设定义了大类范围、各题型题量和建议用时。
- **分值**：单选 2、多选 3、判断 1、填空 2、计算 5、代码输出 3、代码填空 4、代码改错 6、编程 12、简答 8、场景分析 12、系统设计 15。
- **抽题**：按难度 3 : 5 : 2 抽取，并在小类之间轮转，避免一套卷集中在同一个知识点；随机种子固定后结果可复现。

## 9. 后续路线

- 扩充题量，提高每个考点的题目数，并补充更多真实工程场景题；
- 增加英文版与题目的岗位标签（算法 / 应用 / 工程）；
- 基于作答数据做难度校准与区分度分析，淘汰区分度低的题目；
- 提供网页版刷题界面与错题本；
- **定期复核时效内容**：模型、框架、协议与基准变化很快（例如 MCP 在 2026-07-28 版改为无状态协议），涉及具体产品、版本和数字的题需要定期对照官方资料复查，并继续提高 `source` 的覆盖率；
- **引入人工复核**：首轮的出题与复核主要借助 AI 完成，复核者之间可能存在相同的知识盲区，盲答一致并不等于一定正确。欢迎领域专家按小类认领审阅，并通过 Issue 反馈。
