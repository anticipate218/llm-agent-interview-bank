<sub>FND-ML-010</sub>　**结论**：k 折交叉验证把数据分成互不重叠的 k 份，轮流把每一份当验证集，共训练 k 次。

优点是每个样本都既参与过训练、也参与过验证，在数据量不大时能更充分地利用数据，估计也更稳定（还可以报告 k 次结果的标准差）。代价是训练 k 次，计算量变为 k 倍。

- A 错：这是重复随机划分（Monte Carlo 交叉验证），不是 k 折。
- C 错：如果模型在全部数据上训练，再在其中一部分上评估，就是在训练集上评估，结果严重偏乐观。
- D 错：用交叉验证成绩来选超参数或选模型后，这个成绩已经被「挑选」过，偏乐观。要得到无偏的泛化估计，需要一个从未参与选择的独立测试集，或者使用嵌套交叉验证（外层评估、内层调参）。

**2. D**

<sub>FND-DL-015</sub>　**结论**：两者都源于反向传播时梯度要连乘很多个雅可比矩阵：连乘的因子普遍小于 1 就消失，大于 1 就爆炸。但对策不同。

- **梯度爆炸**：表现为 loss 突然跳高、出现 NaN，梯度范数骤增。梯度裁剪（把总范数限制在阈值以内）能直接挡住异常的大步长；同时可以降低学习率、改进初始化、加归一化。
- **梯度消失**：表现为靠近输入的层几乎不更新、loss 很早就停滞。梯度裁剪只会把梯度变小，帮不上忙；需要让梯度有不衰减的通路（残差、LSTM 的细胞状态）、避免饱和激活（ReLU 代替 sigmoid）、让每层尺度稳定（Kaiming 初始化、BN / LN）。

- A 错：裁剪只在范数超过阈值时等比例缩小，范数小时原样保留，不会放大，所以对消失无效。
- B 错：深层前馈网络（如不带残差的深层 sigmoid 网络）同样会梯度消失；几十层的连乘就足以让各层梯度相差几个数量级。
- C 错：学习率对所有层一视同仁，按浅层的衰减倍数调大，梯度正常的深层会先发散；统一调大学习率不能修复层间梯度量级的悬殊。

**3. D**

<sub>TRN-PEFT-037</sub>　**结论**：LoRA 省的是模型状态，省不了激活。

梯度必须穿过每一层才能传到前面层的 LoRA 参数，所以每层的激活照样要保存。按每层约 $34sbh$ 字节估算（用 FlashAttention、$b=1$），7B 模型（32 层、$h=4096$）在 $s=16384$ 时每层约 2.3 GB，32 层约 73 GB，加上 14 GB 的模型状态必然 OOM。开启梯度检查点后每层只存输入（约 $2sbh$），激活可降到 10 GB 以内，代价是多一次前向计算。

- A 错：LoRA 参数量只与秩和矩阵形状有关，与序列长度无关。
- B 错：优化器状态是「每个参数一份」，只与可训练参数量有关，而且 LoRA 的优化器状态本来就很小。
- C 错：权重不会因为序列变长而复制；QLoRA 省的是底座权重，同样不减少激活。

**4. D**

<sub>INF-KERNEL-029</sub>　**结论**：Triton（Tillet 等, 2019；由 OpenAI 开源维护）是「块级」的 GPU 编程语言。

CUDA 以线程为单位编程，程序员要自己管理线程下标、共享内存、访存合并与同步；Triton 以程序实例（program）处理一个数据块为单位，块内的细节交给编译器，写一个融合 kernel 或 FlashAttention 类的 kernel 只需几十行 Python。torch.compile 的 Inductor 后端会生成 Triton kernel，vLLM、SGLang 中也有不少 Triton 实现的算子（如部分注意力、MoE、量化 kernel）。

- B 错：Triton 以块为单位编程，线程下标、访存合并与同步由编译器处理；它经 MLIR / LLVM 直接编译成 GPU 代码（NVIDIA、AMD 等），不是 CUDA C++ 的模板库。
- C 错：追求极致性能、使用最新硬件特性（如 Hopper 的 TMA、WGMMA）时，手写 CUDA / CUTLASS 往往仍更快，FlashAttention-3 就基于 CUTLASS；Triton 的优势是开发效率与可移植性。

**6. C**

<sub>FND-MATH-009</sub>　**结论**：二次型的梯度是 $\nabla_x(x^\top Ax)=(A+A^\top)x$，只有 $A$ 对称时才简化为 $2Ax$。

**计算**：$A+A^\top=\begin{pmatrix}2&2\\2&6\end{pmatrix}$，乘以 $(1,1)^\top$ 得 $(4,8)^\top$。

**用分量验证**：$f=x_1^2+2x_1x_2+3x_2^2$，$\partial f/\partial x_1=2x_1+2x_2=4$，$\partial f/\partial x_2=2x_1+6x_2=8$。

- A 错：$2Ax=(6,6)^\top$，误把 $A$ 当成对称矩阵套用 $2Ax$。
- B 错：$Ax=(3,3)^\top$，只对一侧的 $x$ 求导，漏了另一侧。
- D 错：$A^\top x=(1,5)^\top$，同样只对一侧求导。

**方法**：$f=\sum_{i,j}A_{ij}x_ix_j$，对 $x_k$ 求导时，$x_k$ 既可能作为 $x_i$ 出现、也可能作为 $x_j$ 出现，两部分分别贡献 $(A^\top x)_k$ 与 $(Ax)_k$。

<sub>LLM-MODEL-026</sub>　**结论**：「能下载权重」只说明是开放权重；OSI 意义上的开源 AI 要求使用、研究、修改、分享四项自由，并提供修改所需的「首选形式」：参数、代码、数据信息。

- **代码**：数据处理、训练、推理的完整源代码；
- **数据信息**：足够详细，让有经验的人能构建出实质等价的系统，包括数据来源、筛选、清洗方法；公开数据要列出获取途径。

- A 错：能下载、可商用只说明是开放权重，开源 AI 还要求完整代码和数据信息；带有月活门槛、可接受使用政策的自定义许可（如 Llama 社区许可）更是限制了「任意用途使用」的自由，不满足开源定义。
- C 错：定义要求的是「数据信息」，对无法公开的数据允许只做描述，并不强制公开全部原始数据。
- D 错：Apache 2.0 解决了权重的许可问题，但大多数开放权重模型并不公开训练代码与数据信息。

这就是为什么业界常说 Qwen3、Mistral 等是「许可宽松的开放权重模型」，而 OLMo（Ai2）、Pythia（EleutherAI）这类同时公开数据、代码和中间检查点的模型才更接近「完全开源」。

**9. C**

<sub>LLM-NEW-004</sub>　**结论**：$\Delta$ 相当于一个由内容决定的门。

$\bar A=\exp(\Delta A)$ 中 $A$ 为负：$\Delta$ 大时 $\bar A$ 接近 0，旧状态被「重置」；输入的系数 $\bar B\approx\Delta B$ 也变大，当前输入被重点写入。$\Delta$ 小时 $\bar A$ 接近 1、$\bar B$ 接近 0，状态原样保留，当前输入被跳过。Mamba 论文正是这样解释的：大的 $\Delta$ 重置状态、聚焦当前输入，小的 $\Delta$ 保持状态、忽略当前输入。论文还指出，在最简单的设定下，选择性 SSM 退化为经典的门控 RNN：$h_t=(1-g_t)h_{t-1}+g_tx_t$。

- A 错：在 Mamba 中，$\Delta$ 恰恰是实现选择性的核心参数。
- B 错：方向说反了。$\Delta$ 越大，$\bar A=\exp(\Delta A)$ 越接近 0，旧状态被遗忘得越多。
- D 错：$\Delta$、$B$、$C$ 都由输入算出，$A$ 本身与输入无关（但通过 $\Delta$ 间接受输入影响）。

为什么需要选择性：在「选择性复制」（从夹杂噪声的序列中只复制有用的 token）和「归纳头」（看到 A B … A 时预测 B）这类任务上，LTI 模型对所有 token 一视同仁，无法按内容过滤；选择性 SSM 能解决这些任务，这被认为是语言建模所需的「基于内容的推理」能力。

<sub>INF-KV-009</sub>　**结论**：PagedAttention 用一个算子上的小损失，换来了整个系统 batch 的大幅提升。

Decode 每步要把权重读一遍，batch 越大，权重读取被分摊得越薄，吞吐越高。以前 KV 显存只有两三成真正用来存 token，batch 被浪费的显存卡住；分页后几乎所有 KV 显存都在存 token，batch 可以大几倍。分页 kernel 要按块表间接寻址、访存不连续，单个算子确实略慢；但注意力 kernel 只是每步耗时的一部分，它慢 20% 对端到端的影响远小于 batch 翻几倍带来的收益。

- A 错：论文在普通的单序列采样上同样报告了明显提升，例如 ShareGPT 负载下可承受的请求速率是 Orca (Oracle) 的 1.7～2.7 倍、Orca (Max) 的 2.7～8 倍；并行采样、束搜索中的 KV 共享是在此基础上的额外收益。
- B 错：长上下文、大 batch 下的 KV 远大于 L2 缓存，分页也不会让访存更「局部」，反而更零碎。
- C 错：PagedAttention 管理的是显存，注意力的计算量一点没少。

**11. C**

<sub>FND-OPT-004</sub>　**结论**：动量是对梯度的「低通滤波」，保留持续一致的分量，抵消来回变号的分量。

- **陡峭方向**：每步梯度方向交替，$v$ 中的正负项相互抵消，振荡幅度变小。
- **平缓方向**：梯度方向持续一致，$v$ 不断累积，稳态时 $v=g/(1-\mu)$；$\mu=0.9$ 时等效步长约放大 10 倍。

物理类比：小球在山谷中滚动，惯性让它沿谷底加速前进，而不会在两侧谷壁之间来回弹跳。对强凸二次函数，合适参数下的（重球）动量可以把收敛所需的迭代次数从 $O(\kappa)$ 量级降到 $O(\sqrt\kappa)$ 量级。

- A 错：动量的方向是历史梯度的加权和，并不总是指向当前最陡的方向，正是这一点抑制了振荡。
- B 错：动量不改变学习率，反而在一致的方向上放大了等效步长。
- D 错：动量只是把历史梯度加权累积，只用到一阶梯度，不估计海森矩阵，也不求牛顿方向。

**Nesterov 动量**先沿动量方向「预走一步」，在预估位置计算梯度再修正，对过冲有更好的抑制作用。

**12. A**

<sub>INF-SPEC-016</sub>　**结论**：EAGLE 让一个轻量的草稿头（约一层 Transformer）在「特征」上做自回归，而不是在 token 上。

论文的两个观察：
1. 顶层特征（LM head 之前的那一层，论文称 second-to-top-layer）比 token 更有规律，在特征层面自回归更容易预测；

- B 错：草稿头需要训练（在目标模型的特征上训练），只是成本很低；截取前几层做草稿是自投机（self-speculative）一类方法的思路。
- C 错：这是 Medusa 的结构，各头独立、互不依赖。
- D 错：这是 Lookahead 解码的思路。

**13. C**

<sub>INF-SCHED-012</sub>　**结论**：预算太小时，每一步都要完整读一遍权重，却只处理几十个 token：线性层的算术强度约等于本步的 token 数，远低于拐点，Prefill 变成带宽瓶颈，TTFT 变长，总吞吐下降。

以 8B 模型为例：每步读权重约 4.8 ms，64 个 token 的计算只需约 1 ms，每步仍约 5 ms，Prefill 速度只有约 $64\div5\ \text{ms}\approx1.3$ 万 token/s；预算为 2048 时每步受算力限制，约 33 ms 处理 2048 个 token，速度约 6 万 token/s。一个 8K 提示词，前者要 128 步、约 0.64 s，后者只要 4 步、约 0.13 s。

所以预算至少要让每步的 token 数（Decode 加 Prefill）明显超过拐点，常见设置在几百到几千之间，再在 TPOT / ITL 的 SLO 约束下通过压测确定。

- A 错：后面的块会读取前面各块已写入的 KV，分块 Prefill 的结果与一次做完相同。
- B 错：每步本来就要读一遍权重，夹带少量 Prefill token 并不会多读；预算越小，每步越短，ITL 越平稳。
- D 错：块哈希只取决于 token 内容和前缀，与分几步写入无关；命中的部分照样跳过。

**14. C**

<sub>LLM-MOE-012</sub>　**结论**：在因果模型里，任何依赖「未来 token」的路由决策都会泄露信息。

ST-MoE 明确说明：容量不足时按从左到右的顺序丢弃，就是为了避免模型作弊；Batch Prioritized Routing 只能用在 Encoder 一侧，用在 Decoder 上模型会学会利用未来 token 的信息来改进当前预测。推理时后面的 token 还不存在，这种「信息」就消失了，效果会下降。

- D 错：每个 token 仍按 top-k 路由，只是在容量内被保留或丢弃，不会被重复计算。

<sub>INF-SPEC-008</sub>　**结论**：无损性的前提是——接受判断中的 $q$ 必须是草稿**实际采样所用**的分布；$p$ 必须是目标模型**实际要采样**的分布（施加温度、top-p 等变换之后的分布）。

- C 破坏无损：草稿实际按温度 0.5 的分布 $q'$ 采样，接受判断却用温度 1.0 的 $q$。证明中「草稿提议 $x$ 且被接受」的概率 $q(x)\min(1,p/q)=\min(p,q)$ 要求两个 $q$ 相同；用错了分布，各 token 的输出概率就不再等于 $p$。
- A 无损：$\gamma$ 只依赖已经生成的内容，不影响「给定前缀时下一个 token 的条件分布等于 $p$」这一性质。
- B 无损：贪心草稿相当于 $q$ 是 one-hot。接受概率为 $\min(1,p(x))=p(x)$；拒绝后从 $\max(0,p-\delta_x)$ 归一化，也就是把 $x$ 去掉后的 $p$ 重新归一化。合起来每个 token 的概率仍是 $p$。
- D 是标准规则本身：拒绝位置之后的草稿以被拒 token 为前提，必须作废。

**16. ABCD**

<sub>FND-MATH-013</sub>　**结论**：A、B、C、D 正确。

- A 对：$E[e^X]$ 就是正态分布的矩母函数在 $t=1$ 处的值，$M(t)=e^{\mu t+\sigma^2t^2/2}$，所以均值为 $e^{\mu+\sigma^2/2}$。由于 $e^x$ 是凸函数，按 Jensen 不等式 $E[e^X]\ge e^{E[X]}=e^{\mu}$；$e^{\mu}$ 是它的中位数而不是均值。对数正态分布取值恒为正、右偏。
- B 对：泊松分布的均值与方差都是 $\lambda$，常用来建模计数数据。
- C 对：$U(-a,a)$ 的方差为 $(2a)^2/12=a^2/3$。代入 $a^2=6/(n_{in}+n_{out})$，得 $2/(n_{in}+n_{out})$，这就是 Xavier（Glorot）初始化的目标方差。
- D 对：$\mathrm{Var}=E[X^2]-E[X]^2=p-p^2$，开口向下的抛物线，在 $p=0.5$ 处取最大值 0.25。

## 三、判断题（每题 1 分，共 10 分）

**22. 错误**

<sub>FND-DL-014</sub>　**错误**。全部相同的初始化会让同一层的所有隐藏单元保持**对称**：
- 它们的输入相同、权重相同，前向输出相同；
- 反向时收到的梯度也相同，更新后依然相同。

无论训练多久，一层里的 $h$ 个神经元都只相当于 1 个，网络容量严重退化。全零初始化更糟：对于 $y=W_2\,\mathrm{ReLU}(W_1x)$，$W_1=0$ 时隐藏层输出为 0，$W_2$ 的梯度为 0；$W_2=0$ 时传回隐藏层的梯度也为 0，参数可能完全不动。

**正确做法**：用随机初始化打破对称性（Xavier、Kaiming 等），并控制好尺度。偏置通常可以初始化为 0，因为权重的随机性已经打破了对称。一个相关的特例是 LoRA 中的 $B=0$：$A$ 是随机初始化的，$B$ 收到的梯度不为 0，所以不存在对称性问题。

**23. 错误**

<sub>LLM-TOK-006</sub>　**错误**。LLaMA 的分词器开启了**字节回退**（byte fallback）：LLaMA 论文写明，未知的 UTF-8 字符会退回字节表示。词表里专门有 256 个字节 token（`<0x00>`～`<0xFF>`），例如「龘」（U+9F98）会被编码成 `<0xE9>`、`<0xBE>`、`<0x98>` 三个 token，信息没有丢失，解码时可以原样还原。

如果 SentencePiece 训练时没有开启字节回退，字符覆盖率（character_coverage）之外的字符才会被映射为 `<unk>`。字节回退的代价是：生僻字占用多个 token，而且这些字节组合训练得少，模型对它们的理解有限。LLaMA 还把所有数字拆成单个数字，这也是它分词器的特点之一。

**24. 错误**

<sub>TRN-DIST-013</sub>　**错误**。ZeRO 只切「存储」，不切「计算」：每张卡仍要对自己那份数据做完整的前向和反向，用到某层时把参数临时拼完整（ZeRO-3）或者本来就有完整参数（ZeRO-1/2）。与相同 micro-batch 的 DDP 相比，每卡的前向、反向计算量完全一样。唯一被切分的计算是优化器更新（每卡只更新自己那 $1/N$ 参数），这在总计算中占比很小。

ZeRO 的代价是通信：ZeRO-1/2 与 DDP 持平，ZeRO-3 约为 1.5 倍。真正把计算分摊到多卡的是数据切分（数据并行）、层内矩阵切分（张量并行）和按层切分（流水线并行）。

**25. 错误**

<sub>INF-SERVE-023</sub>　**错误**。逐步掩码只在每一步局部重新归一化：

$$
P_{\text{mask}}(y)=\prod_t\frac{p(y_t\mid y_{<t})}{Z_t(y_{<t})}
$$

其中 $Z_t$ 是这一步合法 token 的概率之和。拒绝采样得到的是 $p(y)$ 在合法集合上的条件分布 $p(y)/Z$，分母是整个序列层面的常数。只要各步的 $Z_t$ 随前缀变化，两者就不相等：如果模型开头更倾向一个「之后很难写成合法格式」的前缀，掩码只会在后面硬拐，最终结果可能是低概率、不自然的输出。Grammar-Aligned Decoding（Park 等, 2024）专门分析了这种分布扭曲，并提出了修正方法。

**工程启示**：约束解码保证格式合法，但可能把模型逼向不自然的写法。在提示词里写清 Schema 并给出示例，让模型「本来就想」按格式输出，能减小这种扭曲；字段顺序与命名也尽量贴近模型的习惯。

**26. 错误**

<sub>TRN-PEFT-002</sub>　**错误**。两者都为零时：
$$\frac{\partial\mathcal{L}}{\partial B}=\frac{\alpha}{r}\,g\,(Ax)^\top=0,\qquad \frac{\partial\mathcal{L}}{\partial A}=\frac{\alpha}{r}\,B^\top g\,x^\top=0$$
其中 $g$ 是该层输出的梯度。$A=0$ 让 $B$ 的梯度为零，$B=0$ 让 $A$ 的梯度为零，两者永远停在原点（这是一个鞍点），LoRA 支路学不到任何东西。

所以只能让其中一个为零：标准做法是 $A$ 随机（论文用高斯分布，PEFT 库默认用 Kaiming 均匀分布）、$B$ 为零。也有工作换一种思路，例如 PiSSA 用原权重的主奇异向量同时初始化 $A$、$B$，再从 $W_0$ 中减去这部分，同样保证初始输出不变。

**27. 正确**

<sub>LLM-ATTN-037</sub>　**正确**。因果掩码下第 $t$ 个输出只累加 $j\le t$ 的项：
$$\sum_{j\le t}\phi(q_t)^\top\phi(k_j)\,v_j=\Big(\sum_{j\le t}\phi(k_j)v_j^\top\Big)^{\!\top}\phi(q_t)=S_t^\top\phi(q_t)$$
$S_t$ 是 $d\times d_v$ 的矩阵、$z_t$ 是 $d$ 维向量，大小固定，每步更新与读取都是 $O(d\,d_v)$。这正是论文标题「Transformers are RNNs」的含义。

对比 Softmax 注意力：KV Cache 随长度线性增长，单步注意力是 $O(t\cdot d)$。线性注意力的代价是把全部历史压缩进固定大小的状态，精确回忆能力较弱；后续的 RetNet、GLA、Mamba-2 等加入了衰减或门控来更好地管理这份状态。

**28. 错误**

<sub>FND-NLP-003</sub>　**错误**。这些步骤属于词袋 / TF-IDF 时代的预处理，不适用于大模型。

**传统流水线为什么要做**：词袋模型里每个词形都是一个独立特征，「run」「runs」「running」互不相通，「The」和「the」也是两个维度；去停用词、词干化、转小写能合并特征、缓解稀疏，对分类、检索这类只看「有哪些词」的任务影响不大。

**大模型为什么不做**：
1. 大模型要理解并**生成**自然文本，输入和输出都必须是原始文本。删掉「不」「not」「的」会改变语义或语法，词干化会丢掉时态、单复数，转小写会丢掉专有名词、缩写和代码中的大小写信息。
2. 稀疏和未登录词问题已经由子词分词（如字节级 BPE）解决，不需要再靠规范化词形来缩小词表。

大模型语料处理的重点是另一些事：语言识别、质量过滤、去重、去除隐私信息、清理 HTML 残留与乱码，以及按需做 Unicode 规范化（规范化也要谨慎，例如全角半角转换可能影响代码和特定格式文本）。

**30. 错误**

<sub>FND-ML-005</sub>　**错误**。经典的 U 形曲线描述的是插值阈值之前的情形，阈值之后的走势恰好相反。

**双下降（double descent）**：Belkin 等（2019, arXiv:1812.11118）发现，模型复杂度越过「插值阈值」（刚好能把训练集拟合到零误差）后，测试误差会**再次下降**，而且常常低于 U 形曲线的最低点。Nakkiran 等（2019, arXiv:1912.02292）在深度网络上观察到了同样的现象，不仅随模型大小出现，也会随训练轮数出现。测试误差的峰值通常就出现在插值阈值附近：此时模型「刚好够」拟合训练数据，只能用很扭曲的方式去拟合噪声；参数远多于样本的模型往往泛化更好。

**原因**：参数远多于样本时，能完全拟合训练集的解有无穷多个；梯度下降等训练方法带有隐式正则化，倾向于找到「范数较小、较平滑」的那个解，泛化反而更好。

**正确理解**：偏差-方差分解本身仍然成立，只是方差不一定随参数量单调增大。「参数比样本多就一定过拟合」不成立，这也是大模型能在过参数化区域良好泛化的背景之一。

**31. 正确**

<sub>TRN-SFT-018</sub>　**正确**。因果注意力下，位置 $t$ 的预测只依赖 $x_{<t}$。第 $k$ 个 assistant 回合中每个 token 的条件概率，在长样本里和在「以第 $k$ 回合结尾」的拆分样本里，看到的前缀完全相同，位置编号也相同，所以每个 token 的 log 概率一模一样，损失之和相同，梯度也相同。长样本把共享的前缀只算一次，3 个拆分样本则把第 1 轮重复算了 3 次、第 2 轮算了 2 次。

等价性会被以下情况打破：
- 模板会改写历史（如推理模型在历史回合中删掉思考内容），拆分样本中的前缀与长样本不同；
- 超出最大长度被截断；
- 损失归一化方式不同（按样本平均时，拆分后每个回合的权重不同）。
这也是多轮 SFT 通常整段训练的原因。

- **线性缩放**（适用于 SGD，Goyal 等, 2017）：$0.1\times8=0.8$。
- **平方根缩放**（适用于 Adam、RMSprop 等自适应方法）：$10^{-4}\times\sqrt8\approx2.83\times10^{-4}$。

**为什么不同**：从随机微分方程（SDE）近似的角度看，SGD 的「学习率 / batch」决定了梯度噪声的强度，batch 扩大 $k$ 倍时，学习率也扩大 $k$ 倍，才能保持同样的动力学。Adam 的更新经过了 $\sqrt v$ 的归一化，Malladi 等（2022, arXiv:2205.10287）推导出平方根缩放规则：学习率乘以 $\sqrt k$，同时把 $1-\beta_1$、$1-\beta_2$ 都乘以 $k$，$\epsilon$ 除以 $\sqrt k$。

**实践**：两条规则都只是起点。batch 超过「临界 batch size」后，规则会失效；改了 batch 之后，仍需要在小范围内重新搜索学习率，并配合 warmup。

**36.** 128；192

<sub>FND-MATH-018</sub>　**公式**：对相互独立的 $X$、$Y$，
$$\mathrm{Var}(XY)=E[X^2]E[Y^2]-(E[X]E[Y])^2,\qquad E[X^2]=\mathrm{Var}X+(EX)^2$$

**第一问**：$E[q_i^2]=1+1=2$，$E[k_i^2]=1$，$E[q_i]E[k_i]=0$，所以 $\mathrm{Var}(q_ik_i)=2$。64 个独立项相加：$64\times2=128$。

**第二问**：$E[q_i^2]=E[k_i^2]=2$，$E[q_i]E[k_i]=1$，$\mathrm{Var}(q_ik_i)=4-1=3$，合计 $64\times3=192$。此时点积的均值也变成了 64。

**启示**：常见的「点积方差 $=d\sigma_q^2\sigma_k^2$」只在**零均值**时成立。均值不为 0 时，方差（以及均值）会变大，这也是在点积之前常对向量做中心化或归一化的原因之一。用蒙特卡洛模拟（40 万次）验证，两问分别约为 128 与 192。

## 七、编程题（每题 12 分，共 12 分）

**41.** 参考实现：

```python
def span_corrupt(tokens, spans):
    merged = []
    for s, e in sorted(spans):
        if merged and s == merged[-1][1]:     # 与上一个片段首尾相接，合并
            merged[-1][1] = e
        else:
            merged.append([s, e])
    inp, tgt, prev = [], [], 0
    for i, (s, e) in enumerate(merged):
        sentinel = f"<extra_id_{i}>"
        inp += tokens[prev:s] + [sentinel]
        tgt += [sentinel] + tokens[s:e]
        prev = e
    inp += tokens[prev:]
    tgt.append(f"<extra_id_{len(merged)}>")
    return inp, tgt
```

<sub>FND-NLP-031</sub>　**思路**：先排序并合并首尾相接的区间，再一次遍历：区间之前的原文放进输入，区间本身换成哨兵；目标里写「哨兵 + 被遮盖的原文」，最后补一个结束哨兵。

**为什么这样设计**：
- 目标序列只包含被遮盖的片段。T5 默认破坏 15% 的 token、平均片段长度为 3，目标长度大约只有原文的 15% 再加上少量哨兵，解码器的计算量远小于「重建全文」。
- 每个片段用**不同**的哨兵，目标里的哨兵告诉模型「接下来填的是哪一处」，输入和目标之间的对应关系清楚。
- 哨兵是词表中预留的特殊 token（T5 的词表预留了 100 个 `<extra_id_*>`）。

**易错点**：区间没有排序就直接编号，导致哨兵顺序与位置不一致；忘了最后的结束哨兵；把相邻区间当成两个片段（T5 的实现中，连续被选中的 token 本来就构成一个片段）。
